# Latch 界面设计

Latch 是跨设备的 Agent 工作台：任务在 Host 上运行，用户从桌面、浏览器或手机查看、审批、取消并继续同一段工作。界面要同时表达会话内容、执行状态、设备连接与设备权限，且只展示真实存在的能力。传输、续期与阅读位置的机制见 [STREAMING.md](./STREAMING.md)。

日常发送保持相同入口，只有 Host 实际要求首次信任或高风险确认时才展开确认内容。连接手机的默认流程为开启、扫码和电脑允许；网络自动选择。原项目失效时保留可编辑草稿，并就地选择有效项目继续；模型切换结果未知时保留真实选中值，先读取结果，不自动重复写入。详细状态规则见 [项目恢复](./WORKSPACE-RECOVERY.md)、[模型配置](./MODEL-CONFIGURATION.md) 和 [按需加载](./CLIENT-LOADING.md)。

## 品牌与原则

- **名称与图标。** 名称为 Latch。应用图标是炭黑圆角方块、两片象牙色折面与一个橙色接点；`apps/web/public/icon.png`（512px）用于界面、窗口与主屏幕，`apps/web/public/favicon.png`（64px）用于浏览器标签，`build/icon.png` 是高分辨率源图。不要改动图形本身。图标是界面里唯一的暖色元素，不使用它的橙色表达状态。
- **简约、克制。** 蓝白为主：中性的近白与近黑，近黑的墨色文字；深色是近黑的底与柔和的白字，黑不是纯黑、白不是纯白。层次只靠几层平涂的表面（侧栏灰、画布、浮起、凹陷）、1px 的细线与墨色深浅，不靠装饰色、渐变、底纹、插画或表情；玻璃（浮起色的 88% 加模糊）只给菜单与选值这类浮在内容上的层。控件按数据的形状选择，一种意思只用一种画法。
- **每种颜色只表达一件事。**

| 颜色 | 只用于 | 不用于 |
| --- | --- | --- |
| 蓝 | 执行动作的主按钮（发送、允许一次、请求本机确认），每个界面最多一个；被勾选的控件（开关的开、复选框、单选）；焦点环与选中文字的底；跳到别处的链接文字 | 运行中、计数与进度、图标、用户气泡、徽标；菜单里的对勾；列表的选中行（会话行、设置导航）；视图、筛选与外观的选中；切换按钮的「开」 |
| 琥珀 | 等你处理（等你允许、在系统窗口中确认，与等你处理的计数）；警告（连接中断、原内容未知、含不可见字符、已开启的完全访问会话）；演示标记 | 可按的按钮；普通信息；没被选中的选项与常驻的属性（菜单与列表里的完全访问 Harness、Agent 行的 L3） |
| 红 | 真实的失败与风险：高风险（R2）审批、失败、权限模式漂移、审计记录回滚、设备撤销、差异中的删除、危险操作的文字与确认对话框里的销毁按钮 | 完全访问、开发版、停止按钮 |
| 绿 | 差异中的新增；短暂的成功对勾（本机确认后的对勾） | 已连接、已就绪、已检测到、已验证这类默认状态；已保存、已启用这类本地操作的结果（值原位更新就是反馈） |
| 墨色 | 运行中与加载中的转圈、「运行中」与流式光标、未读的对勾、计数与进度、所有静止的图标、菜单里的对勾、列表的选中行（浅色是侧栏灰上的白色卡片，深色是一层柔和的白）、视图与外观的选中、切换按钮的「开」 | — |

- **默认状态安静。** 连接正常、逐项询问、已检测到、已验证的预设这类默认状态不用颜色，也不加标记；顶栏只在偏离默认时出现标记（连接异常、完全访问、演示，以及失败、已取消、已中断、正在取消的会话），运行中与已完成不标；侧栏页脚不写「已连接」。风险色只在风险值真的被选中时出现。
- **内容优先。** 对话列是主角；导航安静，不使用大面积饱和色。只有用户自己的消息有气泡，且是中性的。
- **每个状态只出现一次，并出现在正确的位置。** 会话级状态在顶栏状态标签与侧栏图标；进行中的活动在最新一轮末尾的状态行；等你允许只在它自己的卡片上说一次，卡片不在视野里时由「回到最新」的位置带你回去；单步状态在它的工作行。
- **只展示真实能力。** 选择器只列出 Host 目录中真实的 Harness、模型与项目；只有一个选项时以只读标签显示。演示模型必须带琥珀色"演示"标记。不展示虚构的数量、进度或尚未实现的菜单。设备做不到的操作直接隐藏或停用并说明原因，不让用户提交后再失败。
- **默认隐藏内部细节。** 路径中段省略并提供复制；工具 ID 作为次要文字；空参数显示"无参数"。

自定义插件使用紧凑的列表与编辑对话框；列表先呈现名称、用途与状态，编辑器区分「未保存修改」「草稿」「有未应用修改」「已应用」「已停用」及真实不可用原因。技能正文直接编辑；文件与高级声明另设页签。只有应用执行主按钮使用蓝色。纯技能修改不出现系统确认，新的 Host 或界面模块代码经同一条行内确认流程。丢失响应时保留编辑内容并提供「重试同一请求」，不会创建第二份插件。启用与导出只对已保存状态操作。

个人助手在 Agent 入口里（手机在 Agent 标签页）。列表突出名字和职责，详情先提供新对话，再切换对话与记忆。创建、编辑沿用同一套表单原语；记忆只由用户明确保存。新对话无需选择项目，模型和插件回到助手配置中调整。会话头部和回复署名使用助手的名字；旧 Host 或暂未读到名称时显示「个人助手」。普通项目与个人对话切换时不夹带附件或引用，范围收紧时撤下私有内容。

群聊和例行任务作为个人助手页的内容标签，仅在 Host 声明支持时出现。群聊显示真实共享记录、明确选择的回复顺序与当前轮次；完整执行记录链接到只读成员会话，可一键返回原群，未发送草稿保留在内存。例行任务沿用编辑表单与真实状态，创建后关闭，电脑上明确开启，手机可暂停。隐藏页面停止读取，撤回个人访问立即卸载私有表单与草稿。

已有会话的未发送文字仅在当前工作台内存中按会话保存，最多二十条、合计 256000 个字符；切换只恢复目标会话的文字，不携带附件或文件引用。超出单条上限时保留当前输入并提示先复制。当前会话被其他设备删除时清空活动草稿，不能转入普通新会话；个人访问撤回时移除私有草稿。未知提交仍保留原请求编号。

## 设计令牌

令牌在 workspace 包 `@latch/ui` 的 [tokens.css](../packages/ui/src/tokens.css)，页面的样式入口 [index.css](../apps/web/src/styles/index.css) 第一行导入它。页面的每个颜色、阴影、字号与行高、间距、圆角与时长都只读这些令牌。[styles.test.ts](../apps/web/test/styles.test.ts) 检查：样式表只读已定义的令牌；颜色不写字面值（遮罩与配对二维码的白底除外，二维码在深色下也要深色模块配白底才能扫描）；字号与行高只用角色令牌，字重只有 400、500、600；内外边距与间隔不落在台阶之间；圆角只取台阶上的值（磁贴按边长 × 0.225 取整）。[tokens.test.ts](../packages/ui/test/tokens.test.ts) 核对两种主题的颜色与设计取值一致，退役的令牌名不再出现。

**主题。** 浅色写在 `:root`；深色重写每个含颜色的令牌，同时写在 `@media (prefers-color-scheme: dark)`（仅当根元素没有 `data-theme="light"`）与 `:root[data-theme="dark"]` 下，两份完全相同（tokens.test.ts）。只由其他令牌组成的令牌（`--surface`）只写一次，随主题变化。中性色是不带色相的灰：浅色是近白上的近黑墨，深色是近黑上的柔和白字；悬停与按下是黑（深色是白）加透明度，所以叠在任何表面上读起来都一样。主题偏好（跟随系统 / 浅色 / 深色）按设备保存，写入根元素的 `data-theme`。换主题不播放任何过渡：`switchTheme` 在改写前给根元素标 `data-theme-switching`，base.css 在这期间关掉所有过渡，两帧后再去掉；跟随系统时 `followSystemTheme` 对系统的切换做同样的事。浏览器的 `theme-color` 在每个宽度都取侧栏色（`--sidebar`）：768px 起画布嵌在侧栏色上，手机上会话列表与会话页的页头也在侧栏色上；`index.html` 按配色方案写成两条，选定主题时 `applyTheme` 改写它们（[styles.test.ts](../apps/web/test/styles.test.ts) 核对它们与令牌一致）。manifest 不分深浅，`theme_color` 与 `background_color` 都用浅色的侧栏色；桌面端窗口在首次绘制前的底色与它的错误页也用两种主题的侧栏色。主色在浅色是 `#2461E0`、深色是 `#2F6FEB`，悬停都更深一级（`#1D53C8`、`#2A63D4`），所以蓝底上的白字在两种主题里都至少 4.5:1；蓝色的字（链接）用 `--accent-ink`：浅色是比主色深一点的 `#215BD5`，深色是更亮的 `#6B9BFA`，在每层表面以及叠在上面的悬停与按下上都至少 4.5:1。黑不是纯黑、白不是纯白：浅色正文 `#18181B`，深色正文 `#F4F4F5`；只有浅色的画布与浮起是纯白。深色下应用图标的炭黑方块会和侧栏融在一起，所以沿方块自己的边画一圈 1px 的环（`--app-ring`，浅色下透明）：图片四周有透明留白，环画在留白内侧方块的边上，不画在图片的方框上，图形本身不变。

**表面。** 都是平涂：令牌里没有渐变、底纹与带色相的底（tokens.test.ts）。侧栏色 `--sidebar` 由 base.css 画在根元素与 body 上，外壳、侧栏、图标栏、平板与手机的会话列表、手机的会话页头、设置导航与底部面板都用它；画布 `--canvas` 是对话列与设置的分区内容，768px 起嵌在侧栏色上；浮起 `--raised` 是菜单与弹层、输入框、卡片、对话框与 Toast；凹陷 `--sunken` 是代码块与表头。浅色里画布与浮起都是白色，靠 1px 的线与阴影分开；深色里侧栏最暗，凹陷、画布、浮起依次提亮。列表里被选中的行（侧栏的会话行、设置导航）是 `--selected` 加 `--selected-ring`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 的落影），深色是一层柔和的白；从不用蓝。所有墨在侧栏、画布、浮起、凹陷、用户气泡与选中行上，以及叠在侧栏与画布上的悬停与按下上都达到 WCAG 对比度：正文 `--ink`、次级 `--ink-2` 与红字 4.5:1，提示墨色 `--muted` 与主色 3:1；提示墨色与琥珀字在它们常驻的画布、浮起与侧栏上是 4.5:1，提示墨色在悬停的行上也是，琥珀字在琥珀控件的悬停底上也是；琥珀图形 `--amber-icon` 在这些表面上至少 3:1。`tokens.test.ts` 逐项计算并核对这些下限；调整任何表面、选中或墨色的值都要通过它。

**层叠层。** tokens.css 第一行声明层的顺序：`tokens, base, ui, app, security`。`@latch/ui` 的 [ui.css](../packages/ui/src/ui.css) 把元素默认样式（[base.css](../packages/ui/src/base.css)：盒模型、文档字体与颜色、焦点环、按键、减少动效）导入 base，把每个原语的样式表（`packages/ui/src/styles/`）导入 ui；页面的 index.css 先导入 tokens.css 再导入 ui.css，然后把自己的每个样式表导入一个层：还没有做成原语的共用部件（`ui.css`：品牌图标、状态点、字母磁贴、进度条、表单字段与值选择 chip）也在 ui，页面自己的布局与界面在 app，登记、设备、权限与本机确认的样式（`auth.css`、`security.css`）在最上面的 security。后面的层总是胜过前面的层，与选择器的权重无关，所以页面可以在 app 层按位置调整原语，安全相关的界面不会被普通样式改写；新增的安全界面放进 security 层。

**安全界面的锁定。** 审批、登记、配对与确认带 `data-secure`，样式放 security 层。

| --- | --- | --- |

| 阴影 | `--sh-1`、`--sh-pop`、`--sh-dialog`、`--sh-accent`、`--sh-thumb`、`--sh-tip`、`--seg-on-shadow` | `--sh-pop` 与 `--sh-dialog` 自带 1px `--line` 环，带它们的元素不再加边；深色的阴影更深，浮层在顶部加一条内侧的亮线。`--sh-1` 给描边按钮与输入框（composer）；`--sh-pop` 给菜单、弹层、Toast 与「回到最新」；`--sh-dialog` 给对话框、底部面板与抽屉；`--sh-accent` 是主按钮的内侧高光与淡蓝落影；静止的行与卡片不带阴影 |
| 主色 | `--accent`、`--accent-hover`、`--accent-ink`、`--accent-soft`、`--on-accent` | `--accent` 是白字下面的蓝底（主按钮、发送）、焦点环与被勾选的控件，浅色 `#2461E0`、深色 `#2F6FEB`，悬停更深（`#1D53C8`、`#2A63D4`），白字在蓝底与悬停上都至少 4.5:1；蓝色的字（链接）只用 `--accent-ink`（浅色 `#215BD5`、深色 `#6B9BFA`），在每层表面上都至少 4.5:1；焦点环是非文字，3:1 即可；`--accent-soft` 只给焦点外晕与选中文字的底，没有其他蓝色的底 |
| 琥珀 | `--amber`、`--amber-icon`、`--amber-soft`、`--amber-line` | 只表示等你处理与警告：`--amber` 是文字，`--amber-icon` 是图形（盾牌、三角），琥珀永远落在中性表面上，不做底色：`--amber-soft` 只是琥珀控件（连接状态）的悬停底（叠在浮起上为 `#FCF4EB`、`#2A251C`），`--amber-line` 只是行内不可见字符标记的描边 |
| 红与绿 | `--red`、`--red-solid`、`--red-soft`、`--red-line`、`--green`；差异 `--diff-add`、`--diff-del`、`--diff-add-word`、`--diff-del-word` | `--red` 是失败与风险的文字与图形，`--red-solid` 只给确认对话框里的销毁按钮；`--green` 只给差异里的新增与短暂的成功对勾。差异只染行背景，文字保持 `--ink`，加减号与行数用色调文字 |
| 控件 | `--seg-on`、`--switch-off`、`--tip-bg`、`--tip-ink`、`--app-ring`、`--preview-light-a`、`--preview-light-b`、`--preview-dark-a`、`--preview-dark-b` | 分段控件的选中块、关闭的开关轨道、提示框（浅色是近黑底配白字，深色是比浮起亮一级的灰）、深色下应用图标的环、图片预览的透明棋盘格 |
| 语法 | `--syn-plain`、`--syn-keyword`、`--syn-string`、`--syn-comment`、`--syn-number`、`--syn-function`、`--syn-constant`、`--syn-punctuation` | 代码高亮；在画布与凹陷上普通角色 4.5:1、注释 3:1（tokens.test.ts） |
| 字级 | `--fs-<角色>`、`--lh-<角色>`、`--lh-<角色>-para`、`--ls-mono-display` | 角色有 meta（11/14：按键、元信息）、caption（12/16：状态词、说明、侧栏第二行）、ui（13/18：行、菜单、按钮）、input、prose（14/24：对话正文）、heading（15/22：分区标题）、title（20/28：页面标题）、hero（24/32：问候）、mono（12/18：界面里的路径与命令）、code（12/20：代码块）、term（12.5/18：终端）、mono-display（核对码）。每个角色一个字号、一个单行行高，可能换行的角色另有段落行高；手机（<768px）整体换大一档，界面 15/20、正文 16/26，输入 16px 防止 iOS 聚焦时缩放。字重只有 400、500、600：600 只给卡片标题、标题、问候、核对码与品牌名，界面框架不超过 500，正文里的强调用 500，未读不加粗。字距为 0，只有核对码用 `--ls-mono-display`；时间、计数与表格数字用等宽数字 |
| 字体 | `--font`、`--mono` | 平台系统字体与中文字体，不加载网络字体；等宽用于代码、参数、工具 ID、设备指纹、核对码与内容哈希 |
| 间距 | `--sp-2` 到 `--sp-64`、`--bleed` | 台阶为 2、4、6、8、10、12、16、20、24、32、40、48、64；2 与 6 只在控件内部；14、18、22、26 不是台阶。可悬停的行可以向两侧外扩 `--bleed`（6px），让文字仍对齐列边 |
| 圆角 | `--r-2`、`--r-4`、`--r-6`、`--r-8`、`--r-12`、`--r-16`、`--r-full` | 4 给按键与徽标；6 给列表行、标签页、小按钮与提示框；8 给按钮、输入框、菜单、代码块与 Toast；12 给卡片、设置分组与弹层；16 给输入框（composer）、对话框、用户气泡与底部面板；`--r-full` 给发送与停止、状态点、lg 按钮与胶囊；2 只给 4px 细条；嵌套圆角等于外圆角减内边距；磁贴按 round(边长 × 0.225)。圆角矩形不加 `corner-shape` |
| 动效 | `--m-micro`、`--m-enter`、`--m-panel`、`--m-sheet`、`--m-push`；`--e-micro`、`--e-enter`、`--e-panel`、`--e-sheet`、`--e-push`、`--e-exit` | 见下面的「动效」 |
| 布局 | `--sidebar-width`、`--sidebar-open-width`、`--inspector-width`、`--inspector-open-width`、`--content-width`、`--gutter`、`--topbar-height`、`--shell-inset`、`--touch` | 见「布局」；侧栏与会话信息栏的宽度由页面写在外壳上 |

**动效。** 动效说明因果：短、安静、有物理感，没有空闲时的动画。五档时长各配一条曲线：`--m-micro` 120ms（悬停与按下的底、图标替换、状态词与标签页内容的交叉淡化；`cubic-bezier(.2, 0, 0, 1)`）、`--m-enter` 160ms（菜单、弹层与提示框从 98% 放大并淡入，消息与行的到达；`cubic-bezier(.2, .8, .2, 1)`）、`--m-panel` 200ms（侧栏收起、会话信息栏的宽度、展开与折叠的网格行）、`--m-sheet` 260ms（对话框从 98.5% 放大并淡入、底部面板、平板的会话列表）、`--m-push` 320ms（手机的推入与返回）；后三档是同一条 `cubic-bezier(.32, .72, 0, 1)`。离开用进入时长的 70%，配退出曲线 `cubic-bezier(.4, 0, 1, 1)`。脚本里要按过渡计时的地方读 `MOTION`（`micro`、`enter`、`panel`、`sheet`、`push` 与各自的 `…Exit`）与 `EASING`，[motion.test.tsx](../packages/ui/test/motion.test.tsx) 核对它们与令牌相等。会循环的只有运行中的转圈、「正在思考」的光带、检测中磁贴的进度弧、加载骨架与流式光标；除流式光标外，它们离开视野时都暂停。减少动效（`prefers-reduced-motion: reduce`）时 tokens.css 把五档缩到 120ms 以内（micro 100ms，其余 120ms）；没有全局规则，每个样式表只保留它所移动之物的淡入淡出（不滑动、不缩放、不长高、不转动），原语的关键帧换成只有不透明度的版本，循环停在静帧。换主题时不播放任何过渡（见「主题」），拖拽中跟手的部分也不做过渡。

语义文字色除了满足现有对比度检查，还按 [Chromium 的色觉缺陷模拟矩阵](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/css/vision_deficiency.cc) 检查红、绿、蓝三类色觉缺陷。浅色与深色的蓝、琥珀、红、绿逐对转换到 OKLab，色差 `100 × ΔE` 至少为 3，用于防止近似同色；这不是可访问性合格的独立判据。状态始终同时带文字和图形。

## 布局

断点定义在 [breakpoints.ts](../apps/web/src/breakpoints.ts)，CSS 媒体查询使用相同数值；侧栏另在 1440px 处变宽。

| 宽度 | 结构 |
| --- | --- |
| ≥1024 桌面 | 52px 标题行横跨窗口；其下是 52px 图标栏、紧贴图标栏的面板（默认 248px，可调宽与收起，见下）、主区域与右侧面板（默认 520px、未打开，放不下时换成浮层，见「会话信息栏」）。画布铺满，不再嵌在侧栏灰上，只在面板收起时由图标栏的 1px 内线隔开。消息列最大 760px 居中。 |
| 768–1023 平板 | 标题行与图标栏不变；会话入口的面板是浮在左侧的一张侧栏灰，从标题行下开始（桌面端不盖住红绿灯），带浮层阴影与遮罩（`Scrim`），以 `--m-sheet` 滑入、它的 70% 滑出（减少动效时只淡入淡出）；其余入口保留 200px 的行内分区列表。右侧面板放得下时并排，否则是浮层。 |
| <768 手机 | 页面叠放（见下面「手机的页面栈」）：根页共用底部标签栏（会话、Agent、设置）；会话列表是根页；会话页推入在列表之上，页头在侧栏灰上，对话是一张画布；新会话是列表上的底部面板；会话信息是推入的整页；选择器、菜单与本机确认使用底部面板；输入框贴底并留出安全区；触控目标至少 44px。 |

平板的会话列表打开时主区域与图标栏设为 `inert`，焦点限制在列表内，Esc 关闭后焦点回到打开按钮。对话框与底部面板同样捕获并恢复焦点。

**标题行与入口。** 标题行（[TitleBar.tsx](../apps/web/src/shell/TitleBar.tsx)）左端是桌面端红绿灯的内边距与「收起侧栏」，面板收起时还有「新建会话」与带琥珀计数的「等你处理」；其余是对话的头部，或其他入口的标题。桌面端（macOS 用 `hiddenInset`）靠它移动窗口，控件除外，有对话框、弹层或抽屉时不移动；窗口最小 768px，保证它一直在；登记、连接与崩溃页没有标题行，画一条同高的拖动带。图标栏（[Rail.tsx](../apps/web/src/shell/Rail.tsx)）上面是会话、Agent、自动化、插件，下面是手机、设置，⌘1–⌘4 与 ⌘,（浏览器用 Alt）切换；连接有问题时手机上方是一个琥珀或红色的点，提示写出原因；有会话在等你处理且不在会话入口时，会话图标带一个点。入口与分区的对应在 [routes.ts](../apps/web/src/shell/routes.ts)：窗口跨过手机断点时留在同一分区；手机只有三个标签，自动化归 Agent，插件与手机归设置。设备不能用的分区不画，全部不能用的入口也不画。切换入口不卸载会话：页面盖在会话各栏上，阅读位置、草稿与面板不变，被盖住时快捷键不作用于会话，需要会话的命令（面板里的搜索、打开文件）先回到会话。冷启动打开新会话，重新加载回到打开的会话。

**手机的页面栈。** 手机不放并排的栏，而是一页叠一页（[PhoneSessionList.tsx](../apps/web/src/components/PhoneSessionList.tsx)、[NewSessionSheet.tsx](../apps/web/src/components/NewSessionSheet.tsx)，样式在 `phone.css` 与 `phone-*.css`）。

- **会话列表是根页**，在画布上：52 高的头行是 22/30·600 的「会话」与 44 的墨色幽灵按钮（新建会话），下面是常驻的搜索框；再往下依次是「等你处理」（有时才有，组名后是中性计数）、每个项目、「对话」，分组规则与侧栏相同，置顶的会话排在各自分组的最前面并带一枚图钉；组名旁一条 `--line` 细线，项目组右端有「在 … 中新建会话」，列表末尾是「已归档」；点开后顶部有返回的一行。还没有会话时，列表开头左对齐地写「还没有会话」（次级墨色）、一行提示墨色的说明与 xs 次按钮「新建会话」，不放插画。列表末尾是一行提示墨色的 `laptop` 图标与运行 Host 的电脑名称，右端是幽灵按钮「同步最新状态」（重新读取 Host 的状态，进行中转圈）：连接正常时也能在列表上同步，没有会话时同样在。
- **行高 64**：第一行是标题（有事要你看时 `--ink`·500，否则 `--ink-2`）与状态槽（与侧栏同一套词）；第二行是 16 的引擎图形（单色）、Agent 名称与一件事：在「等你处理」里是项目，其余是分支，有结果未知时是「N 条结果未知」。文件数尚无来源（`TaskSummary` 没有这个字段），所以不写。没有会话内容的预览：Host 不提供。行间是一条 `--line`；按下与被打开的那一行是悬停底。按住一行（触屏或手写笔 500ms，或右键与上下文菜单键）打开这个会话的菜单底部面板（重命名、置顶、归档、导出 Markdown、删除；重命名与删除再各开一个「取消 · 问题 · 动作」的底部面板），这次松手不会打开会话；菜单开着时这一行保持按下的底色，看得出菜单属于哪一行。
- **搜索**：搜索框按标题即时过滤，并搜索正文；使用时右边出现「取消」，它清空搜索并离开输入框。桌面与平板没有这个搜索框：面板里的「搜索」打开命令面板。
- **新开的标签页**停在会话列表上（桌面与平板打开最近的会话）；重新载入的标签页回到它上次打开的会话。
- **会话页**推入在列表之上：新的一页以 `--m-push` 从右侧滑入，列表同时左移 24% 并在遮罩色下变暗，被盖住时设为 `inert`，焦点移到新一页的返回按钮（从新会话面板开始的会话同样如此）；返回（页头的「返回会话列表」）反向，页面以退出曲线用 70% 的时长滑出后才放开这个会话，焦点落回它在列表里的那一行。随页面一起载入的会话直接在那里，不滑入。减少动效时页面只淡入，什么都不移动。页头在侧栏灰上（52 加安全区）：左侧 44 的返回，中间居中的标题按钮（16/22·600 加常显的向下箭头，打开会话菜单的底部面板：重命名、置顶、归档、导出 Markdown、删除与「同步最新状态」），标题下面一行是提示墨色的「Harness · 项目」以及不是默认时的状态词、完全访问、演示与连接状态，右侧 44 的「会话信息」。刚开始的会话在 Host 列出它之前就已推入：这时页头的形状不变，标题写「新会话」，标题菜单、下面一行与「会话信息」等它被列出后出现。对话是页头下面一张从下往上铺开的画布：上圆角 16、1px `--line` 描边，文字在画布顶部 4–18px 之间淡出，永远不压在圆角下；横幅在画布的顶部，输入框浮在画布内底部，只有一行：静止时 52 高，发送或停止在这一行的右端；内容变多时按行长高，按钮留在最后一行旁边。模型与 Agent 的选项在「会话信息」里改（选择器在手机上是底部面板，触屏上值后面的箭头常显）；下一条消息要换模型时，会话信息写出「下一条消息起使用 …」与「撤销切换」，输入框上方只多一个说明它的小块，输入框本身仍是一行。
- **新会话**是列表上的底部面板（打开即停在窗口的 92%）：「取消 · 新会话 · 开始」，没有内容或不能开始时开始不可用。先是与桌面共用的紧凑 Harness 选择：内置 Agent 与只对话分成两项，不能选的项保持可聚焦并说明原因，末尾的「添加 Agent」在嵌套面板里列出预设并原地添加。打开时焦点在选中的磁贴上，键盘不会立即弹出。下面的画布卡片显示电脑（只读）、项目（只对话时不显示）与模型，各自打开底部选择面板，包含与桌面相同的添加和管理入口；只有旧 Host 没有目录时才保留方式分段控件。演示模型有明确标记；缺少模型时在引导卡片里添加服务。输入框五行高，正文在固定高度的面板内滚动，原因换行时页头不动。取消保留草稿；开始后面板收起、会话页推入。每个嵌套面板使用自己的高度档位，不继承外层的 92%。新会话不绘制环境背景。
- **返回**：推入的每一页（会话页、会话信息、设置与它的每一级）和每个底部面板打开时都在浏览器的历史里占一条（地址不变，[backStack.ts](../apps/web/src/hooks/backStack.ts)），所以平台的返回（Android 的返回键、iOS 的边缘滑动、浏览器的后退）关闭最上面的那一层，而不是离开 Latch；会话页用同样的滑出（浏览器自己已经画了返回时不再滑），焦点回到列表里的那一行。在页面上关闭的一层把它那一条还回去（一次后退越过所有不再有人用的条目）；与此同时打开的新一层接着用这一条，不会被这次后退关掉。重新载入时随页面回来的会话用原来那一条，不另加；没有对应层的旧条目在后退时被跳过。

**页面入口。** Agent、自动化、插件、手机与设置共用一个页面（[SettingsPage.tsx](../apps/web/src/settings/SettingsPage.tsx)），不是模态，盖在会话各栏上，本机确认对话框照样开在它上面。768px 起，入口的分区列表放在紧贴图标栏的面板位置（1024px 起与面板同宽，平板 200px），分区行 32 高、8 圆角，选中是选中卡片与 500 字重，图标不变蓝；入口落在第一个分区，标题写在标题行；分区内容在主区域，最宽 720px 居中，上下各 48px。分区里的页面（某个 Agent、某个模型服务、「其他设备可用的项目」这类列表，[navigation.tsx](../apps/web/src/settings/navigation.tsx)）在 768px 起原地替换分区内容，上方一个幽灵的返回链接写着上一级的名称。手机上每一级都是一页：分区列表是标签页的根页面，分区从右侧推入，分区里的页面再推入在分区之上，各有自己的标题栏与返回按钮（读屏名称说出回到哪一级），返回留在分区所属的标签页；新的一页以 `--m-push` 从右侧滑入，上一页同时左移 24%，盖住后从阅读顺序中移除，返回是同一滑动的反向；一级只有一个返回，页面里不再有返回链接。第一次进入分区也是滑入：分区在进入标签页时就排在屏幕外。换分区、进入分区里的页面或从页面回到分区时内容从下方 4px 淡入（120ms）。减少动效时手机的各级只交叉淡化（120ms），其余只淡入。Esc 在手机上回到上一级。

**会话面板。** 上面是「新会话」与「搜索」（32，幽灵行，快捷键是普通文字）；下面依次是「等你处理」（有时才有，中性计数）、每个项目、「对话」和安静的「已归档 N」。组头 20 高、没有分隔线，字是 12/16·500 `--muted`；悬停时出现折叠箭头（折叠后常显并写出条数）与右端的 ＋、⋯，折叠状态每台设备各记各的。置顶的会话排在各自分组的最前面，带一枚图钉。

已读的会话一行（32）：标题（`--ink-2`）加一个信号，`TaskSummary` 没有文件数，所以这个信号是时间；Agent、引擎与分支在提示里。有事的会话两行（52）：标题加状态槽，第二行是单色的引擎图形、Agent（会话还不记录 Agent，都写「通用」）与一件事。悬停时状态让位给「归档」与 ⋯。

状态词只说 Host 说过的（[sessions.ts](../apps/web/src/sessions.ts) 的 `rowStatus`），变化每秒最多一次，时钟只在这一格里每秒更新：

| 情况 | 状态槽 | 进「等你处理」 |
| --- | --- | --- |
| 审批或提问 | 琥珀「等你处理」（侧栏里分组已说明时不带盾牌，手机上带） | 是 |
| `live.silent` | 琥珀「没有动静 3 分钟」，从 `lastEventAt` 算起；不会因为时间长自己下这个判断 | 是 |
| 引擎发来不认识的请求，之后再无动静 | 琥珀「等你处理」；引擎一有动静，Host 让列表重读，这一行回到运行中 | 是 |
| 运行中 | 蓝色转圈加「运行中 1:12」，从 `live.runStartedAt` 算起，不含等人的时间；旧 Host 没有这个字段时不写时间 | 否 |
| 停止中 | 「正在停止」，直到这次运行真正结算；此前等你处理的会话也离开这个分组 | 否 |
| 结算后 | 「已停止」「已中断」（一行、`--muted`）；「已强制停止」与结果未知时是琥珀，第二行写「N 条结果未知」 | 否 |
| 失败 | 红色「失败」 | 否 |
| 连接中断 | 运行中与等待中的行不转圈也不计时，第二行写「上次确认 10:42」；已结束的状态不变 | 不变 |

归档后行淡出，面板底部出现「已归档 · ⌘Z 撤销」；输入框有焦点时 ⌘Z 仍归输入框。权限模式变化不在行上画红，由会话自己说明。

**可调宽的侧栏（1024px 起）。** 侧栏的内侧边缘（对话画布的左边框）是调整宽度的把手（`ResizeHandle`，见「界面原语」）：宽度在 220–400px 之间，默认 248px，对话画布始终至少 480px，拖拽中与窗口变窄时都按此收紧（会话信息栏并排时也算上它）；双击恢复默认宽度。拖到 160px 以下就收起，与标题行「收起侧栏」按钮是同一个状态：侧栏的格道滑到 0（`--m-panel`），内容保持原宽被裁切、不重新换行，收起后不可聚焦；拖拽越过这个点时（收起，或把收起的侧栏拖出来）格道同样滑过去，而不是跟着指针一下跳到位，之后的宽度才继续跟手。标题行的「新建会话」（有会话等你时还有带琥珀计数的「等你处理」）随格道一起展开与收起（宽度与淡入都是 `--m-panel`，淡出是 `--m-micro`）；侧栏打开时它们不可聚焦，也不在无障碍树里。⌘K 打开命令面板，不动侧栏；展开或从窗口左缘拖出时回到上次的宽度。键盘：把手可聚焦，←/→ 一步 8px（Shift 32px），Home/End 到最窄与最宽，Enter 收起或展开；用标题行的按钮收起、展开时，焦点移到做相反动作的那个按钮。拖拽中跟手的宽度不做过渡、不选中文字，指针由把手捕获。宽度与收起状态按设备保存在本地偏好里（从不发给 Host），读不到或不合规的值按默认处理。平板与手机没有把手。

**会话信息栏。** 打开的会话的信息（[Inspector.tsx](../apps/web/src/components/Inspector.tsx)，放法在 [panelLayout.ts](../apps/web/src/shell/panelLayout.ts)）是侧栏灰上的一列按细线分组的内容，按剩余宽度并排或显示为独立页面。顶栏的「会话信息」切换按钮在每个宽度都有（打开时是中性的悬停底）。768px 起它是外壳网格的最后一列：打开与关闭时格道滑动（`--m-panel`），内容保持打开时的宽度被裁切，不重新换行。它朝画布的边缘是调整宽度的把手（`ResizeHandle`）：默认 520px，360px 到窗口的 70%，双击复原；对话放不下 480px 时换成盖在对话上的浮层，浮层可以拖窄，窄到放得下就回到并排。手机上换成一页：页面从右侧推入（`--m-push`），对话在下面向左移四分之一，返回时反向（70% 的时长），焦点进入页面，返回后回到切换按钮；对话在页面下保持挂载并设为 `inert`，阅读位置不变；切换会话时页面关闭。未打开过时不打开，打开状态与宽度记在本设备；块的收起记在同一份本地偏好里，从不发给 Host。 默认信息块使用留白与底部分隔线，不叠加独立卡片边框。插件包提供的会话面板用同一区域顶部的页签切换，使用现有的窄屏页面与返回行为。

## 界面原语

原语在 workspace 包 `@latch/ui`（[index.ts](../packages/ui/src/index.ts)），是 React 组件加上它们在 ui 层的样式。页面从这里取按钮、状态词、开关、分段控件、选值、菜单、对话框、提示与磁贴，不再各自画一份；同一种意思只有一种画法。样式只读令牌。类名以 `ui-` 开头，变体与尺寸写在 `data-variant`、`data-size`、`data-tone` 上，状态直接用 ARIA 属性（`aria-pressed`、`aria-checked`、`aria-expanded`、`aria-disabled`、`aria-busy`、`aria-invalid`），所以样式跟着可访问性状态走，不另设状态类。

**交互约定。** 悬停与按下的底在 `--m-micro` 里变化；列表里选中的切换同样是交叉淡化，不做滑动的选中块。按下时按钮缩到 97%（打开菜单的按钮、禁用与运行中的按钮以及减少动效时不缩），其余控件按下只深一档（`--press`）。禁用的控件用 `aria-disabled`：整个控件降到 45%，仍能用键盘聚焦，提示框说明原因，点击与表单提交都被拦下（不用原生 `disabled`，否则原因无人能读）。键盘焦点是 2px 的蓝色描边，画在元素边内 2px（`outline-offset: -2px`），所以滚动容器裁不到它；实心的主按钮与销毁按钮画在边外 2px，衬着所在的表面。成组的单选控件（分段控件、文字标签页、筛选、单选列表）整组只有一个 Tab 停靠点，方向键移动并立即选中，Home / End 到首尾，跳过不可选的项。弹层与菜单在顶层（top layer）显示，滚动容器与对话框都裁不到它；打开时焦点进入当前项或第一项，Escape 关闭并把焦点还给触发器，Tab 离开即关闭，点外面或滚动让触发器移动了 1px 以上时关闭（打开时把触发器滚进视野的那次滚动、别处的滚动都不算）。手机宽度（<768px）下，菜单、选值与弹层都换成底部面板。对话框与底部面板里 Tab 只经过真正的 Tab 停靠点（`tabindex="-1"` 的菜单项和单选组里的其余项不在其中），从最后一个回到第一个。

**图标与转圈。** Lucide（ISC）线性图标只用 12、14、16、20、24 五个尺寸，描边 1.75，最小的 12 与 14 是 2；`ICON_STROKE` 按尺寸取值，用其他尺寸时类型检查失败。静止的图标是提示墨色，悬停与激活时是正文墨色，和文字放在一起时随文字颜色；图标只在表示状态时带色相：失败是红色的 `circle-alert` 或三角，等你处理是琥珀色的盾牌，被选中的完全访问是琥珀色的 `shield-alert`。箭头各有一种意思：向右是进入下一层或展开（展开时转 90°），上下双箭头是原地选值，向下是下拉动作。停止是 10×10、圆角 2 的实心方块，不是描边图形。转圈（`Spinner`）是一圈当前颜色 22% 的轨道加满色的上四分之一，800ms 一圈，12、14、16 的线宽 1.5px，20 的 2px；页面上所有转圈按文档时间线对齐相位，并排时不会错开；离开视野时暂停，减少动效时停在静帧。它表示正在进行的事：运行中的 Agent 与工具、加载行、按钮运行中、取消中；颜色随所在的文字，状态词与过程行里是墨色。

**按钮。** 尺寸只有四档：xs 24（圆角 6、12/16 字：提示与行内的动作、回合脚部与会话信息里的行内动作）、sm 28（桌面默认：页头、卡片按钮行、行尾）、md 32（对话框与面板的脚部）、lg 44（手机，胶囊形）；圆角 8、13/18·500，带前导图标时起始内边距少 4。变体：主按钮（primary）是一个界面里唯一的蓝色，只给执行或创建的动作（发送、允许一次、请求本机确认、添加服务），带一层内侧高光与淡蓝的落影；「保存」「保存默认值」这类不执行操作的确认用次按钮。次按钮（secondary）是悬停底那样的中性填充，没有环，悬停换成按下的深度；描边按钮（outline）是浮起的表面加一圈 `--line-strong` 与 `--sh-1`，用在要和静止内容分开的地方；放在警告或红色调的容器里（容器标 `data-tint`，内联提示自己会标）时次按钮也换成描边的样子，因为半透明的墨叠在红色调上会发脏，警告里与它保持一致。幽灵按钮（ghost）是次级墨色的字，悬停时出现底并换成正文墨色，用于工具栏、行尾与「重置」这类安静的动作；链接样式只用于跳到别的页面或位置（`ButtonLink` 是同样画法的 `<a>`），悬停时出现点状下划线；页面上的危险操作（danger）是红字的描边按钮；实心红（destroy）只在确认对话框里。运行中的按钮宽度不缩、前导位换成转圈、文案可以换成进行时（「检测中…」），并标 `aria-busy`，不再接受点击；运行中的按钮不算禁用，页面同时禁用它时也不降透明度，主按钮运行中仍是蓝色。快捷键写在提示框里（「允许一次 ⌘⏎」），从不放进按钮。每张卡、每个对话框脚部与面板头部最多两个可见按钮，次在前、主在最后，第三个动作进 ⋯ 菜单。图标按钮是 24、28（圆角 6）、32（圆角 8）、44（圆形）的正方形（图标 14、16、16、20），名称同时是它的提示框；静止是提示墨色，悬停是悬停底与正文墨色；切换按钮的「开」与菜单打开时的触发器（`aria-expanded`）也是悬停底与正文墨色，不用蓝；输入框里的发送与停止是圆形。图标按钮的面（悬停、按下与「开」的底，以及键盘焦点环）按它自己的尺寸画在中间，所以在任何屏幕上看起来一样大；触屏上它的盒子长到 44×44，工具栏与图标栏里相邻的按钮因此相隔 44，点按区不重叠；页面在密集的行里保留较小的盒子时（回合脚部的复制、列表头的筛选），透明的点按区仍伸到面四周的 44×44。计数放在面的右上角外 4px，垫着一层所在表面的颜色并镂空一圈 2px（`--surface`），字形不被遮住。`--surface` 默认是画布色；放在别的表面上的容器把它改成自己的颜色：图标栏与侧栏在侧栏色上，所以是侧栏色；菜单、弹层、对话框、Toast 与单选列表是浮起色，底部面板是侧栏色。

**提示框。** 悬停 400ms 后出现，键盘聚焦时立即出现；离开、按下或 Escape 立即消失；一个提示框消失后的 300ms 内移到相邻的控件时，新的提示框立即出现，并从上一个的位置滑到新位置（`--m-micro`），不再从头淡入。提示框是反色的：浅色里是近黑底配白字，深色里是比浮起亮一级的灰；圆角 6、至少 24 高、12/16 字、最宽 320，从 98% 放大并淡入（`--m-enter`），不接收指针；提示文字同时是触发器的读屏描述（图标按钮的名称已经是同一段文字时除外）。禁用控件的原因（按钮、图标按钮、选值）、开关与分段的说明和开发版标记的整句都用它，不用浏览器原生的 `title`。触屏上不出现。

**状态词、徽标、计数、状态点与按键。** 状态用几个字说出，最多带一个 12 的图形，颜色就是它的意思（`StatusWord`，12/16·500、等宽数字）：等你处理是琥珀字加盾牌，运行中是墨色字加转圈（「运行中 1:12」随计时不变宽），失败是红字加 `circle-alert`，已完成是墨色字加对勾，警告（不可用、演示、原内容未知）是没有图形的琥珀字，其余（已停止、已停用）是提示墨色。状态没有胶囊，也没有前导点；`StatusPill` 按页面与插件面板用的 `Tone`（`neutral`、`warn`、`err`、`ok`）画同一种状态词：提示墨色、琥珀字、失败与已完成；插件面板经 `PluginPanelProps.ui` 拿到它。徽标（`Badge`）是跟在名字后面的属性（默认、本机、内置、离线、开发版、演示）：18 高、圆角 4、11/14·500，中性是淡填充配提示墨色，琥珀是同样的中性淡填充配琥珀字，红是淡红底配红字；它从不表示卡片或行的状态。计数（`Count`）是 12/16·500 的等宽数字，不加底，超过 99 写 99+：被动计数随周围文字，新结果是墨色，等你处理是琥珀；页面亲眼看到计数变了时新数字淡入（`--m-micro`）。状态点桌面 6、手机 8，琥珀与红点总要和文字或图形一起出现，叠在磁贴上时用所在表面的颜色（`--surface`）镂空一圈。按键（kbd）是 18 高、圆角 4 的浮起小块，一圈细线、11/14·500 提示墨色，只出现在提示框、菜单项尾部、搜索框与审批卡聚焦时的提示行里。

**选值（ValuePicker）。** 在原地从一组互斥的值里选一个，只显示当前值：幽灵、28 高（会话信息里是 24、箭头只在悬停或聚焦时出现；触屏上常显）、值 13/18 常规字重、末尾上下双箭头，前导、值与箭头彼此相隔 6。值总是紧跟前导（没有前导时从内边距开始），所以会话信息里外扩的一列值与列的边缘对齐；手机设置面板里的值离箭头 6，同一张卡的值右缘对齐。悬停与菜单打开时是悬停底，值换成正文墨色；只有一个可能值时是不可点的文字；没有选择时写「选择模型」这类说法，用提示墨色，不用警示色。读屏名称是「标签：值」。菜单打开时焦点在当前值上，Enter 选中，可以按首字母跳转；不可选的值也能聚焦，下面一行带禁止图标的原因保持原色并被读出。选中即生效，不弹提示；值改变时淡入（`--m-micro`）。调高权限这类要验证的改动返回一个 Promise，等待期间前导位是转圈、值换成「等待验证…」，取消验证时值不变。箭头不动：设置行尾部的选值向左伸展；输入框工具栏里左对齐的权限菜单（`reserve`）预留值与「等待验证…」中较宽的宽度，多出的宽度留在值和箭头之间。只有可能等待验证的选值才预留，模型、项目这类选值、会话信息的 24 高选值与手机行都不预留。设置行尾部的选值按 `--bleed` 向右外扩 6px，使箭头与同卡导航行的箭头对齐。长列表可以带搜索行。值可以带自己的图（`media`，Harness 或模型服务的磁贴），放在勾选槽之后；一组值可以在组标题前带服务的磁贴。值与列表里的写法不同时（下一条消息才生效的模型切换，「下一条：…」），`valueText` 写出触发器上显示的话，读屏名称随之改变。`panel` 让弹层原地换成一块小面板（在选值的地方添加一个值，例如从「添加模型服务…」进入），弹层保持打开，手机上由底部面板承载；面板与脚部动作用 `useLayerClose` 关闭所在的弹层，焦点回到触发器；`onOpenChange` 报告每一次打开与关闭。只有一个可能值、又没有脚部与面板时才显示为不可点的文字。禁用的选值降到 45%，原因在提示框里。手机上是底部面板里的单选列表，打开时焦点在当前值上（单选组唯一的 Tab 停靠点），不论它排在第几；`variant="row"` 是手机设置面板里的一行（标签、值、箭头），同一张卡里相邻的行之间有一条从文字边开始的 `--line` 细线，最后一行下面没有。

**权限菜单（PermissionMenu）。** 有序的权限等级只用这一个菜单，不用一排分段：整层 320 宽，头部写作用对象，四个两行项从低到高，每项一句后果，默认项带中性徽标「默认」，越级的项不可选并写出原因，脚部是一行导航或带锁的说明。菜单里的完全访问不带琥珀；只有它被选中后，触发器前才出现琥珀色 `shield-alert`。调低立即生效，调高走上面的验证流程。等级的文案由页面传入，原语只负责顺序、画法与交互。手机上的单选面板用同一份文案：头部写在列表上方并作为单选组的名称，「默认」徽标跟在标题后面，脚部说明与单选和标题两列对齐。

**菜单与弹层。** 菜单与选值的层是玻璃（浮起色的 88% 加 16px 模糊）、圆角 8、内边距 4、`--sh-pop`；内容自管的弹层（`Popover`，例如计划）与选值里原地换上的面板是不透明的浮起表面、圆角 12。最小宽 220（给出的宽度都是整层的外宽，内边距在内；可搜索的选值 360），距触发器 6，设置行与会话信息里右缘对齐触发器，输入框里左缘对齐。放在整层放得下的一侧（先试给定的一侧，再试另一侧）；两侧都放不下时，留在至少有 240 的一侧，限高并在层内滚动，始终离窗口边缘 8。层的内容改变大小时（菜单原地换成添加面板、宽度变宽）重新放置，已在的一侧仍放得下就不换边。打开时从 98% 放大并淡入（`--m-enter`），放大的原点在它朝向触发器的那一侧、对齐的那一边，像是从触发器里长出来；关闭倒放，用 70% 的时长与退出曲线。菜单项 28 高（带说明 44），圆角 6，前导槽 16：选值菜单里当前项是墨色对勾、标题换成 500 字重，动作菜单里是图标；没有任何项带图标的动作菜单（例如审批卡的 ⋯）不留前导槽，文字从菜单的内边距开始；尾部只放一样（元信息、徽标或按键），元信息是最安静的墨色；两行项（带说明或不可选的原因）把前导与尾部放在标题那一行，不放在两行中间；原因行在上一行下 4、禁止图标与文字相隔 6；高亮瞬时变化。菜单项的图标静止时是提示墨色，悬停、键盘高亮与按下时换成正文墨色。危险项（删除）排在最后，前面一条贯穿整层的分隔线，文字与它的图标都是红色。菜单的读屏名称是它的标签加头部写的作用对象（「权限：在这台电脑上发起的会话」，头部只重复标签时不再加），头部的元信息是它的读屏描述。分隔线下的脚部行与菜单项用同一网格，28 高、圆角 6，文字从标题那一列开始：导航行（「电脑与权限上限…」）是正文墨色 13/18，前导槽空着，末尾向右箭头；留在原地的动作（「撤销切换」「添加模型服务…」）不带箭头，可以在前导槽放一个 14 的图标，`closes` 的动作先关闭弹层；说明行（「调高要在这台电脑上验证身份」）把锁放在前导槽中间，文字 12/16 提示墨色。脚部行不在菜单列表里时（弹层里一列按钮之后，或底部面板里）是普通按钮，用 Tab 到达，没有图标时不留前导槽。菜单项可以带值自己的磁贴（`media`），在前导槽之后、标题之前。`Popover` 的焦点进入它的第一个控件。

**输入。** 文本字段是浮起的表面加一圈 1px `--line-strong`；聚焦时（不只是键盘）环换成蓝色，外面一圈 3px 的淡蓝外晕。标签在上（12/16·500），提示在下（12/18 提示墨色），占位符是最安静的墨色；出错时环变红、下面一行红字写原因与改法，并作为读屏描述。桌面 32 高、圆角 8；手机 44 高、圆角 12、16px 字，iOS 聚焦时不缩放。页面内的搜索框是悬停底那样的淡填充、没有环，前导 14 的放大镜（与文字相隔 6，控件内图标与文字的间距），有内容时尾部是 24 的清除按钮（触屏上四周有 44×44 的透明点按区），Escape 先清空；聚焦时升到浮起表面并带同样的蓝环与外晕。侧栏里的搜索用 `variant="ghost"`：与那一列的行同样 36 高、16 的放大镜距起点与文字各 8，静止时没有底，悬停是悬停底，只有聚焦时升到浮起表面并带蓝环。

**开关与选择。** 开关只给能立即开关的行：桌面轨道 30×18、滑块 14（触屏 44×26、22），关是淡中性的 `--switch-off`，开是蓝色；滑块是白色、带自己的小阴影，与轨道的颜色一起在 `--m-micro` 里到位，按住时向前进方向拉宽 4px；Space 切换；键盘焦点环画在轨道外 2px，跟着胶囊的形状，不画在更大的点按盒子上。`SwitchRow` 整行是开关的标签，点标题也能切换，整行不响应悬停；被策略锁住时开关关闭并降到 45%，前面一把锁，说明换成原因。分段控件只用于 2–3 个对等的视图或模式（类型只允许 2 或 3 项）：淡填充的轨道（圆角 8、内边距 2）里放等宽的段，24 高、12/16·500；选中段是浮起的块（`--seg-on` 与它自己的阴影）配正文墨色，其余是提示墨色、悬停换成正文墨色；选中在 `--m-micro` 里交叉淡化，不滑动；md 是 28 高，手机 32；它是一个单选组，段的说明（例如为什么不可选）在提示框里。文字标签页与筛选（`Tabs`、`FilterPills`）没有轨道：24 高（手机 32）、圆角 6、12/16·500，可以带 12 的图标；选中是悬停底配正文墨色，其余是提示墨色，选中不滑动、从不下划线、不用蓝；标签页是 tablist，筛选是一组 `aria-pressed` 的切换按钮。复选框与单选框是 16px 的原生输入：未选中是浮起底加 1.5px 的 `--line-strong` 环，选中是蓝色（实心加白勾，或 5px 的蓝环）。单选列表放在浮起的卡片里，每行 48（手机 56），前导单选、标题与一句后果，选中项标题 500，单选与标题在同一行，下面有说明或原因时也不下移；不可选的行降低单选与标题，原因一行保持原色。

**选中的三种画法。** 列表里的对象（侧栏的会话行、设置导航）是 `--selected`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 落影），深色是一层柔和的白，标题换成正文墨色；被勾选的控件（单选、复选、开关的开）是蓝色，菜单里的当前项是墨色对勾；视图、筛选与外观（分段、标签页、筛选）是中性的浮起块或悬停底。蓝色从不画在选中行上。

**对话框与底部面板。** 对话框是原生模态 `<dialog>`：480（确认）、560（表单）、720（双栏），浮起表面、圆角 16、`--sh-dialog`，后面的遮罩把内容模糊 4px；头部 56（标题 15/22·600、可选副标题、关闭），下面不画线；正文左右与底部留 24；脚部 56，是侧栏灰的一条，上缘一条细线（左侧说明，右侧最多两个 md 按钮，次在前、主在最后）；没有头尾的确认四边留 24。打开时聚焦第一个输入（没有输入时是正文的第一个控件），Tab 在对话框里循环，Escape 与点遮罩关闭（从对话框或面板里再打开的一层，例如新会话面板里的选择器，Escape 只关闭最上面这一层），关闭后焦点回到打开它的控件；打开时从 98.5% 放大并淡入，遮罩一起淡入（`--m-sheet`），关闭倒放，用 70% 的时长与退出曲线。底部面板（手机）是侧栏灰、上圆角 16，抓手、52 高的头部（左「取消」是常规字重的幽灵按钮、中间标题、右侧动作：执行操作的主按钮，或只关闭面板的次按钮「完成」，热区都是 44；只用来查看的面板（弹层在手机上的样子，例如计划）没有「取消」，只有右侧的「完成」；「取消」的文字与动作的右缘都落在下面卡片的 16 那条线上；两侧按钮从不被挤窄，标题短时居中，长时在两侧之间以省略号结束），从底部滑入（`--m-sheet`），以 70% 的时长滑出；内容高时先停在窗口的 65%，向上拖到 92%，向下拖过三分之一或快速下滑则关闭；`detent="large"` 的表单类面板（例如新会话）一打开就停在 92%，不随内容伸缩。页面可以经 `LayerHistory` 给每个打开的底部面板一个返回的位置（手机上是浏览器历史里的一条，见「手机的页面栈」）。手机上的菜单也是这样的底部面板：菜单项放在一张浮起的卡片里，48 高；标题只写对象本身（会话菜单的标题是会话名，菜单的读屏名称仍是「会话：…」）；用触屏打开时焦点仍在第一项（或选中项）上，但在按下按键之前不画焦点底，不会看起来像选中了什么。改动即时生效的面板不放「确定」。

**调整宽度（ResizeHandle）。** 侧边列（侧栏与会话信息栏）的边缘：跨在边缘上的 6px 透明命中区，光标是 `col-resize`；悬停 300ms 后（避免划过时闪烁）、拖拽中立即、键盘聚焦时随焦点环一起，在中间画一条 1px 的 `--line-strong` 竖线，不用蓝色，也不占布局。它是竖向的 `role="separator"`，读屏名称写明作用（「调整侧栏宽度」），`aria-valuenow`、`aria-valuemin`、`aria-valuemax` 是像素宽度，收起时 `aria-valuetext` 为「已收起」。它只报告宽度：拖拽中报告指针下的原始宽度、松开时再报告一次（由页面收紧、吸附收起并保存），键盘一步 8px（Shift 32px）、Home/End 到两端，Enter 切换收起，双击复原；拖拽时捕获指针，并在根元素上标 `data-resizing`，整页显示调整光标、不选中文字。

**提示与 Toast。** 内联提示（也用作消息区顶部的横幅；横幅在页面看着条件变化时像折叠块一样展开与收起，收起时保留原来的文字，加载、重连或切换会话后直接在位）是浮起的表面加 1px 细线，圆角 8：错误叠淡红配红色的边，中性与警告只有浮起与细线；警告配三角，错误配圆形叉号，中性配信息图标；图标与标题用色调文字，说明是次级墨色 12/18；最多一个 xs 动作（警告与红色调里是描边按钮），可选一个关闭按钮。先写保留了什么，再写原因，最后给动作。错误提示是 `alert`，其余是 `status`。本地操作成功（保存、启用、获取到模型）用中性提示或只让值原位更新，不用绿色。Toast 是浮起的一小块（圆角 8、至少 36 高、`--sh-pop`），从下方 4px 升起并淡入（`--m-enter`），前面一个色调图形，用于发生在别处的事（「已由「设备名」处理」）和失败；置顶、归档、删除这类在本页做的操作成功时不弹 Toast，列表行的移动或收起就是反馈。

**空、加载与错误。** 空状态是一句短名词（「还没有会话」）、一行说明和最多一个 xs 按钮，左对齐，不放插画。加载在对象旁边放 14 的转圈和一行提示墨色的文字；页面中央的连接状态用 20 的转圈；列表的骨架只做缓慢的明暗（不透明度在 1 与 .55 之间分四步来回，2.4s，离开视野时暂停，减少动效时不动），不做扫光，占的盒子与内容相同。界面出错的卡片是一张 480 宽的浮起卡片：红色三角、标题、一行说明会话和草稿都在执行端，最多两个按钮。

**磁贴。** Harness 与模型的方形磁贴：14、16、20、24、32、40、56，圆角按 round(边长 × 0.225)。磁贴放品牌自己的标志文件（`mark`），在浮起的表面上，外面一圈 1px `--line` 细环画在图形之上，标志贴到边时细环仍在；只有没有图标的东西才放调用方给的图形（`icon`），放在淡填充上；类型上二者必有其一，磁贴从不画字母。标志居中占 72%，文件自己带了很宽的留白时（`margin`）铺满；图形占 60%。彩色标志原样放（`<img>`），品牌另有深色版文件时（`dark`）按页面的主题换用；单色标志按品牌的单色复制方式，以文件为 CSS 遮罩、填成 `--ink`，所以浅色里是近黑、深色里是柔和的白，图形本身不改；品牌自己的应用图标（`tile`）自带底色与外形，原样显示，不加底与细环，也不按磁贴的圆角裁切。标志文件从不作为标记内联进页面。图形是正文墨色的 Lucide 图标，描边 1.75，16 的磁贴里是 2.2，10px 的图形也认得出来；16 及以下的位置上（选择器的按钮、顶栏与回复的来源行）没有图标的东西只画图形本身（`plain`），因为底上 10px 以下的图形认不出来；我的 Agent 的中性图形磁贴也一样。`plain` 只有图形没有磁贴，图形用次级墨色（单色标志仍是 `--ink`）。就绪度画在磁贴上，就绪不加任何标记：不可用（例如找不到命令）灰度并降到 40%；启动或检测中灰度、降到 70%，外面一圈 2px 的进度环（有进度时从 12 点起顺时针按比例画弧，否则一段弧 1.4s 绕一圈，离开视野时暂停，减少动效时停住）；失败在右上角放一个 8px 的红点并镂空一圈表面色。就绪度也要在文字里写出。

**磁贴选择（`TileChoice`）。** 支持大磁贴与紧凑两种布局，默认保留大磁贴供需要图片辨识的选择场景。新会话使用 `variant="compact"`：20px 身份图标与名称、说明同行，桌面最小 36px、触屏最小 44px，选中是选中行那样的卡片（`--selected` 与它的环），长名称省略且保留提示。添加 Agent 使用同样的紧凑形态，不再常驻显示可添加数量。整组只有一个 Tab 停靠点；方向键选择并跳过不可选项，Home / End 到首尾。不可选项保持可聚焦，原因由说明与读屏描述给出，按下时在整行下面展开。

**状态。** 只有正在进行的工作会动（它的转圈），等你处理、失败、已完成与时间从不动；状态变化被页面亲眼看到时，新旧状态在同一格里交叉淡化（`--m-micro`），这是它们唯一的过渡。没有空闲动画，也没有闪烁、弹跳、扫光与涟漪。样式在 [status.css](../packages/ui/src/styles/status.css)。

- **状态槽（`StatusSlot`）。** 列表行第一行行尾的一格，右对齐、至少 24 宽，只显示一样：运行中（转圈加「运行中」，页面给出时长时写「运行中 1:12」，正在停止时写「正在停止」）、等你处理（琥珀盾牌加「等你处理」）、注意（没有盾牌的琥珀字，文字由页面给出）、失败（`circle-alert` 加红字，文字由页面给出，默认「失败」）、未读（12 的墨色对勾，会话被读过后消失）、已结束（`--muted` 的「已停止」）、时间（`--muted`、常规字重），或什么都没有。会话行按 `rowStatus` 选择。状态变了且页面看见时，旧的在同一格里以退出曲线淡出（70% 的 `--m-micro`），新的淡入；淡出播完就从页面上移走，离开的转圈不会在看不见的地方继续转。它对读屏隐藏，行自己用一句隐藏文字说出状态与时间。
- **过程行的状态（`StatusGlyph`、`StatusWords`）。** 工具的过程行与计划步骤共用：图形格里运行中是转圈（行里 12，工具卡 14），其余是这一行的图标（计划步骤按状态是空心圆、带点的圆与对勾，都是静止的）；`state` 写明图形表示什么。页面看着它变化时，旧图形淡出、新图形从 80% 长到原大并淡入，在同一格里交叉淡化（`--m-micro`）；状态文字（执行中 → 完成）淡入。失败只换图标与文字，不抖动。
- **只为看见的变化播放。** 这些过渡（还有计数的淡入）只为页面亲眼看到的变化播放一次：页面经 `LiveChanges` 给出重新同步的纪元，在上一次渲染之后换了纪元的变化直接显示新值；没有纪元或减少动效时也直接显示。外壳（侧栏、图标栏）的纪元是 Host 状态重新同步的次数（首次加载、重连后的快照同步、页面重新可见，见 [STREAMING.md](./STREAMING.md)「客户端：事件流、凭据与版本门禁」）；对话区与会话详情的纪元另加打开的会话，切换会话时那里不播。会话列表跨会话存在，所以打开一个未读的会话时，它那一行的对勾淡出、时间淡入。只在有东西等待时才出现的计数（侧栏的「等你处理」行、图标栏的待批准按钮）由所在的组件用 `useLivePrevious` 记住它出现前的值并传给 `Count` 的 `from`，所以第一项到达（0 → 1）也淡入。页面里的其他一次性过渡用同一个 `useLiveChange`。
- **正在思考（`Shimmer`）。** 进行中的文字是提示墨色：挂载 600ms 后，一道墨色的窄光用 1s 从左到右扫过文字，然后休息到 4s 一个周期结束，只动文字背后渐变的位置；离开视野时暂停，减少动效时是静止的提示墨色。`variant="working"` 是运行中的工作标签：一道光以 30 步、2.2s 一轮不休息地扫过，全页共用一个时钟，暂停与减少动效的规则相同。

**展开、替换与离开（[motion.tsx](../packages/ui/src/motion.tsx)）。** 动效只用来说明一个变化：高度只经网格行变化，其余只动不透明度与位移，所以展开的东西上方什么都不移动；减少动效时高度直接到位，只保留淡入淡出。`Collapse` 是展开块的身体：打开时网格行从 0fr 到 1fr，内容同时淡入（`--m-panel`）；关闭用 70% 的时长与退出曲线；打开并停稳后不再裁切（焦点环、外扩的行不被切掉）。关闭时身体留在文档里，是 `hidden="until-found"`：不在 Tab 顺序与无障碍树里，但浏览器的页内查找能找到它，并经 `onReveal` 请主人打开；关闭过程中是 `inert`。`lazy` 的身体第一次打开时才渲染，之后保留（工具的输出这类重内容）。首次渲染直接显示当时的状态。`Swap` 在值变化时替换内容：图形从 80% 长到原大并淡入（复制图标变成对勾，`IconButton` 的 `swap`），文字原地淡入（`effect="fade"`，例如「正在思考」变成「思考了 6 秒」），都是 `--m-micro`，首次渲染不播。`usePresence` 让离开的东西在退出动画期间留在页面上并标为离开（「回到最新」淡出、会话信息页滑走），默认留 70% 的 `--m-micro`。`Shimmer` 是进行中的文字（见「状态」）。

**开发版与演示标记。** `DevMark` 是中性徽标「开发版」，整句说明（「开发模式：Host 代码可被本机修改」）是它悬停时的提示与读屏名称，从不用红；`DemoMark` 是琥珀色徽标「演示模型」（窄处写「演示」）。

**操作与面板部件。**

- **`SplitButton`。** 一个动作加一个收着同类动作的 V 形（「提交 ⌄」）：同一张面、两个控件、两个 Tab 停靠点，菜单与按钮右缘对齐。主动作禁用时 V 形仍可用，除非 `menuDisabled`，因为菜单里可能还有能做的事。
- **`SelectButton`。** 设置行里打开选择器的值：16 的磁贴或 14 的图形、值与 V 形，28 高，只画按钮，触发属性来自 `Menu` 或 `ValuePicker`。禁用时保持可聚焦，点击与按键都打不开。
- **`Button` 的 `pending` 与 `done`。** 用于打开系统表单的动作：表单打开时转圈留在原位，成功后绿色对勾变形进来并换成 `doneLabel`，这期间不接收点击。
- **`CopyButton`。** 图标在 `--m-micro` 里变成对勾，「已复制」锚定在按钮旁 1 秒；失败时在同一位置说明，读屏用 polite 状态。
- **`PanelTabs`。** 侧面板的标签条：24 高、圆角 6、12/16·500、最宽 160，选中立即移动不滑动，可带行数（`+60 −6`）与 6px 的新内容点。可关闭的标签悬停时图形让位给 ×，触屏上选中的标签一直是 ×，没有图形的也留出这一格；Delete 关闭并把焦点移到相邻标签。只有一个 Tab 停靠点，←/→ 移动并选择，溢出时横向滚动。
- **`DrawerStack` 与 `Drawer`。** 附在输入框上等待的东西（审批、问题、队列）：左右内缩 20、与卡片重叠 14、上圆角 16，从卡片后面滑上来（`--m-panel`），以 70% 的时长滑回，只为页面看见的变化播放。最后一个子项在最前，其余露出 10px 的边、宽 96% 且 inert，指针或焦点进入（触屏是点按）时展开。`arming` 让抽屉到达或回到最前后 320ms 内 inert，展开的堆叠里上一个抽屉离开时也一样。
- **`FoldHeader`。** `Collapse` 的整行头部，12 的 V 形在 `--m-panel` 里转 90°。
- **`ProgressBar`。** 2px 的线，给不知道时长的工作：缓动到 90% 后等待，结束时 150ms 走完并淡出；对读屏始终是不确定进度，因为 90% 不是测量值。
- **`Group` 与 `Row`。** 设置卡片：圆角 12 的浮起分组，可带标题，行之间是细线；里面的任何内容都有内边距。
- **`Scrim`。** 不是原生对话框的滑出层背后的遮罩：淡入 `--m-sheet`，`open` 转假后留下以 70% 的时长淡出，这期间不接收按下。

**原语与页面。** 页面里的按钮、图标按钮、开关、分段控件、筛选、状态词与徽标、计数、内联提示、发送方式的单选列表、加载行、Toast、开发版标记、Harness 与模型服务的磁贴、新会话的紧凑选择、输入框里的选值（项目、模型、Agent 的模型选项）、侧栏的调整宽度把手，以及会话行的状态槽、过程行的状态图形和文字、展开块、替换与进行中的文字都来自原语。菜单、模态外壳、异步确认与输入框也由 `@latch/ui` 提供；页面的 `overlays.tsx` 只保留兼容导出。内容自管的 `Modal` 支持 dialog、sheet、page，共用原生顶层、焦点循环和归还；`ActionMenu` 与 `ActionSheet` 把页面动作映射到同一菜单原语。页面负责内容、请求和布局。

[packages/ui/test/gallery](../packages/ui/test/gallery) 是只供测试的原语总览页：每个原语的每种状态都在一页上（悬停、按下与键盘焦点由截图时强制），不进入 `dist/web`。状态的变化在总览页挂载后一帧重放一次，另有几格把状态槽与过程行的交叉淡化、思考的光带定格在中途，便于评审；「动效」一节是收起与展开的块（可以点开）与两种替换；「状态」一节是四种尺寸的转圈、状态槽的每一种、侧栏的一组行、变化、过程行与正在思考；总览页自己的排版只作用于它自己的元素，原语的标题与字号保持原样；就地画出的对话框、弹层与底部面板在手机宽度下收进卡片，完整可见；截图时视口长到整页高度，手机与平板的截图因此带着触屏尺寸（44 的点按盒子、44×26 的开关）。

## 组件

**Harness 与模型服务的图标。** 每个 Harness 与模型服务都显示它真实的品牌图标，放在磁贴上（`BrandTile`，[brands.ts](../apps/web/src/brands.ts)）：先用品牌自己的文件（项目仓库里的或官网上不需登录即可取得的），没有时用开源图标集 LobeHub Icons（MIT）在固定提交中的文件，品牌标志是彩色的就用彩色版，否则用单色版。文件原样复制到 `apps/web/src/assets/brands/`，不作为 npm 依赖；以 `?no-inline` 导入，构建产物里是同样字节的文件，不被改写成内联数据；只经 `<img>` 或 CSS（遮罩）使用，从不内联成标记。来源（仓库与路径及提交，或网址与日期）、许可证、图标集的 MIT 声明与「标志属于各自的所有者，只用于标明服务或工具」写在仓库根的 `NOTICE`。目录里的会话与服务不带预设标识，所以按 Host 由预设派生的标识（`codex`、`codex-2`……）认出它的预设；设置里有预设标识时直接用它。没有图标的才用中性图形：自定义的 Agent 命令是 `bot`，插件是 `puzzle`，自定义的 OpenAI 兼容服务是 `plug`，演示模型是 `flask-conical`；Latch 内置的 Harness 用应用图标原样显示。[brands.test.ts](../apps/web/test/brands.test.ts) 检查每个 Harness 预设与模型服务预设都有图标，演示、插件与自定义各有图形，图标目录里正好是映射用到的文件，且每个 SVG 不含脚本、外来内容、事件属性、嵌入图片、样式表或指向文件外的引用。图标出现在侧栏的会话行、顶栏与每轮回复的来源行、选择器，以及设置里的模型服务（预设、列表与表单）与 Agent（预设、列表与表单）。

**侧栏。** 内容、分组与状态词见「会话面板」。抽屉里头行另有「关闭会话列表」；新会话页打开时「新会话」是切换按钮的「开」。设备只从「手机」入口（手机上是设置）进入。连接有问题由图标栏的点与顶栏的话说出；桌面端保持这台 Mac 唤醒时，面板底部写提示墨色的「保持唤醒中」，悬停说明原因，点它同步最新状态。会话的工作目录落在哪个保存的项目里（取最深的一个）就归哪一组，其余归「对话」；组按其中最近更新的会话排序，组内置顶在前、最新的在前；Host 不提供项目列表时按工作目录分组。上一个与下一个会话的快捷键按屏幕上的顺序走：「等你处理」在前，跳过折叠的组。组头的 ＋ 在这个项目里新建会话（项目在本次启动时不可用，或设备不能发起会话时没有）。菜单提供重命名、置顶、归档、导出 Markdown、删除（需确认，运行中不可删除）；悬停、键盘聚焦或菜单打开时状态让位给「归档」与 ⋯。标题太长时最后 16px 渐隐，不用省略号；菜单打开时这一行保持悬停底。行标题默认用次级墨色；选中的行是选中卡片（浅色是侧栏灰上的白色卡片，深色是一层柔和的白；120ms 切换）与 500 字重；未读的行把标题换成正文墨色并在状态槽显示墨色对勾；连接中断时，等你处理的行仍是 500 字重。未读按设备记录。列表随 Host 变化时，移动的行与组从原位置滑到新位置，新到的行淡入（都是 `--m-enter`），离开的行（归档、删除、移到别的组）高度收起并淡出（`--m-micro`）；移动的行超过 30 个或换到已归档时直接重画，减少动效时都不动。

**新会话。** 问候「今天要做什么？」、紧凑的 Harness 选择、输入框与上下文行按同一左边缘排列（[NewSession.tsx](../apps/web/src/components/NewSession.tsx)）。整块顶边固定为 `max(48px, 38vh − 96px)`；输入框变高与说明展开都向下增长。通常图标用 16px、Agent 身份用 20px、设置页身份用 24px；不把选择器画成大图标展架。页面不叠加环境背景。完全访问保留上下文行的琥珀盾牌与文字，主按钮写「开始会话」，进入确认时再显示本次具体启动详情与风险。

- **Harness 磁贴**（[HarnessChoice.tsx](../apps/web/src/components/HarnessChoice.tsx)）：先是能在这台设备上开始的，再是不能的，各自说明原因（未找到命令等 Harness 的状态说明；完全访问的 Agent 在执行端以外的设备上写「仅本机桌面端」）。内置 Harness 是两项：「Latch 内置 · Agent」（默认，可以读写项目文件、运行命令，有风险的操作先问你）与「Latch 内置 · 只对话」（不读写文件、不运行命令），这就是全部的「对话 / Agent」选择；同时接受两种方式的插件 Harness 也拆成两项。完全访问的 Agent 在说明行写「完全访问」（中性，没被选中时不报警）。最后一项「添加 Agent」打开一层：列出 Host 认识、还没添加的预设（磁贴、名称与许可证、一行说明、这台电脑上是否已找到它的命令），点一项原地换成它的面板：说明、缺的是哪个程序与可复制的安装命令、「重新检测」、项目主页与「添加」（保存需要本机确认；不能定义 Agent 的设备看到在哪里添加）；添加后选中它。层的脚部是导航行「管理 Agent 成员…」；在手机的底部面板里，面板标题已写「添加 Agent」，列表头只留「开源，在这台电脑上运行」。只有内置 Harness 时，输入框下还有一行「还可以添加 Codex、OpenCode 等 Agent」，它打开的是「添加 Agent」那一层（在原地添加），设置是第二个入口。
- **输入框工具栏**：项目（只对话没有项目）与模型（只在 Harness 使用 Host 的模型时）各是一个选值，随所选的 Harness 淡入（`--m-micro`）、以它的 70% 淡出。项目菜单头部写「项目」，保存的项目带路径与「默认」，Host 的启动目录单独一组写「启动目录」；桌面端在运行 Latch 的电脑上可以「新建项目…」（系统的文件夹面板，选中新项目），其他设备的菜单写明新项目在哪里创建；脚部「管理项目…」。模型菜单按服务分组、组标题前是服务的磁贴，演示模型带「演示」；脚部「添加模型服务…」把弹层原地换成添加面板：选一个服务，粘贴密钥（只在执行端电脑的桌面端；其他设备只能添加不需要密钥的本地服务），获取模型并选一个使用，「保存并使用」，保存密钥照常要本机确认；需要密钥的服务在不能设置密钥的设备上只写在哪里设置，没有主按钮，脚部是「管理模型服务…」；自定义地址进设置。手机上项目与模型在新会话面板里各占一行；已有会话从会话信息里修改。
- **上下文行**：这台电脑的名称（只读，提示写「会话在这台电脑上运行」）；它与下面的说明都从工具栏第一个图标那一列开始；选中完全访问的 Agent 时，琥珀色 `shield-alert` 加「完全访问」，通往「设置 › 电脑」。逐项询问是默认，不显示。本次启动的访问风险在确认详情中说明。在执行端电脑的桌面端，发送键换成主按钮「开始会话」，Enter 同样开始，并打开本机确认；还没有内容或这台电脑的本机确认不可用时，它和空的发送键一样退为中性填充（保留锁），仍可聚焦，提示写出原因。
- 新会话从哪里开始就在哪里：在打开的会话里新建时，预选那个会话所在的项目；从侧栏项目组的「+」新建时预选那个项目；其余用上次的选择。选择按设备记忆，并按 Host 当前目录修正。
- 缺少可用模型或 Harness 时显示一张卡片：缺模型服务时它的「添加模型服务」在卡片里原地展开同一块添加面板（服务的磁贴每格至少 104 宽，一行排下卡片宽度放得下的个数，弹层里是三列），其他情况通往设置。演示模式下显示带「演示」标记的示例卡片。Host 不发目录时只保留「对话 / Agent」分段控件。

**会话。** 顶栏（画布内 48）左侧是标题：一个幽灵按钮，悬停时露出向下箭头，打开会话菜单（重命名、置顶、归档、导出 Markdown、删除）；接着是会话在哪里运行（16 的 Harness 磁贴与提示墨色的「Harness · 项目文件夹名」）和不是默认时的状态词（失败为红字，已取消、已中断、正在取消为提示墨色；运行中与已完成不标）。右侧依次是连接状态（只在连接不正常时出现：琥珀字写出状态与「· 重试」并带刷新图标，静止时没有底与边，悬停才有淡琥珀底，没有圆点，手机上同样写出文字；点击同步）、完全访问会话的琥珀状态词（`shield-alert` 加「完全访问」）、演示标记（"演示模型"，手机为"演示"）、「会话信息」开关（每个宽度都有，打开时是中性的悬停底，不用蓝色）与更多菜单（会话的操作与「同步最新状态」；新会话页里只有后者）。手机上标题是文字，会话的操作都在更多菜单里。连接中断或离线时，消息区顶部有一行琥珀色提示：三角图标与琥珀色标题（「连接已中断，正在重连…」或「当前设备已离线」），说明为次级墨色，右侧「重试」。Host 宣布过原因时，标题改为这个原因与开始时间：「电脑已休眠（22:41 起）」「电脑上的 Latch 正在重启」「电脑上的 Latch 正在更新」「电脑上的 Latch 已停止（21:03 起）」，说明写何时自动重新连接；桌面端再按主进程的判断写出「Latch Host 意外退出，2 秒后重新启动（10 分钟内第 2 次）。」等，反复崩溃后停止自动重启或 Host 没有响应时这行提示为红色，前者右侧换成「启动 Host」。

**对话与回合。** 对话按回合排列（[Transcript.tsx](../apps/web/src/components/Transcript.tsx)，推导在 [conversation.ts](../apps/web/src/conversation.ts)）：一个回合是用户的一条消息和回答它的一切。回合之间 32，回合内的块之间 12；只在悬停时出现的东西盖在回合下方的间隙里，不预留空间。对话列的第一行在顶栏下 16，避开 16px 的渐隐。只有用户消息有气泡：右侧的中性气泡，超过 176 高时收在渐隐后，带「显示全部」；下面是时间、「复制」与「从这里编辑」（在这条消息之前分叉，文字进入输入框；第一轮没有），桌面上悬停或聚焦时淡入（120ms），触屏上最新一条常显。消息送达的过程写在气泡下：发送中、Mac 已收到、Agent 已开始，Agent 开始回答后消失。页面亲眼看着到达的消息才有到达的动效：用户的气泡上移 6px 淡入（`--m-enter`），回复的第一块淡入（`--m-micro`），流进块里的文字不动；加载、重连与切换会话不播放。每个回合以作者行开始：16 的引擎标记、Agent 的名字（没有选 Agent 时是「通用」），后面是提示墨色的引擎与模型；演示模型回答时引擎的位置写「演示」。撤销之后下一条消息带给引擎的说明不进气泡，在气泡上方写一行「已告诉 Agent 改动被撤销了」。分叉出来的会话在第一轮之上写一行来源。

**工作行。** 思考与每次工具调用都是一行安静的工作（24 高，手机 28）：24 宽的图形列（16 的图标；运行中是 12 的蓝色转圈；失败是 12 的红色叉号）、按工具类型的动词加对象（文件写文件名，命令与搜索词是等宽字；读不出对象时只写工具自己的标题；工具声明了标题时写这个标题加对象；既没有标题、也读不出对象的工具写它的原名，不猜）、改动的行数，紧跟着 12 的箭头，展开时转 90°。行尾常驻决定的记录（「已允许 · 14:36」「已拒绝 · 14:32」「已过期」），用时只在悬停时出现。同一类的行相邻时图标只出现一次，紧接在展开的行之后除外。结束的回合里相邻的读取合成一行「读取 4 个文件」，展开是它们原来的行；运行中不合并，行不会跳。文件编辑写「编辑 providers.ts」加增删行数，新文件写「新建 a.ts · 42 行」；展开是最多 12 行改动的预览（新文件最多 8 行）和「在变更中打开」（新文件是「打开文件」）。右侧面板打开时它只有一行，选中文件时带悬停底，点击在面板里打开这个文件。其他工具展开是参数与输出，向内缩进 28，最高 320；输出在自己的框里，运行中跟随最新的行，运行中的命令有输出时自动展开，结束后收起。失败的行下面一行写第一行原因（不含内部代码）和「重试」，「重试」只出现在这一轮最后失败的地方。Agent 在审批未通过时仍报告执行了调用，行下多一行写出来。思考行运行中写「思考中」（带光）与秒数，身体自动展开，答案开始后收起并写「思考了 6 秒」。

**折叠的工作。** 回合结束后，工作收成一行「已工作 2 分 13 秒 ›」，下面一条 60% 的细线；Host 没有记录用时的旧历史只写「已工作」。折叠只收工作行：工具之间的正文和答案永远不折叠，问题和它的回答留在阅读顺序里。这一行不掩盖问题：折进去的行有失败或被拒绝时写出来（「· 1 步失败」「· 1 步被拒绝」）。失败、停止、中断的回合，以及结束时没有一句话的回合，工作保持展开。工作行在回合运行与结束时是同一棵树，页面亲眼看着回合结束时它们收起（网格行加淡出），重新打开的会话直接是收起的样子。

**状态行。** 运行中的回合以一行状态结束，说的是真实在运行的东西，不只是时间（[StatusLine.tsx](../apps/web/src/conversation/StatusLine.tsx)）：「运行中 · 0:47」「命令运行中 · swift test · 1:12」，全局只有这一种走时格式，文字每秒最多变一次。模型或命令沉默超过 Host 的阈值时变成琥珀色的询问：「等模型回应 · 3 分钟没有新内容」「pnpm test · 12 分钟没有输出」，带「继续等」（Host 翻倍这一轮的阈值）和「停止」；Agent 发来 Latch 不认识的请求而之后没有动静时写「Codex 发来一个看不懂的请求 · 查看」。按下停止后写「正在停止…」，直到真实结算。等你允许或回答时这一行不出现。连接中断时不再转圈或走时，只写「上次确认 10:42」。运行不是以普通回答结束时，回合下留一行：「Codex 已退出 · 这一轮没有完成」为红色，强制停止与中断为琥珀色，并列出结果未知的命令，带「重试」与「在新会话中继续」。

**回合卡片。** 结束的回合有文件变化时带一张卡（[TurnCards.tsx](../apps/web/src/conversation/TurnCards.tsx)）：「改动了 3 个文件 +64 −8」「显示文件」展开每个文件，点一行或「打开变更」在右侧面板的「变更」页签打开这一轮和这个文件；设备的数据范围不含项目文件时打开这个文件：工具编辑过的显示它的修改记录，只被命令改过的显示文件本身，已删除的不能打开。数字来自 Host 这一轮的记录；回合与记录按时间匹配，有歧义时不匹配，因为撤销本轮只作用于匹配到的那一轮。没有记录（旧 Host、设备的数据范围不含项目文件、匹配不上）时卡片来自这一轮工具的编辑和观察到的文件变化，没有撤销。「撤销本轮」在卡片头部，或在同一位置写出不能撤销的原因（运行中、之后又改过这些文件、内容没有留存；另一台设备上的 Agent 会话写「在 Mac 的 Latch 中撤销」）。有文件恢复不了时先在卡片里列出，确认后才执行，否则立即执行。撤销后卡片让位给一行记录「已撤销本轮改动 · 恢复 · 下一条消息会告诉 Codex」和没有恢复的文件；消息发出后「会告诉」不再出现。撤销或恢复没有得到答复时写「结果未知」，重试用原请求；Host 的记录表明已经生效时就按记录显示。Host 拒绝或回到页面时重读记录，另一台设备的撤销由此反映；卡片与「变更」页签在同一设备上互相通知，一处撤销后另一处随之更新。记录不完整时（文件夹太大）卡片写出，撤销碰不到没列出的文件。这一轮新生成的文档与媒体在「生成了 2 个文件」卡片里，每个文件一个「打开」；所有改动都是这些文件时只有这张卡，撤销放在它的头部。

**回合脚部。** 结束的回合的事实与操作盖在回合下方的间隙里（24 高，提示墨色、等宽数字），悬停或聚焦时淡入，触屏的最新一轮常显、点按显示其他的：回复发出的时间（悬停写开始、结束与不含审批等待的用时）、用时、「输入 12.4k tokens」「输出 850 tokens」（各步合计），Agent 只报告整个会话的上下文时最新一轮写「上下文 74k tokens」；然后是「复制」「重试」（最新一轮；可能重复副作用时先在回合里说明要重复什么）、「从这里分叉」和更多菜单（复制到这里为止的记录）。没有正常完成的回合另有一行常驻的记录：「已停止 · 14:33 · 保留了部分回复」，失败时为红色并带「重试」。

**说明。** 会话里的系统说明是一行提示墨色的记录；报告失败（模型服务出错、运行被中断）时与失败的工作行画法相同：红色叉号、红字、「重试」。

**回到最新。** 读者离开最新输出时，输入框上方 16 处浮起 32 的圆形按钮（上移 8px 淡入，`--m-enter`；回到底部时以 70% 的时长淡出），带离开后新到的块数。有等你允许的请求、而它的卡片不在视野里时，这个位置变成琥珀字的「需要你允许 ↓」，点它滚到那张卡片，不在视野里才出现；读者上翻时有问题等你回答，同样写「等你回答 ↓」。块数按会话计，切换会话不算新内容。

**计划。** Harness 报告计划时，最新一轮的作者行下有一行工作「计划 2/5 ›」，展开是步骤列表；会话信息里也有「计划」块。步骤的标记是静止的：空心圆、带点的圆（进行中，正文墨色与 500 字重）与对勾，已完成的步骤最淡；会话停下后，进行中的那一步读作未完成；步骤状态变化时标记交叉淡化。

**运行条与输入框。** 运行中输入框仍可编辑（占位写「可以先写，本轮结束后发送…」），但需等本轮结束才能发送；空闲时占位写出收件人（「回复 Latch 内置…」）。运行条只在一次停止的结果未知时出现在输入框顶部（高度随展开动效变化）：停止结果尚未确认时「尚未确认 · 重试」，这是唯一说它的地方：结果未知不是失败，不出红色提示，顶栏与侧栏也不说「正在取消」；以及计划小块。每张等待中的卡片用 IntersectionObserver 报告自己是否在对话滚动区里露出，运行条只读这一个结果。运行在做什么、做了多久由对话里最新一轮的活的一行说，运行条不再写。停止键是浮起的圆、`--line-strong` 的边与实心方块，停止不是风险操作，不变红；停止进行中它转圈且不可按（`aria-disabled`），结果未知时仍是方块，再按一次就是再停止一次。运行开始或结束时，发送键与停止键在同一格里替换（从 90% 长到原大并淡入 120ms，只在页面看着它变化时）。输入框随内容按行长高，最多十行，高度过渡 120ms（量高度时先撤掉过渡、放回原高，再设新高度，所以从原来的高度开始走；减少动效时直接变化）。输入框浮在自己的阴影上，聚焦时环换成 `--line-strong`，不变蓝：静止与聚焦的阴影是框上的两层，交叉淡化（进 `--m-micro`、出它的 70%），阴影本身不做动画；发送是输入框里唯一的蓝色按钮，没有内容时退为中性填充，仍可聚焦，提示框写出原因（「输入内容后发送」，或不能发起的原因），可用时提示框写出快捷键；发送中箭头与转圈交叉替换。这台设备只能查看时（完全访问会话在执行端以外的设备上，或没有发起权限），输入框换成虚线框、凹陷底，里面是锁与原因；运行条与停止键保留。不再接受输入的会话同样如此。模型选值的切换从下一条消息起生效，触发器写「下一条：…」并铺一层填充底，菜单脚部第一行是「撤销切换，继续使用 …」；Agent 自己报告的模型选项也在工具栏里，其他选项（模式等）在会话信息里。桌面 Enter 发送、Shift+Enter 换行；触屏设备 Enter 换行；⌘/Ctrl+Enter 总是发送；输入法组字时不会发送。

**会话信息的块。** 每块是侧栏灰上的一张画布（圆角 12、静止的线、不带阴影），36 高的头部，点标题收起或展开（收起按设备记住），行 32 高：16 的图标、提示墨色的标签与正文墨色的值；没有内容的块不出现。Agent：32 的磁贴、名称与来源（插件，或 ACP 加许可证；管理这台 Host 的设备在中间看到 Agent 运行的命令名，悬停写出完整命令行；「Latch 内置」的名字已经说明来源，没有来源行），模型（使用 Host 模型时可在这里换，从下一条消息起生效；Agent 自己的模型与模式选项也在这里，24 高的选值，箭头悬停时出现，触屏上没有悬停，箭头常显），方式，以及这台设备不能修改时带锁的原因。环境：运行 Host 的电脑（桌面端加「本机」）与项目目录（目录名，下面是完整路径：按可用宽度在中段省略，最后一段保持完整，可复制）。权限：逐项询问或完全访问（琥珀 `shield-alert`）、权限模式变化后的红色状态词，「权限说明」展开执行方、定义是否已验证、模式能否读回、是否请求审批与 Harness 的说明。用量：输入、输出（「12.4k tokens」，悬停写出精确数与各部分，Agent 报告的注明）、Agent 报告的上下文（「74k / 200k tokens」与 4px 的墨色进度条，80% 起琥珀并写「接近上限」）与费用（注明「由 Agent 报告，不是账单」）、各轮用时合计与轮数、开始于。计划：完整步骤，头部是进度。变更：会话中工具改过的每个文件一行（目录、文件名、合计增删行数；原内容未显示时不写删除数），点它在对话里展开并定位到最后改它的那次工具调用。

**设置。** 分区：通用、电脑、模型服务、Agent 成员、项目、插件、设备、关于。模型服务、Agent 成员、项目与插件需要「管理此 Host」权限；没有该权限的设备看到通用、电脑（只读）、设备与关于，分区列表下面有一行带锁图标的提示墨色说明「其他设置需要「管理此 Host」权限 · 在运行 Latch 的电脑的 设置 › 设备 中授予」，不让分区无声地消失；旧版 Host 没有电脑与设备。每个分区由页头（18/26 的标题、13/20 的说明与最多一个次按钮）和若干组构成：组头 13/18·500 次级墨色，右侧可放提示墨色的元信息（计数写出数的是什么：「2 个项目」「1 个 Agent」）或一个链接按钮；组是画布上的卡片（1px `--line`、圆角 12），卡片下方最多一行 12/18 的说明，可带锁或信息图标；组之间 32px。卡片里的行至少 56 高、内边距 16，副行 12/16、只写一句（偏好写所选值的后果，记录写状态），命令与路径是一行等宽字，放不下时从中间省略、保留末尾，完整内容在提示里；尾部只放一样东西：选值（按 `--bleed` 外扩，箭头与导航行的箭头对齐）、开关、一个按钮、一个图标按钮（⋯ 菜单、复制、在访达中显示），或提示墨色的值；分隔线从文字左缘画起。进入对象或列表的行整行可点，尾部是提示墨色的值与向右箭头，悬停铺满整行；离线、不可用的对象只淡化磁贴、名字改次级墨色，状态写在副行。不能用的选项写出原因：12 的禁止图标加 12/16 次级墨色的一行，不随行淡化。危险操作（撤销此设备、删除 Agent、移除密钥、删除服务）放在页面末尾一张红色描边的卡片里。在页面上增删的行与卡片（出站白名单、项目）高度展开并淡入（`--m-panel`），移除时收起淡出（`--m-micro`）。只改一个值的操作（重命名、修改地址、设置密钥、添加环境变量、编辑启动定义）打开 560 的表单对话框，保存即生效。

- 通用：主题（跟随系统 / 浅色 / 深色的分段控件）、发送键（单选列表）；桌面端另有「后台运行」卡片：开关「让 Latch 在后台运行，手机随时能连上这台 Mac」（开发运行时停用，副行说明只有打包后的应用能登记登录项）、开关「有任务时保持唤醒」（副行是当前状态）、「Latch Host」一行（副行是主进程看到的状态，尾部在桌面端启动的 Host 上是「重新启动 Host」，Host 停止或反复崩溃后是「启动 Host」，没有响应时没有按钮，只有不正常的状态用状态词）与「时间机器备份」一行（哪些数据不进入备份、建议加密备份盘），卡片下方说明合盖仍会睡眠、关闭窗口后仍在后台运行；有「管理此 Host」权限的设备还有新会话默认值：Agent、方式（对话 / Agent，副行随所选值写出后果）、模型（只在该 Harness 使用 Host 的模型时）与项目各是一行选值，选中即保存到 Host，失败时退回 Host 的值并显示原因。内置 Harness 由 Host 命名为「Latch 内置」（ID 仍是 `standard`，插件页与导出的 Markdown 用同一个名字），页面用 Host 给的名字；新页面由仍在运行的旧 Host 提供时（旧 Host 叫它「Standard Harness」），设置里把 ID 为 `standard` 的内置 Harness 与它的插件仍写成「Latch 内置」。名字已经写着「内置」时，会话信息的 Agent 块与插件页不再另加「内置」。

- 模型服务：列表卡片（默认服务带「默认」，停用的写「已停用」，地址尚未确认的带琥珀「未确认」并写「需要在运行 Latch 的电脑上确认这个地址」；预置服务商地址上没有密钥的带琥珀「缺密钥」并写「还没有填写密钥」；演示与插件提供的服务在「其他来源」；还没有服务时，那一行进入「选择服务」）。页头按钮是「添加服务…」，表单的提交按钮是「保存服务」，可添加的模型按钮叫「添加模型 <ID>」，手动添加的按钮叫「添加输入的模型 ID」，同一页里没有同名按钮。点进去是该服务的页面，每个值单独生效：页头的「重命名…」；「连接」卡片里的启用开关、API 地址与「修改…」（改到另一个源时，对话框先说明保存会移除已保存的密钥），以及「检测连接」（结果写在副行：延迟与模型数；失败时是一句原因，例如「密钥不对或已过期。」「Host 连不上这个地址：那里没有服务在监听。」，按钮变成「重新检测」）；「密钥」卡片写「已保存（不回显）」与只发往的源与路径（省略协议默认的 :443 与 :80），或「未设置」，执行端桌面端有「设置密钥…」或「替换…」，其他设备在卡片下方看到「密钥只能在运行 Latch 的电脑上用桌面端填写：设置 › 模型服务。」（不需要密钥、也没有密钥的本机服务不显示这句）；命令行 `pnpm latch provider set-key` 只在没有本机确认的桌面端出现；「模型」卡片每个模型一行，单选框选默认、尾部移除，最后一行手动添加模型 ID（超过 200 个字符或带不可见字符时在行内说明，不添加），组头的「获取模型」把服务提供而尚未添加的模型列在「可添加的模型」卡片里（多于 8 个时可筛选），获取失败时卡片下的说明写原因并指向手动添加；末尾红色卡片里是「移除密钥」与「删除服务」。地址尚未确认时页首是琥珀提示「这个服务的地址还没有确认，Latch 不会使用它。」：桌面端带「用 Touch ID 确认地址」（带锁），没有本机确认的桌面端写出 `pnpm latch provider confirm <ID>`（本机确认组件需要修复的 Mac 改写 Host 给出的原因与修复方法，例如停止 Host 后重新登记签名），其他设备写「需要在运行 Latch 的电脑上确认这个地址：设置 › 模型服务 › <名称>。」；这时启用开关写「确认地址后 Latch 内置才能使用它的模型」，「检测连接」与「获取模型」停用，悬停说明「确认地址后才能检测」「确认地址后才能获取模型」。预置服务商地址上还没有密钥的服务页首是琥珀提示「还没有填写密钥，Latch 不会使用它。」：执行端桌面端带「设置密钥…」，其他设备写「在运行 Latch 的电脑上 设置 › 模型服务 › <名称> 填写密钥。」，检测与获取模型停用（「填写密钥后才能检测」「填写密钥后才能获取模型」）。检测就是获取模型列表：服务回答了却没有可用的模型列表（404、5xx、不是模型列表）时副行是中性的「无法自动检测：这个服务不提供模型列表」，不算失败，也不建议移除。刚保存的服务立即检测一次，表单里获取模型已经失败或服务还没有密钥时不检测：成功只改副行；连不上或密钥被拒时副行写「没有通过」，下方红色提示写原因：密钥被拒、这台设备又能填写密钥时带「替换密钥…」，其他情况带「移除此服务」。「添加服务…」先选预设，再在卡片里填名称、接口类型（自定义时）、API 地址、密钥（只在执行端桌面端）与模型，最后是「保存服务」。地址不是预置服务商的、也没有确认过时，桌面端的提交按钮是带锁的「用 Touch ID 保存」，按下后读「等待 Touch ID…」，表单下方说明「第一次使用这个地址：保存时在这台电脑上用 Touch ID 确认一次，之后不再询问。」；本机或局域网地址在获取模型时得到中性提示「这个地址在本机或局域网。保存时会一并确认，允许 Host 访问 127.0.0.1:11434。」，屏幕上只有提交按钮这一个锁。没有选模型就保存时先获取模型；本机或局域网地址要先确认，所以「用 Touch ID 保存」直接确认地址（唯一一次 Touch ID），再获取模型：只有一个就直接保存，有多个时说明要先选，确认过的地址之后保存不再询问。已确认地址的出站许可被移除时，提示才带自己的「用 Touch ID 允许并获取模型」。不能填写密钥的设备添加需要密钥的预置服务商时，密钥卡片先说明「这个服务需要密钥：保存后，在运行 Latch 的电脑上 设置 › 模型服务 填写密钥，它才能使用。」。
- Agent 成员：「本机 Agent」卡片每行是磁贴、名称与小徽标（完全访问、许可证、未验证的定义、已停用，以及还没有以当前定义开启过会话时的「还没有开启过会话」）、命令与检测结果（找到时是一行从中间省略的路径），尾部是启用开关；点行进入该 Agent 的页面：页头的「重命名…」、启用开关；「启动定义」卡片里命令与参数各一行（还没有开启过会话时，上面多一行「还没有开启过会话」：开始会话时会在这台电脑上确认它要运行的命令、参数和环境变量名），执行端桌面端从组头的「编辑…」在对话框里修改，其他设备只读并在卡片下方说明原因；「环境变量」卡片只列变量名，桌面端可以添加（对话框）与移除；保存定义不需要确认，表单与对话框写明「保存不需要确认；每次用它开始会话，都会在这台电脑上确认要运行的命令。」；「检测」卡片写找到的命令路径（可复制）或缺什么、定义的问题、是否已验证的预设，以及安装命令（可复制）与项目主页，组头是「重新检测」；末尾红色卡片里是「删除 Agent」。预设需要另一个程序时（pi-acp 连接 pi），检测写出缺的是哪一个：「已安装 pi，还差让 Latch 连接它的适配器 pi-acp」「已找到适配器 pi-acp，还没找到 pi」或两者都没找到。窗口重新获得焦点或回到前台时页面重新读取检测结果，读取本身也让 Host 重新查找命令。Latch 不安装 Agent，所以只提供可复制的安装命令，没有「安装」按钮。添加 Agent（先选预设，再在卡片里填启动定义与环境变量）在执行端桌面端进行，其他设备看到原因。
- 项目：每个保存的项目一张卡片，点开编辑器管理名称、十种中性图标与有序文件夹。第一个是主文件夹；支持键盘上下移动、拖动排序、设为主文件夹、移除和对缺失文件夹重新选择。添加与重新选择只经桌面端原生面板。不可用项目与每个失效文件夹保留并写明原因；活动会话使用的文件夹不能移除。会话数只作统计；已有会话保留创建时固定的目录。各 Agent 的文件夹支持按真实能力说明，完全访问不表示隔离。其他设备入口转到电脑设置的权限配置。启动目录单列且不能移除。
- 插件：按类型分组（组头写「N 个插件」），每行是名称与版本、内置与使用中的标记（名字已经写着「内置」的不再加内置标记），以及一句说明（它做什么，或为什么现在不能停用），提供的能力在提示里。尾部只放这里真正能做的事：能启停的插件是开关，有会话正在使用它时开关锁住（锁图标加「有 N 个会话正在使用，结束后才能停用」；只是加载而没有会话运行不算使用中）；由模型服务或 Agent 成员管理的插件是进入该分区的导航（「在模型服务中管理」）；内置的写「始终启用」。
- 设备、关于：见下。

**插件包界面。** 一个插件包可以同时提供技能、工具、界面与 Harness。插件页先按完整插件包列出，一个包只出现一次；包含的能力按类别计数，不把它拆散到每个技术类别，也不在普通说明里罗列内部 ID。模型服务和 Agent 的管理入口仍回到各自设置页。会话面板的标题与来源可见，加载、失败、空内容各有实际状态，失败允许重试。React 面板可以实现自己的表单和交互；示例的「写入对话」只生成当前会话草稿，保留用户原有输入，实际发送与审批仍由原工作台承担。数据面板只显示文本，详见 [PLUGIN-DEVELOPMENT.md](./PLUGIN-DEVELOPMENT.md)。

## 设备与权限

桌面端「连接手机」只有一个动作：打开配对面板。面板显示二维码、三步提示与关闭，二维码每分钟换一张，手机确认时变暗并停住。没有地址、端口、权限选择、倒计时或复制。三十天未验证、待复核与正文锁定分别写明。

界面按设备的权限隐藏或禁用操作，只是为了不展示做不到的事；每条规则都由 Host 再次执行。门控规则集中在 [permissions.ts](../apps/web/src/core/permissions.ts)。

**安全文案。** 这些错误文案集中在 [securityCopy.ts](../apps/web/src/core/securityCopy.ts)。

**登记页。** 未登记或凭据失效的浏览器在侧栏灰上看到一张安静的画布卡片（[EnrollmentPage.tsx](../apps/web/src/components/EnrollmentPage.tsx)，静止卡片的 12px 圆角）：标题「连接到 Latch」、说明、设备名称、权限清单与主按钮「请求本机确认」。输入框与主按钮在 768px 起是 32px，手机上是 44px。浏览器的权限清单中，查看会话、发起和继续会话、批准普通操作为固定项，「管理此 Host」为复选框，默认不勾选，下面一行说明它允许什么、哪些仍只能在运行 Latch 的电脑上完成（「可以修改模型服务、插件、项目列表和设备。密钥、Agent 的启动设置、新建项目和放宽安全策略仍只能在运行 Latch 的电脑上完成。」）；桌面端在 `host.sock` 上登记，六项权限全部列为固定项，没有复选框。表单用 `TextField` 与 `Checkbox` 原语。提交后进入等待状态：琥珀色的指纹图块（等待时不动）、「等待本机确认」、琥珀色的剩余秒数、一条琥珀色倒计时细线与「取消」；设备指纹是页面上唯一的大号文字（等宽 24px、字距略宽，20 位、按 4 字符分为 5 组，排成三组与两组两行，不会有一组单独落在一行），它就是要比对的码：桌面端的配对面板也显示它，电脑上的系统表单只写设备的名称；指纹下面用小字写出电脑上的系统表单会写的那句话（Host 给出 `reason` 时）。没有另外的核对码。被拒绝、超时与指纹不一致用红色提示；需要邀请的入口要求重新获取邀请。本机确认不可用时，桌面端开头的说明改为用离线登记码完成登记（不再提 Touch ID），琥珀色提示写出原因与 `pnpm latch device enroll --offline`，表单只接受离线登记码，Host 接受离线登记码时正常表单下方也提供「使用离线登记码」；浏览器与手机上的琥珀色提示说明新设备要在运行 Latch 的电脑上确认，主按钮停用，不提供离线登记码。没有邀请时只显示获取邀请的说明：手机与其他电脑指向桌面端 设置 › 设备 的配对二维码（其他电脑用「复制链接」得到的配对链接），不写终端命令；这台电脑上的浏览器指向桌面端「在这台电脑的浏览器中打开」与 `pnpm latch device invite --loopback`；浏览器无法在当前地址安全保存设备密钥时只显示一行红色说明，建议换用新版浏览器或桌面端。旧版登录状态显示「此设备需要在本机重新确认」并沿用旧设备名。撤销（红色）、满 30 天、换地址、丢失密钥、登记后浏览器没有保存凭据（例如禁止了 Cookie）与续期后浏览器没有保存新凭据（琥珀色）各有一行说明；后者建议允许 Cookie 后重新加载页面。设备名称可以包含表情（如「❤️ iPhone」「👨‍💻 Mac」）；含换行、不可见字符或改变文字方向的字符时，输入框下方用红色小字说明，提交按钮停用；旧设备名只在符合同一规则时沿用。登记完成后若第一次读取执行端状态失败，页面停在一行琥珀色提示与「重试」上，重试只重新读取状态，不会再登记一台设备。第一次连上 Host 之前，页面只显示「正在连接执行端…」，失败时显示琥珀色提示与「重试」。

**电脑与权限上限。** 「设置 › 电脑」（[ComputerSettings.tsx](../apps/web/src/settings/ComputerSettings.tsx)，逻辑在 [ceilings.ts](../apps/web/src/core/ceilings.ts)）讲的是运行 Host 的这台电脑：名称（这台设备是这台电脑上的桌面端、经 `host.sock` 连接时带「本机」，回环上的浏览器不带；以及开发版标记）、本机确认不可用时的一行原因、手机接入（HTTPS 地址与复制，或「未配置」与去处「连接设置在 设置 › 设备 中」，不写启动参数）。「权限上限」卡片：

- 「在这台电脑上发起」是一条阶梯，对应 `local.maxLevel` 与 `local.allowL3` 两个字段：允许完全访问时显示完全访问，否则显示内置 Harness 的上限。选完全访问写 `{maxLevel: 不低于逐项询问, allowL3: true}`，选更低的级别写 `{maxLevel, allowL3: false}`，两个字段在一次请求、一次确认里改。副行按保存的两个字段写出后果：允许完全访问时「在 Latch 桌面端发起；每个完全访问的会话仍要单独确认」（内置上限为只读时说 Latch 内置的会话不能发起）；不允许时「Agent 成员（完全访问）不能在这台电脑上发起会话」，只读时「只能查看、拒绝和停止会话」，自动编辑时先说它尚未实现、按逐项询问执行。
- 「从手机和其他电脑发起」写 `remote.maxLevel`，副行说明它也管这台电脑上的浏览器（只读时先说只能查看、拒绝和停止会话）；完全访问总是不可选，原因是完全访问会话只能在这台电脑的 Latch 桌面端发起。
- 「允许其他设备在这里新建会话」是开关（`remote.allowRemoteStart`）。
- 「其他设备可用的 Agent」「其他设备可用的项目」进入列表页：「全部」开关（`null`，包括以后添加的）或逐项勾选（`remote.harnesses`、`remote.workspaces`，组头写「N 个 Agent」「N 个项目」）；卡片下方说明加入或改为全部要在这台电脑的 Latch 桌面端验证身份，浏览器里不能勾选的条目写出带禁止图标的原因；列表还记着但 Host 上已经没有的条目显示为已移除，只能取消勾选。
- 卡片下方写「调高上限要在这台电脑上的 Latch 桌面端验证身份。高风险操作只能在这台电脑上批准。」

两条阶梯是 `PermissionMenu`，四项从低到高：只读（只能查看、拒绝和停止会话）、逐项询问、自动编辑、完全访问。自动编辑还没有自己的行为（内置 Harness 固定按逐项询问运行），所以它的说明写「尚未实现，目前按逐项询问执行」，保存的上限是自动编辑时副行写同样的话，从不说它会直接编辑。降低（级别降低、关闭开关、从列表移除、移除白名单条目）在任何管理设备上立即生效，值先原位更新，Host 拒绝时退回；调高（含打开开关、加入列表、选「全部」、加入白名单）只在执行端桌面端经本机确认进行：选择器原位显示「等待验证…」，本机确认对话框照常打开，取消时值不变、不报错。浏览器和手机在调高的选项、开关与按钮上直接写出原因（「只能在这台电脑的 Latch 桌面端调高」「…开启」「…添加」），桌面端在本机确认不可用时同样停用并说明。Host 对降低回应 `x-latch-audit: failed` 时，页面顶部用红色提示说明修改已生效但没有写入审计记录（[securityCopy.ts](../apps/web/src/core/securityCopy.ts)）。没有「管理此 Host」权限的设备只读地看到快照里的两个上限，副行与可修改时相同。「出站白名单」卡片列出 `hostEgressAllow` 的每个 `host:port` 与「移除」，没有条目时写「没有例外」与「Host 只访问公网地址（启动参数放行的地址除外）」；执行端桌面端在组头有「添加…」，打开表单对话框，地址必须是精确的 `host:port`，加入需要本机确认；其他设备没有这个按钮，卡片下方的说明在策略之后写出只能在这台电脑的 Latch 桌面端添加。

**本机确认。** 需要本机确认的操作（开启完全访问会话、批准高风险操作、首次使用自定义或本机模型服务地址、放宽安全策略（例如把地址加入出站白名单）、放宽完全访问会话的权限模式、授予设备权限）只能在执行端的桌面端发起。高风险操作只能在运行 Latch 的电脑上确认。页面不是批准入口，没有核对码或页内倒计时。页面在发起的地方处理这次确认（[InlineConfirm.tsx](../apps/web/src/components/InlineConfirm.tsx)），自己没有确认卡片：发起请求的按钮转圈并保持文字与宽度，系统窗口是唯一的确认界面，读屏读出「在系统窗口中确认」。位置仍由这次请求开始时正在等待回答的那个地方决定（`InlineConfirm` 的 `active`）：新会话的「开始」在输入框上方，会话的权限模式在会话信息的 Agent 块里（从输入框改时也在那里，会话信息没打开时在输入框上方），其余在各自的表单或对话框里。系统窗口打开时页面只留它写不下的内容：Host 给出的警告；系统 Touch ID 表单只有一句话，所以完全访问的启动（那句话只写运行什么，不写工作目录与项目配置能改什么）和那句话里有槽被截断（带「…」）时，还有「确认详情」，列出 Host 给出的各行（命令、参数、环境变量名、工作目录等，等宽，转义不可见字符），不列指纹与哈希。其他情况不显示详情；原生 sheet 自己列出这些行，旁边也不显示；页面不重复那句话。拒绝、超时、出错或核对不一致时，这次操作立即结束，留一行红色提示（在表单里取消、Touch ID 或密码没有通过、系统取消都算；Touch ID 因多次失败被锁定时说明再试一次可以用登录密码），带「关闭」，要再试就从原来的按钮重新发起。Host 无法开始确认时（连续拒绝 3 次后的冷却，附倒数；另一个确认还没完成；完全访问会话正在运行或等你处理）同样是一行：被会话挡住时说出是哪个会话与它挡住了什么，附「查看」「停止」；Host 没有说出会话时只写通用的一句。每个入口都有行内位置；没有活动位置时取消请求，离开面板或渲染出错也会取消仍在等待的确认。底部停靠框已移除。

`timer-off`，都用图标墨色），状态位写记录（[DecisionRecord.tsx](../apps/web/src/components/DecisionRecord.tsx) 的 `DecisionWords`，提示墨色）：人的选择写「已拒绝 · 14:32」（时间按消息时间的写法），提示框写完整时间与「在运行 Latch 的询问只是提示，所以 Agent 报告已经开始或完成的调用保留它报告的状态与差异，行下面多一行 28 高的说明「已拒绝 · 14:32 · Agent 报告仍执行了这次调用」（提示框说明询问只是提示、显示的是 Agent 自己的报告）。差异按已经应用的算：等待审批或排队中的调用，以及审批让它没有开始的调用，其差异不显示在行下面，会话信息的「变更」与导出的 Markdown 也不列它（导出里写一行「审批：已拒绝 · 完整时间 · 在哪里决定」）。升级之前记下的拒绝（失败、输出以 `APPROVAL_REJECTED:` 开头、没有记录）同样读作「已拒绝」，输出里去掉内部代码。减少动效时这些过渡都近乎瞬时。

**差异。** 折叠行只显示文件名、变更行数与展开控件，完整路径在提示与读屏名称中保留。展开后直接阅读变更，不常驻显示目录前缀、「新文件」或「新内容哈希」。Host 确认文件不存在时直接显示新增内容；文件存在但原文未能展示时保留琥珀色「原内容未显示」，没有说明时保留「原内容未知」，两者都说明可能覆盖已有内容且不显示删除行数。新增与删除行数仅在非零时使用相应色调。差异容器只有一层边框，代码区域不再套一张卡片。

`DiffView` 有三种模式。`hunks` 是默认：每段在 @@ 头下带符号与两列行号，审批提案必须这样完整呈现。`full` 用于审阅：一列行号、不画符号（3px 的色条表示增删）、标出改动的词、段之间是「N 行未改动」的带（每按一次展开 20 行），长行在代码区内横向滚动、页面向下滚动时文件头留在视野内；Host 或来源说明的新文件与已删除文件画成文件本身，不分栏。`compact` 是对话里的预览：没有头部，至多 12 行改动（新文件是前 8 行），每行截断在边缘，脚部写还剩多少。三种模式都照实说原内容未知或未显示，二进制文件不显示行数。`layout="split"` 时行内批注横跨两栏，两栏的行保持对齐。`gutter` 与 `annotation` 是留给评论的位置。目前工具卡、审批与文件历史都用 `hunks`，还没有页面使用 `full`、`compact` 与这两个位置。

**会话权限。** 只有完全访问会话在顶栏右侧显示琥珀色的「完全访问」状态词，前面是 `shield-alert`（手机上同样）；逐项询问（L1）是默认，顶栏不显示。会话信息的「权限」块写出级别、权限模式变化后的红色「权限模式已变化」状态词，「权限说明」展开执行方、定义是否已验证、模式能否读回、是否请求审批与 Harness 的说明。输入框在以下情况换成带锁图标的只读说明（虚线 `--line-strong` 边的托盘，不带阴影，不像一个等待输入的输入框），运行条与停止按钮保留：完全访问会话在执行端以外的设备上（「完全访问会话只接受执行端电脑上 Latch 桌面端的输入。此设备可以查看、拒绝和取消。」），或设备没有「发起和继续会话」权限。会话不再接受输入时，消息区顶部出现横幅并附「新建会话」，输入框换成「该会话不再接受输入。」：权限模式漂移为红色，来自会话状态；Agent 定义变化、项目中的 Agent 配置在确认后变化、会话创建于安全升级之前，以及无法确认 Harness 已进入预期的权限模式为琥珀色，在这台设备的输入或选项修改被 Host 以对应错误码拒绝后出现。新会话选择器中的完全访问 Harness 带中性的 L3 小徽标（没被选中的选项不报警，选中后由顶栏的琥珀标记表达），在执行端以外的设备上禁用并注明「仅本机桌面端」；在桌面端选中时，输入框下方用琥珀色小字提示「开启完全访问会话需要本机确认。该会话可以读写 Latch 数据和 Host 身份私钥。」

**开发版标记。** Host 报告开发模式时（当前的构建都未经签名发布，所以总是如此），「设置 › 电脑」在电脑名旁显示一个中性小标签「开发版」，悬停提示与读屏名称为「开发模式：Host 代码可被本机修改」；「设置 › 设备」在「此设备」卡片下写出整句说明：此版本未经签名发布，能修改本机文件的程序也能修改 Host 与桌面端。它不使用红色。

**设备设置。** 「此设备」（[DevicesSettings.tsx](../apps/web/src/settings/DevicesSettings.tsx)）：可修改的设备名称，以及连接方式、状态（正常是默认状态，只写文字；需要处理的状态才用徽标）、设备指纹、权限与登记有效期，各占卡片的一行；「撤销此设备」在页面末尾红色描边的卡片里。「已登记的设备」（需要「管理此 Host」）：每台设备一行，显示名称（当前设备带「此设备」）、非正常状态的徽标（待复核（仅查看）与需重新确认为琥珀色，已撤销为红色并排在最后）、连接方式与最近使用（或撤销时间）、权限；其他未撤销的设备尾部是 ⋯ 菜单：「调整权限…」（需重新确认的设备没有）与「撤销设备…」。撤销前说明由它邀请配对的设备会降为仅查看，等待复核。「调整权限」对话框中，「批准高风险操作」与「设置密钥」只对在执行端桌面端登记的设备提供；增加权限或恢复待复核的设备时按钮为「授予权限（需要本机确认）」，只能在执行端的桌面端进行，其他设备上按钮停用并说明原因；只收回权限时按钮为「保存权限」，任何管理设备都可以。设备名中的隐藏字符按审批区的规则显示为 `\u{XXXX}`，包括撤销确认与权限对话框里的名称；改名时的校验与登记页相同。「这台电脑的浏览器」只在执行端桌面端的管理设备上出现，是一张卡片里的一行「一次性登记链接」：macOS 上副行说明链接的有效期与之后的确认，尾部是次按钮「在这台电脑的浏览器中打开」，打开后卡片下方显示一行灰色小字说明下一步，失败时显示红色提示，邀请码不在页面上出现；其他系统上副行指向 `pnpm latch device invite --loopback`，没有按钮。手机配对见本节开头的「连接手机」。审批卡与错误文案统一说「运行 Latch 的电脑」。

桌面端配对面板另列正在登记的设备与其指纹，供与新设备比较。

配对被完全访问会话阻塞时，桌面端说明是哪一会话，并提供查看与停止；会话结束后重用仍有效的邀请。匿名登记请求不返回会话信息。

**模型服务与 Agent。** 执行端以外的设备不能输入或更换密钥（仍可移除），字段换成一行原因与去处，命令行替代 `pnpm latch provider set-key <id>` 只在没有本机确认的桌面端给出；已保存的密钥注明「密钥只发往 <源与路径>」，修改地址时提示会清空密钥，改到没有确认过的地址时另说明保存时要用 Touch ID 确认。预置服务商地址的密钥直接保存，不弹确认；自定义与本机地址在桌面端确认一次（地址、密钥与出站许可一次确认），之后不再询问。已确认的地址列在「设置 › 电脑」的「已确认的模型服务地址」里，任何管理设备都可以移除。已确认的地址出站许可被移除时，检测失败处给出「用 Touch ID 允许访问 <地址>」。添加 Agent 以及修改启动命令、参数与环境变量只能在执行端桌面端进行，名称与启用状态任何管理设备都可以改；每个 Agent 标注中性的 L3 与许可证小徽标；未验证的定义另带中性小徽标「未验证的定义」，已验证的预设是默认，不加标记。

Agent 的「测试启动」沿用设置页的一组紧凑行：右侧一个 14 图标的次按钮，等待系统认证仍在原位显示行内卡片，结果写「启动握手成功」「需要先登录」或「测试启动失败」。成功时明确写「登录状态与模型访问尚未验证」，能力只说 Agent 声明了什么；最近测试时间、程序名与版本用次级文字，不增加成功徽标。失败时诊断用可换行、最多 240 高的等宽区域和「复制诊断」，隐藏字符仍由 VisibleText 标出。结果未知时提供同一次请求的重试。旧 Host 没有能力标记时隐藏这一组。列表同时显示最近测试、当前可见会话数与最近会话时间；未开启过会话的定义写「还没有开启过会话」，与仅做握手的诊断区分。

**旧版 Host。** 快照中没有 `host` 时，Host 来自升级前的构建：界面退回旧规则（普通的允许与拒绝、由旧的主设备身份决定设置），隐藏设备、邀请与本机确认相关的界面，并在消息区顶部显示一行中性提示「此 Host 仍是旧版本，重启 Host 后启用设备确认。」；未登录的浏览器在这样的 Host 上看到「此 Host 版本过旧，请在电脑上重启 Latch。」

**审计回滚。** 审计记录被回滚时显示红色横幅，可核对或关闭。

**界面出错。** 工作区渲染出错时不会整页空白：显示一张卡片「界面出错，当前内容无法显示。」，提供「回到新会话」与「重新加载」；本机确认对话框不受影响。单条回复渲染出错时，这一条按纯文本显示。

## 流式与阅读

| 情况 | 界面行为 |
| --- | --- |
| 等待首段输出 | 最新一轮的状态行写正在启动 Agent 或运行中；不伪造思考内容或百分比 |
| 推理到达 | 思考行写「思考中」与秒数，身体自动展开并跟随最新的推理 |
| 正文到达 | 在稳定身份的同一消息行内更新 Markdown，完成后沿用该行；思考行收起并写出思考用时 |
| 工具调度 | 工作行区分等待执行、等待确认、执行中、完成、失败、取消；运行中的输出在自己的框里跟随最新的行 |
| 审批 | 合并在对应工具卡片内，展示原因、参数与预览；卡片写「需要你允许」，回合里没有第二处说它，已运行时间停住 |
| 取消 | 请求中保留取消状态；超时显示"尚未确认"并允许重试（同一请求，不会停止之后开始的一轮）；要停止的一轮已经结束时立即退出取消状态，并用提示说明；部分回复保留，回合下留一行「已停止 · 保留了部分回复」（没有正文时只写「已停止」） |
| 结束 | 状态行消失，事实进入回合脚部；正常完成的回合把工作收成一行，正文不折叠 |
| 离线 | 保留已读内容；运行中的回合不再转圈或走时，写「上次确认 10:42」；连接状态单独标注，恢复并同步后才显示已连接 |
| 上翻阅读 | 进入阅读模式，流式输出不夺走位置；"回到最新"带着新到的块数，点它恢复跟随 |
| 切换会话 | 阅读位置按会话保存；旧会话的异步结果不得写入当前会话；消息内容层淡入，带遮罩的滚动容器不做透明度动画（避免可见控件失去点击命中）；不播放消息到达的动效 |

所有程序性滚动集中在 `useReadingPosition`（`jumpToLatest`、`reveal`）；消息与工具行使用 `data-message-id` 作为锚点。不要在组件中另外写入 `scrollTop` 或调用 `scrollIntoView`。布局改变、代码展开、展开块的动画与视口变化不等于用户主动滚动。思考与工具输出这类嵌套的滚动框用 `column-reverse` 从末尾排布来跟随最新内容，不写滚动位置。从会话信息的「变更」定位到一个已折叠的工具时，页面先请折叠的祖先打开（与页内查找同一个 `beforematch` 路径），再交给 `reveal`。

Markdown 支持标题、列表、引用、表格、内联代码与代码块；原始 HTML 不执行，URL 只允许安全协议；只有网页与邮件地址是链接（加上回复自己的脚注），图片从不加载，网页图片显示为「外部图片：说明」链接；嵌套过深的回复以一行灰色说明加纯文本显示；表格与代码在自身容器内滚动；代码可复制与展开，剪贴板失败有明确提示；代码中的不可见字符显示为 `\u{XXXX}` 标记，工具栏注明「含不可见字符」，复制内容保持原样。实际点击的网页或邮件链接由桌面主进程直接交默认应用打开；脚本触发的外链另需确认。流式全文不设 `aria-live`，避免逐字播报。

**路径标记。** 回复里指向文件的链接（相对路径、`../`、绝对路径、`file://`，带 `:行` 的文件名也算）不是链接，是路径标记（[FileChip.tsx](../apps/web/src/components/FileChip.tsx)），点击从不让页面离开：中性的 `--hover` 小块（悬停、按下与菜单打开时 `--press`，圆角 4），前面是按扩展名选的 12 号文件类型图标（演示文稿、表格、图片、文档、代码、压缩包、文件夹，其他是普通文件），后面是链接自己的文字，文字就是路径或文件名时用等宽字。一行放不下时从路径的文件夹部分省略，文件名始终完整（`/Users/me/acme/…deck.pptx`），完整路径在提示里。在桌面端，看起来像路径的行内代码（`deck.pptx`、`src/app.ts:12`）在回复结束后、Host 确认它是会话文件夹里的文件时，也画成同样的标记，其余行内代码不变；完成的工具打开后，最上面一节「文件」列出它读写过、Host 确认存在的文件。文件图片（`![说明](chart.svg)`）是同样的标记：次级墨色的「图片」，然后是说明，最后是三级墨色的文件名；没有说明时只有文件名。每台设备上点击都打开同一种 260 宽的菜单（手机上是底部面板）：标题是文件名，然后是可做的动作，分隔线后是「复制路径」，底部一行写原因或去处。不在 Latch 桌面端时只有「复制路径」，底部带锁写「在运行 Latch 的 Mac 上用桌面端可以快速查看和打开。」；没有文件动作的旧桌面端写「重新启动 Latch 桌面端后，可以在这里快速查看和打开。」（info 图标）。复制后图标换成勾（120ms），读屏播报「已复制路径」。在桌面端的会话里，点击先问一次 Host（400ms 内有回答就直接带着结果打开，更慢时先写「正在检查…」；问的过程中再点同一个标记不会再问，双击的第二下不会关掉菜单），菜单只列 Host 允许的动作「快速查看」（仅 macOS）、「用默认应用打开」「在访达中显示」（按平台叫「在资源管理器中显示」「在文件管理器中显示」），「复制路径」复制的是从会话文件夹算起的完整路径（不带行号），可以直接用于访达的「前往文件夹」或终端。不提供的动作直接不出现，原因写在菜单底部的一行，文案来自 `securityCopy.ts`：锁只用于 Latch 有意拒绝的情况（可能含密钥、Latch 的私有数据、不在会话的文件夹里、会话的文件夹已不在项目里、类型不放行或暂不快速查看、内容与扩展名不符），并写出原因与去处，例如「网页和 SVG 用浏览器打开时可以联网，Latch 不直接打开；可以在访达中显示后自己打开。」「这个文件不在会话的文件夹里，Latch 不替你打开它。复制路径后，可以在访达中按 ⇧⌘G 前往。」；去处与说明用 info 图标（「这是文件夹；Latch 只在访达中显示项目的文件夹。」「重新启动 Host 后可以在这里打开文件。」）；没有成功的事用 circle-alert（「找不到这个文件。」「没有找到能打开这个文件的应用。」「上一个操作还没有完成，请稍后再试。」）。成功不提示（访达、快速查看或应用本身就是反馈）；被拒绝或失败时菜单重新打开，底部写出原因。旧 Host 缺少文件预览能力时保留这一菜单；支持内容服务时，单击改为打开文件标签。

## 验收

UI 改动需要在桌面、平板、手机宽度检查真实渲染，覆盖正常、进行中、失败或等待状态，以及浅色与深色。`e2e/design.e2e.ts` 覆盖 320 / 375 / 414 / 768 / 1440px 的可达性、溢出与真实点击区域，包括开发版标记；`e2e/enrollment.e2e.ts` 在 1440×1000、768×1024、390×844 下截取登记页的表单、等待、拒绝、本机确认不可用与旧版重新确认，并检查登记页在注入的样式下不变；`e2e/permissions-ui.e2e.ts` 截取高风险审批、完全访问只读（桌面与手机）、权限漂移（含深色）与 Harness 选择器；`e2e/visual.e2e.ts` 在 390×844、768×1024、1440×900 下以浅色与深色截取浏览器能到达的每个状态与原语总览页（`ui-gallery`），并可与上一次运行逐像素比较（见 [TESTING.md](TESTING.md#视觉截图)「视觉截图」）。原语的角色与名称、键盘、焦点、提示框、禁用与运行中、对话框的焦点限制与归还、手机上的底部面板、触屏命中区、减少动效，以及转圈的同一相位与离开视野时暂停、状态词与状态槽、只为亲眼看到的变化播放的一次性动效、动效令牌与减少动效，由 `packages/ui/test/` 在真实浏览器里检查（`pnpm test --project @latch/ui`）。截图写入被忽略提交的 `test-results/`，不包含任何凭据。桌面端才有的界面由 `e2e/desktop.e2e.ts`（`LATCH_ELECTRON_E2E=1`）覆盖并以浅色与深色截图：审批卡里的高风险确认（等待与没有通过）、行内卡片（等待、没有执行与被完全访问会话挡住）、手机配对（未生成、二维码、过期与被运行中的会话挡住）以及桌面端可以回应的「仅提示」询问；`e2e/permissions-ui.e2e.ts` 另把审批卡到达与收起的过渡停在 0、60、120、180ms 截图，并核对时长与曲线取自动效令牌。浏览器尺寸模拟不等于 iOS/Android 真机的软键盘、后台挂起与读屏验收。

Electron 另截输入框、设置和审批卡里的行内确认；自动化不会替代系统表单的人工验收。

从模型选择器添加服务时，预置服务和自定义服务都在同一个弹层内使用与设置页共用的表单：可手动填写模型 ID，自定义地址只确认一次；保存并使用后关闭弹层并选中模型。

## 工作台搜索与起步

会话切换保留原会话的未发送文字，返回相同会话 ID 才恢复；切到其他会话不带入。最多在内存保留二十份、合计 256,000 个 UTF-16 字符，优先保留最近使用的草稿，不写浏览器存储。提交确认后清除该会话缓存，换设备清空，撤回个人访问时清私有草稿。新建会话仍从空输入开始，未知提交继续复用原请求，不从草稿另发一次。

手机的列表搜索先显示标题匹配，再显示「内容中包含」的正文结果；其他宽度由命令面板搜索。正文请求防抖 300ms，旧查询在切换时取消；命中项保留原会话与消息身份，通过阅读位置控制器定位，短暂提示该行。归档视图提供批量恢复和删除，支持 Shift 范围选择，部分失败保留失败项供重试；删除前明确说明只删除记录。

⌘K（Windows/Linux 浏览器为 Ctrl K）打开命令面板（[palette/](../apps/web/src/palette)）：宽 576、距顶 12vh、最高 420、无模糊的薄遮罩。未输入时是「最近会话」与「命令」，有请求等你处理时命令里多一行跳转；输入后依次是「会话」「文件」「Agent」「设置」「命令」，「在消息中」总在最后。再按 ⌘K 收起。Esc 先清空输入、再退回上一层（「搜索项目文件」是一层，⌘P 直接进入），最后才关闭；页脚的字随之写「返回」或「关闭」。关闭后键盘回到输入框，除非刚运行的动作把焦点带走，或是触屏（不弹键盘）。回车打开的是看到的那一行：第一行一出现就按身份记住，迟到的结果或重新排序的会话不会换掉它，被推到视野外时跟过去；输入法组合期间回车不触发。「会话」最多二十行，多出时明说。关闭面板或查找条后，接着落下的 Esc（以及按住不放的 Esc）不会停止运行，也不会拒绝请求，要先停顿半秒或按过别的键。搜索进行中写「正在搜索消息…」，失败写「消息搜索失败：原因」，只有 Host 答完才写「消息里没有「…」」或「没有匹配结果」；结果不全时明说。危险动作只从其具体页面执行；缺少能力的旧 Host 不显示对应入口。文件检索只在 Host 声明能力、设备拥有完整文件数据范围且预览回调可用时出现。

⌘F 打开当前会话的查找条：宽 300，浮在对话右上角（距顶 10、距右 20），不挤压对话；匹配在会话最上方、滚动也无法移出条下时，内容下移到让出它为止。条已打开时再按回到输入框并选中文字。Enter/Shift Enter 切换、Esc 关闭并归还焦点；匹配用选区色，当前项更深。文字通过 CSS Highlight API 标记，不替换消息 DOM；搜索也覆盖尚未挂载的工具输出，只展开当前匹配所在的卡片；最多五百项，不为查找挂载全部输出。匹配的内外折叠经 `beforematch` 展开，滚动仍只由阅读位置控制器写入：当前项已在可读范围内就不滚动，否则放到视口三分之一处，长回答里的匹配同样如此。运行中新增的文字只更新计数，读者留在当前项：匹配按所在行与行内次序认定，前面多出匹配时序号跟着变，高亮不换。

快捷键只有一张表（[workbenchShortcuts.ts](../apps/web/src/workbenchShortcuts.ts)），命令面板与设置 › 快捷键（⌘/，手机上没有）只显示当前客户端的按键，且只列已经实现的绑定。

首次使用的新会话页显示三个可操作步骤：选择 Agent 与模型、选择项目、写下首个任务；已有模型或项目显示勾选；Agent 与模型直接复用当前页的添加面板，保留草稿。每步可以跳过，产生首个会话后隐藏，关于页可重新显示。真实模式提供三个只填草稿的任务灵感，演示模式仍使用标明演示的示例。桌面端首次后台任务完成后，仅在前台显示一次「开启通知 / 暂不需要」；选择经主进程持久化，设置仍可更改，不声称已获得系统通知许可。旧壳与普通浏览器不显示此入口。其他会话新增待处理请求时显示六秒内嵌提示。侧栏悬停或键盘聚焦时可点「下一个」，与桌面端 ⌥⌘A、浏览器 Alt Shift A 共用按时间排序的游标。

提示模板在通用设置中管理名称、正文与适用范围。模板建议与 Agent 实际上报的 slash 命令只改变草稿，模板列表只在版本变化时重读。命令面板可切换侧栏、会话信息、文件标签与外观，打开设备实际可用的设置分区并导出当前会话；缺少权限或能力时不列入口。桌面端导航为 ⌘N、⌘B、⇧⌘[ / ⇧⌘]、⌘1–⌘4、⌘/、⌘L（聚焦输入）；浏览器使用对应 Alt 组合。空输入框 ↑ 取回上一条用户消息；输入框连续两次 Esc 取消当前运行，单次不清草稿，输入法组合期间不触发。文件快捷键由具备能力的宿主处理：⇧⌘E / Alt Shift E 在没有文件标签时打开文件树，否则轮换已有标签。

模型选择器在超过八项时提供模糊文字搜索，按字符顺序容忍名称中的标点。最近五次选择单列在「最近使用」，其他分组不重复它们；已经移除的模型不在最近列表中恢复显示。通用设置中的模型列表开关只影响这台设备，隐藏不关闭模型服务。当前已选模型保持可见，切换之后才从普通列表隐藏；选择器可展开隐藏项。用量提供最近七天与三十天，以实际记录的 tokens 为准，细分缺失如实说明，表格在窄屏内横向滚动。

保存的项目常驻侧栏的「项目」区，没有项目时显示创建入口或执行端桌面端的说明。项目组菜单可原地重命名、用原生面板添加文件夹，并进入编辑器；分组按记录的项目身份，旧会话才按最深主目录回退。无项目会话在「对话」中，自己的专用文件夹在会话信息里称为「这个会话的文件夹」，桌面端通过主进程签名的会话 ID「存为项目…」。从组内新建优先使用该组，普通新建继承当前项目；只对话没有项目选择。新会话选择器保留不可用项目及原因，显示多文件夹摘要与 Agent 的数量上限，使用主文件夹的 Agent 在输入区下说明实际范围。会话信息显示开始时记录的所有文件夹，标记已移出项目、找不到或未传给 Agent 的文件夹，并提供可用的显示与复制操作。

文件预览与会话信息、插件包共享右侧区域，标题栏保留文件名、菜单、展开与关闭，更新、下载、复制、引用与可用的本机动作收在菜单中。正文上方显示相对路径与带单位大小。文档默认半窗、最小 480px；文本、代码与图片记住独立内容列宽度，默认 320px、最小 280px。对话至少 520px；手机和平板窄屏推入一页。文件变化、已删除、秘密、超限与权限失效都有文字状态。会话及选中项目按上下文记住最多六个文件标签，不保存字节。文本提供行号、分页、查找、跳行与换行；文档保留自己的内容排版，外壳使用 UI 令牌。细节见 [DOCUMENT-PREVIEWS.md](DOCUMENT-PREVIEWS.md)。

### 从轮次分叉

已结束轮次的更多菜单提供「从这里分叉」与「复制到这里为止的记录」。分叉进入新会话设置，预选项目和 Agent，二者可改，输入可编辑；说明文件不复制或回滚，同一项目会话共用文件夹。提交前等待本机确认时不生成会话气泡。首条消息的 Host 上下文默认折叠，展开内容按纯文本显示，保留隐藏字符提示；环境块的「分叉自」可以返回来源。没有 `catalog.features.fork` 的 Host 不出现分叉入口，查看设备仍可复制记录。

代码使用八个 `--syn-*` 角色令牌：正文、关键字、字符串、注释、数字、函数、常量和标点。关键字以 600 字重辅助识别；颜色保持低彩度墨色，不复用动作蓝、警告琥珀、风险红或差异绿。深浅主题均核对 OKLCH 彩度不超过 .06，且在 pane 与 sunken 背景上的对比度至少 4.5；注释有意更淡，至少 3。安全区域同样锁定这些令牌。

### 后续输入托盘

支持排队的 Host 上，运行中草稿非空时发送槽显示箭头，提示「本轮完成后发送」，停止移到左侧；草稿为空时仍只显示停止。托盘在输入框内部、运行信息下方，用折叠原语展开，行上可编辑或移除。多行编辑使用表单对话框，保留正常草稿。暂停项写 Host 原因并提供明确发送按钮；失去权限的项显示未发送，不承诺自动继续。远程完全访问会话可以查看托盘，有 run 时仍可移除，没有编辑或继续入口。消息时间提示附排队时间；结果未知沿用原请求标识并保留待确认项。

### Agent 提问卡

内置 Agent 的提问显示在对应工具行的位置，用琥珀「等你回答」标记。多题向导显示题号、上一题与下一题，支持单选、多选和「其他…」；提交要求每题有效，其他答案非空。草稿仅保存在本设备，提交中锁定选择，结果未知时保留同一回答供重试。已提交的结果折叠为「已回答 N 题」，展开可核对选择，随后显示模型继续的回复。缺少功能标记的旧 Host 保留普通工具展示。

### 附件与显式文件引用

附件用输入框工具栏的单个文件按钮，以及紧凑的文件行表达，上传比例使用中性墨色。取消发送保留文字与文件；长粘贴折叠成可编辑文字附件。已提交附件进入统一文件列，新会话的草稿只在输入框预览。独立的 `@` 打开项目文件选择，结果表明相对路径与文件夹 ID，普通邮件地址保持文字。模型图片能力由模型设置中的显式开关表示。

### 发送中的消息

支持消息身份的 Host 上，提交文字立即出现在本设备的消息位置，500ms 后才写「发送中…」。确认的消息取代临时投影，不重复追加。结果未知写「未确认送达」，可原样重试；排队输入与等待本机确认的首次启动不显示气泡。临时状态只表示提交过程，不生成完成轮次或模型回复。
文件变化的范围、运行结算、可选插件契约与验证见 [运行期间的文件变化](FILE-OUTPUTS.md)。

右侧面板的「变更」页签见 [CHANGES.md](CHANGES.md)：一行放范围、合计与撤销（或没有撤销的原因），琥珀只给要留意的行，红色只在不能恢复的确认框里。文件树从 6 个文件起、差异还能留 560 宽时自己打开；差异列 760 宽起左右对照；路径放不下时整段丢掉前面的文件夹。

会话信息的变更按文件夹与路径区分同名文件，单击在文件列从最新一次开始查看工具差异，可切换本轮与历史、行内与左右对照；悬停或键盘聚焦时出现当前文件的预览入口。历史与当前预览在同一标签切换，不新增整页审阅界面，已删除文件的记录仍保留。

文档预览保留当前文件的页码与适应状态；缩放使用键盘或双指，窄列收起页工具栏。自动打开新增文档为默认开启的本设备偏好，在 1024px 起的宽窗口上按右侧面板此时的位置打开（放得下对话时在旁边，否则盖在对话上），至少 480px，并保留输入焦点与草稿；手机只显示文件入口，用户可关闭自动展开，见 [文档预览](DOCUMENT-PREVIEWS.md)。

项目文件树按需出现在右侧文件区，窄屏沿用文件页。首次打开默认展开主根；目录按展开读取，长列表分批显示，隐藏项开关收进菜单。文件单击预览，菜单可复制相对路径或引用到草稿；新会话未发出消息时也能预览选中项目。文件搜索沿用命令面板和键盘导航，返回相同的文件列，不另开工作流。

项目编辑页的会话数是静态信息；「最近会话」另列当前设备快照中归属该项目的最近三条记录。归属复用项目分组规则，个人助手不会混入；打开入口返回同一工作台，权限撤回后撤下。
