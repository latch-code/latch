# Latch 界面设计

Latch 是跨设备的 Agent 工作台：任务在 Host 上运行，用户从桌面、浏览器或手机查看、审批、取消并继续同一段工作。界面要同时表达会话内容、执行状态、设备连接与设备权限，且只展示真实存在的能力。传输、续期与阅读位置的机制见 [STREAMING.md](./STREAMING.md)。

日常发送保持相同入口，只有 Host 实际要求首次信任时才展开确认内容。连接手机的默认流程为开启、扫码和电脑允许；网络自动选择。原项目失效时保留可编辑草稿，并就地选择有效项目继续；模型切换结果未知时保留真实选中值，先读取结果，不自动重复写入。详细状态规则见 [项目恢复](./WORKSPACE-RECOVERY.md)、[模型配置](./MODEL-CONFIGURATION.md) 和 [按需加载](./CLIENT-LOADING.md)。

## 品牌与原则

- **名称与图标。** 名称为 Latch。应用图标是炭黑圆角方块、两片象牙色折面与一个橙色接点；`apps/web/public/icon.png`（512px）用于界面、窗口与主屏幕，`apps/web/public/favicon.png`（64px）用于浏览器标签，`build/icon.png` 是高分辨率源图。不要改动图形本身。图标是界面里唯一的暖色元素，不使用它的橙色表达状态。
- **简约、克制。** 蓝白为主：中性的近白与近黑，近黑的墨色文字；深色是近黑的底与柔和的白字，黑不是纯黑、白不是纯白。层次只靠几层平涂的表面（侧栏灰、画布、浮起、凹陷）、1px 的细线与墨色深浅，不靠装饰色、渐变、底纹、插画或表情；菜单、选值与对话框是最高的不透明面（弹层面），不用玻璃。控件按数据的形状选择，一种意思只用一种画法。
- **每种颜色只表达一件事。**

| 颜色 | 只用于 | 不用于 |
| --- | --- | --- |
| 蓝 | 执行动作的主按钮（发送、允许、请求连接），每个界面最多一个；被勾选的控件（开关的开、复选框、单选）；焦点环与选中文字的底；跳到别处的链接文字 | 运行中、计数与进度、图标、用户气泡、徽标；菜单里的对勾；列表的选中行（会话行、设置导航）；视图、筛选与外观的选中；切换按钮的「开」 |
| 琥珀 | 等你处理（等你允许、在系统窗口中确认，与等你处理的计数）；警告（连接中断、原内容未知、含不可见字符、已开启的完全访问会话）；演示标记 | 可按的按钮；普通信息；没被选中的选项与常驻的属性（菜单与列表里的完全访问 Harness、Agent 行的 L3） |
| 红 | 真实的失败与风险：高风险（R2）审批、失败、权限模式漂移、审计记录回滚、设备撤销、差异中的删除、危险操作的文字与确认对话框里的销毁按钮 | 完全访问、开发版、停止按钮 |
| 绿 | 差异中的新增；短暂的成功对勾（本机确认后的对勾） | 已连接、已就绪、已检测到、已验证这类默认状态；已保存、已启用这类本地操作的结果（值原位更新就是反馈） |
| 墨色 | 运行中与加载中的转圈、「运行中」与流式光标、未读的对勾、计数与进度、所有静止的图标、菜单里的对勾、列表的选中行（浅色是侧栏灰上的白色卡片，深色是一层柔和的白）、视图与外观的选中、切换按钮的「开」 | — |

- **默认状态安静。** 连接正常、逐项询问、已检测到、已验证的预设这类默认状态不用颜色，也不加标记；顶栏只在偏离默认时出现标记（连接异常、完全访问、演示），会话的状态与侧栏同一套词：运行中带计时，等你处理、没有动静、正在停止、失败与结束的方式，已完成不标；侧栏页脚不写「已连接」。风险色只在风险值真的被选中时出现。
- **内容优先。** 对话列是主角；导航安静，不使用大面积饱和色。只有用户自己的消息有气泡，且是中性的。
- **每个状态只出现一次，并出现在正确的位置。** 会话级状态在顶栏状态标签与侧栏图标；进行中的活动在最新一轮末尾的状态行；等你允许只在它自己的卡片上说一次，卡片不在视野里时由「回到最新」的位置带你回去；单步状态在它的工作行。
- **少说明，用界面说。** 控件、图标、色调与状态词能说的，不再写成句子。说明性的话只留一个短标签（大约十二个字以内）加图标或色调；规则要求能找到的细节（Latch 不隔离 Harness、密钥发往哪里、一项授权打开了什么）收进 `Hint`：短标签常显，细节在 ⓘ 后原地展开，触屏与键盘都能打开。审批卡对动作本身的描述、系统确认的固定句子、Host 照抄的提醒、删除与移除这类不可逆操作的说明、告诉人哪里失败与怎么办的错误不在此列。菜单、弹层或行里超过一行的灰字是缺陷。
- **只展示真实能力。** 选择器只列出 Host 目录中真实的 Harness、模型与项目；只有一个选项时以只读标签显示。演示模型必须带琥珀色"演示"标记。不展示虚构的数量、进度或尚未实现的菜单。设备做不到的操作直接隐藏或停用并说明原因，不让用户提交后再失败。
- **默认隐藏内部细节。** 路径中段省略并提供复制。审批只在动作完整写出同一路径时省去单文件差异的文件名。工具 ID 作为次要文字。手机总览的普通文件写入完整显示动作和路径、且「更多」可用时，工具 ID 收在「更多」里。空参数显示「无参数」。

自定义插件使用紧凑的列表与编辑对话框；列表先呈现名称、用途与状态，编辑器区分「未保存修改」「草稿」「有未应用修改」「已应用」「已停用」及真实不可用原因。技能正文直接编辑；文件与高级声明另设页签。只有应用执行主按钮使用蓝色。纯技能修改不出现系统确认，新的 Host 或界面模块代码经同一条行内确认流程。丢失响应时保留编辑内容并提供「重试同一请求」，不会创建第二份插件。启用与导出只对已保存状态操作。

早先的助手与群聊跑过的会话照常列在会话列表里，打开只能查看：输入框的位置是一行「这个会话来自已移除的 Agent，只能查看」，没有模型、权限等控件（手机相同）；本轮改动卡没有「撤销本轮」，改动面板在撤销的位置写「这个会话只能查看」，会话菜单没有「清空上下文」。

会话与新会话的未发送文字按设备与会话存在本机浏览器存储，刷新、重启后还在（存储不可用时只在内存），最多二十条、合计 256000 个字符；切换只恢复目标会话的文字，附件与文件引用只在内存，不保存也不随切换携带。超出单条上限时保留当前输入并提示先复制。含凭据的文字只在内存，14 天未改的丢弃；会话被删除（这里删除、Host 报告已删除，或完整列表里不再有它）、设备被移除或退出时立即清除，列不全或已归档不算删除，不能转入普通新会话；设备不再能读私有内容时，移除 Agent 会话的草稿。未知提交仍保留原请求编号。

## 设计令牌

令牌在 workspace 包 `@latch/ui` 的 [tokens.css](../packages/ui/src/tokens.css)，页面的样式入口 [index.css](../apps/web/src/styles/index.css) 第一行导入它。页面的每个颜色、阴影、字号与行高、间距、圆角与时长都只读这些令牌。[styles.test.ts](../apps/web/test/styles.test.ts) 检查：样式表只读已定义的令牌；颜色不写字面值（遮罩与配对二维码的白底除外，二维码在深色下也要深色模块配白底才能扫描）；字号与行高只用角色令牌，字重只有 400、500、600；内外边距与间隔不落在台阶之间；圆角只取台阶上的值（磁贴按边长 × 0.225 取整）。[tokens.test.ts](../packages/ui/test/tokens.test.ts) 核对两种主题的颜色与设计取值一致，退役的令牌名不再出现。

**主题。** 浅色写在 `:root`；深色重写每个含颜色的令牌，同时写在 `@media (prefers-color-scheme: dark)`（仅当根元素没有 `data-theme="light"`）与 `:root[data-theme="dark"]` 下，两份完全相同（tokens.test.ts）。只由其他令牌组成的令牌（`--surface`）只写一次，随主题变化。中性色是不带色相的灰：浅色是近白上的近黑墨，深色是近黑上的柔和白字；悬停与按下是黑（深色是白）加透明度，所以叠在任何表面上读起来都一样。主题偏好（跟随系统 / 浅色 / 深色）按设备保存，写入根元素的 `data-theme`。换主题不播放任何过渡：`switchTheme` 在改写前给根元素标 `data-theme-switching`，base.css 在这期间关掉所有过渡，两帧后再去掉；跟随系统时 `followSystemTheme` 对系统的切换做同样的事。浏览器的 `theme-color` 在每个宽度都取基础侧栏色（`--sidebar`）；`index.html` 按配色方案写成两条，选定主题时 `applyTheme` 改写它们（[styles.test.ts](../apps/web/test/styles.test.ts) 核对它们与令牌一致）。manifest 不分深浅，`theme_color` 与 `background_color` 都用浅色的侧栏色；桌面端窗口在首次绘制前的底色与它的错误页也用两种主题的侧栏色。主色在浅色是 `#2461E0`、深色是 `#2F6BE6`，悬停都更深一级（`#1D55CC`、`#2A62D6`），所以蓝底上的白字在两种主题里都至少 4.5:1；蓝色的字（链接）用 `--accent-ink`：浅色是比主色深一点的 `#1D52C4`，深色是更亮的 `#6B9BFA`，在每层表面以及叠在上面的悬停与按下上都至少 4.5:1。黑不是纯黑、白不是纯白：浅色正文 `#17171A`，深色正文 `#ECECEF`；只有浅色里地面以上的各层是纯白。深色下应用图标的炭黑方块会和侧栏融在一起，所以沿方块自己的边画一圈 1px 的环（`--app-ring`，浅色下透明）：图片四周有透明留白，环画在留白内侧方块的边上，不画在图片的方框上，图形本身不变。

**表面。** 都是平涂：令牌里没有渐变、底纹与带色相的底（tokens.test.ts）。表面分六级，由深到浅：凹陷 `--sunken`、地面 `--sidebar`、画布 `--canvas`、浮起 `--raised`、卡面 `--card`、弹层面 `--pop`；几乎不用线，层次靠阴影。地面 `--sidebar`（沿用旧名）由 base.css 画在根元素与 body 上（浅色 `#EBEBEF`，深色 `#09090B`）；工作台内的地面和画布 `--canvas` 都用 `--work-canvas`；浮起 `--raised` 是输入框、菜单与弹层、对话框与 Toast；卡面 `--card` 是浮在面板上的卡（审批）；弹层面 `--pop` 是控件的面与卡上再浮起的一层；凹陷 `--sunken` 是井：代码块、命令输出、表头与搜索框，比它所在的表面更深。浅色里地面以上各层都是白色，靠阴影分开；深色里地面最暗，凹陷、画布、浮起、卡面、弹层面依次提亮（tokens.test.ts 核对这个顺序）。列表里被选中的行（侧栏的会话行、设置导航）是 `--selected` 加 `--selected-ring`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 的落影），深色是一层柔和的白；从不用蓝。所有墨在侧栏、画布、浮起、凹陷、卡面、弹层面、用户气泡与选中行上，以及叠在侧栏与画布上的悬停与按下上都达到 WCAG 对比度：正文 `--ink`、次级 `--ink-2` 与红字 4.5:1，提示墨色 `--muted` 与主色 3:1；提示墨色与琥珀字在它们常驻的画布、浮起、卡面与侧栏上是 4.5:1，提示墨色在悬停的行上也是，琥珀字在琥珀控件的悬停底上也是；琥珀图形 `--amber-icon` 在这些表面上至少 3:1。`tokens.test.ts` 逐项计算并核对这些下限；调整任何表面、选中或墨色的值都要通过它。

**层叠层。** tokens.css 第一行按 `tokens, custom, base, ui, app, security` 声明层。`custom` 只收根节点上由外观文档编译出的允许令牌。`@latch/ui` 的 [ui.css](../packages/ui/src/ui.css) 把元素默认样式（[base.css](../packages/ui/src/base.css)：盒模型、文档字体与颜色、焦点环、按键、减少动效）导入 base，把每个原语的样式表（`packages/ui/src/styles/`）导入 ui；页面的 index.css 先导入 tokens.css 再导入 ui.css，然后把自己的每个样式表导入一个层：还没有做成原语的共用部件（`ui.css`：品牌图标、状态点、字母磁贴、进度条、表单字段与值选择 chip）也在 ui，页面自己的布局与界面在 app，登记、设备、权限与本机确认的样式（`auth.css`、`security.css`）在最上面的 security。后面的层总是胜过前面的层，与选择器的权重无关，所以页面可以在 app 层按位置调整原语，安全相关的界面不会被普通样式改写；新增的安全界面放进 security 层。

**安全界面的锁定。** 审批、登记、配对与确认带 `data-secure`，样式放 security 层。`data-lock` 给安全状态与其文字使用同样的主题令牌锁，把继承的字号和行高恢复为产品值。锁定的状态继续使用原布局。设置的自定义外观只提供主色、圆角和字号。见 [CUSTOMIZATION.md](CUSTOMIZATION.md)。

看不到项目文件的设备仍显示文件操作的动作、路径和原审批按钮，差异正文与编辑内容由 Host 在 HTTP/SSE 出口省略，不靠 CSS 隐藏。工具的结果说明、失败或结果未知、决定时间保持；缺少文件内容不是“没执行”或“成功”的证据。会话 Markdown 导出使用相同投影，完整数据范围的原差异仍可查看。

| 类别 | 令牌 | 规则 |
| --- | --- | --- |
| 墨色 | `--ink`、`--ink-2`、`--muted`、`--faint` | 正文与标题 / 静止的正文与次级强调（侧栏行的标题、说明）/ 次级文字、元信息与静止的图标 / 占位符与时间这类最安静的字。禁用只有一种画法：整个控件降到 45% 不透明度，颜色不变；菜单里不可选的项只降图标、标题与说明，下面的原因行保持原色。前景透明度不是一档墨色，除隐藏、淡入淡出与禁用外不用（`styles.test.ts` 检查） |
| 表面 | `--sidebar`、`--canvas`、`--raised`、`--sunken`、`--card`、`--pop`、`--hover`、`--press`、`--selected`、`--selected-ring`、`--bubble`、`--glass`、`--scrim`、`--surface` | 见「表面」。`--bubble` 是用户消息的气泡；`--glass` 是浮起色的 88%，配 16px 模糊，原语不再用它（菜单与选值是 `--pop`），只剩页面里的个别浮层；`--scrim` 是模态的遮罩，配 4px 模糊；`--surface` 是元素下面那层表面（默认画布），状态点与计数用它镂空，放在别的表面上的容器把它改成那层表面 |
| 线 | `--line`、`--line-strong`、`--joint` | 一律 1px。`--line` 是静止容器的边与分隔线；`--line-strong` 是输入框、复选框与描边按钮的环，以及虚线框；`--joint` 是卡与它下面输入框之间 3px 的接缝 |
| 阴影 | `--sh-panel`、`--sh-lift`、`--sh-well`、`--sh-1`、`--sh-pop`、`--sh-dialog`、`--sh-accent`、`--sh-thumb`、`--sh-tip`、`--seg-on-shadow` | 层次用阴影画：`--sh-panel` 把工作面板从地面上托起，`--sh-lift` 把输入框与卡从面板上托起，`--sh-well` 把井压进它所在的表面，三者都自带一圈细环；`--sh-pop` 与 `--sh-dialog` 自带 1px `--line` 环；带这些阴影的元素不再加边；深色的阴影更深，浮层在顶部加一条内侧的亮线。`--sh-1` 给描边按钮；`--sh-lift` 也给输入框（composer）、菜单、弹层与 Toast；`--sh-pop` 给提示类的小浮层与「回到最新」；`--sh-dialog` 给对话框、底部面板与抽屉；`--sh-accent` 是主按钮的内侧高光与淡蓝落影；静止的行不带阴影 |

**动效。** 动效说明界面发生的变化。我的 Agent 头像保留既有的活动表现（见「组件」的「Agent 头像」）。五档时长各配一条曲线：`--m-micro` 120ms（悬停与按下的底、图标替换、状态词与标签页内容的交叉淡化；`cubic-bezier(.2, 0, 0, 1)`）、`--m-enter` 160ms（菜单、弹层与提示框从 98% 放大并淡入，消息与行的到达；`cubic-bezier(.2, .8, .2, 1)`）、`--m-panel` 200ms（侧栏收起、右侧面板的宽度、展开与折叠的网格行）、`--m-sheet` 260ms（对话框从 98.5% 放大并淡入、底部面板、平板的会话列表）、`--m-push` 320ms（手机的推入与返回）；后三档是同一条 `cubic-bezier(.32, .72, 0, 1)`。离开用进入时长的 70%，配退出曲线 `cubic-bezier(.4, 0, 1, 1)`。脚本里要按过渡计时的地方读 `MOTION`（`micro`、`enter`、`panel`、`sheet`、`push` 与各自的 `…Exit`）与 `EASING`，[motion.test.tsx](../packages/ui/test/motion.test.tsx) 核对它们与令牌相等。会循环的包括运行中的转圈与活动边、「正在思考」的光带、检测中磁贴的进度弧、加载骨架与流式光标。除流式光标外，它们离开视野时都暂停。减少动效有两个来源：系统偏好（`prefers-reduced-motion: reduce`）与这台设备上的「减弱」（根上的 `data-motion="reduce"`，见「动效的开关」）。两者下 tokens.css 都把五档缩到 120ms 以内（micro 100ms，其余 120ms），v9 的弹簧换成线性；对系统偏好没有全局规则，每个样式表只保留它所移动之物的淡入淡出（不滑动、不缩放、不长高、不转动），原语的关键帧换成只有不透明度的版本，循环停在静帧。换主题时不播放任何过渡（见「主题」），拖拽中跟手的部分也不做过渡。

**工作面。** 两种布局共用静态画布、浮起、凹陷与墨色令牌。标题行、设置导航和布局预览沿用同一画布。Code 的可选背景画在工作内容下面，设置沿用静态画布。输入框和决定卡用浮起面，任务词、图标与卡片持续表达实际状态。
**v9 动效（[moves.ts](../packages/ui/src/moves.ts)、[moves.css](../packages/ui/src/styles/moves.css)）。** 两条弹簧曲线用 `linear()` 写：`--e-spring`（阻尼 0.72，过冲 3.8%）给人触发后落定的东西（按压松开、行让位、药丸升起），`--e-settle`（阻尼 0.85，过冲 0.6%）给要准的（角标、发送）；不支持 `linear()` 的浏览器回退到 `--e-panel`。设计系统的具名动效原语只动 `transform` 与 `opacity`，经 Web Animations 交给合成线程：`enter` / `exit`（行进入 160ms 上移 `--rise`，离开 112ms）、`flip`（位置变化前后各量一次，200ms 弹簧，超过 12 行直接换）、`resolveAndRise`（回执到了：一块表面色的遮片 140ms 扫过卡，卡撤下，其余上升；卡上的字不动）、`moveLane`（换道：出、让位、进，不做横穿屏幕的飞行）、`crossFade`（布局切换，整窗 160ms 交叉淡化，页面、焦点、草稿与滚动位置不变）、`stagger`（菜单条目相隔 18ms，最多 8 条）、`sendLift`（发送的话从输入框升到对话里，320ms）、`sheenOnce`（动作真的完成时过一道光，一次；失败不播）。CSS 原语包括`.ui-press`（按下 80ms 到 0.97，松开 420ms 弹簧；按钮同此）、`PillMove`（升起两倍 `--rise`、420ms，离开 112ms）、`Roll`（计数滚动 240ms，增加向上、减少向下）、`SectionTitle` 的线（从左画出 420ms，一次）、角标（向内收 6px，延迟 `--m-enter`）、`RunningEdge`（运行行底部一条走动的细光，2.4s）、`LiveDot`（在线的连接点，一圈 2.4s）。规矩：新的一次从上一次所在处出发并取消上一次，不排队；减少动效时直接换或只留不超过 120ms 的淡化，活动边与连接点的圈不出现；没有 Host 的事件或回执不播放，乐观更新不配动画；计数滚动与标题线只为页面亲眼看到的变化播放（`LiveChanges` 纪元不变），首次加载与重新同步时直接显示。外壳已接入布局交叉淡化。队列移位、发送、决策回执等场景的专用接线仍待后续实现。单元素具名动效跳过安全界面（`[data-secure]`）、里面的元素和包含安全界面的容器。`flip` 在布局变动后重新检查。审批、确认与配对显示的东西出现后不位移、不淡化、不过光，卡的撤下也是直接撤下。安全界面已显示时，布局直接切换，省去整窗快照。正在出字的层用 `useStreamingLayer` 标记（[stream.ts](../packages/ui/src/stream.ts)）：会话的正文、展开的流式思考与可见旁支回答用这一标记保护正文。标记进入视野时活动边、连接点与背景层暂停，被遮住、滚出视野或结束后恢复。该层及其内部跳过具名动效。

**动效的开关。** 「设置 › 通用 › 动效」只在这台设备：跟随系统、减弱。「减弱」在根上写 `data-motion="reduce"`，跟随系统时没有这个属性；脚本只问 `motionAllowed()`（头像、外壳的推入返回、输入框的发送槽、列表重排都经它），不单看媒体查询。「减弱」对全页生效：令牌缩短，`base.css` 让每个过渡与动画立即结束、循环只走一遍，脚本动效不播放，返回上一页不再等退出动画的时长。 系统或设备减少动效时，流式回复立即画出已到达的文字，终端光标停止闪烁。新样式里减少动效的规则写两份：`@media (prefers-reduced-motion: reduce) { … }` 与 `:root[data-motion='reduce'] …`；循环只写在 `no-preference` 里。截图用的冻结是另一个属性 `data-capture="still"`（`captureStill()`）：头像与背景层认它，设置写入或移除 `data-motion` 时不会清掉它。

**背景层原语。** [Backdrop](../packages/ui/src/backdrop.tsx) 在宿主内容之下使用单独一张画布。它提供三种效果，分别是点阵（28px 间距的细点慢慢漂，一条斜的亮带缓慢扫过）、粒子场（有远近的点，近处的点之间连细线）、柔光（一团很淡的光）；原语用 `--fx-ink`，令牌缺失时什么都不画。它不承载信息，只接收三个真实状态，每一个前景都用字和图标写着：在跑的会话数（多一点就动得快一点，上限 5；为 0 时几秒后停在当前一帧）、是否专注输入（向输入框聚拢）、刚处理完一个决定的位置（一圈涟漪，同一个决定只有一圈）。它不画在 `[data-secure]` 之下（柔光也用硬边挖掉，不给安全界面染色），也不在安全界面内渲染；文字直接放在画布上的区域标 `data-backdrop-clear`，整块挖掉，边缘 56px 羽化。这些区域的位置在它们可能变动时重新量：区域出现、离开或改变大小，页面任何一处滚动，窗口改变大小；暂停时照样量，所以流式输出期间出现的安全界面也会从静止帧里挖掉；祖先有缩放时按缩放比换算。每秒至多 30 帧，每帧只由一个定时器加一次动画帧唤起，不按显示器刷新率空转；点数按面积算并封顶（轻 60、标准 110），窗口改变大小时原有的点按比例挪位，不重新撒；循环只写画布像素，不引起内容层的布局或重绘。标签页隐藏、窗口失焦（包括挂载时已经失焦）、视野里有流式文字、减少动效（画一帧静止的，每次相同）、截图冻结、电量低都停在一帧；平台不报告电量时，手机默认停在静止帧，桌面与平板照常。背景效果的偏好是关、轻、标准，只在这台设备，桌面默认标准、手机默认轻。Code 总览、专注输入和前台对话使用粒子场。在「设置 › 通用 › 背景效果」选择关闭或强度。会话用固定阅读区避让正文，正文增长和跟随滚动时保留避让范围。

**密度。** 在「设置 › 通用 › 外观」选择标准或紧凑，只保存在这台设备。根上的 `data-density` 通过 `--density-row` 改变总览的常规工作摘要、侧栏会话和全部会话的行距。触屏行保留至少 44px 命中区，审批与其他安全表面沿用标准尺寸。

命令面板可按「背景效果」「动效」「密度」搜索并直接应用对应选项。命令和通用设置共用名称、选值与本机存储，切换后返回原工作台与草稿。

语义文字色除了满足现有对比度检查，还按 [Chromium 的色觉缺陷模拟矩阵](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/css/vision_deficiency.cc) 检查红、绿、蓝三类色觉缺陷。浅色与深色的蓝、琥珀、红、绿逐对转换到 OKLab，色差 `100 × ΔE` 至少为 3，用于防止近似同色；这不是可访问性合格的独立判据。状态始终同时带文字和图形。

## 布局

**侧栏与顶栏。** 工作台有两种布局，按样子起名：「侧栏」（按项目）与「顶栏」（按状态）；首页在两种布局里都叫「总览」，「总览」不是布局名。切换入口有三个：窗口顶行最右端的两段图标开关（[LayoutSwitch.tsx](../apps/web/src/shell/LayoutSwitch.tsx)，两种布局在同一位置，由壳层只画一次，悬停写名字与键位，⌥⌘L、浏览器 Alt Shift L）、设置的「通用 → 外观 → 布局」两张预览卡（名字下各一行「按项目」「按状态」）、命令面板的「切换到顶栏布局 / 侧栏布局」。标题栏不再有布局下拉。默认侧栏，偏好沿用本设备 `latch.preferences` 的 `workbenchLayout`，存储键仍是改名前的 `overview`（侧栏）与 `triage`（顶栏），所以已保存的选择照常读出；不写到 Host 或改变其他设备。侧栏布局用项目侧栏，平板为 60px 图标轨；顶栏布局用 56px 顶栏，会话旁是 300px 的紧凑队列。两种布局共用底色。顶栏布局平板待处理占整宽，进行中与交付在下一行；手机分段选择三道，并以一条文字导航保留全部会话与搜索入口。全部会话是真实项目分组页，仍能筛选项目、查看归档与使用原会话菜单。桌面与平板使用整页项目分组；手机从首页的「全部会话」进入共用会话列表，保留搜索、项目筛选、归档与长按菜单，并有「返回总览」。手机 Code 入口始终回首页；从首页决定卡进入会话后返回首页，从历史进入后返回历史，不把旧列表作为 Code 首页。旧会话恢复的列表返回仍兼容。发送回执晚到时，设置、Agent 与历史页面保持原处。

「总览」覆盖当前会话，阅读 `selectedId` 与编辑 `inputTarget` 分开，仍只有一个 `useSubmission`。「新会话」与 ⌘N 就是回到总览并聚焦输入框：没有单独的新会话页，也没有手机上的新会话面板；没有打开会话的 Code 就是总览。项目、文件夹或新工作树、Harness、模型、思考、权限、首次使用与设置引导、离线、未确认送达的提交都在这一个输入框上。没选项目时地点行写「不选项目」，可以直接发送，在 Host 的默认文件夹开始。分叉与「在新会话继续」放下原会话后同样落在总览。被总览盖住的会话在侧栏（侧栏布局）或「全部会话」（顶栏布局）里仍是当前那一行，点它回去；总览上没有返回箭头。总览是一个真实的去处：盖着会话时从设置等页面「返回」仍回到总览，重新载入这个标签页也回到总览（按设备记在 `sessionStorage` 的 `latch.home.<origin>.<deviceId>`），会话仍在其下。首页编辑独立新草稿、附件和引用；首页的项目文件浮层按新草稿选中的项目与 Harness 读取，复用文件树、预览和同一文件标签存储，关闭或引用后回到原输入；旧会话保持挂载、文件标签、原草稿、附件及阅读位置，返回恢复。布局切换停在同一页：总览对总览、会话对同一会话（阅读位置、草稿、附件与打开的面板不变）、设置对设置；不换输入目标、不重挂载会话、不发写请求、不取消任何运行。整窗以 160ms（`--m-enter`）交叉淡化。安全界面已显示、减少动效或浏览器不支持视图过渡时，布局直接切换。焦点留在原控件上；原控件属于另一种布局不画的导航时，焦点落到当前页面区域。重新显示的审批重新等待320ms防误触时间。新建与分叉的显式输入选择在文件编辑离开guard之后执行，消费命令时重核输入目标与精确文本；未知提交不被新动作覆盖。

首页只展示Host获授权的Code会话，排除归档与我的Agent话题，分为「等你处理」「进行中」「可交付」。两种布局都只展开选中的决定。多条请求时，会话概要与当前决定分开，宽处并排。列表滚动和展开状态在切换请求时保持，已处理的请求退场后接到相邻项。只有当前决定懒读既有 TaskDetail，复用原审批/问题控制器、权限和requestId，不建立第二套决定状态。顶栏布局中位于首项并已展开的普通 R1 请求可使用数字 1 拒绝、2 允许，浏览队列或使用输入框、菜单及对话框时，这组键不处理决定；R2与Agent自带审批不扩大快捷批准。Host 明确确认目录不适用 Git 交付时，首页不把它算作可交付，概要不显示「交付」一节；损坏或无法读取的 Git 状态仍保留失败和重试，不冒称没有改动。失败与结果未知的条目以人要做的动作为题：淡色的动词（「重试」「核对」，不能重试的失败是「查看」）加墨色的对象；Host 没有给出对象时对象是会话标题。红色与琥珀只在图标上，标题不是孤零零的「失败」；侧栏布局的行第二行只写项目。高风险请求的红色原因后面是短句「每次都要确认」，Host 的整句在它的 ⓘ 里，1440 宽时不折行。失败与结果未知都写出原因；可重试失败经唯一sender重新定位并核对原会话状态，未知执行不冒称可安全重放。

「接着做」取最多三条快照中的空闲 Code 会话，排除归档、会话本身只读、我的 Agent 和已经出现在状态分组中的会话。只显示该会话的标题、所属项目与最近更新时间，打开即回到原会话。

两种布局只在连接有效且 Host 状态仍为运行的行底画活动边。等你处理、没有动静、停止中和断线沿用各自的文字与图标。活动边离开视野时暂停，减少动效时隐藏。

桌面和平板的会话工作台在窗口底部显示当前电脑、连接状态和搜索键位。电脑入口沿用原菜单与「设置 › 电脑」。已连接时，本机 Electron 显示 `host.sock`，桌面远程窗口与 HTTPS 页面显示 `HTTPS`，本机回环浏览器显示「回环 HTTP」。在线数来自桌面端实际提供的完整电脑清单。失去连接时，连接点停止并显示正在重连或离线。底条为终端与侧边面板留出独立空间，平板或触屏的电脑入口高至少 44px。专注时隐藏底条，手机继续使用原 Tab 栈。

审批答复丢失后，请求行与当前决定显示结果尚未确认。原选择无法在当前连接或设备权限下发送时，仍保留这个状态。恢复后，重试只发送原来的选择、说明和请求号。

普通单文件编辑有已授权差异时，Code 总览把请求和「拟议改动」分开排版，宽处并排，窄处顺序阅读。差异仍由同一审批预览、同一个决定控制器负责；没有差异、高风险、未知回执、多文件或有安全提示的请求保留完整审批卡。

Code 总览的导航和输入框不会随队列滚动。手机的顶栏布局把两个空间的全名和布局开关放在第一行，将额度与设置放在会话导航行。桌面上，侧栏布局的待处理占主列，右侧依次列进行中、可交付和接着做；顶栏布局按状态并列，接着做在状态栏下方。长状态列表各自在剩余高度内滚动，空组只占一段短行。平板和手机由输入区外的内容区滚动，手机输入区在底部占实际高度，不盖住队列的最后一项。矮窗内，长草稿在输入框内滚动，附件和选择器仍可达；浏览器窗口高度不足 480px 或需要展示设置引导时，由内容区统一滚动。

交付最多读取最近12个可见候选的真实Git摘要，仅按获授权同cwd去重。未覆盖的历史与真实零项分开；权限不足、读取失败、绑定PR读取失败都不称为没有改动。工作区未提交文件、未推送提交与绑定PR检查是分别观察的事实，不归因某个会话；较新的会话不能掩盖同工作区已绑定PR。运行仓库至多1.5秒、活动PR至多30秒刷新，隐藏或后台停止读取；断线只显示上次状态。概要聚合本轮观察到的文件、实际命令记录及交付证据，不把命令完成推断为测试通过，不累加逐工具diff冒充本轮净差异。合并PR及全局已合并计数尚未实现，不显示假按钮或计数。

断点定义在 [breakpoints.ts](../apps/web/src/breakpoints.ts)，CSS 媒体查询使用相同数值。

| 宽度 | 结构 |
| --- | --- |
| ≥1024 桌面 | 侧栏布局使用 264px 项目侧栏（可调宽与收起）与整页工作画布，空间导航与电脑名留在侧栏；顶栏布局使用 56px 顶栏，首页整宽，会话旁是 300px 队列。会话概要栏在放得下时默认常驻，宽 400px；改动等页签按自身内容选宽，人可调整。对话内容侧栏布局最宽 700px、顶栏布局 820px，两侧分别留 40px、48px。 |
| 768–1023 平板 | 侧栏布局保留 60px 图标轨与可打开的会话抽屉；顶栏布局保留顶栏，待处理整宽，下方并列进行中与交付。右侧面板需要人明确打开才覆盖对话，默认概要栏不会因窗口变窄自动成为覆盖面板；显式拖宽视为已打开。设置覆盖工作台时保留 200px 的分类栏；我的 Agent 与应用的页面占用图标轨那一列时，图标轨只在标题行留下标记，按钮不画出、不可聚焦。 |
| <768 手机 | Code 是决策首页；侧栏布局纵向排待处理与进行中，底部固定输入与标签栏，顶栏布局用顶部空间开关和三道页签、底部固定输入。首页与历史页的头行右端是同一个布局开关。全部会话通过文字入口打开历史列表。会话页与右侧面板按页面叠放，选择器和菜单使用底部面板；控件至少 44px，安全区取真实 env()。 |

**工作画布（768px 起）。** 总览与会话共用有细边的画布，右边与底边距窗口 12px。侧栏布局的画布沿项目侧栏起笔，顶栏布局的画布从 56px 顶栏下开始。右侧栏和底部终端各有独立格道与滚动区，共用画布外缘。面板控制与布局开关同一高度，留出组间距。覆盖式面板从标题区下方叠在对话上，自身有明确关闭入口。覆盖面板打开前与关闭后，会话标题控件都必须可达；并排时标题控件始终可达。设置覆盖工作台，原会话保持挂载。首次准备在宽处使用同样的画布边界，先给出准备目标，再呈现本机检测到的配置与可用动作。


平板的会话列表打开时主区域与标题行设为 `inert`，焦点限制在列表内，Esc 关闭后焦点回到打开按钮。对话框与底部面板同样捕获并恢复焦点。

**标题行与入口。** 侧栏布局的 [TitleBar.tsx](../apps/web/src/shell/TitleBar.tsx) 保留桌面红绿灯内边距与侧栏开关；顶栏布局由 [WorkbenchNav.tsx](../apps/web/src/shell/WorkbenchNav.tsx) 提供 Code / 我的 Agent、总览、全部会话、定时任务、搜索、电脑与设置，没有单独的新建会话图标（总览就是输入框，⌘N 仍可用）。桌面端的红绿灯与顶行在同一条线上：灯的中心距窗口顶 27px（`main.cjs` 的 `LIGHTS_LINE`，页面的 `--lights-line`），侧栏布局 52px 的行落在这条线上，顶栏布局 56px 的顶栏相差不到半像素；灯后的第一个内容从灯的右缘（壳层给出的 `--lights-end`）之后 12px 开始，侧栏收起、设置里都一样；全屏时灯隐藏，行从窗口边缘开始。两种标题行的最右端都为布局开关留出位置；侧栏布局的右栏打开时，位置让给面板页签条的末端。侧栏布局平板把导航收进 60px 图标轨，面板与布局开关留在右上。电脑入口在侧栏布局的侧栏底部、顶栏布局的顶栏；回环浏览器仍按远程设备显示电脑名称，只有连接本机 socket 的桌面端称「这台 Mac」。多电脑菜单保留各自状态、等你处理数及管理入口。

会话自己的页头在工作画布内：[ConversationHeader.tsx](../apps/web/src/shell/ConversationHeader.tsx) 显示大标题、项目、分支与电脑，以及 Host 报告的运行、等待、静默、停止、失败状态。计时每秒更新；断线不画实时进行中。改动与会话菜单仍在页头。宽屏的面板开关在工作台顶栏；改动增删数只在实际读到后出现，不猜数字。交接来源与待交回见 [HANDOFFS.md](HANDOFFS.md#界面)。标题按钮、页头菜单与侧栏菜单共用同一组会话操作。桌面和平板的标题按钮按文字行高留出悬停底与点击范围。重命名铅笔紧接标题，鼠标和键盘在这组控件上时显现，长标题省略时保留铅笔的空间。项目、分支与电脑共用标题下方一行，窄窗省略超长文字。手机从标题菜单重命名。

Code 与我的 Agent 是两个空间，开关不是列表筛选；主操作、列表与主页一起切换，另一空间有待处理时带琥珀点。应用与设置是共用目的地，仍按 Host 能力与设备权限决定是否出现。分区定义见 [routes.ts](../apps/web/src/shell/routes.ts)，Agent 与应用的详情见 [CUSTOM-AGENTS.md](CUSTOM-AGENTS.md#界面) 和 [APP-PAGES.md](APP-PAGES.md#壳层)。页头可拖动桌面窗口，控件、弹层和安全界面除外。切换页面保留会话、阅读位置、草稿与面板，被盖住的内容 inert 且不接会话快捷键。冷启动进入 Code 首页，重新载入恢复原会话；晚到的发送回执不能抢走人已打开的设置或历史页面。

**我的 Agent 的人。** 这个空间的左边是人：侧栏布局是名册（34 高的行：22 的脸、名称、行尾 14 的状态图标；正在看的 Agent 的话题挂在脸中线下的一条树线上，超过 5 个折成「还有 N 个」），顶栏布局是队列（56 高的行：32 的脸、名称，第二行是人话状态），按等你、在工作、最近活动排序，队列在这个空间的「总览」旁边也在。图标与第二行只用状态的颜色：琥珀是等你，蓝是在工作，红是失败，断线或空闲时是淡色且不转；行尾只有图标时文字在页头，一屏只写一次。页头在侧栏布局是 40 的脸、名称、单行省略的职责，右边状态词与小片（话题标题太长时在末尾省略，脸与名称保留。平板保留完整的定时片，动作放不下一行时整块换行）；在顶栏布局是对话上方居中的在场块（52 的脸）。这个空间的「总览」与「全部话题」沿用 Code 的总览与全部会话的部件和尺寸，把项目与 Harness 换成脸和名字；这里不出现 Harness 与模型（只在创建与 资料 › 设置）。手机上名册或队列是根页；顶栏布局的根页顶上是空间开关与设置，标签栏让位。被设置或我的 Agent 的页面盖住的会话整块透明，受保护的审批卡不会透到页面上。机制见 [CUSTOM-AGENTS.md](CUSTOM-AGENTS.md)。

**手机的页面栈。** 手机不放并排的栏，而是一页叠一页（[PhoneSessionList.tsx](../apps/web/src/components/PhoneSessionList.tsx)，样式在 `phone.css` 与 `phone-*.css`）。

- **Code 首页是根页**：底栏 Code 始终回决策首页，首页保留独立输入草稿。全部会话是明确的历史入口，不用点 Code 代替。两种布局共用同一历史列表与会话控制器。
- **全部会话是历史页**，在画布上，有「返回总览」：52 高的头行是 22/30·600 的「会话」与 44 的墨色幽灵按钮（新建会话），下面是常驻的搜索框；再往下依次是「等你处理」（有时才有，组名后是中性计数）、每个项目、「无项目」，分组规则与侧栏相同，置顶的会话排在各自分组的最前面并带一枚图钉；组名旁一条 `--line` 细线，项目组右端有「在 … 中新建会话」，列表末尾是「已归档」；点开后顶部有返回的一行。页面不是那台电脑上的 Latch 时（`isLocalListener` 为假，回环上的浏览器也算），头行上方是一行提示墨色的 `laptop` 图标与等宽的电脑名称。还没有会话时，列表开头左对齐地写「还没有会话」（次级墨色）、一行提示墨色的说明与 xs 次按钮「新建会话」，不放插画。列表末尾不再有同步按钮：连接的提示与横幅里有「重试」。
- **行高 64**：第一行是标题（有事要你看时 `--ink`·500，否则 `--ink-2`）与状态槽（与侧栏同一套词）；第二行是 16 的 Harness 图形（单色）、Agent 名称与一件事：在「等你处理」里是项目，其余是分支，有结果未知时是「N 条结果未知」。文件数尚无来源（`TaskSummary` 没有这个字段），所以不写。没有会话内容的预览：Host 不提供。行间是一条 `--line`；按下与被打开的那一行是悬停底。按住一行（触屏或手写笔 500ms，或右键与上下文菜单键）打开这个会话的菜单底部面板（重命名、置顶、归档、导出 Markdown、删除；重命名与删除再各开一个「取消 · 问题 · 动作」的底部面板），这次松手不会打开会话；菜单开着时这一行保持按下的底色，看得出菜单属于哪一行。
- **搜索**：搜索框按标题即时过滤，并搜索正文；使用时右边出现「取消」，它清空搜索并离开输入框。桌面与平板没有这个搜索框：面板里的「搜索」打开命令面板。
- **新开的标签页**进入 Code 首页；重新载入恢复上次打开的会话。来源 ref 不跨刷新保存，旧恢复会话仍兼容返回历史列表。
- **会话页**：从历史行打开时以 `--m-push` 从右侧推入，历史左移 24% 并变暗，设为 inert，焦点进入会话返回按钮。返回历史时，先经过未保存文件的离开确认；接受后页面按退出曲线用 70% 时长滑出，再释放选择并把焦点还给原行。取消确认保留原会话与编辑，不留下退场状态。从首页决定卡打开则返回首页，保留首页草稿及其下的阅读。减少动效时只淡入，不滑动。手机页头的返回与侧边面板目标为 44px，标题按钮打开共享会话菜单；正常页头为上下各 8px 留白与 1px 分隔的 61px，内容需要时可增长。输入框贴底：框内上面一行是可横滑的小片（首页先是项目与文件夹，再是 Harness、模型、思考、权限），下面一行是 ＋、输入、发送；不可修改时仍显示真实当前值与禁用原因。切换到下一条消息的配置仍沿用原会话配置规则。

- **新会话**没有单独的面板：首页底部的输入框就是它，项目、文件夹、Harness、模型、思考、权限在输入框上方那一行小片里各自打开底部选择面板；演示模型的琥珀标记、缺少模型时的引导卡片与分叉提示都在首页。
- **复核**：上一轮改了文件而这台设备还没看过、或反馈在等人的会话，行下多一条 44 高的带：次按钮「复核 N 处改动」（`DiffGlyph` 图标，读不到轮次时写「复核改动」）。它把复核页推入在列表之上（与会话页同样的滑入、遮暗与 `inert`，跟着可见视口，键盘不会盖住底栏）：页头是 44 的返回、「改动」与会话名、范围的 `+a −d`；下面是「本轮 · 这个会话 · 未提交」的分段控件，再下是文件行：两端 44 的上一个、下一个文件，中间文件名与文件夹、反馈数与琥珀的「位置可能过期」、「n / N」。正文一次只画一个文件，整页只上下滚，代码行在自己的块里横向滚；每一行整行都能按（28 高）：按一行开始选，再按一行延伸，再按唯一选中的那一行取消，选中的行是蓝边浅蓝底。底栏（贴底、留出安全区）只有一个蓝色主操作：选中时「第 a–b 行 · 取消 · 写反馈」，写反馈打开底部面板（「取消 · 第 a–b 行 · 加入待发」，上面是选中代码的引用，下面四行的输入框）；有待发反馈时「清空 · 发给 Agent (N)」（运行中「排到下一轮」）；发送结果未知时「放弃这次发送 · 重试同一请求」；否则左边是反馈的状态词（「Agent 在修订 N 条反馈」「N 条待你复核」），右边「去提交」。去提交推入「提交」：交付页签整页，页脚按钮 44 高，提交之后主按钮是「推送」，返回直接回到列表，焦点回到那一行的「复核」。数据范围不是 `all` 的设备在改动页看到锁和去哪里开启，交付页是锁住的列表、提交信息、「提交已暂存的」与「推送」。
- **返回**：推入的每一页（会话页、右侧面板、设置与它的每一级）和每个底部面板打开时都在浏览器的历史里占一条（地址不变，[backStack.ts](../apps/web/src/hooks/backStack.ts)），所以平台的返回（Android 的返回键、iOS 的边缘滑动、浏览器的后退）关闭最上面的那一层；历史返回 Code 首页，从历史打开的会话回原行，从首页打开的会话回首页。会话页用同样的滑出（浏览器自己已经画了返回时不再滑）；未保存文件先确认，取消时留在原页。在页面上关闭的一层把它那一条还回去（一次后退越过所有不再有人用的条目）；与此同时打开的新一层接着用这一条，不会被这次后退关掉。重新载入时随页面回来的会话用原来那一条，不另加；没有对应层的旧条目在后退时被跳过。

**设置。** 设置是盖在工作台上的独立面板（[SettingsPage.tsx](../apps/web/src/settings/SettingsPage.tsx)）。原会话、阅读位置、面板和草稿留在底下，运行照常继续。背景无法操作，本机确认可以照常在设置上方打开。768px 起面板居中，左边的分类栏独立于工作台侧栏，右边是可滚动的内容，右上角可关闭。搜索框附 `/` 键帽。浏览器的分类按通用、模型、用量、Harness、MCP、项目、插件、设备、快捷键、关于排列；无管理权限时只显示通用、用量、设备、快捷键、关于。Host 提供目录且 `catalog.features.modelUsage` 为 `true` 时显示「用量」。分类行 32 高、8 圆角，选中为中性卡片和 500 字重。首次打开显示第一类，指定分类的入口直接进入对应页。分类内容最宽 720px，顶上是 20/28·600 的分类名；子页原地替换分类内容，带上一级的返回链接。

手机上面板占满窗口，分类列表是根层。分类与子页沿用手机页面栈，各有标题和返回按钮，浏览器返回与 Esc 先关闭最上一级。右上角关闭整个设置面板，返回工作台之前的位置。768px 起 Esc 关闭设置；内部菜单、对话框或输入法先处理自己的 Esc。设置外壳直接出现，内层切换与减少动效继续沿用既有样式。

**会话面板。** 侧栏布局的 Code 项目树每行 34px，画完整状态图标与标题，Host 确认待交回的目标另保留短词「待交回」；Harness、模型、状态和未知结果仍保留在无障碍名称及必要的提示中，不裁出半个状态字。待处理集合集中在首页。顶栏布局会话旁为按状态组织的紧凑队列，完整项目与会话操作经「全部会话」进入。平板抽屉仍保留完整分组与管理入口：上面是开关、「新会话」与「搜索」（32，幽灵行，末端是按下它的键位字，淡色、不画框：桌面端 ⌘N、⌘K，浏览器 Alt N 与 ⌘K 或 Ctrl K；抽屉与触屏不画）；下面依次是「等你处理」（有时才有，中性计数）、每个项目、「无项目」和安静的「已归档 N」，都不含委托给 Agent 的会话；底行固定，列表再长也够得着。组头 20 高、没有分隔线，字是 12/16·500 `--muted`；悬停时出现折叠箭头（折叠后常显并写出条数）与右端的 ＋、⋯，折叠状态每台设备各记各的。置顶的会话排在各自分组的最前面，带一枚图钉。

桌面项目树与平板抽屉使用紧凑行，避免把原两行模型信息挤进 34px 的高度。 会话长标题在预留的行尾操作区之前省略，鼠标经过或键盘聚焦时，归档与更多操作只改变显隐，标题位置与宽度不变。 项目分组沿用输入框项目选项中的已保存图标，侧栏、会话历史和手机列表使用同一项目图标。手机历史的双行展示见前面的页面栈。Harness、模型、分支与工作树按 Host 记录进入相应可见信息或无障碍名称；没有模型记录时写「默认模型」，有未知结果时保留「N 条结果未知」。品牌使用已登记的官方静态资源，自定义且无官方标记的 Harness 使用中性图形与名字。状态仍来自同一 `rowStatus`，连接中断不把上次状态画成实时运行。其他电脑的等待摘要只在提供它的导航里显示。在线待处理项的按钮第二行显示来源电脑与等待种类，长电脑名可换行，保留同名电脑的区分后缀。离线时每台电脑仅一行，用中性色显示离线前的数量与上次在线时间。全局计数只算在线项。分组计数为等宽数字，归档与会话菜单仍通过明确控件访问。


状态词只说 Host 说过的（[sessions.ts](../apps/web/src/sessions.ts) 的 `rowStatus`），变化每秒最多一次，时钟只在这一格里每秒更新：

| 情况 | 状态槽 | 进「等你处理」 |
| --- | --- | --- |
| 审批或提问 | 琥珀盾牌加「等你处理」（侧栏的「等你处理」里是时间，等的种类写在第二行；手机上带盾牌） | 是 |
| `live.silent` | 琥珀「没有动静 3 分钟」，从 `lastEventAt` 算起；不会因为时间长自己下这个判断（侧栏的「等你处理」里写在第二行） | 是 |
| Harness 发来不认识的请求，之后再无动静 | 琥珀「等你处理」；Harness 一有动静，Host 让列表重读，这一行回到运行中 | 是 |
| 运行中 | 蓝色转圈加摘要里的活动种类与时钟：「在跑命令 0:42」「在等模型 0:04」「在用工具」「在启动」，没有种类时「运行中 1:12」；时钟从 `live.runStartedAt` 算起，不含等人的时间，旧 Host 没有这个字段时不写时间 | 否 |
| 停止中 | 「正在停止」，直到这次运行真正结算；此前等你处理的会话也离开这个分组 | 否 |

| 失败 | 红色「失败」 | 否 |

归档后行淡出，面板底部出现「已归档 · ⌘Z 撤销」；输入框有焦点时 ⌘Z 仍归输入框。权限模式变化不在行上画红，由会话自己说明。

**可调宽的侧栏（1024px 起）。** 侧栏的内侧边缘（对话画布的左边框）是调整宽度的把手（`ResizeHandle`，见「界面原语」）：宽度在 220–400px 之间，侧栏布局默认 264px、顶栏布局默认 300px，对话画布始终至少 480px，拖拽中与窗口变窄时都按此收紧（右侧面板并排时也算上它）；双击恢复默认宽度。拖到 160px 以下就收起，与标题行「收起侧栏」按钮是同一个状态：侧栏的格道滑到 0（`--m-panel`），内容保持原宽被裁切、不重新换行，收起后不可聚焦；拖拽越过这个点时（收起，或把收起的侧栏拖出来）格道同样滑过去，而不是跟着指针一下跳到位，之后的宽度才继续跟手。标题行的「新建会话」（有会话等你时还有带琥珀计数的「等你处理」）随格道一起展开与收起（宽度与淡入都是 `--m-panel`，淡出是 `--m-micro`）；侧栏打开时它们不可聚焦，也不在无障碍树里。⌘K 打开命令面板，不动侧栏；展开或从窗口左缘拖出时回到上次的宽度。键盘：把手可聚焦，←/→ 一步 8px（Shift 32px），Home/End 到最窄与最宽，Enter 收起或展开；用标题行的按钮收起、展开时，焦点移到做相反动作的那个按钮。拖拽中跟手的宽度不做过渡、不选中文字，指针由把手捕获。宽度与收起状态按设备保存在本地偏好里（从不发给 Host），读不到或不合规的值按默认处理。平板与手机没有把手。

**右侧面板。** 改动、文件、打开的文件标签与插件面板共用一个面板（[SessionPanels.tsx](../apps/web/src/components/SessionPanels.tsx)，放法在 [panelLayout.ts](../apps/web/src/shell/panelLayout.ts)），按剩余宽度并排或显示为独立页面。标题行的「侧边面板」开关在每个宽度都有（打开时是中性的悬停底），⌥⌘B 关上后再打开回到关上时那一面，页面被 Esc 或平台的返回送走时也一样。1024px 起它是外壳网格的最后一列，面板紧贴工作画布，不保留旧浮底板之间的 8px 间隙；并排时两种布局都用 1px 分隔线标出对话和侧边面板的边界，悬停、拖动或键盘聚焦时增强把手的线。顶栏布局的标签条与对话的标题行同高、同样可以拖动窗口：打开与关闭时格道滑动（`--m-panel`），内容保持打开时的宽度被裁切，不重新换行。它朝画布的边缘是调整宽度的把手（`ResizeHandle`）：概要默认 400px，其余页签按内容选宽（通用回退 520px），可调 360px 到窗口的 70%，双击复原；对话放不下 480px 时换成盖在对话上的浮层，留在工作面板里、标题行之下，右边与下边贴着面板的边，浮层可以拖窄，窄到放得下就回到并排。手机上换成一页：页面从右侧推入（`--m-push`），对话在下面向左移四分之一，返回时反向（70% 的时长），焦点进入页面，返回后回到切换按钮；对话在页面下保持挂载并设为 `inert`，阅读位置不变；切换会话时页面关闭。手机或其他没有标题面包屑的入口，概要保留会话目录、限制和只读选项的真实事实。概要可在宽屏并排时默认显示；窄屏覆盖式面板只由人明确打开，拖动调整也算明确打开。打开状态与宽度记在本设备，从不发给 Host。

**启动面板。** 右栏打开而没有选中的内容时显示「打开一个面板」。选项包括这段会话可用的改动（D）、文件（F）、浏览器（B）、交付和插件面板。浏览器只在这台 Mac 的桌面端、有项目的会话里出现（[PREVIEW-BROWSER.md](./PREVIEW-BROWSER.md#界面)）。开关或命令面板明确打开它时焦点进入，切换会话或重新载入时保持原焦点。「我的 Agent」中只对话的会话默认折叠辅助面板，点开后仍可查看会话资料和可用页签。首页选了可浏览的项目后，右栏显示项目文件，手机仍用底部面板。

**标签条。** 右栏用 `PanelTabs` 切换改动、文件、浏览器、交付、已打开的文件以及插件面板。改动的增删数在别的页签显示时才列出。已打开的文件沿用文件图标、悬停关闭和未读圆点。标签已满 6 个时，新文档留在这一轮的文件卡片上。行尾是「铺满」与「关闭」，手机用页头返回。

**底部终端。** 这台 Mac 上具有终端能力时，工作台上方的终端按钮与左栏、右栏开关各自工作。终端在对话下方，右栏并排或在终端上方的空间浮出。拖动上边缘调整高度，↑/↓ 一步 8px、Shift 一步 32px，Home/End 到允许的边界，双击恢复默认。矮窗保留输入区域。折叠保留同一个 xterm 和 shell，重新载入读取 Host 原有终端。会话用其主目录，首页用所选项目或合法默认目录。手机与远程浏览器没有终端入口。 [终端机制](TERMINAL.md)

设置的「模型」与「用量」切页立即呈现快照中已有的模型控件、统计期间和分组。服务配置、请求统计与预算在各自区域读回或报告失败。切回时已经读到的结果直接出现，快速换筛选只显示与当前筛选匹配的记录。读回范围见 [客户端的加载边界](./CLIENT-LOADING.md)。

## 界面原语

原语在 workspace 包 `@latch/ui`（[index.ts](../packages/ui/src/index.ts)），是 React 组件加上它们在 ui 层的样式。页面从这里取按钮、状态词、开关、分段控件、选值、菜单、对话框、提示与磁贴，不再各自画一份；同一种意思只有一种画法。样式只读令牌。类名以 `ui-` 开头，变体与尺寸写在 `data-variant`、`data-size`、`data-tone` 上，状态直接用 ARIA 属性（`aria-pressed`、`aria-checked`、`aria-expanded`、`aria-disabled`、`aria-busy`、`aria-invalid`），所以样式跟着可访问性状态走，不另设状态类。

**事实与小部件（[facts.tsx](../packages/ui/src/facts.tsx)）。** 都只显示传给它的事实：`Fact` 是等宽的读数；`ChecksBar` 把 PR 的检查画成分段，每项一段，通过是绿、失败是红、其余是轨道色，没有真实计数或超过 12 项时不画，旁边仍写「检查 4/6」；`StatusStrip` 是窗口最底一条等宽的事实（这台电脑、连接方式、在线电脑数），没有事实就不存在；`SectionTitle` 是带线的分组标题，计数为 0 时变淡、不写句子；`TickFrame` 的四角角标标出按键此刻作用在哪张卡或哪个输入框，站在框外 7px，不盖内容；`KeyHint` 是不画框的淡色等宽键位，只在那个键按住时亮（松开 ⌘ 或窗口失焦时全部熄灭），它不执行动作，只在有键位提示挂载时监听窗口。

**交互约定。** 悬停与按下的底在 `--m-micro` 里变化；列表里选中的切换同样是交叉淡化，不做滑动的选中块。按下时按钮在 80ms 里缩到 97%，松开用 420ms 的弹簧回到原位（打开菜单的按钮、禁用与运行中的按钮以及减少动效时不缩），其余控件按下只深一档（`--press`）。禁用的控件用 `aria-disabled`：整个控件降到 45%，仍能用键盘聚焦，提示框说明原因，点击与表单提交都被拦下（不用原生 `disabled`，否则原因无人能读）。键盘焦点是 2px 的蓝色描边，画在元素边内 2px（`outline-offset: -2px`），所以滚动容器裁不到它；实心的主按钮与销毁按钮画在边外 2px，衬着所在的表面。成组的单选控件（分段控件、文字标签页、筛选、单选列表）整组只有一个 Tab 停靠点，方向键移动并立即选中，Home / End 到首尾，跳过不可选的项。弹层与菜单在顶层（top layer）显示，滚动容器与对话框都裁不到它；打开时焦点进入当前项或第一项，Escape 关闭并把焦点还给触发器，Tab 离开即关闭，点外面或滚动让触发器移动了 1px 以上时关闭（打开时把触发器滚进视野的那次滚动、别处的滚动都不算）。手机宽度（<768px）下，菜单、选值与弹层都换成底部面板。对话框与底部面板里 Tab 只经过真正的 Tab 停靠点（`tabindex="-1"` 的菜单项和单选组里的其余项不在其中），从最后一个回到第一个。

**图标与转圈。** 界面图标是 Latch 自己画的一套（`packages/ui/src/glyphs/`，随 Latch 用 MIT）：16×16 网格，16px 时线宽 1.5，方头、尖角，容器圆角 1；每个图形至多一处实心，落在意义上（终端的光标、锁孔、分支的当前节点、文件的折角、Harness 立方体的顶面、「更多」的方点）。它覆盖最常见的约五十个：侧栏、标题行、输入框、右侧面板页签、菜单、设置导航与全部状态图形；其余长尾仍用 Lucide（ISC），经同一个 `Icon` 画出，改到哪个界面再补画那里的。两套都只用 12、14、16、20、24 五个尺寸，线宽按屏幕像素定（`ICON_STROKE`：1.2、1.35、1.5、1.75、1.75），Lucide 的线不再随 24 格缩放；用其他尺寸时类型检查失败。12px 有七个图形另画（分支、PR、已合并的节点画成实心方点，定时任务去掉耳朵，模型的引脚减到四根，结果未知的点加大，我的 Agent 的眼睛加宽；`SMALL_GLYPHS`）。v9 重画了进行中（弧线前端一个实心头，不再像刷新）、结果未知、分支、电脑（屏幕落在底座上）、PR、已合并、总览（三行落在整像素）、我的 Agent（圆括号 `FaceGlyph`，导航仍用 `AgentsGlyph`，换用在下一批）、设置（两条滑杆、一个实心钮）；新增失败（圈里一个叉，只给失败）、项目（文件夹上沿涂实，当前目录仍是空心文件夹）、权限三态（半实心、斜线、问号）与附件。Harness 与模型的品牌标志原样，不重画。转圈仍是下面写的圆环，与重画的进行中图形暂不相同（尚未实现：转圈在状态那一批换成带头的弧）。`Icon` 的 `icon` 收 `IconComponent`，两套都行。每个 Latch 图形带一个实心版（`solid`），只给选中或当前项：手机标签栏的当前页、设置导航的当前项、侧栏顶部 Code / 我的 Agent 切换里当前的地点；选中不用蓝色。有面的图形实心时整面填满、细节镂空，只有线的图形（箭头、叉、加号）实心是加重的线。不用「AI 产品」式的剪贴画：机器人、大脑、星光、烧瓶、眼镜、望远镜由 lint 拒绝导入，包括它们的别名与 `lucide-react/` 深路径（`.oxlintrc.json`）；Agent 是我的 Agent 的 `{··}`（`AgentsGlyph`，同一网格与线宽），思考是逐行变短的三行，设置与通用是滑杆，模型是芯片（`ModelGlyph`），Harness 是立方体（`HarnessGlyph`），演示模型是 Lucide 的讲台（`presentation`）。文件按类型：文档是带两行字的页（`FileGlyph`），类型未知的是没有字行的页（`PageGlyph`）。静止的图标是提示墨色，悬停与激活时是正文墨色，和文字放在一起时随文字颜色；图标只在表示状态时带色相：失败是红色的 `alert` 或三角，等你处理是琥珀色的盾牌，被选中的完全访问是琥珀色的 `shield-alert`。箭头各有一种意思：向右是进入下一层或展开（展开时转 90°），上下双箭头是原地选值，向下是下拉动作。停止是 10×10、圆角 2 的实心方块，不是描边图形。转圈（`Spinner`）是一圈当前颜色 22% 的轨道加满色的上四分之一，800ms 一圈，12、14、16 的线宽 1.5px，20 的 2px；页面上所有可见转圈按文档时间线对齐相位，并排时不会错开。离开视野时暂停，回到视野后重新对齐。系统或设备减少动效时停在静帧，恢复时只对齐可见转圈。它表示正在进行的事：运行中的 Agent 与工具、加载行、按钮运行中、取消中；颜色随所在的文字，状态词与过程行里是墨色。

**按钮。** 尺寸只有四档：xs 24（圆角 6、12/16 字：提示与行内的动作、回合脚部与项目弹层里的行内动作）、sm 28（桌面默认：页头、卡片按钮行、行尾）、md 32（对话框与面板的脚部）、lg 44（手机，胶囊形）；圆角 8、13/18·500，带前导图标时起始内边距少 4。变体：主按钮（primary）是一个界面里唯一的蓝色，只给执行或创建的动作（允许一次、请求本机确认、添加服务），带一层内侧高光与淡蓝的落影；「保存」「保存默认值」这类不执行操作的确认用次按钮。次按钮（secondary）是悬停底那样的中性填充，没有环，悬停换成按下的深度；描边按钮（outline）是控件的面（`--pop`）加一圈 `--line-strong` 与 `--sh-1`，在面板、卡片与对话框上一样立得起来，用在要和静止内容分开的地方；放在警告或红色调的容器里（容器标 `data-tint`，内联提示自己会标）时次按钮也换成描边的样子，因为半透明的墨叠在红色调上会发脏，警告里与它保持一致。幽灵按钮（ghost）是次级墨色的字，悬停时出现底并换成正文墨色，用于工具栏、行尾与「重置」这类安静的动作；链接样式只用于跳到别的页面或位置（`ButtonLink` 是同样画法的 `<a>`），悬停时出现点状下划线；页面上的危险操作（danger）是红字的描边按钮；实心红（destroy）只在确认对话框里。运行中的按钮宽度不缩、前导位换成转圈、文案可以换成进行时（「检测中…」），并标 `aria-busy`，不再接受点击；运行中的按钮不算禁用，页面同时禁用它时也不降透明度，主按钮运行中仍是蓝色。非审批控件可以把此刻生效的键画在按钮上（`keys`，如 `['mod', 'enter']`）：文字后是一段淡色的键位字（「⌘N」连写，不画框），末端比只有文字时少 4 的内边距；主按钮与销毁按钮上是同色字；触屏（粗指针）不画；读屏名称只有文字，键进 `aria-keyshortcuts`，提示框不再重复这些键。其他快捷键只在需要时写在提示框里，审批动作不重复提示。每张卡、每个对话框脚部与面板头部最多两个可见按钮，次在前、主在最后，第三个动作进 ⋯ 菜单。图标按钮是 24、28（圆角 6）、32（圆角 8）、44（圆形）的正方形（图标 14、16、16、20），名称同时是它的提示框；静止是提示墨色，悬停是悬停底与正文墨色；切换按钮的「开」与菜单打开时的触发器（`aria-expanded`）也是悬停底与正文墨色，不用蓝；输入框里的发送与停止是圆形。图标按钮的面（悬停、按下与「开」的底，以及键盘焦点环）按它自己的尺寸画在中间，所以在任何屏幕上看起来一样大；触屏上它的盒子长到 44×44，工具栏与图标栏里相邻的按钮因此相隔 44，点按区不重叠；页面在密集的行里保留较小的盒子时（回合脚部的复制、列表头的筛选），透明的点按区仍伸到面四周的 44×44。计数放在面的右上角外 4px，垫着一层所在表面的颜色并镂空一圈 2px（`--surface`），字形不被遮住。`--surface` 默认是画布色；放在别的表面上的容器把它改成自己的颜色：图标栏与侧栏在侧栏色上，所以是侧栏色；菜单、弹层、对话框与 Toast 是弹层面（`--pop`），单选列表是浮起色，底部面板是侧栏色。

按钮缓存最近可见的自然宽度，字体、内容和容器尺寸变化由 ResizeObserver 更新；首次挂载和离开忙态时才同步读取尺寸，不随父组件的每次渲染重新测量。连续的运行、等待与完成状态保持其中最宽的宽度，隐藏不把缓存清零；回到空闲后恢复自然宽度。调用方的 minWidth 长度与保持宽度取较大者，max-content 等固有尺寸约束原样保留；block 按钮始终跟随容器，不用旧的最小宽度阻止容器变窄。

**提示框。** 悬停 400ms 后出现，键盘聚焦时立即出现；离开、按下或 Escape 立即消失；一个提示框消失后的 300ms 内移到相邻的控件时，新的提示框立即出现，并从上一个的位置滑到新位置（`--m-micro`），不再从头淡入。提示框是反色的：浅色里是近黑底配白字，深色里是比浮起亮一级的灰；圆角 6、至少 24 高、12/16 字、最宽 320，从 98% 放大并淡入（`--m-enter`），不接收指针；提示文字同时是触发器的读屏描述（图标按钮的名称已经是同一段文字时除外）。禁用控件的原因（按钮、图标按钮、选值）、开关与分段的说明和开发版标记的整句都用它，不用浏览器原生的 `title`。触屏上不出现。

**状态词、徽标、计数、状态点与按键。** 状态用几个字说出，最多带一个 12 的图形，颜色就是它的意思（`StatusWord`，12/16·500、等宽数字）：等你处理是琥珀字加盾牌，运行中是墨色字加转圈（「运行中 1:12」随计时不变宽），失败是红字加 `alert`，已完成是墨色字加对勾，警告（不可用、演示、原内容未知）是没有图形的琥珀字，其余（已停止、已停用）是提示墨色。状态没有胶囊，也没有前导点；`StatusPill` 按页面与插件面板用的 `Tone`（`neutral`、`warn`、`err`、`ok`）画同一种状态词：提示墨色、琥珀字、失败与已完成；插件面板经 `PluginPanelProps.ui` 拿到它。徽标（`Badge`）是跟在名字后面的属性（默认、本机、内置、离线、开发版、演示）：18 高、圆角 4、11/14·500，中性是标签底（`--tag`，没有边与下唇，和按键分开）配提示墨色，琥珀是同样的标签底配琥珀字，红是淡红底配红字；它从不表示卡片或行的状态。计数（`Count`）是 12/16·500 的等宽数字，不加底，超过 99 写 99+：被动计数随周围文字，新结果是墨色，等你处理是琥珀；页面亲眼看到计数变了时新数字淡入（`--m-micro`）；分组标题旁的计数用 `Roll` 滚动。绿色除差异的新增与成功对勾外，只再用于通过的检查段与在线的连接点。状态点桌面 6、手机 8，琥珀与红点总要和文字或图形一起出现，叠在磁贴上时用所在表面的颜色（`--surface`）镂空一圈。按键（kbd）像一个键：18 高、圆角 4，自己的键面（`--key`）带一圈边与 2px 的下唇（`--sh-key`），11/14·500 提示墨色，只出现在提示框、菜单项尾部、搜索框、审批卡聚焦时的提示行，以及此刻按了真会生效的按钮上（见「按钮」）。计量（`Meter`）是格子不是胶囊：整数个格子、整像素的间距（sm 是 3px 的格相隔 1、8 高，12 格 47 宽，用在状态行；md 是 14px 的格相隔 2、10 高，用在图例与面板），调用方给数字，填满的格数按比例取整、大于零时至少一格；填满的格是 `--meter`，其余是 `--track`，两个主题都不带色相，也没有动画；读屏是 `role="meter"`，名称是它量的东西，`valueText` 写出值（「62k / 128k」）。上限刻线与超出的一段尚未实现（等第 3 步的用量上限）。

**选值（ValuePicker）。** 在原地从一组互斥的值里选一个，只显示当前值：幽灵、28 高（`size="xs"` 是 24、箭头只在悬停或聚焦时出现；触屏上常显）、值 13/18 常规字重、末尾上下双箭头，前导、值与箭头彼此相隔 6。值总是紧跟前导（没有前导时从内边距开始），所以外扩的一列值与列的边缘对齐；手机设置面板里的值离箭头 6，同一张卡的值右缘对齐。悬停与菜单打开时是悬停底，值换成正文墨色；只有一个可能值时是不可点的文字；没有选择时写「选择模型」这类说法，用提示墨色，不用警示色。读屏名称是「标签：值」。菜单打开时焦点在当前值上，Enter 选中，可以按首字母跳转；不可选的值也能聚焦，下面一行带禁止图标的原因保持原色并被读出。选中即生效，不弹提示；值改变时淡入（`--m-micro`）。调高权限这类要验证的改动返回一个 Promise，等待期间前导位是转圈、值换成「等待验证…」，取消验证时值不变。箭头不动：设置行尾部的选值向左伸展；输入框工具栏里左对齐的权限菜单（`reserve`）预留值与「等待验证…」中较宽的宽度，多出的宽度留在值和箭头之间。只有可能等待验证的选值才预留，模型、项目这类选值、24 高选值与手机行都不预留。设置行尾部的选值按 `--bleed` 向右外扩 6px，使箭头与同卡导航行的箭头对齐。长列表可以带搜索行。值可以带自己的图（`media`，Harness 或模型服务的磁贴），放在勾选槽之后；一组值可以在组标题前带服务的磁贴。值与列表里的写法不同时（下一条消息才生效的模型切换，「下一条：…」），`valueText` 写出触发器上显示的话，读屏名称随之改变。`panel` 让弹层原地换成一块小面板（在选值的地方添加一个值，例如从「添加模型服务…」进入），弹层保持打开，手机上由底部面板承载；面板与脚部动作用 `useLayerClose` 关闭所在的弹层，焦点回到触发器；`onOpenChange` 报告每一次打开与关闭。 页面要求打开选择器时，只响应可见且不在 inert、hidden 或 aria-hidden 区域内的触发器；保留在后台的页面不打开弹层。程序打开同样在关闭后归还焦点到触发器。只有一个可能值、又没有脚部与面板时才显示为不可点的文字。禁用的选值降到 45%，原因在提示框里。手机上是底部面板里的单选列表，打开时焦点在当前值上（单选组唯一的 Tab 停靠点），不论它排在第几；`variant="row"` 是手机设置面板里的一行（标签、值、箭头），同一张卡里相邻的行之间有一条从文字边开始的 `--line` 细线，最后一行下面没有。

**权限菜单（PermissionMenu）。** 有序的权限等级只用这一个菜单，不用一排分段：整层 320 宽，头部写作用对象，四个两行项从低到高，每项一句后果，默认项带中性徽标「默认」，越级的项不可选并写出原因，脚部是一行导航或带锁的说明。菜单里的完全访问不带琥珀；只有它被选中后，触发器前才出现琥珀色 `shield-alert`。调低立即生效，调高走上面的验证流程。等级的文案由页面传入，原语只负责顺序、画法与交互。手机上的单选面板用同一份文案：头部写在列表上方并作为单选组的名称，「默认」徽标跟在标题后面，脚部说明与单选和标题两列对齐。

**菜单与弹层。** 菜单、选值的层、内容自管的弹层（`Popover`，例如计划）与选值里原地换上的面板都是最高的面（`--pop`，不透明）、圆角 12、`--sh-lift`，组与组之间只有一根细线；菜单内边距 6。弹层面上最安静的墨色在深色里差一点到 4.5:1，所以层里的 `--faint` 换成 `--muted`。最小宽 220（给出的宽度都是整层的外宽，内边距在内；可搜索的选值 360），距触发器 6，设置行里右缘对齐触发器，输入框里左缘对齐。放在整层放得下的一侧（先试给定的一侧，再试另一侧）；两侧都放不下时，留在至少有 240 的一侧，限高并在层内滚动，始终离窗口边缘 8。层的内容改变大小时（菜单原地换成添加面板、宽度变宽）重新放置，已在的一侧仍放得下就不换边。打开时从 98% 放大并淡入（`--m-enter`），放大的原点在它朝向触发器的那一侧、对齐的那一边，像是从触发器里长出来；关闭倒放，用 70% 的时长与退出曲线。菜单项 32 高（带说明 48），圆角 8，内边距 10，前导槽 16 与标题相隔 8：选值菜单里当前项是墨色对勾、标题换成 500 字重，动作菜单里是图标；没有任何项带图标的动作菜单（例如审批卡的 ⋯）不留前导槽，文字从菜单的内边距开始；尾部只放一样（元信息、徽标或按键），元信息是最安静的墨色；两行项（带说明或不可选的原因）把前导与尾部放在标题那一行，不放在两行中间；原因行在上一行下 4、禁止图标与文字相隔 6；高亮瞬时变化。菜单项的图标静止时是提示墨色，悬停、键盘高亮与按下时换成正文墨色。危险项（删除）排在最后，前面一条分隔线（`--line-strong`，左右缩到项的文字边），文字与它的图标都是红色。菜单的读屏名称是它的标签加头部写的作用对象（「权限：在这台电脑上发起的会话」，头部只重复标签时不再加），头部的元信息是它的读屏描述。分隔线下的脚部行与菜单项用同一网格，32 高、圆角 8，文字从标题那一列开始：导航行（「管理项目…」）是正文墨色 13/18，前导槽空着，末尾向右箭头；留在原地的动作（「撤销切换」「添加模型服务…」）不带箭头，可以在前导槽放一个 14 的图标，`closes` 的动作先关闭弹层；说明行（「在 Mac 上的 Latch 里添加项目」）把锁放在前导槽中间，文字 12/16 提示墨色。脚部行不在菜单列表里时（弹层里一列按钮之后，或底部面板里）是普通按钮，用 Tab 到达，没有图标时不留前导槽。菜单项可以带值自己的磁贴（`media`），在前导槽之后、标题之前。`Popover` 的焦点进入它的第一个控件。

**输入。** 要输入的地方是井：文本字段与搜索框沉在所在的表面下（`--sunken` 与 `--sh-well`），悬停时叠一层悬停底；聚焦时（不只是键盘）井的边换成 1px 蓝环，外面一圈 3px 的淡蓝外晕。标签在上（12/16·500），提示在下（12/18 提示墨色），占位符是最安静的墨色；出错时环变红、下面一行红字写原因与改法，并作为读屏描述。桌面 32 高、圆角 8；手机 44 高、圆角 12、16px 字，iOS 聚焦时不缩放。页面内的搜索框也是井，前导 14 的放大镜（与文字相隔 6，控件内图标与文字的间距），有内容时尾部是 24 的清除按钮（触屏上四周有 44×44 的透明点按区），Escape 先清空；聚焦时留在井里并带同样的蓝环与外晕。侧栏里的搜索用 `variant="ghost"`：与那一列的行同样 36 高、16 的放大镜距起点与文字各 8，静止时没有底，悬停是悬停底，只有聚焦时成为井并带蓝环。

**开关与选择。** 开关只给能立即开关的行：桌面轨道 34×20、滑块 16（触屏 44×26、22），关是计量轨道的灰（`--track`），开是蓝色；滑块是白色、带自己的小阴影，与轨道的颜色一起在 `--m-micro` 里到位，按住时向前进方向拉宽 4px；Space 切换；键盘焦点环画在轨道外 2px，跟着胶囊的形状，不画在更大的点按盒子上。`SwitchRow` 整行是开关的标签，点标题也能切换，整行不响应悬停；被策略锁住时开关关闭并降到 45%，前面一把锁，说明换成原因。分段控件只用于 2–3 个对等的视图或模式（类型只允许 2 或 3 项）：一口井（`--sunken` 与 `--sh-well`，圆角 8、内边距 2）里放等宽的段，24 高、12/16·500；选中段立在井里：控件的面（`--seg-on`）加一圈 `--line-strong` 与它自己的阴影，配正文墨色，其余是提示墨色、悬停换成正文墨色；选中在 `--m-micro` 里交叉淡化，不滑动；md 是 28 高，手机 32；它是一个单选组，段的说明（例如为什么不可选）在提示框里。文字标签页与筛选（`Tabs`、`FilterPills`）没有轨道：24 高（手机 32）、圆角 6、12/16·500，可以带 12 的图标；选中是悬停底配正文墨色，其余是提示墨色，选中不滑动、从不下划线、不用蓝；标签页是 tablist，筛选是一组 `aria-pressed` 的切换按钮。复选框与单选框是 16px 的原生输入：未选中是浮起底加 1.5px 的 `--line-strong` 环，选中是蓝色（实心加白勾，或 5px 的蓝环）。单选列表放在浮起的卡片里，每行 48（手机 56），前导单选、标题与一句后果，选中项标题 500，单选与标题在同一行，下面有说明或原因时也不下移；不可选的行降低单选与标题，原因一行保持原色。

**选中的三种画法。** 列表里的对象（侧栏的会话行、设置导航）是 `--selected`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 落影），深色是一层柔和的白，标题换成正文墨色；被勾选的控件（单选、复选、开关的开）是蓝色，菜单里的当前项是墨色对勾；视图、筛选与外观（分段、标签页、筛选）是中性的浮起块或悬停底。蓝色从不画在选中行上。

**对话框与底部面板。** 对话框是原生模态 `<dialog>`：480（确认）、560（表单）、720（双栏），弹层面（`--pop`）、圆角 16、`--sh-dialog`，后面的遮罩把内容模糊 4px；头部 56（标题 15/22·600、可选副标题、关闭），下面不画线；正文左右与底部留 24；脚部 56，是状态带（`--band`，对话框自己的面上淡淡的一条），上缘一条细线（左侧说明，右侧最多两个 md 按钮，次在前、主在最后）；没有头尾的确认四边留 24。打开时聚焦第一个输入（没有输入时是正文的第一个控件），Tab 在对话框里循环，Escape 与点遮罩关闭（从对话框或面板里再打开的一层，例如新会话面板里的选择器，Escape 只关闭最上面这一层），关闭后焦点回到打开它的控件；打开时从 98.5% 放大并淡入，遮罩一起淡入（`--m-sheet`），关闭倒放，用 70% 的时长与退出曲线。底部面板（手机）是侧栏灰、上圆角 16，抓手、52 高的头部（左「取消」是常规字重的幽灵按钮、中间标题、右侧动作：执行操作的主按钮，或只关闭面板的次按钮「完成」，热区都是 44；只用来查看的面板（弹层在手机上的样子，例如计划）没有「取消」，只有右侧的「完成」；「取消」的文字与动作的右缘都落在下面卡片的 16 那条线上；两侧按钮从不被挤窄，标题短时居中，长时在两侧之间以省略号结束），从底部滑入（`--m-sheet`），以 70% 的时长滑出；内容高时先停在窗口的 65%，向上拖到 92%，向下拖过三分之一或快速下滑则关闭；`detent="large"` 的表单类面板（例如新会话）一打开就停在 92%，不随内容伸缩。页面可以经 `LayerHistory` 给每个打开的底部面板一个返回的位置（手机上是浏览器历史里的一条，见「手机的页面栈」）。手机上的菜单也是这样的底部面板：菜单项放在一张浮起的卡片里，48 高；标题只写对象本身（会话菜单的标题是会话名，菜单的读屏名称仍是「会话：…」）；用触屏打开时焦点仍在第一项（或选中项）上，但在按下按键之前不画焦点底，不会看起来像选中了什么。改动即时生效的面板不放「确定」。

**调整宽度（ResizeHandle）。** 侧边列（侧栏与右侧面板）的边缘：跨在边缘上的 6px 透明命中区，光标是 `col-resize`；悬停 300ms 后（避免划过时闪烁）、拖拽中立即、键盘聚焦时随焦点环一起，在中间画一条 1px 的 `--line-strong` 竖线，不用蓝色，也不占布局。它是竖向的 `role="separator"`，读屏名称写明作用（「调整侧栏宽度」），`aria-valuenow`、`aria-valuemin`、`aria-valuemax` 是像素宽度，收起时 `aria-valuetext` 为「已收起」。它只报告宽度：拖拽中报告指针下的原始宽度、松开时再报告一次（由页面收紧、吸附收起并保存），键盘一步 8px（Shift 32px）、Home/End 到两端，Enter 切换收起，双击复原；拖拽时捕获指针，并在根元素上标 `data-resizing`，整页显示调整光标、不选中文字。

**提示与 Toast。** 内联提示（也用作消息区顶部的横幅；横幅在页面看着条件变化时像折叠块一样展开与收起，收起时保留原来的文字，加载、重连或切换会话后直接在位）是浮起的表面加 1px 细线，圆角 8：错误叠淡红配红色的边，中性与警告只有浮起与细线；警告配三角，错误配圆形叉号，中性配信息图标；图标与标题用色调文字，说明是次级墨色 12/18；最多一个 xs 动作（警告与红色调里是描边按钮），可选一个关闭按钮。先写保留了什么，再写原因，最后给动作。错误提示是 `alert`，其余是 `status`。本地操作成功（保存、启用、获取到模型）用中性提示或只让值原位更新，不用绿色。Toast 是弹层面的一小块（`--pop`、圆角 8、至少 36 高、`--sh-lift`），从下方 4px 升起并淡入（`--m-enter`），前面一个色调图形，用于发生在别处的事（「已由「设备名」处理」）和失败；置顶、归档、删除这类在本页做的操作成功时不弹 Toast，列表行的移动或收起就是反馈。 窗口的 Toast 在输入框露出时升到它上方 12 并对齐它的中线，不盖住模型控件与发送（[Overlays.tsx](../apps/web/src/shell/Overlays.tsx)）。

**空、加载与错误。** 空状态是一句短名词（「还没有会话」）、一行说明和最多一个 xs 按钮，左对齐，不放插画。加载在对象旁边放 14 的转圈和一行提示墨色的文字；页面中央的连接状态用 20 的转圈；列表的骨架只做缓慢的明暗（不透明度在 1 与 .55 之间分四步来回，2.4s，离开视野时暂停，减少动效时不动），不做扫光，占的盒子与内容相同。界面出错的卡片是一张 480 宽的浮起卡片：红色三角、标题、一行说明会话和草稿都在执行端，最多两个按钮。

**磁贴。** Harness 与模型的方形磁贴：14、16、20、24、32、40、56，圆角按 round(边长 × 0.225)。磁贴放品牌自己的标志文件（`mark`），在浮起的表面上，外面一圈 1px `--line` 细环画在图形之上，标志贴到边时细环仍在；只有没有图标的东西才放调用方给的图形（`icon`），放在淡填充上；类型上二者必有其一，磁贴从不画字母。标志居中占 72%，文件自己带了很宽的留白时（`margin`）铺满；图形占 60%。彩色标志原样放（`<img>`），品牌另有深色版文件时（`dark`）按页面的主题换用；单色标志按品牌的单色复制方式，以文件为 CSS 遮罩、填成 `--ink`，所以浅色里是近黑、深色里是柔和的白，图形本身不改；品牌自己的应用图标（`tile`）自带底色与外形，原样显示，不加底与细环，也不按磁贴的圆角裁切。标志文件从不作为标记内联进页面。图形是正文墨色的图标（Latch 图形或 Lucide），线宽按屏幕定为 1.5，16 的磁贴里是 1.25，不随图形缩放；16 及以下的位置上（选择器的按钮、顶栏与回复的来源行）没有图标的东西只画图形本身（`plain`），因为底上 10px 以下的图形认不出来；我的 Agent 的中性图形磁贴也一样。`plain` 只有图形没有磁贴，图形用次级墨色（单色标志仍是 `--ink`）。就绪度画在磁贴上，就绪不加任何标记：不可用（例如找不到命令）灰度并降到 40%；启动或检测中灰度、降到 70%，外面一圈 2px 的进度环（有进度时从 12 点起顺时针按比例画弧，否则一段弧 1.4s 绕一圈，离开视野时暂停，减少动效时停住）；失败在右上角放一个 8px 的红点并镂空一圈表面色。就绪度也要在文字里写出。

**磁贴选择（`TileChoice`）。** 支持大磁贴与紧凑两种布局，默认保留大磁贴供需要图片辨识的选择场景。紧凑布局 `variant="compact"`：20px 身份图标与名称、说明同行，桌面最小 36px、触屏最小 44px，选中是选中行那样的卡片（`--selected` 与它的环），长名称省略且保留提示。整组只有一个 Tab 停靠点；方向键选择并跳过不可选项，Home / End 到首尾。不可选项保持可聚焦，原因由说明与读屏描述给出，按下时在整行下面展开。

**状态。** 只有正在进行的工作会动（它的转圈），等你处理、失败、已完成与时间从不动；状态变化被页面亲眼看到时，新旧状态在同一格里交叉淡化（`--m-micro`），这是它们唯一的过渡。样式在 [status.css](../packages/ui/src/styles/status.css)。

- **状态槽（`StatusSlot`）。** 列表行第一行行尾的一格，右对齐、至少 24 宽，只显示一样：运行中（转圈加「运行中」，页面给出时长时写「运行中 1:12」，正在停止时写「正在停止」）、等你处理（琥珀盾牌加「等你处理」）、注意（没有盾牌的琥珀字，文字由页面给出）、失败（`alert` 加红字，文字由页面给出，默认「失败」）、未读（12 的墨色对勾，会话被读过后消失）、已结束（`--muted` 的「已停止」）、时间（`--muted`、常规字重），或什么都没有。会话行按 `rowStatus` 选择。状态变了且页面看见时，旧的在同一格里以退出曲线淡出（70% 的 `--m-micro`），新的淡入；淡出播完就从页面上移走，离开的转圈不会在看不见的地方继续转。它对读屏隐藏，行自己用一句隐藏文字说出状态与时间。
- **过程行的状态（`StatusGlyph`、`StatusWords`）。** 工具的过程行与计划步骤共用：图形格里运行中是转圈（行里 12，工具卡 14），其余是这一行的图标（计划步骤按状态是空心圆、带点的圆与对勾，都是静止的）；`state` 写明图形表示什么。页面看着它变化时，旧图形淡出、新图形从 80% 长到原大并淡入，在同一格里交叉淡化（`--m-micro`）；状态文字（执行中 → 完成）淡入。失败只换图标与文字，不抖动。
- **只为看见的变化播放。** 这些过渡（还有计数的淡入）只为页面亲眼看到的变化播放一次：页面经 `LiveChanges` 给出重新同步的纪元，在上一次渲染之后换了纪元的变化直接显示新值；没有纪元或减少动效时也直接显示。外壳（侧栏、图标栏）的纪元是 Host 状态重新同步的次数（首次加载、重连后的快照同步、页面重新可见，见 [STREAMING.md](./STREAMING.md)「客户端：事件流、凭据与版本门禁」）；对话区与会话详情的纪元另加打开的会话，切换会话时那里不播。会话列表跨会话存在，所以打开一个未读的会话时，它那一行的对勾淡出、时间淡入。只在有东西等待时才出现的计数（侧栏的「等你处理」行、图标栏的待批准按钮）由所在的组件用 `useLivePrevious` 记住它出现前的值并传给 `Count` 的 `from`，所以第一项到达（0 → 1）也淡入。页面里的其他一次性过渡用同一个 `useLiveChange`。
- **正在思考（`Shimmer`）。** 进行中的文字是提示墨色：挂载 600ms 后，一道墨色的窄光用 1s 从左到右扫过文字，然后休息到 4s 一个周期结束，只动文字背后渐变的位置；离开视野时暂停，减少动效时是静止的提示墨色。`variant="working"` 是运行中的工作标签：一道光以 30 步、2.2s 一轮不休息地扫过，全页共用一个时钟，暂停与减少动效的规则相同。

**展开、替换与离开（[motion.tsx](../packages/ui/src/motion.tsx)）。** 动效只用来说明一个变化：高度只经网格行变化，其余只动不透明度与位移，所以展开的东西上方什么都不移动；减少动效时高度直接到位，只保留淡入淡出。`Collapse` 是展开块的身体：打开时网格行从 0fr 到 1fr，内容同时淡入（`--m-panel`）；关闭用 70% 的时长与退出曲线；打开并停稳后不再裁切（焦点环、外扩的行不被切掉）。关闭时身体留在文档里，是 `hidden="until-found"`：不在 Tab 顺序与无障碍树里，但浏览器的页内查找能找到它，并经 `onReveal` 请主人打开；关闭过程中是 `inert`。`lazy` 的身体第一次打开时才渲染，之后保留（工具的输出这类重内容）。首次渲染直接显示当时的状态。`Swap` 在值变化时替换内容：图形从 80% 长到原大并淡入（复制图标变成对勾，`IconButton` 的 `swap`），文字原地淡入（`effect="fade"`，例如「正在思考」变成「思考了 6 秒」），都是 `--m-micro`，首次渲染不播。`usePresence` 让离开的东西在退出动画期间留在页面上并标为离开（「回到最新」淡出、右侧面板的页面滑走），默认留 70% 的 `--m-micro`。`Shimmer` 是进行中的文字（见「状态」）。

**开发版与演示标记。** `DevMark` 是中性徽标「开发版」，整句说明（「开发模式：Host 代码可被本机修改」）是它悬停时的提示与读屏名称，从不用红；`DemoMark` 是琥珀色徽标「演示模型」（窄处写「演示」）。

**操作与面板部件。**

- **`SplitButton`。** 一个动作加一个收着同类动作的 V 形（「提交 ⌄」）：同一张面、两个控件、两个 Tab 停靠点，菜单与按钮右缘对齐。主动作禁用时 V 形仍可用，除非 `menuDisabled`，因为菜单里可能还有能做的事。
- **`SelectButton`。** 设置行里打开选择器的值：16 的磁贴或 14 的图形、值与 V 形，28 高，只画按钮，触发属性来自 `Menu` 或 `ValuePicker`。禁用时保持可聚焦，点击与按键都打不开。
- **`Button` 的 `pending` 与 `done`。** 用于打开系统表单的动作：表单打开时转圈留在原位，成功后绿色对勾变形进来并换成 `doneLabel`，这期间不接收点击。
- **`CopyButton`。** 图标在 `--m-micro` 里变成对勾，「已复制」锚定在按钮旁 1 秒；失败时在同一位置说明，读屏用 polite 状态。复制经 `writeClipboard`，Clipboard API 不可用时退到选区复制，两种都失败才说「复制不可用」。
- **`PanelTabs`。** 侧面板的标签条：24 高、圆角 6、12/16·500、最宽 160，选中立即移动不滑动，可带行数（`+60 −6`）与 6px 的新内容点。可关闭的标签悬停时图形让位给 ×，触屏上选中的标签一直是 ×，没有图形的也留出这一格；Delete 关闭并把焦点移到相邻标签。只有一个 Tab 停靠点，←/→ 移动并选择，溢出时横向滚动。
- **`DrawerStack` 与 `Drawer`。** 附在输入框上等待的东西（审批、问题、队列）：左右内缩 20、与卡片重叠 14、上圆角 16，从卡片后面滑上来（`--m-panel`），以 70% 的时长滑回，只为页面看见的变化播放。最后一个子项在最前，其余露出 10px 的边、宽 96% 且 inert，指针或焦点进入（触屏是点按）时展开。`arming` 让抽屉到达或回到最前后 320ms 内 inert，展开的堆叠里上一个抽屉离开时也一样。
- **`FoldHeader`。** `Collapse` 的整行头部，12 的 V 形在 `--m-panel` 里转 90°。
- **`ProgressBar`。** 2px 的线，给不知道时长的工作：缓动到 90% 后等待，结束时 150ms 走完并淡出；对读屏始终是不确定进度，因为 90% 不是测量值。
- **`Group` 与 `Row`。** 设置卡片：圆角 12 的浮起分组，可带标题，行之间是细线；里面的任何内容都有内边距。
- **`Scrim`。** 不是原生对话框的滑出层背后的遮罩：淡入 `--m-sheet`，`open` 转假后留下以 70% 的时长淡出，这期间不接收按下。

**原语与页面。** 页面里的按钮、图标按钮、开关、分段控件、筛选、状态词与徽标、计数、内联提示、发送方式的单选列表、加载行、Toast、开发版标记、Harness 与模型服务的磁贴、新会话的紧凑选择、输入框里的选值（项目、Harness、模型、Agent 的模型选项）、侧栏的调整宽度把手，以及会话行的状态槽、过程行的状态图形和文字、展开块、替换与进行中的文字都来自原语。菜单、模态外壳、异步确认与输入框也由 `@latch/ui` 提供；页面的 `overlays.tsx` 只保留兼容导出。内容自管的 `Modal` 支持 dialog、sheet、page，共用原生顶层、焦点循环和归还；`ActionMenu` 与 `ActionSheet` 把页面动作映射到同一菜单原语。页面负责内容、请求和布局。

[packages/ui/test/gallery](../packages/ui/test/gallery) 是只供测试的原语总览页：每个原语的每种状态都在一页上（悬停、按下与键盘焦点由截图时强制），不进入 `dist/web`。状态的变化在总览页挂载后一帧重放一次，另有几格把状态槽与过程行的交叉淡化、思考的光带定格在中途，便于评审；「动效」一节是收起与展开的块（可以点开）与两种替换；「状态」一节是四种尺寸的转圈、状态槽的每一种、侧栏的一组行、变化、过程行与正在思考；总览页自己的排版只作用于它自己的元素，原语的标题与字号保持原样；就地画出的对话框、弹层与底部面板在手机宽度下收进卡片，完整可见；截图时视口长到整页高度，手机与平板的截图因此带着触屏尺寸（44 的点按盒子、44×26 的开关）。

## 组件

**新建 Agent 与话题输入。** 创建先选运行它的 Harness，再填写头像、名字、职责与可展开的指令；模型、技能和默认项目收在「更多」里。返回候选保留已填的共同字段，改选 Harness 只放下不适用的模型。外部程序的「不隔离」说明始终可打开，看管程度按真实能力与当前读回显示，不按程序名字推断。创建结果未知时保留原请求，提供重试与明确放弃等待；切换入口或刷新不自动视作成功或取消，详情见 [CUSTOM-AGENTS.md](CUSTOM-AGENTS.md#创建的待确认请求)。

我的 Agent 的回复用头像和名字表示来源，工作过程用「在想」「在跑命令」等状态词，保留真实失败、等待与权限说明；模型和用量不占对话正文。输入区只留文字、附件与项目的「＋」、发送或停止，输入 `/` 仍能使用会话实际发布的命令；选择命令只填草稿。附件沿用会话上传和同一提交请求，上传中取消保留文字，结果未知时重试原请求，明确放弃后需要重新附加文件。

**Harness 与模型服务的图标。** 每个 Harness 与模型服务都显示它真实的品牌图标，放在磁贴上（`BrandTile`，[brands.ts](../apps/web/src/brands.ts)）：Harness 只用厂商官方仓库、官网或官方应用发布物中的真实资源；官方只提供位图时保留原图，不描摹。模型服务沿用已记录来源的品牌资源与 LobeHub Icons（MIT），品牌标志是彩色的就用彩色版，否则用官方单色版；浅深色有官方变体时分别使用。文件原样复制到 `apps/web/src/assets/brands/`，不作为 npm 依赖；以 `?no-inline` 导入，构建产物里是同样字节的文件，不被改写成内联数据；只经 `<img>` 或 CSS（遮罩）使用，从不内联成标记。来源（仓库与路径及提交，或网址与日期、官方应用版本）、许可证、图标集的 MIT 声明与「标志属于各自的所有者，只用于标明服务或工具」写在 `apps/web/public/licenses/brands/`（`SOURCES.txt` 与图标集的许可证）。目录里的会话与服务不带预设标识，所以按 Host 由预设派生的标识（`codex`、`codex-2`……）认出它的预设；设置里有预设标识时直接用它。没有图标的才用中性图形：自定义的 Agent 命令是 Harness 立方体（`HarnessGlyph`），插件是四格（`PluginsGlyph`），自定义的 OpenAI 兼容服务是 Lucide 的 `plug`，演示模型是 Lucide 的 `presentation`；Latch 内置的 Harness 用应用图标原样显示。[brands.test.ts](../apps/web/test/brands.test.ts) 检查每个 Harness 预设与模型服务预设都有图标，演示、插件与自定义各有图形，图标目录里正好是映射用到的文件，且每个 SVG 不含脚本、外来内容、事件属性、嵌入图片、样式表或指向文件外的引用。图标出现在侧栏的会话行、顶栏与每轮回复的来源行、选择器，以及设置里的模型服务（预设、列表与表单）与 Agent（预设、列表与表单）。 Harness 选择菜单的普通项只显示名称、官方标志与当前勾选，不重复通用能力描述；Host 给出的真实异常与不可用原因保留。iOS 的 `Brands.xcassets` 使用同一份源文件，矢量保留矢量，位图不重绘；原生 Harness 菜单以 `Label` 的图片复用同一映射，并由系统 `Picker` 显示当前勾选，单色资源在资产目录声明模板渲染。商标使用条件与软件许可证分别记录，适配器的开源许可证不授予厂商品牌许可。

**Agent 头像。** 我的 Agent 的头像是一对括号围着两只眼睛（[AgentAvatar.tsx](../apps/web/src/agents/AgentAvatar.tsx)，几何在 [avatarFace.ts](../apps/web/src/agents/avatarFace.ts)，iOS 是 `AgentFace.swift`）：40 网格，圆角 13 的方块，线条全是圆头圆角，眼睛比中线略低；括号四种、眼睛四种、颜色九种，由人在 Agent 页头的选择器里组合。极简、带一点极客气，有温度但不幼稚：没有嘴、腮红、高光和大眼睛。挨着名字时是装饰（`aria-hidden`），状态词始终写在旁边，头像只陪衬。尺寸：列表 40、Agent 页头 56、侧栏与委托会话页头 24、命令面板 16；「我的 Agent」入口是单色线稿 `(··)`，不动；不为放头像新增位置。动作偶尔、平静：空闲时每隔几秒随机眨眼、看一眼（约 1–1.5 秒后回正）或笑眯眯；运行中右下角闪烁的 `_`、眼睛看向它；等你处理时眼睛抬起，右上角不时冒出琥珀色「?」；失败时眼睛低下，右上角红色「!」；不可用时闭眼，飘出「z」；会话在页面打开时结束，笑眯眯一次。32 起有全部动作与配件，20–31 只偶尔眨眼，16 不动。全页一个调度器、一个计时器，只驱动视口内的头像，页面隐藏时暂停，只动 transform 与 opacity，同时笑眯眯或冒配件的不超过 3 个。减少动效时完全不动，配件静态显示（光标常亮，「?」「!」常显，「z」静止）；截图与 e2e 经根元素的 `data-motion="still"` 冻结到同一帧（`stillMotion`，在 `visualContext` 里与固定时钟一起）。选择器：桌面是弹层，手机是底部面板；上方是会动的预览，下面是括号、眼睛、颜色三行，选项本身就是不动的头像并有名称（「圆括号」「弯眼」「松」），每行一个 Tab 停靠点、方向键在行内移动，选中项是 2px 墨色环；选了立即提交，只显示 Host 读回的值。

**Agent 资料的连续性。** 跨桌面、平板与手机保留一个资料实例；同一 portal 容器移动到当前插槽或原有 Sheet，未保存设置、当前页签和待确认写入不复制、不丢失。活动面板内恢复原控件焦点，真正关闭才回到资料入口；撤权与换设备卸载私有内容。设置复用新会话的模型、思考与权限原语，“家”的路径与非隔离说明按需展开（[CUSTOM-AGENTS](CUSTOM-AGENTS.md#家与工具)）。

**和 Agent 对话。** 每个 Agent 有一条持续聊天。页头的一组头像、名称和职责打开资料面板，右侧显示实际状态、定时任务与会话操作。手机的次行显示状态或聊天标题。未发送首条消息时，页头仍是唯一身份区，输入框沿用聊天的位置。名册中行尾的省略号与打开聊天的按钮并列，悬停、焦点或触屏可达。资料面板宽窗口占右侧面板的位置（新话题上 400 宽、左边一条线，窄于 1024 时浮在对话上，带 `--sh-pop`），手机是 92% 的底部面板（「完成」关闭）；内容自上而下是 56 头像、名称与职责、分段「动态 · 资料库 · 记忆」（动态按「今天 / 本周 / 更早」分组的凸起列表，每行提示墨色的种类词、名称、时间与状态词；资料库每个会话一张凸起卡，标题行是名称与时间，定时运行前有闹钟图标，下面是等宽的文件路径与「新增 / 修改 / 已删除 / 你给的」）、「即将进行」（凸起的列表，每行名称、计划与开关）、电脑与工作位置等事实、「设置」。没有常驻的侧栏列。记忆提议在对话里是提议来自的那一轮之后的一张凸起卡（`--raised`、1px `--line`、圆角 12，与「交回的结果」同一族）：「想记住：」（提示墨色）与文字，下面一行提示字号的来源短词（「你说的」「它推断的」）、外部内容时琥珀状态词「来自外部内容」、理由在 `Hint` 后，右端「不要」（幽灵）与「保存」（这一处唯一的蓝色主按钮）；保存后右端是「已保存」与生效时机，不要后整卡变透明、文字转提示墨色写「不要了」。资料面板的「记忆」最上面以「提议 N」列出同样的卡，保存在那里是次级按钮，面板的蓝色留给它的表单。定时提议是同一张卡，写「想定时：」与名称 · 计划，右端「不要」与蓝色「打开」（进入预填的定时编辑）。定时结果是对话里按结算时间排进去的一张卡，与「交回的结果」同一族：卡外一行提示字号的闹钟、「定时」、名称、时间，右端结果状态词（已完成 `done`、失败红、已中断与结果未知琥珀、已停止中性）；卡里是失败原因、最后回复的开头与「展开」、等宽的文件行（删除的划线、不能打开），右下「立即运行」（只在失败的下一步是重试时）与幽灵「打开运行」。卡不是消息，没有头像与作者行；没有动画。同一处多于 3 张时只画最新的 3 张，上面一个幽灵小按钮「还有 N 条结果」打开「动态」。定时提议打开的编辑表单在输入框上方写提示字号的「它写的」（外部内容时加琥珀「来自外部内容」），输入框按行数长高到一屏。

**侧栏。** 内容、分组与状态词见「会话面板」。抽屉里头行另有「关闭会话列表」；新会话页打开时「新会话」是切换按钮的「开」。页面不是那台电脑上的 Latch 时（回环上的浏览器也算），头部第一行是井里的 `laptop` 图标与等宽的电脑名称；那台 Mac 上的 Latch 不写。底行左边是「添加项目」（只在那台 Mac 上的 Latch 里），右边是带图标和字的幽灵按钮「设置」，设备在 设置 › 设备 里，没有单独的入口。连接有问题由「设置」旁的点与顶栏的话说出；桌面端保持这台 Mac 唤醒时，底行上方写提示墨色的「保持唤醒中」，悬停说明原因，点它同步最新状态。会话的工作目录落在哪个保存的项目里（取最深的一个）就归哪一组，其余归「无项目」；组按其中最近更新的会话排序，组内置顶在前、最新的在前；Host 不提供项目列表时按工作目录分组。上一个与下一个会话的快捷键按屏幕上的顺序走：「等你处理」在前，跳过折叠的组。组头的 ＋ 在这个项目里新建会话（项目在本次启动时不可用，或设备不能发起会话时没有）。⋯ 是会话菜单，与标题行同一份（见「会话」）；悬停、键盘聚焦或菜单打开时状态让位给「归档」与 ⋯。标题太长时最后 16px 渐隐，不用省略号；菜单打开时这一行保持悬停底。行标题默认用次级墨色；选中的行是选中卡片（浅色是侧栏灰上的白色卡片，深色是一层柔和的白；120ms 切换）与 500 字重；未读的行把标题换成正文墨色并在状态槽显示墨色对勾；连接中断时，等你处理的行仍是 500 字重。未读按设备记录。列表随 Host 变化时，移动的行与组从原位置滑到新位置，新到的行淡入（都是 `--m-enter`），离开的行（归档、删除、移到别的组）高度收起并淡出（`--m-micro`）；移动的行超过 30 个或换到已归档时直接重画，减少动效时都不动。

**新会话。** 标题只说项目，居中（`--fs-question`）：有项目时就是项目名，它是内联选值，点它换项目；没有项目时是「选择项目 ⌄」（见下面「新会话页」），页脚多一个「选择项目」。要做什么由输入框问，占位字只写「@ 文件，/ 命令」。下面是输入框（[NewSession.tsx](../apps/web/src/newSession/NewSession.tsx)）；选了项目时输入框下是「这个项目最近的会话」（最多三条，不含归档，点开即进入）。项目里有能列出已有会话的 Harness 时，紧贴输入框下面是幽灵按钮「接入已有会话」（`history` 图标）；设备看不到私有会话时是同一行的上锁提示（锁、提示墨色的字、ⓘ 说明去 Mac 上开启「可以看项目文件」），不是按钮。它打开 640 宽、720 高的对话框（手机上是整页，预览从右推入，减少动效时只淡入）：标题行下一行写项目、Harness 与「主文件夹里的会话」ⓘ，列表每行 44 高，标题在左，右边是已接入的勾、等宽的子目录与相对时间（手机上落到第二行），列表末尾提示墨色写其他文件夹的数量与「尚未支持」。预览是只读的对话：用户的话在中性气泡里，回复是正文，工具是一行提示墨色的等宽标题加「完成 · 输出已隐藏」；忙碌是居中的琥珀三角与「这个会话正在别处使用」，下面一句说先在那里退出，只有「再看一次」。底栏是「继续用」与 Harness 选值、方式（「原样接入」ⓘ，或琥珀色的「按文字重建，不是原样恢复」ⓘ）与唯一的蓝色按钮「接入」（手机上占满一行）；没有答复时按钮左边琥珀字「结果未确认」，按钮变「重试」，被拒绝时红字写原因（[HistoryImport.tsx](../apps/web/src/history/HistoryImport.tsx)，样式在 [history.css](../apps/web/src/styles/history.css)）。没有建议卡片或提示行。页面唯一的底纹是一层点阵（24px 一格，墨色是 `--line-strong`），以遮罩从标题与输入框向外淡去，碰不到要读的字；它是页面自己的地面，随页面滚动，不接收指针。整块顶边固定为 `max(48px, 36vh − 52px)`，输入框下面出现说明时只向下长。

- **页脚**（[Composer.tsx](../apps/web/src/composer/Composer.tsx)，没有上下文条）：四个控件平铺，左边「+」、Harness、模型（谁来做、用哪个模型），中间空开，右边挨着发送是思考、权限（想多深、多小心），然后是用量环（上下文过半且 Harness 报告了才有）、「⋯」、发送。每个控件只写值，四个在任何宽度都看得见，放不下就换到下一行（右边一组仍靠右），不收进菜单。每个控件外面一层带 `data-composer-control`（`harness`、`model`、`thinking`、`permission`），按键找的是它里面的按钮。手机的会话页里四个控件都在输入框里，排成两行：Harness 与模型一行（模型 ID 太长时先省略模型，Harness 的名字不截），「+」、思考、权限与发送一行，发送在行尾；框外不再有一排控件。手机的新会话面板仍是它自己的几行。分支在卡片下面一行（项目或会话有可验证的分支时才有）。新会话的项目是只有一个文件夹的 Git 项目时，这一行最前面是「文件夹」选值（`xs`，菜单向右展开）：「当前文件夹」或「新工作树」，后者的说明先写「不带未提交的改动」再写起点（分支名太长时省略的是分支名），菜单脚部是 `Hint`「工作树只分开文件」，端口、进程与权限仍然共用在 ⓘ 后；选了「新工作树」时分支换成「从 main 的 3f2a1c9」。手机的新会话面板在「项目」下面有同样的「文件夹」一行。在工作树里开始的会话，这一行、顶栏项目名后面（提示墨色，宽度不够时先让位）与手机页头的第二行写「工作树 · <分支>」，侧栏与手机列表的行在标题前有 12 的工作树图标，提示只写「工作树 · <分支>」。 这台电脑的 Harness 菜单脚部有「设为新会话默认」：之后这台电脑上每个新会话都从这个 Harness 与模型开始，在草稿里换一个只影响那一次（开始或重新载入后回到默认，也不写入记忆）；「取消新会话默认」后回到这台设备记住的上次选择。其他设备看不到也收不回这个默认，所以它只在这台电脑上生效，其他设备照旧记住各自的选择。它的 Harness 或模型用不了时（例如移除了服务的地址）默认不生效，也不替它换一个，恢复后重新生效。
- **Harness**（[ModelControl.tsx](../apps/web/src/composer/ModelControl.tsx)）：磁贴与名字。菜单头是「开始后不能换 Harness」，每个可用 Harness 一行，下面几个字写能做什么（「读写文件、运行命令」，Latch 内置是「只读写文件，不运行命令」），Latch 内置排最后；选模型从不换 Harness。新会话默认只有「设为新会话默认」「取消新会话默认」这一行与它的图钉，不另写说明。开始后是不带箭头的磁贴与名字，点开是带锁的「开始后不能换 Harness」、能分叉时的「分叉 · 从最后一轮，可以换 Harness」与「新会话」；文件不复制、不回滚写在分叉后草稿上方那条通知的 ⓘ 里。
- **模型**：只写模型，等宽的 ID；经服务时前面是 14 的服务标记。Harness 还没报告的模型写「默认模型」，菜单里一个短标签说明（开始之前写「发第一条消息后可以换」，因为 ACP 要开会话才报告；开始后仍没报告写「由 <Harness> 决定」）。外部 Harness 先列它自己的模型（组名是 Harness 的名字与标记，按真实名称列出，新会话默认的那个旁标「默认」小徽标），再列已保存的模型服务：Latch 能把这个 Harness 的请求转给的服务（协议相同，如 Codex 与 Responses 服务）列出它的模型，组名写「<服务> · 经 Latch」（Codex 写「<服务> · 实验性 · 经 Latch」）；列表下面的 `Hint`「经 Latch 转发」在 ⓘ 后说请求由这台 Mac 上的 Latch 转发、用设置里的密钥；会话里写「经 Latch 用「<服务>」」，有一轮没经过 Latch 时琥珀色，服务用不了时照写失败与怎么办。其他服务折成一行「N 个服务用不了」，展开后每个写明原因（如「Codex 只说 Responses，这个服务是 Chat Completions」）；Latch 不为它转发任何服务的 Harness 没有这一行，见 [MODEL-CONFIGURATION.md](./MODEL-CONFIGURATION.md)。Latch 内置列模型服务。
- **服务的健康**：只在不正常时出现，总是一个 `StatusDot` 加状态词，细节（最近一次失败的分类与时间）在悬停或聚焦后。变慢、额度用完、请求过多是琥珀色（会自己过去），出错中、密钥无效是红色（真实失败）。模型菜单只写后三种，状态词在组名里、点在名字前，手机面板只有文字；设置里在服务名下一行与列表行末。由「出错时改用」的服务回答的一轮，作者行写「服务 · 模型」，后面一个中性的「备选」徽标，悬停写是谁回答的；它不是警告，所以不用琥珀。等某个服务的位置的会话在运行状态里写「排队：<服务>」，等全 Host 名额时只写「排队」。
- **思考**（[ThinkingControl.tsx](../apps/web/src/composer/ThinkingControl.tsx)）：小字「思考」加值。Latch 内置写自己的词（默认、低、中、高……，档位来自 设置 › 模型 里对这个模型的声明）；外部 Harness 写它自己报告的名字（`Low`、`High`），每档下面是它自己的一句说明。没有值或没有报告时写「默认」：这时不画箭头，但总能点开，菜单里只有「默认」一行和至多一个短标签（「发第一条消息后可以换」「开始后才知道」「用模型默认值」，去哪里设在 ⓘ 后），因为触屏没有提示框。只有 Harness 报告了档位才有可选的行，Latch 不替没声明的模型编档位。会话里 Latch 内置换档与换模型一样从下一条消息起生效，写「下一条：低」。
- **权限**：始终显示、始终能点开（触屏没有悬停），菜单头是「什么时候问你？」。开始之前来自 `HarnessInfo.permission`：Harness 会询问时写「先问你」，下面的 `Hint` 说其他档什么时候能换：读取会报告模式的 Harness 写读取中、读取后可以换或没读到，打开权限就读取，Codex 这类读取不报告模式的写「发第一条消息后可以换」，原因在 ⓘ 后（见 [HARNESSES.md](./HARNESSES.md)「开始前的选项」）；Latch 知道它的模式时下面一行用这一档在这个 Harness 里的说明（与开始后同一行），否则写「改文件或运行命令前问你」；执行工具前不询问（「不询问 · 由 pi 决定」，下面一行「只有扩展要求确认时才问你」，带标志的 `Hint`「pi 自己决定」在 ⓘ 后说 Latch 不限制、不隔离它）和读不回（「权限无法确认」）是琥珀色；Latch 没有 profile 的 Harness 能读取时写「读取后可以选」，打开权限就读取，读取中写「正在读取…」；读到的列表没有模式或读不了时写「开始后可以选」，这三种标题已经说清，下面不再加一行。开始后（或读到列表后）列 Harness 报告的模式：有档位的标题是「只看不改」「先问你」「按规则放行」「由模型判断」「不再询问」，下面一行是这个 Harness 自己在这一档怎么做，只一个短句，可能判错这类性质由档位与图标表达；脚部是带 Harness 标志的 `Hint`「<Harness> 自己的设置」，Latch 只核对选的是哪一项、不隔离它在 ⓘ 后；芯片没有悬停提示，菜单总能点开；模式超过三个时只列三行主档，其余在「更多」里，当前的总在（见 [HARNESSES.md](./HARNESSES.md)「权限菜单」）。只有「不再询问」的标题、说明与图标是琥珀色。任何能发起会话的设备都能直接选任何一档，不弹确认；设备按 Harness 记住人选的档位，Latch 不替人选更宽的一档。这些限制只写在菜单里，输入框下面没有长句。
- **模型的判断**：Harness 自己的模型审阅一次请求的行写「Codex 的模型审阅」，图标是天平，状态词是「放行」「拦下」或「没有判断」，不是人的批准，不用决定记录的写法；拦下不算失败。Harness 在运行之前自己拦下的调用仍是那次调用的行，图标是禁止符号，状态词「拦下」，下面一行灰字写是谁拦下的与它自己的理由（「Claude Agent 的模型审阅：…」「被 Claude Agent 自己的规则或当前模式拦下：…」），不是红色，没有「重试」。在「由模型判断」档里没有问人就运行的调用，状态词是「没有问你」。是谁决定的在展开的行里：一行短标签（「模型的判断，不是你的批准」「由模型代你决定」「要放行，换权限或改规则」），整句在 ⓘ 后，不放在只有悬停才看得到的提示里。
- **第一次用**：Harness 按设备记住。没有记录且可用 Harness 不止一个时询问，什么都不预选；只有一个会询问的 Harness 时不问；不替人选完全访问的 Harness，也不用 Host 的默认代替询问；只有这台电脑上由本人「设为新会话默认」的 Harness 才不问。分叉借用来源的 Harness、项目与方式，以及来源当时的模型、思考与权限档（换 Harness 时按值与档位对应；权限用同一档或更严的最宽一档，目标 Harness 两者都没有时用它最严的一档，可能比来源宽，这时和其他对应不上的一样在分叉说明下逐条写明），只对这份草稿有效，不写入记忆。其他设备只有内置 Harness。
- **菜单**：模型菜单只列这个 Harness 能用的服务，用不了的收成末尾一行「N 个服务用不了」（12/16 提示墨色），每次打开菜单都收着，点开后每个服务一行：磁贴、名字，下面一行原因（[securityCopy.ts](../apps/web/src/core/securityCopy.ts) 的 `MODEL_MENU_COPY`）；已定不做的不写「尚未实现」。会话里的 Harness 弹层（320 宽）在带锁的「开始后不能换 Harness」下有「分叉」：从最新一轮分叉，下一行「从最后一轮，可以换 Harness」；最新一轮运行或等你处理时这一行变淡、不可按，下一行换成「这一轮结束后才能分叉」。分叉进新会话页：上面一条分叉通知（分叉图标、「从「<标题>」分叉」，文件不复制、不回滚与同一项目共用文件夹在 ⓘ 后，「取消分叉」在右；对应不上的模型与权限在下面逐条，权限写成「权限「a」→「b」」），输入框预填「请接着这个会话继续。」，Harness 菜单开着。Harness、模型、思考、权限四个菜单的标题行末尾写打开它的键（⌥⌘1–⌥⌘4），只在桌面 app 里；浏览器的键没有核实，不画。不是那台 Mac 上的 Latch 时，菜单里 Latch 自己的句子把「这台 Mac」换成电脑名（`computerName`），Harness 自己的说法照抄。思考没有值时在每处都写「默认」。
- 新会话从哪里开始就在哪里：在打开的会话里新建时，预选那个会话所在的项目；从侧栏项目组的「+」新建时预选那个项目；其余用上次的选择。选择按设备记忆，并按 Host 当前目录修正。
- 缺少可用模型或 Harness 时显示一张卡片：缺模型服务时它的「添加模型服务」在卡片里原地展开同一块添加面板（服务的磁贴每格至少 104 宽，一行排下卡片宽度放得下的个数，弹层里是三列），其他情况通往设置。演示模型在顶栏（手机在面板）有明确标记。Host 不发目录时只保留「对话 / Agent」分段控件。

**会话。** 顶栏（画布内 48）左侧是项目与标题：项目是幽灵按钮，打开项目弹层（见下）；会话在自己的文件夹里时只有文件夹图标，也打开它；标题也是一个幽灵按钮，悬停时露出向下箭头，打开会话菜单；接入的会话在标题前多一段提示墨色的「已接入」（`history` 图标，文字重建时「已接入 · 按文字重建」，悬停写来源与方式；手机写在标题下一行）。文字重建的会话发出第一条消息前，输入框下一行琥珀字写「按文字重建，不是原样恢复 · 第一条消息会把重建的对话文字一起发给 <模型服务>」；发出后这段文字在第一条气泡里折叠为「按 <来源> 会话的文字重建」，与分叉的上下文同一种折叠。原样接入的会话被 Harness 弄丢（`harness-session-lost`）时，输入框上方的停止行写「Harness 找不到原来的会话了」，按钮依次是「按文字重建」（`history` 图标）与「在新会话中继续」；「按文字重建」打开一个小对话框（手机上是底部面板）：一句从哪个会话的文字开始、同一个「继续用」选值与琥珀色说明、唯一的蓝色按钮「按文字重建」。重建后原来的会话只能查看，停止行换成「已按文字重建为新会话」与「打开「<标题>」」。接着是不是默认时的状态词（失败为红字，已取消、已中断、正在取消为提示墨色；运行中与已完成不标）。右侧依次是连接状态（只在连接不正常时出现：琥珀字写出状态与「· 重试」并带刷新图标，静止时没有底与边，悬停才有淡琥珀底，没有圆点，手机上同样写出文字；点击同步）、完全访问会话的琥珀状态词（`shield-alert` 加「完全访问」）、演示标记（"演示模型"，手机为"演示"）、「侧边面板」开关（每个宽度都有，打开时是中性的悬停底，不用蓝色）与更多菜单 ⋯。新会话页没有 ⋯。会话菜单只有一份（`sessionMenuSections()`）：标题、标题行的 ⋯、侧栏行的 ⋯ 与手机上按住一行打开的都是它。打开的会话八项，分组为：重命名、置顶、标为未读 | 复制为 Markdown、导出 Markdown | 清空上下文 | 归档 | 删除（需确认）；别的行七项，没有「清空上下文」（只有打开的会话能清空）。会话在自己的文件夹里、还不属于任何项目，并且是那台 Mac 上的 Latch 里能管理的设备时，「清空上下文」那一组另有「存为项目…」。一轮运行或等你处理时，「清空上下文」与「删除」留在原处、灰着，下面写原因：「这一轮结束后才能清空上下文」「运行中的会话需要先停止」。菜单里没有「同步最新状态」：连接不正常时连接状态的「· 重试」同步；分叉在输入框的 Harness 控件里，不在菜单里。手机上没有 ⋯：标题打开会话菜单的底部面板，按住列表里的一行也打开它。连接中断或离线时，消息区顶部有一行琥珀色提示：三角图标与琥珀色标题（请求没有应答时「连不上 <电脑>，正在重连…」，Host 以 5xx 应答时「<电脑> 上的 Latch 出错（HTTP 503）」，浏览器报告没有网络时才写「这台设备没有联网」），右侧「重试」，没有第二句。Host 宣布过原因时，标题改为这个原因与开始时间：「电脑已休眠（22:41 起）」「电脑上的 Latch 正在重启」「电脑上的 Latch 正在更新」「电脑上的 Latch 已停止（21:03 起）」，下面几个字写何时自动重连（「唤醒后自动重连」）；桌面端再按主进程的判断写出「Latch Host 意外退出，2 秒后重新启动（10 分钟内第 2 次）。」等，反复崩溃后停止自动重启或 Host 没有响应时这行提示为红色，前者右侧换成「启动 Host」。Host 早于页面的构建时，同一位置是一条琥珀提示「<电脑> 上的 Latch 还是旧版本」，下一行「重启 Latch 后才能用新功能」与 ⓘ（怎么重启）；只有桌面端那台 Mac 的窗口在右侧给出「重启 Latch」。

**对话与回合。** 对话按回合排列（[Transcript.tsx](../apps/web/src/components/Transcript.tsx)，推导在 [conversation.ts](../apps/web/src/conversation.ts)）：一个回合是用户的一条消息和回答它的一切。回合之间 32，回合内的块之间 12；只在悬停时出现的东西盖在回合下方的间隙里，不预留空间。对话列的第一行在顶栏下 16，避开 16px 的渐隐。只有用户消息有气泡：右侧的中性气泡（圆角 16，靠回复的右下角 4），超过 176 高时收在渐隐后，带「显示全部」；下面是时间、「复制」与「从这里编辑」（在这条消息之前分叉，文字进入输入框；第一轮没有），桌面上悬停或聚焦时淡入（120ms），触屏上最新一条常显。消息送达的过程写在气泡下：发送中、Mac 已收到、Agent 已开始，Agent 开始回答后消失。页面亲眼看着到达的消息才有到达的动效：用户的气泡上移 6px 淡入（`--m-enter`），回复的第一块淡入（`--m-micro`），流进块里的文字不动；加载、重连与切换会话不播放。每个回合以作者行开始：16 的 Harness 标记、Harness 的名字，后面是提示墨色、等宽的模型；演示模型回答时模型前写「演示」。撤销之后下一条消息带给 Harness 的说明不进气泡，在气泡上方写一行「已告诉 Harness 改动被撤销了」。分叉出来的会话在第一轮之上写一行来源。

**工作行。** 思考与每次工具调用都是一行安静的工作（26 高，手机 28），挂在作者行下一条 1px 的细轨上（`--line-strong`，离对话列左缘 8，行在轨右 12）：先是提示墨色的动词，自成一列（至少 40 宽，行与行的对象因此对齐；读不出动词的工具这一列空着），然后是对象：文件是等宽的路径，从会话的文件夹写起，文件夹用 `--faint` 而文件名用正文墨色，放不下时文件夹先让位、文件名从不截断；命令与搜索词是等宽字；读不出对象时只写工具自己的标题；工具声明了标题时写这个标题加对象；既没有标题、也读不出对象的工具写它的原名，不猜。改动的行数 `+a −d` 紧跟在对象之后。行尾是状态：运行中是 12 的蓝色转圈，失败是 12 的红色叉号，取消、拒绝、拦下、过期与排队各有 12 的图形，完成的行没有图形（动词已经说了它是什么）；接着是常驻的决定记录（「已允许 · 14:36」「已拒绝 · 14:32」「已过期」），用时只在悬停时出现。行在悬停时有 `--hover` 底（向两边各多 8）；12 的箭头在悬停、聚焦、展开时与触屏上出现，展开时转 90°。连续 3 条及以上已经结束的读取、列出与搜索合成一行「读取 4 个文件」「读取 3 个文件，搜索 2 次」，展开是它们原来的行，挂在自己的细轨上；运行中的一轮同样合并，正在运行的那一条留在外面，命令、改文件、失败与等人处理的行从不进去。Harness 自己把一条命令分成读取、列出或搜索时（目前只有 Codex），这条命令画成「读取 `SKILL.md`」这样的行，命令原文在提示与展开后的参数里；带管道、重定向或多条命令的命令行始终是命令；Latch 不从命令文字推断。设置 › 通用的「工作过程」可以只留失败，或把其余的行收成「工作过程 · N 步」（只数工具步骤）；等待批准、失败、被拒、结果未知的行在每一档都显示。文件编辑写「编辑 providers.ts」加增删行数，新文件写「新建 a.ts · 42 行」；展开是最多 12 行改动的预览（新文件最多 8 行）和「在改动中打开」（新文件是「打开文件」）。右侧面板打开时它只有一行，选中文件时带悬停底，点击在面板里打开这个文件。其他工具展开是参数与输出，缩进到对象之下，最高 320；输出在自己的框里，运行中跟随最新的行。失败的行下面一行写第一行原因（不含内部代码）和「重试」，「重试」只出现在这一轮最后失败的地方。Agent 在审批未通过时仍报告执行了调用，行下多一行「已拒绝 · 14:32 · Harness 报告仍执行了」，为什么在 ⓘ 后。思考行运行中写「思考中」（带光）与秒数，Harness 给思考分了标题时后面接「· 标题」（放不下时标题让位），身体自动展开，答案开始后带高度过渡收起并写「思考了 6 秒」。展开的身体里标题是小标题（正文墨色、500），正文只画段落、列表、强调与行内代码，链接、图片与 HTML 都是文字。

**命令。** 读得出命令行的命令（`kind: 'execute'` 且参数里有命令）写提示墨色的 `$` 和等宽的命令（动词「运行」只给读屏），用时常显。系统的 `sh`、`bash`、`zsh`（裸名字或在 `/bin`、`/usr/bin`、`/usr/local/bin`、`/opt/homebrew/bin` 下）加 `-c` 或 `-lc` 包着的一条命令只显示里面那一条；别处的 shell 与认不出的形状原样显示，路径按报告的写，报告的原文在提示与展开后的参数里。审批卡显示完整的里层命令，保留换行、不截断，下面一行小字写外壳报告的原样「经 /bin/zsh -lc」；很长时在自己的框里滚动（按钮始终够得着），框下还有内容时框底淡出，并用琥珀小字写「还有 N 行」。已经结束的命令是细轨上的一行，输出展开才出现。运行中、失败、被打断或结果未知的命令是横跨对话列、离开细轨的一口井（`--sunken` 加 `--sh-well`，圆角 8，头部 36 高）：下面是工具报告的输出（`ToolDetail.output`）的最后 5 行，每行不换行、在右边淡出，所以不超过 5 个屏幕行；只有工具报告了输出才有，命令的纯文本形式不是输出。仍在运行的块在最后一行后有一格宽的块状光标（减少动效时不闪）。Harness 报告失败的命令左边一条 2px 的 `--red-solid` 竖线，图形是红色叉号；有输出时块下不再重复原因，只留「重试」。退出码不画：协议没有这个字段。展开块是参数与完整输出，收起时的最后几行让位给它；最后几行不进查找与读屏，它们重复的是展开后的完整输出。

**子 Agent 行。** Harness 为这一轮启动的子 Agent 是挂在同一条细轨上的一行：动词列写「子 Agent」，16 的 `{··}`（`AgentsGlyph`），名字（正文墨色、500），它最后说的状态（运行中、等你处理、已完成、失败、已停止、正在停止…），箭头在行尾；能单独停止的子 Agent 在行外右边自己的一列（48 宽）有「停止」，没有时这一列空着，各行的状态因此对齐。「正在停止…」要等子 Agent 自己报告后才变成「已停止」。展开是它说的与做的，挂在名字下面一条更淡的细轨上。

**折叠的工作。** 回合结束后，工作收成一行「已工作 2 分 13 秒 ›」，下面一条 60% 的细线；Host 没有记录用时的旧历史只写「已工作」。折叠只收工作行：工具之间的正文和答案永远不折叠，问题和它的回答留在阅读顺序里。这一行不掩盖问题：折进去的行有失败或被拒绝时写出来（「· 1 步失败」「· 1 步被拒绝」）。失败、停止、中断的回合，以及结束时没有一句话的回合，工作保持展开。工作行在回合运行与结束时是同一棵树，页面亲眼看着回合结束时它们收起（网格行加淡出），重新打开的会话直接是收起的样子。

**状态行。** 运行中的回合以一行状态结束，说的是真实在运行的东西，不只是时间（[StatusLine.tsx](../apps/web/src/conversation/StatusLine.tsx)）：「运行中 · 0:47」「命令运行中 · swift test · 1:12」，全局只有这一种走时格式，文字每秒最多变一次。模型或命令沉默超过 Host 的阈值时变成琥珀色的询问：「等模型回应 · 3 分钟没有新内容」「pnpm test · 12 分钟没有输出」，带「继续等」（Host 翻倍这一轮的阈值）和「停止」；Agent 发来 Latch 不支持的请求而之后没有动静时写「Codex 发来不支持的请求 terminal/create · 查看」（详情里有方法名时带上）。按下停止后写「正在停止…」，直到真实结算。等你允许或回答时这一行不出现。连接中断时这一行不出现：横幅说连接，侧栏的行写「上次确认 10:42」。运行不是以普通回答结束时，回合下留一行：「Codex 已退出 · 这一轮没有完成」为红色，强制停止与中断为琥珀色（Host 停止或重启写「Latch 重启时中断」），并列出结果未知、在这一轮里没有自己一行的命令（有行的已在行上写「结果未知」，不重复），带「重试」与「在新会话中继续」。没有报告结果的工具行不写成失败：中断的写「已中断 · 结果未知」（没开始的写「已中断」），其他结果未知的写「结果未知」，图标都是琥珀色的提醒；中断留下的系统消息同样用琥珀图标、不用红色。失败的系统消息就是原因（Host 或 Harness 的原话，已脱敏），按钮是它的一个下一步：「重试」「打开设置 › Harness」「换个模型」「打开设置 › 模型服务」「在新会话中继续」之一，项目目录失效时不给按钮；输入框上的拒绝同样在原因旁给出这一个按钮；Harness 起不来时另给「重试」，文字留在输入框。

**回合卡片。** 结束的回合有文件变化时带一张卡（[TurnCards.tsx](../apps/web/src/conversation/TurnCards.tsx)）：「改动了 3 个文件 +64 −8」「显示文件」展开每个文件，点一行或「打开改动」在右侧面板的「改动」页签打开这一轮和这个文件；设备的数据范围不含项目文件时打开这个文件：工具编辑过的显示它的修改记录，只被命令改过的显示文件本身，已删除的不能打开。数字来自 Host 这一轮的记录；回合与记录按时间匹配，有歧义时不匹配，因为撤销本轮只作用于匹配到的那一轮。没有记录（旧 Host、设备的数据范围不含项目文件、匹配不上）时卡片来自这一轮工具的编辑和观察到的文件变化，没有撤销。「撤销本轮」在卡片头部，或在同一位置写出不能撤销的原因；判断与原因和「改动」页签的范围行是同一个函数、同一句话（`turnUndo`：运行中、这一轮没有正常结束、之后又改过这些文件、这些文件的内容没有留存）。持有 `run` 的设备在哪台电脑上都能撤销，Host 再检查；只能查看的设备或会话不显示撤销，原因写在输入框的位置。有文件恢复不了时先在卡片里列出，确认后才执行，否则立即执行。撤销后卡片让位给一行记录「已撤销本轮改动 · 恢复 · 下一条消息会告诉 Codex」和没有恢复的文件；消息发出后「会告诉」不再出现。撤销或恢复没有得到答复时写「结果未知」，重试用原请求；Host 的记录表明已经生效时就按记录显示。Host 拒绝或回到页面时重读记录，另一台设备的撤销由此反映；卡片与「改动」页签在同一设备上互相通知，一处撤销后另一处随之更新。记录不完整时卡片写出琥珀的「记录不完整：文件夹太大」，上限与撤销碰不到没列出的文件在 ⓘ 后。这一轮新生成的文档与媒体在「生成了 2 个文件」卡片里，每个文件一个「打开」；所有改动都是这些文件时只有这张卡，撤销放在它的头部。

**回合脚部。** 结束的回合的事实与操作盖在回合下方的间隙里（24 高，提示墨色、等宽数字），悬停或聚焦时淡入，触屏的最新一轮常显、点按显示其他的：回复发出的时间（悬停写开始、结束与不含审批等待的用时）、用时、「输入 12.4k tokens」「输出 850 tokens」（各步合计；手机宽度下省掉单位，写「输入 12.4k」「输出 850」，回合有「已工作 …」时省掉与它重复的用时，仍放不下时最后一格以省略号结尾），经 Latch 转发的回合用网关从服务回复里读到的令牌，提示里写明来源和每个模型的请求，没有令牌可写时写「经 Latch 3 次请求」（见 [HARNESSES.md](HARNESSES.md)「每轮的模型与用量」）；Agent 只报告整个会话的上下文时最新一轮写「上下文 74k tokens」；然后是「复制」「重试」（最新一轮；可能重复副作用时先在回合里说明要重复什么）、「从这里分叉」和更多菜单（复制到这里为止的记录）。这一轮的改动只经回合卡片的「打开改动」进入，菜单里没有另一个入口。服务说回答的模型与选的不同时，作者行写服务说的模型，旁边一段中性的「选的是 gpt-5.5」，提示写全两者；手机宽度下「选的是」另起一行，缩进到名字下面，两个名字都只在自己比屏幕宽时才截断。远处的回合跳过绘制时会裁掉盒子外的东西，所以结束的回合把下方的间隙算作自己的内边距，脚部始终在盒子里。没有正常完成的回合另有一行常驻的记录：「已停止 · 14:33 · 保留了部分回复」，失败时为红色并带「重试」。

生成中的回合已可在同一脚部复制当前完整的原始回复；桌面悬停或聚焦出现，触屏的最新一轮常显。事实、重试和分叉等结算动作等回合结束才显示。

**回合之间的分隔线。** 会话本身在两轮之间变了时，后一轮的气泡上方画一条横贯对话列的细线（`--line`），提示墨色的字在中间（[Transcript.tsx](../apps/web/src/components/Transcript.tsx)）：清空上下文写「清空了上下文」并带橡皮擦图标；模型或思考深度变了只写变了的那一项：「模型 small → large」「思考 低 → 高」，两者都变时「small · 低 → large · 高」。值来自 Host 记在助手消息上的模型与思考，没有记录的不画。iPhone 画同样的线（`TurnView.swift`，文字来自 `PhoneConversation`）。

**两轮之间的 Harness 命令。** 带 `idleOnly` 的 Harness 命令（pi 的 `/compact`）和其他 Harness 命令一样在斜杠菜单里插入可编辑的草稿，运行中保留禁用行；运行中手动发出时输入框上方写 Host 的拒绝「/compact 不能排队或追加，请等本轮结束后发送。」，草稿留着。

**清空上下文。** 输入框的 `/clear`（斜杠菜单的「Latch」分组，选中后清空输入）与会话菜单的「清空上下文」都只在本设备上选定下一条消息开始新的上下文，不发请求：输入框上方出一个抽屉，橡皮擦图标与「下一条消息开始新的上下文」，右侧「保留上下文」撤销；会话菜单里同一项这时写「保留上下文」。选定后点最新一轮的「重试」，重发的这一轮也在新的上下文里。运行中这一项不可选，写「这一轮结束后才能清空上下文」；一轮开始时选择撤掉、抽屉收起。Harness 不支持时两处都不出现。清空上下文的那条消息被拒绝而 Agent 已放下旧的会话时（Host 的 `contextCleared`），抽屉写「上下文已清空」，没有「保留上下文」，`/clear` 与菜单项也不出现，下一条消息发出后抽屉收起。iPhone 在输入框上方写同样两句，对话里同样画「清空了上下文」的线，但还不能自己选清空上下文。

**说明。** 会话里的系统说明是一行提示墨色的记录；报告失败（模型服务出错、运行被中断）时与失败的工作行画法相同：红色叉号、红字、「重试」。

**回到最新。** 读者离开最新输出时，会话区最下面 40 的一条里（输入框正上方）居中出现 32 高的胶囊（上移 8px 淡入，`--m-enter`；回到底部时以 70% 的时长淡出），写「↓ 回到最新」，离开后有新块到达时写「↓ 3 条新内容」；它显示时会话内容在这一条里淡出，不压在文字或行上。有等你允许的请求、而它的卡片不在视野里时，这个位置变成琥珀字的「等你处理 ↓」，点它滚到那张卡片，不在视野里才出现；读者上翻时有问题等你回答，同样写「等你处理 ↓」。块数按会话计，切换会话不算新内容。

**计划。** Harness 报告计划时，最新一轮的作者行下有一行工作「计划 2/5 ›」，展开是步骤列表。步骤的标记是静止的：空心圆、带点的圆（进行中，正文墨色与 500 字重）与对勾，已完成的步骤最淡；会话停下后，进行中的那一步读作未完成；步骤状态变化时标记交叉淡化。

**运行条与输入框。** 运行中输入框仍可编辑（占位写「可以先写，本轮结束后发送…」），但需等本轮结束才能发送；普通空输入只写「想让 Agent 做什么？」或聊天的「写下问题或想法…」，Agent 话题写收件人；不在占位重复文件权限和命令说明。使用 @ 时再显示实际文件访问限制。等待回答、未知提交、停止接收输入和只读状态仍显示各自原因。运行条只在一次停止的结果未知时出现在输入框顶部（高度随展开动效变化）：停止结果尚未确认时「尚未确认 · 重试」，这是唯一说它的地方：结果未知不是失败，不出红色提示，顶栏与侧栏也不说「正在取消」；以及计划小块。每张等待中的卡片用 IntersectionObserver 报告自己是否在对话滚动区里露出，运行条只读这一个结果。运行在做什么、做了多久由对话里最新一轮的活的一行说，运行条不再写。停止键是浮起的圆、`--line-strong` 的边与实心方块，停止不是风险操作，不变红；停止进行中它转圈且不可按（`aria-disabled`），结果未知时仍是方块，再按一次就是再停止一次。等待提问时这一格也是停止键（退为中性填充），写了回答才换成发送，触屏上停止键留在发送旁边。运行开始或结束时，发送键与停止键在同一格里替换（从 90% 长到原大并淡入 120ms，只在页面看着它变化时）。输入框从一行开始，随内容按行长高，最多八行，高度过渡 120ms（量高度时先撤掉过渡、放回原高，再设新高度，所以从原来的高度开始走；减少动效时直接变化）。输入框浮在 `--sh-lift` 上（圆角 16），正文前是一个提示墨色的等宽「>」；聚焦时环换成 `--line-strong`，不变蓝：静止与聚焦的阴影是框上的两层，交叉淡化（进 `--m-micro`、出它的 70%），阴影本身不做动画；上方的卡（审批、提问、排队、清空上下文、选择项目继续）与输入框同宽，成一个物体：卡的下圆角与输入框的上圆角是 4，中间一条 3px 的接缝（`--joint`），几张卡之间也是；卡本身的颜色与内容不因接缝改变。发送是中性的墨色键（`--ink` 底、`--canvas` 字），一屏唯一的蓝色主动作留给等你的那个决定；没有内容时退为淡色填充，仍可聚焦，提示框写出原因（「输入内容后发送」，或不能发起的原因），可用时提示框写出快捷键；发送中箭头与转圈交叉替换。这台设备只能查看时（完全访问会话在执行端以外的设备上，或没有发起权限），输入框换成虚线框、凹陷底，里面是锁与原因；运行条与停止键保留。不再接受输入的会话同样如此。模型或思考的切换从下一条消息起生效，触发器写「下一条：…」，菜单脚部第一行是「撤销切换，继续使用 …」；Agent 自己报告的模型与思考选项也在工具栏里，其他选项在页脚的「⋯」里（手机在输入框下面一行）；会话不再接受输入时，它们的当前值与原因写在标题行项目的弹层里（手机与没有项目弹层的会话写在启动面板下）。桌面 Enter 发送、Shift+Enter 换行；触屏设备 Enter 换行；⌘/Ctrl+Enter 总是发送；输入法组字时不会发送。

**状态行。** 输入框的最后一行（[ComposerStatus.tsx](../apps/web/src/composer/ComposerStatus.tsx)）：一条淡底的带（`--band`，上缘一条细线），12/16 提示墨色、等宽数字，值用等宽字；段之间是细竖线。左边是会话在哪、模型走哪条路：文件夹（会话写项目名或文件夹名，草稿只写项目名、不写路径；Git 项目的草稿这一段就是「当前文件夹 / 新工作树」的选值）、分支（只用 Host 摘要；工作树的会话写「工作树 · <分支>」，草稿选了新工作树时写起点「从 main 的 3f2a1c9」；提示框写全名）、路（经服务的会话写「<服务名> · 经 Latch」，服务停用或删除时用模型菜单的同一套字；用 Harness 自己的模型时写 Harness 与模型的真实名称，与模型菜单一致（「Codex · GPT-5.5」，没报告模型时只写 Harness）；Latch 内置不写）。右边是用了多少，只写报告了的：上下文「已用 / 总量」带 12 格的计量（`Meter`，两个数都报告了才画格子，只报告了已用时只写数）；输入、输出（Harness 拥有模型时写「由 <Harness> 报告」，一轮结束时才报告，所以第一轮运行中没有）；Harness 报告的费用，总带「由 <Harness> 报告，不是账单」；结算了的各轮用时合计与轮数。用量 / 上限与金额是第 3 步，尚未实现。这些数字与标题行的项目弹层、右侧面板读同一个函数（[sessionTotals.ts](../apps/web/src/composer/sessionTotals.ts)）。放不下时依次收起用时、输入输出、费用、路；文件夹与分支先按全名（最宽 200，工作树 320）量，仍放不下才以省略号截断；上下文留到最后。手机上只有上下文一段，而且只在两个数都有时出现。

**Harness 额度。** Harness 自己报告了订阅额度时（[HARNESSES.md](HARNESSES.md#额度)），输入框的控件之后、发送之前多一个小片（它晚几秒才出现，Host 重启后又消失，所以排在最后：来去都不挪动 Harness、模型、思考与权限；手机上在那一行选项的末尾）（[HarnessQuota.tsx](../apps/web/src/composer/HarnessQuota.tsx)）：14 的环（2 线宽，`--track` 上画 `--meter`）加用得最多的那个窗口的百分比，等宽数字。80% 以下是墨色；80% 起环是 `--amber-icon`、数字是 `--amber`；到上限都是 `--red`，数字一直在，颜色从不单独出现。悬停只有一行：「每周额度已用 68% · 5 天 23 小时后重置」，窗口的叫法与面板相同。点开是 296 宽的弹层（手机上是底部面板，标题「Codex 额度」）：每个窗口一行，名称（5 小时、每周、每周 · Opus、本期）在左、百分比在右，下面是 16 格的 `Meter`（格条只用墨色）与提示墨色的重置时间（一点没用、离重置还有一整个窗口的不写），最后一行是套餐、遮住的账号与大于零的余额。Harness 分组计量时（Antigravity），每组的窗口前有一行提示墨色的组名（「Gemini 模型」「Claude 与 GPT 模型」，是 Latch 自己的叫法），悬停那一行以组名开头。Harness 只给了警告而没有百分比时（Claude Agent），小片是警告图形加重置时间，只留较大的单位（「2 小时后重置」，悬停与面板里写到分钟），不画环，面板里这一行写「将用尽」或「已用尽」、没有格条。没有报告的 Harness、所有窗口都已重置、会话走模型服务时，什么都不画，也不写「不支持」。

**项目弹层。** 顶栏的项目按钮打开：分支、会话的每个文件夹（完整路径，这个 Agent 用不到的是提示墨色；这个文件夹已找不到或已移出项目时带标记；可复制，桌面端可在访达中显示），多文件夹时写出这个 Agent 实际用哪些；位于 Latch 程序目录内时的琥珀提示；上下文用量；整个会话的输入与输出（悬停写出各部分，外部 Harness 写「由 <Harness> 报告」）、Harness 报告的费用（注明「由 <Harness> 报告，不是账单」）、各轮用时合计与轮数、开始于。每轮的数字在回合脚部。

**设置。** 分区：通用、模型、Harness、项目、快捷键、关于，手机上另有插件与设备。模型、Harness、项目与插件需要「管理此 Host」权限，没有该权限的设备看不到它们。面板顶部是「搜索设置」（`/` 聚焦），按分区名和行上的词过滤。页面标题在标题行，内容最宽 640，组与组之间 32；组名是提示墨色的小字（12/16·500，与行同在 16 的内边距上），下面的行放在一口井里（`--sunken` 加 `--sh-well`，圆角 12，行在 16 的内边距上，行之间是细线），没有描边。

- 通用：外观是三张小窗口（跟随系统、浅色、深色）；发送消息是分段控件，自动打开新文档是开关，这两行手机上不显示；桌面端另有通知（完成或需要我处理时、通知中显示标题）。这一组在这台 Mac 上的 Latch 里叫「这台 Mac」，其他设备上写电脑名；写名称，这台 Mac 上的 Latch 有「有任务时保持 Mac 唤醒」，打包后的应用另有「登录时打开 Latch」（开发运行时主进程报告不可用，这一行不出现）。Host 停止时的启动入口在连接横幅。
- 模型：「模型服务」每行是磁贴、名称（本地与默认是小字）、模型数、状态与 ⋯。状态来自这次打开页面时的模型列表请求（不消耗 tokens），不从是否存了密钥推断：回答了写「已连接」，拒绝密钥写红色「密钥无效」与「更新密钥」，连不上写红色「连不上」，服务不提供列表时什么都不写；还在问时写「检测中」。缺密钥与地址未确认是琥珀字。其他设备上「更新密钥」保持可见但不可用，提示写明去处。⋯ 里有编辑、更新密钥、刷新模型列表、移除。「添加模型服务」是 480 宽的面板：品牌网格（末项「自定义地址…」）、地址、密钥、检测连接，找到的模型是一列开关（12 个以内默认全开），也能手动加模型 ID；保存按钮写「保存」，地址要确认时写「用 Touch ID 保存」。新会话卡片、模型菜单与这里打开的是同一张表单（[ProvidersSettings.tsx](../apps/web/src/settings/ProvidersSettings.tsx) 的 `ProviderAddForm`），标题、末项、字段名（「地址」「密钥」，报错里也是）与保存字都相同，只有外框不同。其他设备上送人去 Mac 的句子写出电脑名（`computerName`），前面是锁。服务页的「密钥」组下是带锁的「只存在这台 Mac 上」，不发给浏览器或手机收在 ⓘ 里；地址未确认与缺密钥是琥珀色的标题加一个按钮，确认后才发请求、本机与局域网地址同时放行收在 ⓘ 里；启用开关、移除与删除行不再带说明，后果在确认框里。模型的思考没设时写「思考：默认」，模型组下一行「思考按服务的文档设置」，规则在 ⓘ 里。「用量」是 7 或 30 天的总量与模型、输入、输出表，精确数字在提示里，不画图、不估价，下面一行「不是账单」。「显示的模型」是一列开关（六项起可搜索），只影响这台设备。
- Harness：「已安装」列出 Latch 内置、已添加且找得到程序的 Harness（状态词加启用开关，点开是启动方式、环境变量、检测与测试启动），以及找到了程序但还没有定义的预设（路径加「已找到」，只说有这个名字的可执行文件，不画成可用；点开是它的「自定义启动方式」）。「可以安装」列出没找到的预设和找不到程序的定义；预设行的「怎么装」展开安装命令、复制、「重新检测」与「自定义启动方式…」，Latch 不安装任何东西。Harness 列表下是带盾牌的「Harness 以你的权限运行」，外部 Harness 的页与添加表单下是「外部 Harness，Latch 不隔离」（`SETUP_COPY.externalNote`），它自己决定执行范围收在 ⓘ 里；环境变量组下是带锁的「只存在这台 Mac 上，不再显示」。添加只收录可在本机安装运行的程序：许可证可核对的开源程序，或厂商官方支持的命令（Claude Agent、Cursor，许可证一栏写明专有与条款），Latch 不替你安装。
- 项目：每行是图标、名称、「N 个文件夹 · 路径」（路径从中间省略）与 ⋯（重命名、添加文件夹、在访达中显示、编辑、移除）；点开编辑器管理名称、十种中性图标与有序文件夹。第一个是主文件夹；支持键盘上下移动、拖动排序、设为主文件夹、移除和对缺失文件夹重新选择。添加与重新选择只经桌面端原生面板。不可用项目与每个失效文件夹保留并写明原因；活动会话使用的文件夹不能移除。启动目录是同一列表里的一行。列表下一行「快照保留 20 轮，最多 2 GB」，Host 真实的上限与删除次序在 ⓘ 里。编辑器的文件夹组下是「读到的内容会发给模型服务」，各 Harness 的文件夹组下是「由各 Harness 自己执行，不隔离」，细节都在 ⓘ 里。
- 插件：按架子列出（工具、技能、连接），每行写已开启、未开启或需要处理；点开是这个插件的一页，开关在第一行；自定义插件应用过之后也有这个开关，不必打开编辑器。模型服务与 Harness 只在各自的设置页，这里不重复；一个人自己的包提供它们时仍算插件。内置插件写「始终开启」。
- 快捷键：分区名下是搜索，再下是可搜索的列表，只列当前平台的按键。
- 关于：图标、版本（开发版标记只在这里）、许可与条款（Latch 的开源许可，与每个 Harness 预设的许可证或条款）与带盾牌的一行「Harness 和插件以你的权限运行」，ⓘ 里写在哪台电脑上运行（其他设备上写电脑名）、Latch 不隔离它们。开发运行时版本下另有一行「其他程序可以修改 Latch 的代码」。
- 设备：见下。

**插件包界面。** 一个插件包可以同时提供技能、工具、界面与 Harness，只出现一次，能力按类别计数。「添加插件」只有两个起点：「新建工具」或「导入文件…」；技能与界面经导入文件来，「技能」架子照旧。编辑器与插件页都有一组「代码在哪里运行」，每部分一行：图标、名称和一个短标签，整句在 ⓘ 里：界面面板「每台能看会话的设备，不隔离」（在那台设备的 Latch 页面里运行，iPhone App 不运行它）；工具和后台代码「在这台 Mac 上运行，不隔离」（权限和 Latch 相同，也可以注册界面面板）；技能和静态面板「只是文字，不运行代码」。编辑器随表单里的声明变化，在高级声明里按正在输入的文字（能解析时）说；插件页说保存的声明与 Host 正在运行的能力的并集，因为后台代码可以注册声明里没有的面板，草稿也可能去掉已应用版本仍在发送的面板；读不到声明时说明并可重试。文字在 `securityCopy.ts`。确认句不变。会话面板的标题与来源可见，加载、失败、空内容各有实际状态，失败允许重试。React 面板可以实现自己的表单和交互；示例见 `examples/`。

## 设备与权限

桌面端「连接手机」一行的「显示二维码」只有一个动作：打开配对表单。表单约 420×540，显示二维码、带 Wi‑Fi 图标的「和这台 Mac 连同一个 Wi‑Fi」与信任的那一句，二维码每分钟无提示地换一张，手机确认时变暗、模糊并停住，设备名称升到它上面，写「在系统窗口中确认」或「正在连接…」（手机还没报出名称时也是后者，这时 Mac 上还没有确认窗口）。确认之后表单没有关闭按钮，连按 Esc 也不起作用（`Modal` 的 `dismissible={false}`），只问「手机上显示已连接了吗？」：「是的，完成」或「没有，移除」（直接移除，不再弹对话框）。取消、超时、两台设备扫同一个码与其他网络的尝试各写一行在新二维码上方，下一张二维码没能生成时这一行仍然留着；没有网络或被完全访问的会话拦下时不显示二维码，也不提示扫码，恢复后自动出现；打开时这台 Mac 不能确认的，能确认后自动生成。没有地址、端口、权限选择、倒计时或复制。防火墙提示与「发送到其他设备」尚未实现，不显示；页面读不到这台 Mac 有没有 Touch ID（没有时系统窗口要的是登录密码），所以这里只说「系统窗口」。「关于连接」说明首次配对需同一 Wi‑Fi，连接使用端到端加密。已配对的手机可以通过配置的自建中继继续连接。

界面按设备的权限隐藏或禁用操作，只是为了不展示做不到的事；每条规则都由 Host 再次执行。门控规则集中在 [permissions.ts](../apps/web/src/core/permissions.ts)。

**安全文案。** 这些错误文案集中在 [securityCopy.ts](../apps/web/src/core/securityCopy.ts)。

**连接页。** 未登记或凭据失效的浏览器在侧栏灰上看到一张安静的画布卡片（[EnrollmentPage.tsx](../apps/web/src/components/EnrollmentPage.tsx)，静止卡片的 12px 圆角）：标题「连接到 Latch」、一个短标签「在 Mac 上允许一次，之后直接打开」与一个主按钮「连接这个浏览器」，名称取自浏览器（「Mac 上的 Chrome」），按下才会弹出系统窗口。没有输入框、权限清单、校验码或倒计时；主按钮在 768px 起是 32px，手机上是 44px。链接允许管理这台 Mac 时（Host 经 `POST /link/api/enrollment-invitation` 回答，不用掉链接；只在回环上生效，桌面端的链接不含它，命令行的链接为没有桌面端的 Host 包含它），按钮上方一行琥珀色写「这个链接还可以管理这台 Mac」和「不要」，点后改成中性的「这个浏览器不会管理这台 Mac」和「还是要」；读不到回答时不显示这一行，也不申请。HTTPS 上的设备不申请，之后可以在设备页由 Mac 经本机确认开启。折叠的「连接详情」写名称、可以做的事与能看到的内容；等待时再加校验码与系统窗口的句子，校验码和 Mac 上「手机」页等待中的那一行（也在配对表单里，同样折叠）相同才是这台设备。经二维码的手机只有句子与权限：手机上没有校验码可比，它的核对是确认后的那一问。桌面端自己的第一次打开也是一张卡片：标题「Latch」、一句「第一次在这台 Mac 上打开 Latch。」与「继续」；这台 Host 还从未登记过设备时它不需要确认，之后桌面端再登记时写「用 Touch ID 继续」，名称取自这台 Mac（`enrollment-info` 只在 `host.sock` 上给 `hostName`），之后在「手机」页改；只有离线连接码的流程还有名称输入框，用 `TextField` 原语。提交后是「在 Mac 上确认」、「用 Touch ID 或登录密码允许」、折叠的「连接详情」与「取消」。Mac 上取消、超时与密钥不一致用红色提示；需要邀请的入口要求重新获取邀请。本机确认不可用时，桌面端开头写「用离线连接码连接」（不再提 Touch ID），琥珀色提示写出原因与 `pnpm latch device enroll --offline`，表单只接受离线连接码，Host 接受离线连接码时正常表单下方也提供「使用离线连接码」；浏览器与手机上的琥珀色提示说明新设备要在运行 Latch 的电脑上确认，主按钮停用，不提供离线连接码。没有链接时只显示去哪里取：手机指向桌面端 手机 › 连接手机，其他电脑要运行 Latch 的人发来的链接，不写终端命令；这台电脑上的浏览器指向桌面端「在浏览器中打开」或 `pnpm latch device invite --loopback`；打开已经失效的链接时当场说明；浏览器无法在当前地址安全保存设备密钥时只显示一行红色说明，建议换用新版浏览器或桌面端。旧版登录状态显示「这台设备要在 Mac 上重新确认」与「连接方式已更新」，并沿用旧设备名。撤销（红色）、满 30 天、换地址、丢失密钥、登记后浏览器没有保存凭据（例如禁止了 Cookie）与续期后浏览器没有保存新凭据（琥珀色）各有一行说明；后者建议允许 Cookie 后重新加载页面。设备名称可以包含表情（如「❤️ iPhone」「👨‍💻 Mac」）；含换行、不可见字符或改变文字方向的字符时，输入框下方用红色小字说明，提交按钮停用；旧设备名只在符合同一规则时沿用。登记完成后若第一次读取执行端状态失败，页面停在一行琥珀色提示与「重试」上，重试只重新读取状态，不会再登记一台设备。第一次连上 Host 之前，页面只显示「正在连接…」，失败时显示琥珀色提示与「重试」。

**新会话页。** 永远同一页：项目、输入框。没选项目时标题是「选择项目 ⌄」；列表依次是项目和「不选项目」，下面是「添加项目…」（只在这台 Mac 的应用里：系统面板选完立刻成为项目，被拒绝时列表重新打开并写 Host 的原因）与「管理项目…」；其他设备上页脚写「在 <电脑名> 上的 Latch 里添加项目」。「不选项目」对两类 Harness 用同一种句子：「Latch 内置 只回复文字，不读写文件」或「Codex 在一个新的空文件夹里开始」。选好后标题变成「rust-learn」，光标回到输入框。这里比只放按钮的首屏多一个输入框：人可以先写，按发送才问文件夹，草稿不丢，第二次按发送才开始。什么都不能运行时（[`nothingInstalled`](../apps/web/src/composerChoice.ts)，只在能保存定义的设备上）输入框上方是一张卡片：「没有找到可用的 Harness」、「先装一个：」每个预设一行安装命令与复制、「重新检测」和一行链接「改用 Latch 内置（只读写文件）…」（就地打开添加模型）；已经装了程序只差适配器时（`AgentPreset.agentCommand`）标题是「还差一步」，那一行写「找到 codex，还缺适配器」。这台 Mac 的应用里还没有任何会话、又找到了能运行命令的 Harness 时（[`listsFoundHarnesses`](../apps/web/src/composerChoice.ts)；「第一次」没有记录，只看有没有会话），输入框上方是「在这台 Mac 上找到 N 个 Harness」：找到的预设在前，每行写「已找到」与 Host 找到的路径（只表示有这个名字的可执行文件，Latch 没有运行它，所以不画「可以用」、不用绿色），只差适配器的 Codex 一行写那句话，其余折成一行「还可以装 N 个」；每行的「怎么装」只给命令、复制与「重新检测」，Latch 不安装任何东西。选 Latch 内置又没有模型服务时，「还没有模型服务。」那张卡接在它下面。产生第一个会话后它不再出现。手机的新会话面板里还没有这张卡。

**本机确认。** 只有这些操作要在这台 Mac 上确认：连接新设备、为设备增加权限、首次使用自定义或本机模型服务地址、把地址加入出站白名单、应用含代码的自定义插件。开始会话、放宽权限、批准操作、改 Harness 都不弹窗。按下后系统表单是唯一的窗口：发起的控件转圈，页面不重复表单里的句子；被取消或超时时一行原因留在原位。

**审批。** 审批在输入框上方的抽屉里决定（[ApprovalDrawer.tsx](../apps/web/src/composer/ApprovalDrawer.tsx)），会话记录里只留一行工具。卡与输入框同宽，用输入框的接缝连成一个物体；中性表面，琥珀只给标题前的一个点。标题就是要做的事和对象（工具的标题加对象，等宽）与改动行数，不写「等你处理」；下一行是提示墨色的工具 ID（与标题不同时总写出，因为标题可能是工具自己写的）、子 Agent 的名字、「查看改动」与「‹ 1/2 ›」翻页。只有普通的差异默认折叠在「查看改动」后，原地展开，不打开改动面板；高风险、Agent 的询问、没有差异的调用和隐藏字符的内容一开始就展开参数与原因。按钮在标题旁边、比工具栏大一号（md 32；手机 lg 44），顺序是「更多」·「拒绝」·「允许」：「更多」在每个宽度都叫这个名字（手机上是按钮下面的一整行，打开底部面板），里面是其余选择与「停止这一轮」。标题下面、与卡同宽的是其余要读的话：高风险的原因单独一行红字，后面是 Host 的原句（「这是高风险操作，每次执行前都需要你确认，不能设为始终允许。」）；外部 Harness 的询问是琥珀的短标签「拒绝只会转达，拦不住它」，ⓘ 后是「Harness 的询问只是提示：拒绝会转达给它，但不能阻止它执行其他操作。」；隐藏字符、原内容与这台设备不能允许的原因也在这里。手机上这些话排在按钮之前，参数与差异在按钮之后。按钮到位 320ms 后才接受按压；Enter 不决定，Esc 拒绝一次（有文字时不拒绝；打开的浮层先处理 Esc，已关闭但仍挂载的底部面板不阻止拒绝），⌘/Ctrl+Enter 只在焦点在卡里（不在输入框或菜单里）时允许 Latch 内置普通请求（或旧版 Host 的请求）的「允许一次」，从不允许高风险请求与 Agent 的询问。审批按钮不画数字或快捷键，也不预留隐藏键帽空间；焦点进入卡片不改变按钮宽度。有效的快捷键仍通过 aria-keyshortcuts 提供给辅助技术，数字操作写在快捷键帮助中。请求到达后在输入框打字时（[useRejectionNote.ts](../apps/web/src/composer/useRejectionNote.ts)）「拒绝」变成「拒绝并发送」，文字随拒绝交给模型，拒绝没有生效时文字回到输入框；Agent 的询问带不了文字，文字留作下一条消息。请求到达之前就写着的文字（[useEarlierDraft.ts](../apps/web/src/composer/useEarlierDraft.ts)）仍是下一条消息，不当作回答，清空后再写才算，问题的「其他…」也能认领它。文字发不出去（过长、含隐藏字符）时「拒绝」不受影响，直接拒绝并留下文字，只有按 Enter 才说明原因。结果未知时给「重试」，沿用同一 `requestId`。

**提问与排队。** Agent 的提问也在抽屉里：谁问、1/2、带数字键的选项、「其他…」把焦点交给输入框，那里写的就是这一题的回答。排队的消息在「排队」抽屉里编辑和移除；有文字且运行中时发送键变成「排队」。尚未实现：调整顺序、立即发送并打断（需要 Host 接口）。

**差异。** 折叠行只显示文件名、改动行数与展开控件，完整路径在提示与读屏名称中保留。展开后直接阅读改动，不常驻显示目录前缀、「新文件」或「新内容哈希」。Host 确认文件不存在时直接显示新增内容；文件存在但原文未能展示时保留琥珀色「原内容未显示」，没有说明时保留「原内容未知」，两者都说明可能覆盖已有内容且不显示删除行数。新增与删除行数仅在非零时使用相应色调。差异容器只有一层边框，代码区域不再套一张卡片。

`DiffView` 有三种模式。`hunks` 是默认：每段在 @@ 头下带符号与两列行号，审批提案必须这样完整呈现。`full` 用于审阅：一列行号、不画符号（3px 的色条表示增删）、标出改动的词、段之间是「N 行未改动」的带（每按一次展开 20 行），长行在代码区内横向滚动、页面向下滚动时文件头留在视野内；Host 或来源说明的新文件与已删除文件画成文件本身，不分栏。`compact` 是对话里的预览：没有头部，至多 12 行改动（新文件是前 8 行），每行截断在边缘，脚部写还剩多少。三种模式都照实说原内容未知或未显示，二进制文件不显示行数。`layout="split"` 时行内批注横跨两栏，两栏的行保持对齐。`gutter` 与 `annotation` 是留给评论的位置。目前工具卡、审批与文件历史都用 `hunks`，还没有页面使用 `full`、`compact` 与这两个位置。

**会话权限。** 只有完全访问会话在顶栏右侧显示琥珀色的「完全访问」状态词，前面是 `shield-alert`（手机上同样）；逐项询问（L1）是默认，顶栏不显示。输入框在以下情况换成带锁图标的只读说明（虚线 `--line-strong` 边的托盘，不带阴影，不像一个等待输入的输入框），运行条与停止按钮保留：Agent 定义变化、项目中的 Agent 配置在开始后变化、会话创建于安全升级之前，以及无法确认 Harness 已进入预期的权限模式为琥珀色，在这台设备的输入或选项修改被 Host 以对应错误码拒绝后出现。新会话选择器中的完全访问 Harness 带中性的 L3 小徽标（没被选中的选项不报警，选中后由顶栏的琥珀标记表达）。

**开发版标记。** Host 报告开发模式时（当前的构建都未经签名发布，所以总是如此），「设置 › 关于」在名称旁显示一个中性小标签「开发版」，悬停提示与读屏名称写明这台 Mac 上的程序可以修改 Latch 的代码。

[deviceRows.ts](../apps/web/src/settings/devices/deviceRows.ts)）在每个宽度都是一列，次序是设备、「连接新设备」、「关于连接」；点开一台设备，它是分区里的一页（宽窗口原地替换，名称与图标是页面标题；手机上推入）。设备组在这台 Mac 上叫「连到这台 Mac 的设备」，别处叫「设备」；没有设备时组里只有一行「还没有别的设备连接这台 Toast。需要处理的状态：三十天未验证写「只能查看，去手机上验证」，连接它的设备被移除后写「连接它的设备已移除」（恢复后能做什么在 ⓘ 里）并提供「恢复使用」（Mac 上经本机确认）。开关是安全界面（`data-secure`，开关原语在 security-devices.css 里钉住）：浏览器设备有「可以管理这台 Mac」与「可以看项目文件」（`dataScope` 在 `work` 与 **模型服务与 Agent。** 桌面端以外的设备不能输入或更换密钥（仍可移除），字段换成一行原因与去处，命令行替代 `pnpm latch provider set-key <id>` 只在没有本机确认的桌面端给出；已保存的密钥注明「密钥只发往 <源与路径>」，修改地址时提示会清空密钥；改到没有确认过的地址时保存按钮写「用 Touch ID 保存」，不另加一句。预置服务商地址的密钥直接保存，不弹确认；自定义与本机地址在桌面端确认一次（地址、密钥与出站许可一次确认），之后不再询问。已确认的地址在桌面端模型页列出（[ConfirmedAddresses.tsx](../apps/web/src/settings/ConfirmedAddresses.tsx)）：每行写出哪些服务在用、它带来的出站许可；移除要在对话框里说清后果，不要系统确认，因为只是收回，同一 `host:port` 没有其他地址在用时许可一起移除；不属于任何地址的许可也可以这样移除。没有桌面端时，在 Host 停止时从 `policy.json` 的 `confirmedAddresses` 移除，本机或局域网地址另外从 `hostEgressAllow` 移除，改动写入审计。已确认的地址出站许可被移除时，检测失败处给出「用 Touch ID 允许访问 <地址>」。添加 Agent，以及修改名称、启动命令、参数、环境变量与启用状态，任何能管理这台 Mac 的设备都可以做，不弹确认，每次改动写入审计；每个 Agent 标注中性的 L3 与许可证小徽标；未验证的定义在 Harness 行上就带中性小徽标「未验证的定义」并显示实际命令，不显示预设的说明，已验证的预设是默认，不加标记。程序不在这台 Mac 上的定义列在「可以安装」，不在「已安装」。

「登录」一组在「测试启动」之上，只在 Harness 有登录方式、状态或退出时出现：一行状态（「已登录」带 Agent 自己的标签与到期日，「还没登录」「已退出登录」「登录状态未知」），组标题右侧「重新检查」，没登录时下面列出登录方式（命令、复制、这台 Mac 上的「在终端里登录」），已登录时右侧是「退出登录」（Agent 能退出时，危险确认框）或「换账号」（展开登录方式）。下面的「测试启动」读到不同的登录状态时，这一组重新检查并跟着变；重新检查仍说已登录、最近一次测试启动却说还没登录时，标题是「登录可能已失效」，副行「测试启动说还没登录」，下面列出登录方式，「退出登录」照旧。登录方式只在这一组列出，「测试启动」里不重复。新会话上方，登录 10 天内到期时是一条琥珀色提示，不挡发送。

「在终端里登录」在 Latch 自己的终端里运行登录命令（[TERMINAL.md](TERMINAL.md#登录命令)）：会话里打开底部终端中以 Harness 命名的一个标签；设置与新会话的草稿里是一个 720 宽的对话框，标题是 Harness 的名字，终端画面 360 高，在一条细线框里的画布上，底栏左侧「你的账户，不是沙箱」，右侧「登录中」或「已退出 · 代码 N」与「关闭」。按钮旁用 12 图标和一个词说状态，不加说明句：转圈的「登录中」、对勾的「已登录」（只在 Harness 自己说已登录时）、红色的「失败」，Harness 说不出时是「已结束」。运行中关闭用红色确认框。

Agent 的「测试启动」沿用设置页的一组紧凑行：右侧一个 14 图标的次按钮，按下后不弹确认、直接运行，运行中按钮转圈、说明写「最多等待 20 秒。」，结果写「启动握手成功」「需要先登录」或「测试启动失败」。成功时明确写「登录状态与模型访问尚未验证」，能力只说 Agent 声明了什么；最近测试时间、程序名与版本用次级文字，不增加成功徽标；适配器驱动这个人自己装的程序时（Codex），两个版本写在一起，组合不在适配器构建时的范围内时下面一条琥珀提示「这个组合 Latch 没有核对过」与「仍可以开始会话」，可能的原因在 ⓘ 里，不阻止启动。组下一行「不发送提示词」，会运行程序、只检查启动握手在 ⓘ 里。失败时诊断用可换行、最多 240 高的等宽区域和「复制诊断」，隐藏字符仍由 VisibleText 标出。结果未知时提供同一次请求的重试。旧 Host 没有能力标记时隐藏这一组。列表同时显示最近测试、当前可见会话数与最近会话时间；未开启过会话的定义写「还没有开启过会话」，与仅做握手的诊断区分。

**旧版 Host。** 快照中没有 `host` 时，Host 来自升级前的构建：界面退回旧规则（普通的允许与拒绝、由旧的主设备身份决定设置），隐藏设备、邀请与本机确认相关的界面，并在消息区顶部显示一行中性提示「此 Host 仍是旧版本，重启 Host 后启用设备确认。」；未登录的浏览器在这样的 Host 上看到「此 Host 版本过旧，请在电脑上重启 Latch。」

**审计回滚。** 审计记录被回滚时显示红色横幅，可核对或关闭。

**界面出错。** 工作区渲染出错时不会整页空白：显示一张卡片「界面出错，当前内容无法显示。」，提供「回到新会话」与「重新加载」；本机确认对话框不受影响。单条回复渲染出错时，这一条按纯文本显示。

## 流式与阅读

| 情况 | 界面行为 |
| --- | --- |
| 等待首段输出 | 最新一轮的状态行写正在启动 Agent 或运行中；不伪造思考内容或百分比 |
| 推理到达 | 思考行写「思考中」与秒数（有标题时接「· 标题」），身体自动展开并跟随最新的推理 |
| 正文到达 | 在稳定身份的同一消息行内更新 Markdown，新到的文字约 180ms 内匀速露出（不逐字动画，减弱动效时整段出现），完成后沿用该行；思考行带高度过渡收起并写出思考用时 |
| 工具调度 | 工作行区分等待执行、等待确认、执行中、完成、失败、取消；运行中与失败的命令是块，收起时写工具报告的最后 5 个屏幕行；结束的命令是一行；展开后运行中的输出在自己的框里跟随最新的行 |
| 审批 | 合并在对应工具卡片内，展示原因、参数与预览；卡片写「等你处理」，回合里没有第二处说它，已运行时间停住 |
| 取消 | 请求中保留取消状态；超时显示"尚未确认"并允许重试（同一请求，不会停止之后开始的一轮）；要停止的一轮已经结束时立即退出取消状态，并用提示说明；部分回复保留，回合下留一行「已停止 · 保留了部分回复」（没有正文时只写「已停止」） |
| 结束 | 状态行消失，事实进入回合脚部；正常完成的回合把工作收成一行，正文不折叠 |
| 离线 | 保留已读内容；运行中的回合不再转圈或走时，侧栏的行写「上次确认 10:42」；标题栏只写连接状态，「重试」只在横幅里一个；恢复并同步后才显示已连接 |
| 上翻阅读 | 进入阅读模式，流式输出不夺走位置；命令结束、思考收起与分组合并时锚点不动；"回到最新"在输入框上方自己的一条里写「回到最新」或「N 条新内容」，点它恢复跟随 |
| 定位历史 | 六轮起在对话左边显示短刻度，当前轮次宽且亮。悬停或键盘聚焦显示最多三行正文摘录，点击、轻点或 Enter 跳到该轮。方向键移动焦点，Home 和 End 到两端，Esc 收起摘录。上层对话框和菜单有自己的 Esc 行为。触屏刻度有独立的 44px 命中区，轻点直接跳转 |
| 切换会话 | 阅读位置按会话保存；旧会话的异步结果不得写入当前会话；消息内容层淡入，带遮罩的滚动容器不做透明度动画（避免可见控件失去点击命中）；不播放消息到达的动效 |

对话正文的程序性滚动集中在 `useReadingPosition`（`jumpToLatest`、`reveal`）；消息与工具行使用 `data-message-id` 作为锚点。定位条只滚动自己的刻度列，读者浏览刻度期间保留该列的位置。布局改变、代码展开、展开块的动画与视口变化不等于用户主动滚动。思考与工具输出这类嵌套的滚动框用 `column-reverse` 从末尾排布来跟随最新内容，不写滚动位置。从改动面板定位到一个已折叠的工具时，页面先请折叠的祖先打开（与页内查找同一个 `beforematch` 路径），再交给 `reveal`。

Markdown 支持标题、列表、引用、表格、内联代码与代码块；回复里的原始 HTML 不执行：`<br>` 换行，注释不显示，`<details>` 与 `<summary>` 只留其中的文字并全部展开，其余句中的标签显示为文字、成块的显示为 HTML 代码块，文字不丢失；URL 只允许安全协议；只有网页与邮件地址是链接（加上回复自己的脚注），图片从不加载，网页图片显示为「外部图片：说明」链接；嵌套过深的回复以一行灰色说明加纯文本显示；表格与代码在自身容器内滚动；代码可复制与展开，剪贴板失败有明确提示；工具读取文件的输出按文件名着色；代码中的不可见字符显示为 `\u{XXXX}` 标记，工具栏注明「含不可见字符」，复制内容保持原样。实际点击的网页或邮件链接由桌面主进程直接交默认应用打开；脚本触发的外链另需确认。流式全文不设 `aria-live`，避免逐字播报。

**路径标记。** 回复里指向文件的链接（相对路径、`../`、绝对路径、`file://`，带 `:行` 的文件名也算）不是链接，是路径标记（[FileChip.tsx](../apps/web/src/components/FileChip.tsx)），点击从不让页面离开：中性的 `--hover` 小块（悬停、按下与菜单打开时 `--press`，圆角 4），前面是按扩展名选的 12 号文件类型图标（演示文稿、表格、图片、文档、代码、压缩包、文件夹，其他是普通文件），后面是链接自己的文字，文字就是路径或文件名时用等宽字。一行放不下时从路径的文件夹部分省略，文件名始终完整（`/Users/me/acme/…deck.pptx`），完整路径在提示里。在桌面端，看起来像路径的行内代码（`deck.pptx`、`src/app.ts:12`）在回复结束后、Host 确认它是会话文件夹里的文件时，也画成同样的标记，其余行内代码不变；完成的工具打开后，最上面一节「文件」列出它读写过、Host 确认存在的文件。文件图片（`![说明](chart.svg)`）是同样的标记：次级墨色的「图片」，然后是说明，最后是三级墨色的文件名；没有说明时只有文件名。每台设备上点击都打开同一种 260 宽的菜单（手机上是底部面板）：标题是文件名，然后是可做的动作，分隔线后是「复制路径」，底部一行写原因或去处。不在 Latch 桌面端时只有「复制路径」，底部带锁写「在运行 Latch 的 Mac 上用桌面端可以快速查看和打开。」；没有文件动作的旧桌面端写「重新启动 Latch 桌面端后，可以在这里快速查看和打开。」（info 图标）。复制后图标换成勾（120ms），读屏播报「已复制路径」。在桌面端的会话里，点击先问一次 Host（400ms 内有回答就直接带着结果打开，更慢时先写「正在检查…」；问的过程中再点同一个标记不会再问，双击的第二下不会关掉菜单），菜单只列 Host 允许的动作「快速查看」（仅 macOS）、「用默认应用打开」、「在 <编辑器> 中打开」（这台 Mac 的主窗口，找到编辑器时；还没选过时写「在编辑器中打开…」，先问一次用哪个，之后在「设置 › 通用 › 编辑器」更换）、「在访达中显示」（按平台叫「在资源管理器中显示」「在文件管理器中显示」），「复制路径」复制的是从会话文件夹算起的完整路径（不带行号），可以直接用于访达的「前往文件夹」或终端。不提供的动作直接不出现，原因写在菜单底部的一行，文案来自 `securityCopy.ts`：锁只用于 Latch 有意拒绝的情况（可能含密钥、Latch 的私有数据、不在会话的文件夹里、会话的文件夹已不在项目里、类型不放行或暂不快速查看、内容与扩展名不符），常显一个短标签，原因与去处在 ⓘ 后，例如「Latch 不直接打开」后是「网页和 SVG 用浏览器打开时可以联网；可以在访达中显示后自己打开。」，「不在会话的文件夹里」后是「Latch 不替你打开它。复制路径后，可以在访达中按 ⇧⌘G 前往。」；去处与说明用 info 图标（「这是文件夹；Latch 只在访达中显示项目的文件夹。」「重新启动 Host 后可以在这里打开文件。」）；没有成功的事用 alert（「找不到这个文件。」「没有找到能打开这个文件的应用。」「上一个操作还没有完成，请稍后再试。」）。成功不提示（访达、快速查看或应用本身就是反馈）；被拒绝或失败时菜单重新打开，底部写出原因。旧 Host 缺少文件预览能力时保留这一菜单；支持内容服务时，单击改为打开文件标签。

## 验收

UI 改动需要在桌面、平板、手机宽度检查真实渲染，覆盖正常、进行中、失败或等待状态，以及浅色与深色。`e2e/design.e2e.ts` 覆盖 320 / 375 / 414 / 768 / 1440px 的可达性、溢出与真实点击区域，包括开发版标记；`e2e/enrollment.e2e.ts` 在 1440×1000、768×1024、390×844 下截取连接页的表单、等待、拒绝、本机确认不可用与旧版重新确认，并检查连接页在注入的样式下不变；`e2e/permissions-ui.e2e.ts` 截取高风险审批与拒绝后的记录、拒绝时写下的说明、浏览器里完全访问会话的询问（桌面与手机）与权限漂移（含深色）；`e2e/visual.e2e.ts` 在 390×844、768×1024、1440×900 下以浅色与深色截取浏览器能到达的每个状态与原语总览页（`ui-gallery`），并可与上一次运行逐像素比较（见 [TESTING.md](TESTING.md#视觉截图)「视觉截图」）。原语的角色与名称、键盘、焦点、提示框、禁用与运行中、对话框的焦点限制与归还、手机上的底部面板、触屏命中区、减少动效，以及转圈的同一相位与离开视野时暂停、状态词与状态槽、只为亲眼看到的变化播放的一次性动效、动效令牌与减少动效，由 `packages/ui/test/` 在真实浏览器里检查（`pnpm test --project @latch/ui`）。截图写入被忽略提交的 `test-results/`，不包含任何凭据。桌面端才有的界面由 `e2e/desktop.e2e.ts`（`LATCH_ELECTRON_E2E=1`）覆盖并以浅色与深色截图：审批卡里的高风险审批、行内卡片（等待、没有执行与被完全访问会话挡住）、手机配对（未生成、二维码、过期与被运行中的会话挡住）以及桌面端可以回应的「仅提示」询问。浏览器尺寸模拟不等于 iOS/Android 真机的软键盘、后台挂起与读屏验收。

Electron 另截输入框与设置里的行内确认；自动化不会替代系统表单的人工验收。

从模型选择器添加模型服务时，预置服务和自定义地址都在同一个弹层内使用与设置页共用的表单：可手动填写模型 ID，自定义地址只确认一次；保存后关闭弹层并选中它的默认模型，按钮不另写「保存并使用」。有「管理」但不在这台 Mac 上的设备，两个外框的规则不同，这是有意保留的：设置页的对话框可以先不填密钥保存需要密钥的服务，等在 Mac 上填写；原地面板不打开这类服务（以及地址未确认的无密钥服务）的表单，只说去哪台电脑，因为从这里开始的会话用不了它。

## 工作台搜索与起步

### 首页专注输入

Code 总览点击消息输入区、写入第一个字符或使用新会话快捷键进入专注。自动聚焦时仍显示完整总览。两种布局移动同一个首页表单，保留草稿、附件、输入法组合、选区和已经打开的选择器。手机输入随可视视口，位置与底部控制各有一行，正文至少显示三行，发送和退出沿用触屏命中区。

宽度至少 768、高度至少 480 时，输入卡片由实际的起点移到终点，导航在卡片后淡出或淡入。含受保护决定的队列立即隐藏或显示，并同时切换交互保护。系统或设备减少动效时直接切换。

专注时工作台导航、列表与面板退出焦点顺序，保留当前会话和已打开的面板。人明确打开文件时退出专注，再显示文件面板。底部摘要显示实际待处理数与第一项，点击返回该请求详情。恢复总览时，原决定重新经过防误触等待，Esc 先关闭当前选择器再退出专注。权限撤回时直接回到总览，由原会话和审批权限决定可用操作。

会话切换保留原会话的未发送文字，返回相同会话 ID 才恢复；切到其他会话不带入。最多在内存保留二十份、合计 256,000 个 UTF-16 字符，优先保留最近使用的草稿，不写浏览器存储。提交确认后清除该会话缓存，换设备清空，撤回个人访问时清私有草稿。新建会话仍从空输入开始，未知提交继续复用原请求，不从草稿另发一次。

手机的列表搜索先显示标题匹配，再显示「内容中包含」的正文结果；其他宽度由命令面板搜索。正文请求防抖 300ms，旧查询在切换时取消；命中项保留原会话与消息身份，通过阅读位置控制器定位，短暂提示该行。归档视图提供批量恢复和删除，支持 Shift 范围选择，部分失败保留失败项供重试；删除前明确说明只删除记录。

⌘K（Windows/Linux 浏览器为 Ctrl K）打开命令面板（[palette/](../apps/web/src/palette)）：宽 576、距顶 12vh、最高 420、无模糊的薄遮罩。未输入时是「最近会话」与「命令」，有请求等你处理时命令里多一行跳转；输入后依次是「会话」「文件」「Agent」「设置」「命令」，「在消息中」总在最后。再按 ⌘K 收起。Esc 先清空输入、再退回上一层（「搜索项目文件」是一层，⌘P 直接进入），最后才关闭；页脚的字随之写「返回」或「关闭」。关闭后键盘回到输入框，除非刚运行的动作把焦点带走，或是触屏（不弹键盘）。回车打开的是看到的那一行：第一行一出现就按身份记住，迟到的结果或重新排序的会话不会换掉它，被推到视野外时跟过去；输入法组合期间回车不触发。「会话」最多二十行，多出时明说。关闭面板或查找条后，接着落下的 Esc（以及按住不放的 Esc）不会停止运行，也不会拒绝请求，要先停顿半秒或按过别的键。搜索进行中写「正在搜索消息…」，失败写「消息搜索失败：原因」，只有 Host 答完才写「消息里没有「…」」或「没有匹配结果」；结果不全时明说。危险动作只从其具体页面执行；缺少能力的旧 Host 不显示对应入口。文件检索只在 Host 声明能力、设备拥有完整文件数据范围且预览回调可用时出现。

⌘F 打开当前会话的查找条：宽 300，浮在对话右上角（距顶 10、距右 20），不挤压对话；匹配在会话最上方、滚动也无法移出条下时，内容下移到让出它为止。条已打开时再按回到输入框并选中文字。Enter/Shift Enter 切换、Esc 关闭并归还焦点；匹配用选区色，当前项更深。文字通过 CSS Highlight API 标记，不替换消息 DOM；搜索也覆盖尚未挂载的工具输出，只展开当前匹配所在的卡片；最多五百项，不为查找挂载全部输出。匹配的内外折叠经 `beforematch` 展开，滚动仍只由阅读位置控制器写入：当前项已在可读范围内就不滚动，否则放到视口三分之一处，长回答里的匹配同样如此。运行中新增的文字只更新计数，读者留在当前项：匹配按所在行与行内次序认定，前面多出匹配时序号跟着变，高亮不换。

快捷键只有一张表（[workbenchShortcuts.ts](../apps/web/src/workbenchShortcuts.ts)），命令面板、⌘/ 的浮层与设置 › 快捷键只显示当前客户端的按键，且只列已经实现的绑定。浏览器的 Alt 组合键在输入框里让给打字：键盘布局把它变成字符时（德语 Mac 的 ⌥5 是 [、⌥L 是 @，美式的 ⌥1 是 ¡），或是开始一个重音的死键，它就输入那个字符；离开输入框，或在 Alt 不改变字符的系统上，它才是快捷键。桌面端的 ⌘ 组合不打字，不受影响。⌘/（浏览器 Alt /）不离开会话：快捷键表作为对话框（880 宽，靠近窗口顶部）盖在会话上，会话照常运行；两列、不分组，焦点在标题行右侧的搜索里，Esc、点暗处或再按 ⌘/ 关上并把焦点还给输入框，脚部是「Esc 关闭」与去「设置 › 快捷键」的链接。手机上没有浮层也没有这一页。

尚未准备的本机 Host 在有管理与运行权限的桌面窗口显示「准备这台电脑」。页面内从上到下是 Harness 和模型、项目和已有会话、可选的手机连接。模型与 Harness 沿用原来的添加及本机确认，项目经系统选择器保存，已有会话经其 ACP 适配器列出、预览与逐条接入。可用组合显示中性对勾，已经找到但尚未启用的 Harness 只写「已找到」，原生登录从 Host 的实情读回。使用已确认且兼容的网关模型不等待原生登录。底部在可用组合就绪时提供「开始使用 Latch」，「稍后配置」独立记录暂缓，已配置安装直接进工作台。可以从「设置 › 通用」打开准备页。三类操作各自保存，结果未知时可以在原处核对或重试原请求。

真实模式的工作台提供只填草稿的任务灵感，演示模式仍使用标明演示的示例。桌面端首次后台任务完成后，仅在前台显示一次「开启通知 / 暂不需要」。选择经主进程持久化，设置仍可更改。旧壳与普通浏览器不显示此入口。其他会话新增待处理请求时显示六秒内嵌提示。侧栏悬停或键盘聚焦时可点「下一个」，与桌面端 ⌥⌘A、浏览器 Alt Shift A 共用按时间排序的游标。

提示模板在通用设置中管理名称、正文与适用范围。模板列表只在版本变化时重读。命令面板可切换侧栏、右侧面板、文件标签与外观，打开设备实际可用的设置分区并导出当前会话；缺少权限或能力时不列入口。桌面端导航为 ⌘N、⌘B、⇧⌘[ / ⇧⌘]、⌘1–⌘9（跳到侧栏按屏幕顺序的第 N 个会话，超出不动）、⌥⌘1–⌥⌘4（打开输入框的 Harness、模型、思考、权限控件，只打开菜单、不选值，控件不在、被禁用或在手机宽度时什么都不做）、⌘/、⌘L（聚焦输入）；浏览器使用对应 Alt 组合（跳会话 Alt 1–9，控件 Alt Shift 1–4）。数字键在会话里总归应用，不会把 Mac 上 ⌥ 数字的字符打进草稿。空输入框 ↑ 取回上一条用户消息；输入框连续两次 Esc 取消当前运行，单次不清草稿，输入法组合期间不触发。文件快捷键由具备能力的宿主处理：⇧⌘E / Alt Shift E 在没有文件标签时打开文件树，否则轮换已有标签。

模型选择器在超过八项时提供模糊文字搜索，按字符顺序容忍名称中的标点。最近五次选择单列在「最近使用」，其他分组不重复它们；已经移除的模型不在最近列表中恢复显示。通用设置中的模型列表开关只影响这台设备，隐藏不关闭模型服务。当前已选模型保持可见，切换之后才从普通列表隐藏；选择器可展开隐藏项。用量提供最近七天与三十天，以实际记录的 tokens 为准，细分缺失如实说明，表格在窄屏内横向滚动。

保存的项目常驻侧栏，桌面端的底行有「添加项目」，打开系统文件夹面板，选中后立即建好。项目组菜单可原地重命名、用原生面板添加文件夹，并进入编辑器；分组按记录的项目身份，旧会话才按最深主目录回退。没有项目的会话在「无项目」中，自己的专用文件夹从标题行的文件夹图标打开，桌面端在会话菜单里通过主进程签名的会话 ID「存为项目」。从组内新建优先使用该组，普通新建继承当前项目，「无项目」的 + 选好「不选项目」。不选项目时 Latch 内置只回复文字：项目行写「不读写文件，不运行命令」，权限位置写「不读写文件」；其他 Harness 写「在一个新的空文件夹里开始」。没有单独的开关。新会话选择器保留不可用项目及原因，显示多文件夹摘要与 Agent 的数量上限，使用主文件夹的 Agent 在输入区下说明实际范围。标题行项目的弹层（手机与没有这个弹层的会话写在启动面板下）显示开始时记录的所有文件夹，标记已移出项目、找不到或未传给 Agent 的文件夹，并提供可用的显示与复制操作。

文件标签的内容头是 36 高的一行：面包屑（每一级文件夹连同它后面的箭头是一个菜单，列出这一级的文件，打开时才读取；文件名最后才被省略），右侧是「源码」（Markdown、CSV、HTML、SVG）、「引用到对话」、桌面端的「在访达中显示」与「用默认应用打开」，以及「⋯」。「⋯」里先是渲染器自己的选项（查找、自动换行、复制文件内容、CSV 分隔符、显示修订、适应宽度、运行页面脚本、复制选区、冻结首行首列），后面是在 <编辑器> 中打开（带当前行）、快速查看、查看改动、复制路径、下载文件、更新预览。文件树的行菜单与「改动」里文件行的操作同样有「在 <编辑器> 中打开」。正文不写文件大小与免责说明。「引用到对话」引用选中的内容；文档没有选区时引用当前页，文本没有选区时把文件作为引用放进输入框。打开的 PPTX 是一列幻灯片，每张上方写「3 / 12」与可展开的备注。文档默认半窗、最小 480px；文本、代码与图片记住独立内容列宽度，默认 320px、最小 280px。手机和平板窄屏推入一页。文件变化、已删除、秘密、超限与权限失效都有文字状态，读取失败可重试。会话及选中项目按上下文记住最多六个文件标签，不保存字节。文本有行号与分页，查找与跳行在 ⌘F 或「⋯」打开的一行里；文档保留自己的内容排版，外壳使用 UI 令牌。细节见 [DOCUMENT-PREVIEWS.md](DOCUMENT-PREVIEWS.md)。

### 从轮次分叉

已结束轮次的更多菜单提供「从这里分叉」与「复制到这里为止的记录」。分叉进入新会话设置，预选项目和 Agent，二者可改，输入可编辑；说明文件不复制或回滚，同一项目会话共用文件夹。模型、思考与权限档沿用来源会话的（见 [HARNESSES.md](HARNESSES.md)「权限菜单」的「默认」），没能沿用的在这条说明下每条一行。首条消息的 Host 上下文默认折叠，展开内容按纯文本显示，保留隐藏字符提示；Harness 用自己的记录分叉时（pi）首条消息只写一行分叉图标加「pi 带着「…」的前 N 轮」，没有可展开的文字，因为文字没有发给它；分叉到这样的 Harness 时，草稿的分叉说明下多一行它会用自己的记录分叉、做不到时以文字带上；环境块的「分叉自」可以返回来源。没有 `catalog.features.fork` 的 Host 不出现分叉入口，查看设备仍可复制记录。

代码使用八个 `--syn-*` 角色令牌：正文、关键字、字符串、注释、数字、函数、常量和标点。关键字以 600 字重辅助识别；颜色保持低彩度墨色，不复用动作蓝、警告琥珀、风险红或差异绿。深浅主题均核对 OKLCH 彩度不超过 .06，且在 pane 与 sunken 背景上的对比度至少 4.5；注释有意更淡，至少 3。安全区域同样锁定这些令牌。

### 后续输入托盘

支持排队的 Host 上，运行中草稿非空时发送槽显示箭头，提示「本轮完成后发送」，停止移到左侧；草稿为空时仍只显示停止。托盘在输入框内部、运行信息下方，用折叠原语展开，行上可编辑或移除。多行编辑使用表单对话框，保留正常草稿。暂停项写 Host 原因并提供明确发送按钮；失去权限的项显示未发送，不承诺自动继续。远程完全访问会话可以查看托盘，有 run 时仍可移除，没有编辑或继续入口。消息时间提示附排队时间；结果未知沿用原请求标识并保留待确认项。

### Agent 提问卡

内置 Agent 的提问显示在对应工具行的位置，用琥珀「等你回答」标记。多题向导显示题号、上一题与下一题，支持单选、多选和「其他…」；提交要求每题有效，其他答案非空。草稿仅保存在本设备，提交中锁定选择，结果未知时保留同一回答供重试。已提交的结果折叠为「已回答 N 题」，展开可核对选择，随后显示模型继续的回复。缺少功能标记的旧 Host 保留普通工具展示。

### 附件与显式文件引用

附件用输入框工具栏的单个文件按钮添加。图片经 Host 确认后显示 104px 缩略图，移除按钮独立放在右上角；文字文件是紧凑卡片，名称与大小分两行，上传比例使用中性墨色。卡片横向排列，窄屏内部滚动；点击图片看大图，点击文件看有界内容。取消发送保留文字与文件；长粘贴折叠成可编辑文字附件。已提交图片进入视野后读取缩略图，点击仍打开统一文件列；新会话的草稿只在输入框预览。独立的 `@` 用与 Slash 共用的 Suggest 打开项目文件选择，结果表明相对路径与文件夹 ID。每次打开裸 `@` 都从未选中开始，方向键选择，Tab 或 Enter 补入文件标记。输入查询后默认选择第一条结果。普通邮件地址保持文字。模型图片能力由模型设置中的显式开关表示。


### 发送中的消息

支持消息身份的 Host 上，提交文字立即出现在本设备的消息位置，500ms 后才写「发送中…」。确认的消息取代临时投影，不重复追加。结果未知写「未确认送达」，可原样重试；输入框上方的琥珀卡片在文字下写出最近一次重试为什么仍未确认（ⓘ 里是放弃的后果），次按钮「放弃这次提交」把文字放回输入框（另一个窗口正在重试时，按钮换成一句静音的「另一个窗口正在重试」；会话队列里有同样文字的一项时，按钮前另有一句静音的「队列里有同样的一条在等待」或「…已暂停」，放弃仍在）；排队输入不显示气泡。临时状态只表示提交过程，不生成完成轮次或模型回复。
文件变化的范围、运行结算、可选插件契约与验证见 [运行期间的文件变化](FILE-OUTPUTS.md)。

右侧面板的「改动」页签见 [CHANGES.md](CHANGES.md)：一行放范围、合计与撤销（或没有撤销的原因），琥珀只给要留意的行，红色只在不能恢复的确认框里。文件树从 6 个文件起、差异还能留 560 宽时自己打开；差异列 760 宽起左右对照；路径放不下时整段丢掉前面的文件夹。

底部终端见 [TERMINAL.md](TERMINAL.md#界面)：里面一条「终端 1」「终端 2」…的标签条，行尾是本地服务的蓝字链接、「加入对话」与「+」；屏幕直接在画布上，字体与颜色取令牌，浅深两套；底部 28 高的一行写 shell 与文件夹、前台程序或「已退出 · 代码 N」与唯一的蓝色「重新打开」，右侧是「你的账户，不是沙箱」的提示。重新连接时是琥珀色的一行字，关闭运行中的终端用红色确认框。运行 Harness 登录命令的标签以 Harness 命名，没有「加入对话」与「重新打开」。

「交付」页签见 [GIT-DELIVERY.md](GIT-DELIVERY.md#界面)：顶部一行「暂存 › 提交 › 推送 › PR」，四组文件各带勾选框，脚部一个随状态变化的蓝色主按钮（暂存全部 → 提交 N 个文件 → 推送 → 创建 PR）。PR 一节的检查失败是红色的叉与「失败」，审阅要求修改与「旧提交」是琥珀，通过、跳过与进行中都是中性；「没有 gh」「gh 未登录」是琥珀的一行，终端命令在 ⓘ 里。红色只给钩子失败、远端拒绝等真实失败；没有远端、上游是另一个分支、Agent 正在改这个文件夹都是中性的一行；结果未知是中性的一行加问号图形与「重试同一请求」，不用琥珀；琥珀只给合并进行中与离线。手机上行高 44，页面没有横向滚动，到 320 宽仍可用。

审阅改动在「改动」标签，见 [CHANGES.md](CHANGES.md)。Host 不提供改动时，这一轮改动的文件打开它的工具差异记录，也可以从文件标签的「⋯ › 查看改动」进入；看不到项目文件的设备收不到差异正文，同一入口只打开本会话写出的文件：按文件夹与路径区分同名文件，可切换本轮与历史、行内与左右对照，已删除文件的记录仍保留。

文档预览保留当前文件的页码与适应状态；缩放使用键盘或双指，窄列收起页工具栏。自动打开新增文档为默认开启的本设备偏好，在 1024px 起的宽窗口上按右侧面板此时的位置打开（放得下对话时在旁边，否则盖在对话上），至少 480px，并保留输入焦点与草稿；手机只显示文件入口，用户可关闭自动展开，见 [文档预览](DOCUMENT-PREVIEWS.md)。

项目文件树按需出现在右侧文件区，窄屏沿用文件页。首次打开默认展开主根；目录按展开读取，长列表分批显示，隐藏项开关收进菜单。文件单击预览，菜单可复制相对路径或引用到草稿；新会话未发出消息时也能预览选中项目。文件搜索沿用命令面板和键盘导航，返回相同的文件列，不另开工作流。

项目编辑页的会话数是静态信息；「最近会话」另列当前设备快照中归属该项目的最近三条记录。归属复用项目分组规则，早先助手跑过的会话不会混入；打开入口返回同一工作台，权限撤回后撤下。


Slash 建议使用 `@latch/ui` 的 Suggest：优先贴输入卡片上沿，上方不足且下方更多时贴下沿，焦点留在输入框；桌面行高 32px、手机 44px，宽高与位置跟随可视视口（含缩放），内部滚动不移动输入卡片，隐藏或 inert 的输入卡片不保留建议。输入 `/` 时不预选，依次列最近、Harness 实际命令、技能、提示模板、Latch 动作；输入字符后按命令名、词首、拼音和描述筛选，不截掉后面的命令。最近只保存当前设备、来源与 Harness 下的命令标识，菜单最多显示 5 条，不保存参数、正文或路径；退出或更换设备时清除。

↑↓选择，Tab 补全；点击 Harness 命令只插入，Enter 对无参数命令走当前输入框唯一发送流程，有参数命令只补全并显示参数提示。模板把 `$ARGUMENTS` 留作可选中的占位内容。命令仍是普通 textarea 文字，视觉标记不改变发给 Host 的内容。Harness 报告的带冒号命令和其他 Harness 命令共用这一组及发送方式。技能只按当前 Harness 的真实目录显示原生调用名称，附简短来源；`$name` 在句中也可补全，pi 的 `/skill:name` 只在草稿开头出现，因为它只在首词展开。技能的点按、Tab 和 Enter 都只插入，不发送；同一 pi 技能不在 Harness 组重复列出。目录有界截断时明确显示「仅列出部分技能」，不把它写成完整目录。手机可直接在输入框写 `/` 打开建议。输入法组合期间不运行命令，问题回答与拒绝理由不启用 Slash。

新草稿中来自缓存的命令标记「上次会话」，Enter 也只补全，底部写「选择」；没有命中时写「开始会话后列出」，真实空报告写「上次会话没有列出命令」。来源、刷新与授权见 [HARNESSES.md](HARNESSES.md#会话命令)。

`/new` 与 `/fork` 只准备新草稿，不发送；离开未保存文件的确认完成后，才一次性消费来源草稿并写入目标草稿，期间目标或输入改变就拒绝旧操作。`/model` 可带搜索词，`/think` 与 `/permissions` 打开现有控件，`/changes` 打开已有改动入口，`/clear` 与 `/btw` 复用当前会话动作。命令面板共用这些动作，保留来源草稿。未知结果或正在提交时不能执行新动作；能力不足的动作给出简短原因，保留的 Latch 命令不会意外转发给 Harness。

iOS 的 `PhoneSlash` 与 Web 共用匹配向量，保留拼音首字母、UTF-16 选区和 200 条命令。会话、新会话及人物新话题使用同一个 UIKit 文本编辑器接入；建议列表在输入框上方，44pt 行可滚动，点按只改草稿，模板占位保留原生选区，参数提示不进入正文。硬件键盘只由当前第一响应者处理，marked text 组合期间不接管按键。模板由当前有效正文窗口读取，换电脑、换窗口或离页清除，迟到结果不回填；不新增窗口或持久化历史。

八个 Latch 名字在发送入口统一拦截，只打开页面已有的模型、思考、权限、改动、清空、新会话或分叉入口；人物聊天省去 Latch 的新会话入口。未提供的写「iPhone 尚未实现」，不转发给 Harness。未知提交保留原请求，拒绝理由不启用 Slash。发送在首次异步等待前固定电脑、会话及阅读代次，等待期间切换页面后不向新会话发送，也不清掉新页面的草稿。
