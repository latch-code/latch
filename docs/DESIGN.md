# Latch 界面设计

Latch 是跨设备的 Agent 工作台：任务在 Host 上运行，用户从桌面、浏览器或手机查看、审批、取消并继续同一段工作。界面要同时表达会话内容、执行状态、设备连接与设备权限，且只展示真实存在的能力。传输、续期与阅读位置的机制见 [STREAMING.md](./STREAMING.md)。

## 品牌与原则

- **名称与图标。** 名称为 Latch。应用图标是炭黑圆角方块、两片象牙色折面与一个橙色接点；`apps/web/public/icon.png`（512px）用于界面、窗口与主屏幕，`apps/web/public/favicon.png`（64px）用于浏览器标签，`build/icon.png` 是高分辨率源图。不要改动图形本身。
- **蓝白为主。** 白色工作面、slate 灰中性色、`#2563eb` 系蓝色。蓝色只用于"执行"：发送、批准、当前选择。图标是唯一的暖色元素；琥珀色只表示警告、待审批、等待本机确认与完全访问（L3），不使用图标的橙色表达状态。红色用于失败提示与真实风险：高风险（R2）审批、权限模式漂移、审计记录回滚与设备撤销；开发版等提示性状态不用红色。
- **内容优先。** 对话列是主角；导航安静，不使用大面积饱和色。
- **每个状态只出现一次，并出现在正确的位置。** 会话级状态在顶栏状态标签与侧栏图标；进行中的活动在附着于输入框的运行条；单步状态在工具卡片。
- **只展示真实能力。** 选择器只列出 Host 目录中真实的 Harness、模型与项目；只有一个选项时以只读标签显示。演示模型必须带琥珀色"演示"标记。不展示虚构的数量、进度或尚未实现的菜单。设备做不到的操作直接隐藏或停用并说明原因，不让用户提交后再失败。
- **默认隐藏内部细节。** 路径中段省略并提供复制；工具 ID 作为次要文字；空参数显示"无参数"。

## 设计令牌

全部颜色、字号、圆角、阴影、间距与动效集中在 [tokens.css](../apps/web/src/styles/tokens.css)。浅色在 `:root`；深色同时定义在 `@media (prefers-color-scheme: dark)`（仅当 `:root` 没有 `data-theme="light"`）与 `:root[data-theme="dark"]` 下。主题偏好（跟随系统 / 浅色 / 深色）按设备保存，写入根元素的 `data-theme`。登记、本机确认、设备与权限相关的样式在 [auth.css](../apps/web/src/styles/auth.css) 与 [security.css](../apps/web/src/styles/security.css)，只使用这些令牌。

| 类别 | 规则 |
| --- | --- |
| 颜色 | 背景 `--bg-app / pane / raised / sunken / hover / selected`；文字 `--text-1/2/3`（`--text-3` 是最浅的可读说明色）；`--accent*`；`--warn-* / ok-* / err-*`；差异 `--diff-*` |
| 字体 | `--font-sans` 为平台系统字体与中文字体；`--font-mono` 用于代码、参数、工具 ID、设备指纹、核对码与内容哈希 |
| 字号 | 最小 12px（`kbd` 与徽标可用 11px）；正文 15/26（手机 16/27）；只使用 400、500、600 三种字重 |
| 圆角 | 4 / 6 / 8 / 12 / 16 / 999 |
| 间距 | 4px 基准：4、8、12、16、20、24、32、40、48 |
| 阴影 | `--sh-1` 到 `--sh-4`，深色模式改用描边加深阴影 |
| 动效 | 120 / 180 / 240ms；尊重 `prefers-reduced-motion` |

深色模式不反转主色：按钮仍是 `#2563eb` 配白字。图标在深色背景上加 1px 浅色描边，避免炭黑方块消失。

## 布局

断点定义在 [breakpoints.ts](../apps/web/src/breakpoints.ts)，CSS 媒体查询使用相同数值。

| 宽度 | 结构 |
| --- | --- |
| ≥1280 桌面 | 侧栏 264px / 对话列 / 可选检查器 320px（打开状态按设备记忆）。消息列最大 760px 居中。 |
| 1024–1279 | 侧栏 + 对话列；检查器以右侧面板打开。 |
| 768–1023 平板 | 56px 图标栏；会话列表从左侧滑出。 |
| <768 手机 | 52px 顶栏（菜单、标题与状态、新建、更多）；会话抽屉；选择器、菜单、详情与本机确认使用底部面板；输入框贴底并留出安全区；触控目标至少 44px。 |

抽屉打开时主区域设为 `inert`，焦点限制在抽屉内，Esc 关闭后焦点回到打开按钮。对话框与底部面板同样捕获并恢复焦点。

## 组件

**侧栏。** 品牌行、中性色的"新建会话"、搜索（⌘K）、仅在存在审批时出现的"待批准"行、会话列表与底部设备区（设备名、连接状态、设备与设置入口）。会话分组为置顶、今天、昨天、过去 7 天、更早；筛选菜单包括对话、Agent 与已归档。每行一行高（触屏 44px），左侧是状态图标（运行中、待审批、失败、已取消），右侧是相对时间，悬停或 ⋯ 菜单提供重命名、置顶、归档、导出 Markdown、删除（需确认，运行中不可删除）。未读圆点按设备记录。

**新会话。** 居中的问候与输入框。输入框工具栏依次是 Harness、模型（仅当该 Harness 使用 Host 模型）、项目、模式（只显示 Harness 支持的模式）；手机上合并为一个"运行设置"面板。选择按设备记忆，并按 Host 当前目录修正。缺少可用模型或 Harness 时显示指向设置的引导卡片。演示模式下显示带"演示"标记的示例卡片。

**会话。** 顶栏左侧是标题与状态标签；右侧依次是连接标签（只在连接不正常时出现，点击同步；手机上只显示圆点）、会话权限级别、"Harness · 模型"、演示标记（"演示模型"，手机为"演示"）、检查器开关与更多菜单。用户消息为右侧气泡；助手回复为整宽内容，每轮显示一次来源行。思考过程默认折叠，只有模型真实报告时出现。连接中断或离线时，消息区顶部有一行琥珀色提示与「重试」。

**工具卡片。** 图标按工具类型区分；标题优先使用人类可读的说明，工具 ID 为等宽次要文字；右侧是状态。展开后显示"参数 / 变更 / 输出"，文件变更以统一差异视图展示。待审批时卡片展开为琥珀色审批区，按钮来自审批选项（手机为整宽 44px 按钮）。

**计划与用量。** Harness 报告计划时，在输入框上方显示带进度的计划卡片；检查器中也有完整列表。每条助手回复底部显示该步用量，检查器显示会话合计。

**运行条与输入框。** 运行中输入框仍可编辑，但需等本轮结束才能发送；运行条显示当前活动与耗时，并提供停止。有待审批时运行条变为琥珀色"N 项待批准 · 查看"。桌面 Enter 发送、Shift+Enter 换行；触屏设备 Enter 换行；⌘/Ctrl+Enter 总是发送；输入法组字时不会发送。

**设置。** 桌面为两栏页面，手机为逐级进入的页面。通用（主题、发送键，有「管理此 Host」权限的设备还有新会话默认值）；模型服务（列表与详情，从预设添加，已保存的密钥显示"已保存（不回显）"并提供更换与移除，不修改则保留；获取模型、手动添加、默认模型、检测连接）；Agent（ACP 预设、许可证、安装提示与检测状态，命令、参数与环境变量名）；项目（启动目录带「启动目录」标记；Host 本次启动时停用的项目仍在列表中，带琥珀色「不可用」标记与原因，并保留「移除」；新会话的项目选择器与默认值都不提供它；保存的默认项目被停用时，Host 让新会话改用默认工作区，默认值表单也显示默认工作区）；插件（按类型分组，受管理或使用中的开关附原因禁用）；设备；关于。模型服务、Agent、项目与插件需要「管理此 Host」权限；没有该权限的设备只看到通用、设备与关于。

## 设备与权限

界面按设备的权限隐藏或禁用操作，只是为了不展示做不到的事；每条规则都由 Host 再次执行。门控规则集中在 [permissions.ts](../apps/web/src/core/permissions.ts)。

**安全文案。** 这些错误文案集中在 [securityCopy.ts](../apps/web/src/core/securityCopy.ts)。

**登记页。** 未登记或凭据失效的浏览器看到一张安静的卡片（[EnrollmentPage.tsx](../apps/web/src/components/EnrollmentPage.tsx)）：标题「连接到 Latch」、说明、设备名称、权限清单与主按钮「请求本机确认」。浏览器的权限清单中，查看会话、发起和继续会话、批准普通操作为固定项，「管理此 Host」为复选框，不经配对邀请登记 Host 的第一台设备时默认勾选；桌面端在 `host.sock` 上登记，六项权限全部列为固定项，没有复选框。提交后进入等待状态：琥珀色脉冲点、「等待本机确认」、剩余秒数、一条琥珀色倒计时细线与「取消」；设备指纹是页面上唯一的大号文字（等宽、20 位、按 4 字符分组，手机上略小），下面是较小的核对码，便于和电脑上的确认窗口逐字比对。被拒绝、超时与指纹不一致用红色提示并可重新提交。本机确认不可用时，琥珀色提示写出原因与 `pnpm latch device enroll --offline`，表单只接受离线登记码；Host 接受离线登记码时，正常表单下方也提供「使用离线登记码」。手机等远程设备没有配对邀请时只显示获取邀请的说明；浏览器无法在当前地址安全保存设备密钥时只显示一行红色说明，建议换用新版浏览器或桌面端。旧版登录状态显示「此设备需要在本机重新确认」并沿用旧设备名。撤销（红色）、满 30 天、换地址、丢失密钥、登记后浏览器没有保存凭据（例如禁止了 Cookie）与续期后浏览器没有保存新凭据（琥珀色）各有一行说明；后者建议允许 Cookie 后重新加载页面。设备名称可以包含表情（如「❤️ iPhone」「👨‍💻 Mac」）；含换行、不可见字符或改变文字方向的字符时，输入框下方用红色小字说明，提交按钮停用；旧设备名只在符合同一规则时沿用。登记完成后若第一次读取执行端状态失败，页面停在一行琥珀色提示与「重试」上，重试只重新读取状态，不会再登记一台设备。第一次连上 Host 之前，页面只显示「正在连接执行端…」，失败时显示琥珀色提示与「重试」。

**本机确认对话框。** 高风险操作只能在运行 Latch 的电脑上确认。

**审批。** 审批区标题「需要你批准」旁有徽标：普通操作（中性）、高风险（红色，整张审批卡转为红色调）、提示，不是安全边界（琥珀色，完全访问会话的询问，并附一行说明：Harness 的询问只是提示，拒绝会转达给它，但不能阻止它执行其他操作）。Host 没有给出风险等级时按高风险决定按钮。按钮中拒绝类在前，「允许一次」在最后，且是唯一的蓝色主按钮。设备不能允许时，「允许」按钮不出现，按钮上方用带锁图标的一行说明原因（没有对应权限，或只能在执行端电脑的 Latch 桌面端批准或回应）；「拒绝」始终可用。桌面端批准高风险操作的按钮是「在本机确认后允许」；「本会话始终允许」只出现在普通操作上，完全访问会话的询问在桌面端只提供拒绝与允许一次。审批区里的标题、原因、参数、路径与差异把控制字符、改变显示方向的字符和零宽字符显示为琥珀底的 `\u{XXXX}` 标记，审批区顶部多一行说明，且没有任何允许按钮使用蓝色主按钮样式。决定之后：结果未知（网络中断、超时）时，输入框上方的红色提示附「可重试同一选择，不会重复提交。」；这台设备此前作了不同选择时提示「此设备此前已选择「…」，本次「…」未生效。」；已由其他设备处理或已失效时，以短暂提示显示「已由「设备名」处理」或「该审批已结束」。

**差异与内容哈希。** 差异文件名旁的标记按执行端的说明区分（[DiffView.tsx](../apps/web/src/components/DiffView.tsx)）：执行端确认文件不存在时为中性「新文件」；文件存在但原内容过大、是二进制或无法读取时为琥珀色「原内容未显示」；执行端没有说明时为琥珀色「原内容未知」。后两种在差异内和审批区顶部各有一行说明可能覆盖现有文件，差异不显示删除行数。差异展开后，文件名下方有一行灰色小字「新内容哈希」与等宽的 `xxxx-xxxx-xxxx-xxxx`，格式与本机确认窗口中的同名一行相同，便于核对审批区看到的内容就是确认窗口绑定的内容；哈希在渲染后计算，期间显示「计算中…」，页面没有 WebCrypto 或文本已被 Agent 截断时不显示这一行。

**会话权限。** 顶栏右侧显示「完全访问（L3）」（琥珀色；手机缩写为 L3）或「逐项询问（L1）」（中性；手机不显示）。检查器的「权限」行列出同样的级别徽标、权限模式变化后的红色「权限模式已变化」徽标，以及执行方、定义是否已验证、模式能否读回、是否请求审批与 Harness 的说明。输入框在以下情况换成带锁图标的只读说明，运行条与停止按钮保留：完全访问会话在执行端以外的设备上（「完全访问会话只接受执行端电脑上 Latch 桌面端的输入。此设备可以查看、拒绝和取消。」），或设备没有「发起和继续会话」权限。会话不再接受输入时，消息区顶部出现横幅并附「新建会话」，输入框换成「该会话不再接受输入。」：权限模式漂移为红色，来自会话状态；Agent 定义变化、项目中的 Agent 配置在确认后变化、会话创建于安全升级之前，以及无法确认 Harness 已进入预期的权限模式为琥珀色，在这台设备的输入或选项修改被 Host 以对应错误码拒绝后出现。新会话选择器中的完全访问 Harness 带琥珀色 L3 标记，在执行端以外的设备上禁用并注明「仅本机桌面端」；在桌面端选中时，输入框下方用琥珀色小字提示「开启完全访问会话需要本机确认。该会话可以读写 Latch 数据和 Host 身份私钥。」

**开发版标记。** Host 报告开发模式时（当前的构建都未经签名发布，所以总是如此），侧栏底部设备名旁（≥1024px）、图标栏底部（平板）或设置页标题栏（手机）显示一个中性小标签「开发版」，悬停提示与读屏名称为「开发模式：Host 代码可被本机修改」；「设置 › 设备」在「此设备」下写出整句说明：此版本未经签名发布，能修改本机文件的程序也能修改 Host 与桌面端。它不使用红色。

**设备设置。** 「此设备」（[DevicesSettings.tsx](../apps/web/src/settings/DevicesSettings.tsx)）：可修改的设备名称，以及连接方式、状态、设备指纹、权限与登记有效期，以细分隔线排列，末尾是「撤销此设备」。「已登记的设备」（需要「管理此 Host」）：每台设备一行，显示名称（当前设备带「本机」）、非正常状态的徽标（待复核（仅查看）与需重新确认为琥珀色，已撤销为红色并排在最后）、连接方式与最近使用（或撤销时间）、权限；其他未撤销的设备提供「权限…」（需重新确认的设备没有）与「撤销」。撤销前说明由它邀请配对的设备会降为仅查看，等待复核。「权限…」对话框中，「批准高风险操作」与「设置密钥」只对在执行端桌面端登记的设备提供；增加权限或恢复待复核的设备时按钮为「授予权限（需要本机确认）」，只能在执行端的桌面端进行，其他设备上按钮停用并说明原因；只收回权限时按钮为「保存权限」，任何管理设备都可以。设备名中的隐藏字符按审批区的规则显示为 `\u{XXXX}`，包括撤销确认与权限对话框里的名称；改名时的校验与登记页相同。「手机配对」：只有执行端桌面端的管理设备、且 Host 配置了 HTTPS 时显示「生成配对二维码」；二维码为 data URL 图片，10 分钟内有效、只能使用一次，附剩余时间、三步说明、复制链接（手机上为分享链接）与「重新生成」。其他情况只显示一行原因：没有 HTTPS 时说明启动参数，不在执行端桌面端时指向桌面端或 `pnpm latch device invite`。

**模型服务与 Agent。** 执行端以外的设备不能输入或更换密钥（仍可移除），字段显示锁定状态，已有服务的说明给出 `pnpm latch provider set-key <id>` 的替代方式；已保存的密钥注明「密钥只发往 <地址>」，修改地址时提示会清空密钥。Host 出站策略拒绝某个地址时，执行端桌面端的管理设备会看到一行琥珀色说明与「允许 Host 访问 <地址>（需要本机确认）」，确认后地址加入白名单并重新检测连接。添加 Agent 以及修改启动命令、参数与环境变量只能在执行端桌面端进行，名称与启用状态任何管理设备都可以改；每个 Agent 标注 L3、许可证与「已验证的预设 / 未验证的定义」。

**旧版 Host。** 快照中没有 `host` 时，Host 来自升级前的构建：界面退回旧规则（普通的允许与拒绝、由旧的主设备身份决定设置），隐藏设备、邀请与本机确认相关的界面，并在消息区顶部显示一行中性提示「此 Host 仍是旧版本，重启 Host 后启用设备确认。」；未登录的浏览器在这样的 Host 上看到「此 Host 版本过旧，请在电脑上重启 Latch。」

**审计回滚。** 审计记录被回滚时显示红色横幅，可核对或关闭。

**界面出错。** 工作区渲染出错时不会整页空白：显示一张卡片「界面出错，当前内容无法显示。」，提供「回到新会话」与「重新加载」；本机确认对话框不受影响。单条回复渲染出错时，这一条按纯文本显示。

## 流式与阅读

| 情况 | 界面行为 |
| --- | --- |
| 等待首段输出 | 运行条显示等待模型；不伪造思考内容或百分比 |
| 正文到达 | 在稳定身份的同一消息行内更新 Markdown，完成后沿用该行 |
| 工具调度 | 区分等待执行、等待确认、执行中、完成、失败、取消 |
| 审批 | 合并在对应工具卡片内，展示原因、参数与预览 |
| 取消 | 请求中保留取消状态；超时显示"尚未确认"并允许重试；部分回复保留 |
| 离线 | 保留已读内容；连接状态单独标注，恢复并同步后才显示已连接 |
| 上翻阅读 | 进入阅读模式，流式输出不夺走位置；"回到最新"恢复跟随 |
| 切换会话 | 阅读位置按会话保存；旧会话的异步结果不得写入当前会话 |

所有程序性滚动集中在 `useReadingPosition`（`jumpToLatest`、`reveal`）；消息与工具行使用 `data-message-id` 作为锚点。不要在组件中另外写入 `scrollTop` 或调用 `scrollIntoView`。布局改变、代码展开与视口变化不等于用户主动滚动。

Markdown 支持标题、列表、引用、表格、内联代码与代码块；原始 HTML 不执行，URL 只允许安全协议；图片从不加载，网页图片显示为「外部图片：说明」链接，其他图片只显示说明文字；嵌套过深的回复以一行灰色说明加纯文本显示；表格与代码在自身容器内滚动；代码可复制与展开，剪贴板失败有明确提示；代码中的不可见字符显示为 `\u{XXXX}` 标记，工具栏注明「含不可见字符」，复制内容保持原样。在桌面端，链接要在主进程的原生对话框中确认完整地址后才会在系统浏览器打开。流式全文不设 `aria-live`，避免逐字播报。

## 验收

UI 改动需要在桌面、平板、手机宽度检查真实渲染，覆盖正常、进行中、失败或等待状态，以及浅色与深色。`e2e/design.e2e.ts` 覆盖 320 / 375 / 414 / 768 / 1440px 的可达性、溢出与真实点击区域，包括开发版标记；`e2e/enrollment.e2e.ts` 在 1440×1000、768×1024、390×844 下截取登记页的表单、等待、拒绝、本机确认不可用与旧版重新确认；`e2e/permissions-ui.e2e.ts` 截取高风险审批、完全访问只读（桌面与手机）、权限漂移（含深色）与 Harness 选择器；`e2e/visual.e2e.ts` 在 390×844、768×1024、1440×900 下以浅色与深色截取浏览器能到达的每个状态，并可与上一次运行逐像素比较（见 [TESTING.md](TESTING.md#视觉截图)「视觉截图」）。截图写入被忽略提交的 `test-results/`，不包含任何凭据。本机确认对话框只在桌面端出现，由 `e2e/desktop.e2e.ts`（`HARNESS_ELECTRON_E2E=1`）覆盖并截图。浏览器尺寸模拟不等于 iOS/Android 真机的软键盘、后台挂起与读屏验收。
