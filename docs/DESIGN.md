# Latch 界面设计

Latch 是跨设备的 Agent 工作台：任务在 Host 上运行，用户从桌面、浏览器或手机查看、审批、取消并继续同一段工作。界面要同时表达会话内容、执行状态、设备连接与设备权限，且只展示真实存在的能力。传输、续期与阅读位置的机制见 [STREAMING.md](./STREAMING.md)。

日常发送保持相同入口，只有 Host 实际要求首次信任时才展开确认内容。连接手机的默认流程为开启、扫码和电脑允许；网络自动选择。原项目失效时保留可编辑草稿，并就地选择有效项目继续；模型切换结果未知时保留真实选中值，先读取结果，不自动重复写入。详细状态规则见 [项目恢复](./WORKSPACE-RECOVERY.md)、[模型配置](./MODEL-CONFIGURATION.md) 和 [按需加载](./CLIENT-LOADING.md)。

## 品牌与原则

- **名称与图标。** 名称为 Latch。应用图标是炭黑圆角方块、两片象牙色折面与一个橙色接点；`apps/web/public/icon.png`（512px）用于界面、窗口与主屏幕，`apps/web/public/favicon.png`（64px）用于浏览器标签，`build/icon.png` 是高分辨率源图。不要改动图形本身。图标是界面里唯一的暖色元素，不使用它的橙色表达状态。
- **简约、克制。** 蓝白为主：中性的近白与近黑，近黑的墨色文字；深色是近黑的底与柔和的白字，黑不是纯黑、白不是纯白。层次只靠几层平涂的表面（侧栏灰、画布、浮起、凹陷）、1px 的细线与墨色深浅，不靠装饰色、渐变、底纹、插画或表情；菜单、选值与对话框是最高的不透明面（弹层面），不用玻璃。控件按数据的形状选择，一种意思只用一种画法。
- **每种颜色只表达一件事。**

| 颜色 | 只用于 | 不用于 |
| --- | --- | --- |
| 蓝 | 执行动作的主按钮（发送、允许、请求连接），每个界面最多一个；被勾选的控件（开关的开、复选框、单选）；焦点环与选中文字的底；跳到别处的链接文字 | 运行中、计数与进度、图标、用户气泡、徽标；菜单里的对勾；列表的选中行（会话行、设置导航）；视图、筛选与外观的选中；切换按钮的「开」 |
| 琥珀 | 等你处理（等你允许、在系统窗口中确认，与等你处理的计数）；警告（连接中断、原内容未知、含不可见字符、已开启的完全访问会话）；演示标记 | 可按的按钮；普通信息；没被选中的选项与常驻的属性（菜单与列表里的完全访问 Harness、Agent 行的 L3） |
| 红 | 真实的失败与风险：高风险（R2）审批、失败、权限模式漂移、审计记录回滚、设备撤销、差异中的删除、危险操作的文字与确认对话框里的销毁按钮 | 完全访问、开发版、停止按钮 |
| 绿 | 差异中的新增；短暂的成功对勾（本机确认后的对勾） | 已连接、已就绪、已检测到、已验证这类默认状态；已保存、已启用这类本地操作的结果（值原位更新就是反馈） |
| 墨色 | 运行中与加载中的转圈、「运行中」与流式光标、未读的对勾、计数与进度、所有静止的图标、菜单里的对勾、列表的选中行（浅色是侧栏灰上的白色卡片，深色是一层柔和的白）、视图与外观的选中、切换按钮的「开」 | — |

- **默认状态安静。** 连接正常、逐项询问、已检测到、已验证的预设这类默认状态不用颜色，也不加标记；顶栏只在偏离默认时出现标记（连接异常、完全访问、演示），会话的状态与侧栏同一套词：运行中带计时，等你处理、没有动静、正在停止、失败与结束的方式，已完成不标；侧栏页脚不写「已连接」。风险色只在风险值真的被选中时出现。
- **内容优先。** 对话列是主角；导航安静，不使用大面积饱和色。只有用户自己的消息有气泡，且是中性的。
- **每个状态只出现一次，并出现在正确的位置。** 会话级状态在顶栏状态标签与侧栏图标；进行中的活动在最新一轮末尾的状态行；等你允许只在它自己的卡片上说一次，卡片不在视野里时由「回到最新」的位置带你回去；单步状态在它的工作行。
- **只展示真实能力。** 选择器只列出 Host 目录中真实的 Harness、模型与项目；只有一个选项时以只读标签显示。演示模型必须带琥珀色"演示"标记。不展示虚构的数量、进度或尚未实现的菜单。设备做不到的操作直接隐藏或停用并说明原因，不让用户提交后再失败。
- **默认隐藏内部细节。** 路径中段省略并提供复制；工具 ID 作为次要文字；空参数显示"无参数"。

自定义插件使用紧凑的列表与编辑对话框；列表先呈现名称、用途与状态，编辑器区分「未保存修改」「草稿」「有未应用修改」「已应用」「已停用」及真实不可用原因。技能正文直接编辑；文件与高级声明另设页签。只有应用执行主按钮使用蓝色。纯技能修改不出现系统确认，新的 Host 或界面模块代码经同一条行内确认流程。丢失响应时保留编辑内容并提供「重试同一请求」，不会创建第二份插件。启用与导出只对已保存状态操作。

早先的助手与群聊跑过的会话照常列在会话列表里，打开只能查看：输入框的位置是一行「这个会话来自已移除的 Agent，只能查看」，没有模型、权限等控件（手机相同）；本轮改动卡没有「撤销本轮」，改动面板在撤销的位置写「这个会话只能查看」，会话菜单没有「清空上下文」。

已有会话的未发送文字仅在当前工作台内存中按会话保存，最多二十条、合计 256000 个字符；切换只恢复目标会话的文字，不携带附件或文件引用。超出单条上限时保留当前输入并提示先复制。当前会话被其他设备删除时清空活动草稿，不能转入普通新会话；设备不再能读私有内容时，移除 Agent 会话的草稿。未知提交仍保留原请求编号。

## 设计令牌

令牌在 workspace 包 `@latch/ui` 的 [tokens.css](../packages/ui/src/tokens.css)，页面的样式入口 [index.css](../apps/web/src/styles/index.css) 第一行导入它。页面的每个颜色、阴影、字号与行高、间距、圆角与时长都只读这些令牌。[styles.test.ts](../apps/web/test/styles.test.ts) 检查：样式表只读已定义的令牌；颜色不写字面值（遮罩与配对二维码的白底除外，二维码在深色下也要深色模块配白底才能扫描）；字号与行高只用角色令牌，字重只有 400、500、600；内外边距与间隔不落在台阶之间；圆角只取台阶上的值（磁贴按边长 × 0.225 取整）。[tokens.test.ts](../packages/ui/test/tokens.test.ts) 核对两种主题的颜色与设计取值一致，退役的令牌名不再出现。

**主题。** 浅色写在 `:root`；深色重写每个含颜色的令牌，同时写在 `@media (prefers-color-scheme: dark)`（仅当根元素没有 `data-theme="light"`）与 `:root[data-theme="dark"]` 下，两份完全相同（tokens.test.ts）。只由其他令牌组成的令牌（`--surface`）只写一次，随主题变化。中性色是不带色相的灰：浅色是近白上的近黑墨，深色是近黑上的柔和白字；悬停与按下是黑（深色是白）加透明度，所以叠在任何表面上读起来都一样。主题偏好（跟随系统 / 浅色 / 深色）按设备保存，写入根元素的 `data-theme`。换主题不播放任何过渡：`switchTheme` 在改写前给根元素标 `data-theme-switching`，base.css 在这期间关掉所有过渡，两帧后再去掉；跟随系统时 `followSystemTheme` 对系统的切换做同样的事。浏览器的 `theme-color` 在每个宽度都取侧栏色（`--sidebar`）：768px 起画布嵌在侧栏色上，手机上会话列表与会话页的页头也在侧栏色上；`index.html` 按配色方案写成两条，选定主题时 `applyTheme` 改写它们（[styles.test.ts](../apps/web/test/styles.test.ts) 核对它们与令牌一致）。manifest 不分深浅，`theme_color` 与 `background_color` 都用浅色的侧栏色；桌面端窗口在首次绘制前的底色与它的错误页也用两种主题的侧栏色。主色在浅色是 `#2461E0`、深色是 `#2F6BE6`，悬停都更深一级（`#1D55CC`、`#2A62D6`），所以蓝底上的白字在两种主题里都至少 4.5:1；蓝色的字（链接）用 `--accent-ink`：浅色是比主色深一点的 `#1D52C4`，深色是更亮的 `#6B9BFA`，在每层表面以及叠在上面的悬停与按下上都至少 4.5:1。黑不是纯黑、白不是纯白：浅色正文 `#17171A`，深色正文 `#ECECEF`；只有浅色里地面以上的各层是纯白。深色下应用图标的炭黑方块会和侧栏融在一起，所以沿方块自己的边画一圈 1px 的环（`--app-ring`，浅色下透明）：图片四周有透明留白，环画在留白内侧方块的边上，不画在图片的方框上，图形本身不变。

**表面。** 都是平涂：令牌里没有渐变、底纹与带色相的底（tokens.test.ts）。表面分六级，由深到浅：凹陷 `--sunken`、地面 `--sidebar`、画布 `--canvas`、浮起 `--raised`、卡面 `--card`、弹层面 `--pop`；几乎不用线，层次靠阴影。地面 `--sidebar`（沿用旧名）由 base.css 画在根元素与 body 上，外壳、侧栏、图标栏、平板与手机的会话列表、手机的会话页头、设置导航与底部面板都用它（浅色 `#EBEBEF`，深色近黑 `#09090B`）；画布 `--canvas` 是工作面板（对话列与设置的分区内容），768px 起嵌在地面上；浮起 `--raised` 是输入框、菜单与弹层、对话框与 Toast；卡面 `--card` 是浮在面板上的卡（审批）；弹层面 `--pop` 是控件的面与卡上再浮起的一层；凹陷 `--sunken` 是井：代码块、命令输出、表头与搜索框，比它所在的表面更深。浅色里地面以上各层都是白色，靠阴影分开；深色里地面最暗，凹陷、画布、浮起、卡面、弹层面依次提亮（tokens.test.ts 核对这个顺序）。列表里被选中的行（侧栏的会话行、设置导航）是 `--selected` 加 `--selected-ring`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 的落影），深色是一层柔和的白；从不用蓝。所有墨在侧栏、画布、浮起、凹陷、卡面、弹层面、用户气泡与选中行上，以及叠在侧栏与画布上的悬停与按下上都达到 WCAG 对比度：正文 `--ink`、次级 `--ink-2` 与红字 4.5:1，提示墨色 `--muted` 与主色 3:1；提示墨色与琥珀字在它们常驻的画布、浮起、卡面与侧栏上是 4.5:1，提示墨色在悬停的行上也是，琥珀字在琥珀控件的悬停底上也是；琥珀图形 `--amber-icon` 在这些表面上至少 3:1。`tokens.test.ts` 逐项计算并核对这些下限；调整任何表面、选中或墨色的值都要通过它。

**层叠层。** tokens.css 第一行声明层的顺序：`tokens, base, ui, app, security`。`@latch/ui` 的 [ui.css](../packages/ui/src/ui.css) 把元素默认样式（[base.css](../packages/ui/src/base.css)：盒模型、文档字体与颜色、焦点环、按键、减少动效）导入 base，把每个原语的样式表（`packages/ui/src/styles/`）导入 ui；页面的 index.css 先导入 tokens.css 再导入 ui.css，然后把自己的每个样式表导入一个层：还没有做成原语的共用部件（`ui.css`：品牌图标、状态点、字母磁贴、进度条、表单字段与值选择 chip）也在 ui，页面自己的布局与界面在 app，登记、设备、权限与本机确认的样式（`auth.css`、`security.css`）在最上面的 security。后面的层总是胜过前面的层，与选择器的权重无关，所以页面可以在 app 层按位置调整原语，安全相关的界面不会被普通样式改写；新增的安全界面放进 security 层。

**安全界面的锁定。** 审批、登记、配对与确认带 `data-secure`，样式放 security 层。

| 类别 | 令牌 | 规则 |
| --- | --- | --- |
| 墨色 | `--ink`、`--ink-2`、`--muted`、`--faint` | 正文与标题 / 静止的正文与次级强调（侧栏行的标题、说明）/ 次级文字、元信息与静止的图标 / 占位符与时间这类最安静的字。禁用只有一种画法：整个控件降到 45% 不透明度，颜色不变；菜单里不可选的项只降图标、标题与说明，下面的原因行保持原色。前景透明度不是一档墨色，除隐藏、淡入淡出与禁用外不用（`styles.test.ts` 检查） |
| 表面 | `--sidebar`、`--canvas`、`--raised`、`--sunken`、`--card`、`--pop`、`--hover`、`--press`、`--selected`、`--selected-ring`、`--bubble`、`--glass`、`--scrim`、`--surface` | 见「表面」。`--bubble` 是用户消息的气泡；`--glass` 是浮起色的 88%，配 16px 模糊，原语不再用它（菜单与选值是 `--pop`），只剩页面里的个别浮层；`--scrim` 是模态的遮罩，配 4px 模糊；`--surface` 是元素下面那层表面（默认画布），状态点与计数用它镂空，放在别的表面上的容器把它改成那层表面 |
| 线 | `--line`、`--line-strong`、`--joint` | 一律 1px。`--line` 是静止容器的边与分隔线；`--line-strong` 是输入框、复选框与描边按钮的环，以及虚线框；`--joint` 是卡与它下面输入框之间 3px 的接缝 |
| 阴影 | `--sh-panel`、`--sh-lift`、`--sh-well`、`--sh-1`、`--sh-pop`、`--sh-dialog`、`--sh-accent`、`--sh-thumb`、`--sh-tip`、`--seg-on-shadow` | 层次用阴影画：`--sh-panel` 把工作面板从地面上托起，`--sh-lift` 把输入框与卡从面板上托起，`--sh-well` 把井压进它所在的表面，三者都自带一圈细环；`--sh-pop` 与 `--sh-dialog` 自带 1px `--line` 环；带这些阴影的元素不再加边；深色的阴影更深，浮层在顶部加一条内侧的亮线。`--sh-1` 给描边按钮与输入框（composer）；`--sh-lift` 也给菜单、弹层与 Toast；`--sh-pop` 给提示类的小浮层与「回到最新」；`--sh-dialog` 给对话框、底部面板与抽屉；`--sh-accent` 是主按钮的内侧高光与淡蓝落影；静止的行不带阴影 |
| 主色 | `--accent`、`--accent-hover`、`--accent-ink`、`--accent-soft`、`--on-accent` | `--accent` 是白字下面的蓝底（主按钮、发送）、焦点环与被勾选的控件，浅色 `#2461E0`、深色 `#2F6FEB`，悬停更深（`#1D53C8`、`#2A63D4`），白字在蓝底与悬停上都至少 4.5:1；蓝色的字（链接）只用 `--accent-ink`（浅色 `#215BD5`、深色 `#6B9BFA`），在每层表面上都至少 4.5:1；焦点环是非文字，3:1 即可；`--accent-soft` 只给焦点外晕与选中文字的底，没有其他蓝色的底 |
| 琥珀 | `--amber`、`--amber-icon`、`--amber-soft`、`--amber-line` | 只表示等你处理与警告：`--amber` 是文字，`--amber-icon` 是图形（盾牌、三角），琥珀永远落在中性表面上，不做底色：`--amber-soft` 只是琥珀控件（连接状态）的悬停底（叠在浮起上为 `#FCF5EB`、`#2C2622`），`--amber-line` 只是行内不可见字符标记的描边 |
| 红与绿 | `--red`、`--red-solid`、`--red-soft`、`--red-line`、`--green`；差异 `--diff-add`、`--diff-del`、`--diff-add-word`、`--diff-del-word`、`--diff-add-edge`、`--diff-del-edge` | `--red` 是失败与风险的文字与图形，`--red-solid` 只给确认对话框里的销毁按钮；`--green` 只给差异里的新增与短暂的成功对勾。差异只染行背景，文字保持 `--ink`，加减号与行数用色调文字；`--diff-add-edge`、`--diff-del-edge` 是增删行起首 2px 的边线 |

**动效。** 动效说明因果：短、安静、有物理感，没有空闲时的动画。五档时长各配一条曲线：`--m-micro` 120ms（悬停与按下的底、图标替换、状态词与标签页内容的交叉淡化；`cubic-bezier(.2, 0, 0, 1)`）、`--m-enter` 160ms（菜单、弹层与提示框从 98% 放大并淡入，消息与行的到达；`cubic-bezier(.2, .8, .2, 1)`）、`--m-panel` 200ms（侧栏收起、右侧面板的宽度、展开与折叠的网格行）、`--m-sheet` 260ms（对话框从 98.5% 放大并淡入、底部面板、平板的会话列表）、`--m-push` 320ms（手机的推入与返回）；后三档是同一条 `cubic-bezier(.32, .72, 0, 1)`。离开用进入时长的 70%，配退出曲线 `cubic-bezier(.4, 0, 1, 1)`。脚本里要按过渡计时的地方读 `MOTION`（`micro`、`enter`、`panel`、`sheet`、`push` 与各自的 `…Exit`）与 `EASING`，[motion.test.tsx](../packages/ui/test/motion.test.tsx) 核对它们与令牌相等。会循环的只有运行中的转圈、「正在思考」的光带、检测中磁贴的进度弧、加载骨架与流式光标；除流式光标外，它们离开视野时都暂停。减少动效（`prefers-reduced-motion: reduce`）时 tokens.css 把五档缩到 120ms 以内（micro 100ms，其余 120ms）；没有全局规则，每个样式表只保留它所移动之物的淡入淡出（不滑动、不缩放、不长高、不转动），原语的关键帧换成只有不透明度的版本，循环停在静帧。换主题时不播放任何过渡（见「主题」），拖拽中跟手的部分也不做过渡。

语义文字色除了满足现有对比度检查，还按 [Chromium 的色觉缺陷模拟矩阵](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/css/vision_deficiency.cc) 检查红、绿、蓝三类色觉缺陷。浅色与深色的蓝、琥珀、红、绿逐对转换到 OKLab，色差 `100 × ΔE` 至少为 3，用于防止近似同色；这不是可访问性合格的独立判据。状态始终同时带文字和图形。

## 布局

断点定义在 [breakpoints.ts](../apps/web/src/breakpoints.ts)，CSS 媒体查询使用相同数值；侧栏另在 1440px 处变宽。

| 宽度 | 结构 |
| --- | --- |
| ≥1024 桌面 | 52px 标题行横跨窗口；其下是从窗口左边开始的侧栏（默认 248px，可调宽与收起，见下）、主区域与右侧面板（默认 520px、未打开，放不下时换成浮层，见「右侧面板」）。窗口是地面 `--sidebar`；主区域是浮在地面上的工作面板（见下面「工作面板」），侧栏与标题行的侧栏一段直接在地面上，没有分隔线。对话栏宽 `--content-width`（800px）加两侧 `--gutter` 居中。 |
| 768–1023 平板 | 标题行不变；工作面板四边都留出 `--shell-inset`；侧栏是浮在左侧的一张侧栏灰，从标题行下开始（桌面端不盖住红绿灯），带浮层阴影与遮罩（`Scrim`），以 `--m-sheet` 滑入、它的 70% 滑出（减少动效时只淡入淡出）；设置与手机页保留 200px 的行内列表。右侧面板放得下时并排，否则是浮层。对话栏宽 680px。 |
| <768 手机 | 页面叠放（见下面「手机的页面栈」）：根页共用底部标签栏（会话、设置）；会话列表是根页；会话页推入在列表之上，页头在侧栏灰上，对话是一张画布；新会话是列表上的底部面板；右侧面板是推入的整页；选择器、菜单与本机确认使用底部面板；输入框贴底并留出安全区；触控目标至少 44px。 |

**工作面板（768px 起）。** 主区域是一块画布 `--canvas`，上、右、下与窗口留出 `--shell-inset`（8px），左边紧贴侧栏（侧栏收起或在平板上滑出时也留 8px），圆角 12，用 `--sh-panel` 托起，不加边线。它从窗口顶上 8px 开始，跨过标题行与主区域：标题行里对话的一半是面板的顶部（52 高，下面没有线），对话、新会话页与「铺满」的面板页都在它里面。面板画在外壳的网格上（`.app-shell::before`），各栏的盒子不变，只把内容收进面板：`main.workspace` 仍占整列，内边距让出地面。侧栏收起与展开、拖动宽度时面板的左边随侧栏的格道一起走，减少动效时不滑。设置等页面用同一块面板：分区列表在侧栏的位置、直接在地面上，分区内容在面板里。手机没有面板（页面栈）。标题行的侧栏一段（红绿灯的内边距、「收起侧栏」与 Latch）在地面上；侧栏收起时它移进面板的标题行，离面板边缘 12px（桌面端仍让出红绿灯）。

平板的会话列表打开时主区域与标题行设为 `inert`，焦点限制在列表内，Esc 关闭后焦点回到打开按钮。对话框与底部面板同样捕获并恢复焦点。

**标题行与入口。** 标题行（[TitleBar.tsx](../apps/web/src/shell/TitleBar.tsx)）左端是桌面端红绿灯的内边距与「收起侧栏」，侧栏收起时还有「新建会话」（页面上换成「返回会话」）与带琥珀计数的「等你处理」；其余是对话的头部，或页面的标题。对话的头部依次是：项目 / 会话名 · 状态（[ConversationHeader.tsx](../apps/web/src/shell/ConversationHeader.tsx)，与侧栏同一套词：运行中带每秒走的计时，等你处理、没有动静、正在停止、失败、已停止、已中断；连接中断时不画进行中的状态），右侧是连接异常、演示、改动、侧边面板与 ⋯。「改动」在页面已经读到这个会话的增删行数时（打开过改动面板）在图标后写出 `+a −d`，读屏名称仍是「改动」；没读过时只是图标，不猜数字。桌面端（macOS 用 `hiddenInset`）靠它移动窗口，控件除外，有对话框、弹层或抽屉时不移动；窗口最小 768px，保证它一直在；登记、连接与崩溃页没有标题行，画一条同高的拖动带。没有图标栏：目的地少，每个都不需要自己的一列。侧栏顶部只有新会话与搜索；底行是「添加项目」（只有能用系统文件夹面板的桌面端有）、手机与设置，⌘, 打开设置（浏览器用 Alt ,）。连接有问题时手机图标左边是一个琥珀或红色的点，提示写出原因。页面顶部的「返回会话」在有会话等你处理时带琥珀计数，手机的「会话」标签带一个点。入口与分区的对应在 [routes.ts](../apps/web/src/shell/routes.ts)：窗口跨过手机断点时留在同一分区；手机只有两个标签，其余都在设置里。设备不能用的分区不画，全部不能用的入口也不画。切换页面不卸载会话：页面盖在会话各栏上，阅读位置、草稿与面板不变，被盖住时快捷键不作用于会话，需要会话的命令（面板里的搜索、打开文件）先回到会话。冷启动打开新会话，重新加载回到打开的会话。

**手机的页面栈。** 手机不放并排的栏，而是一页叠一页（[PhoneSessionList.tsx](../apps/web/src/components/PhoneSessionList.tsx)、[NewSessionSheet.tsx](../apps/web/src/newSession/NewSessionSheet.tsx)，样式在 `phone.css` 与 `phone-*.css`）。

- **会话列表是根页**，在画布上：52 高的头行是 22/30·600 的「会话」与 44 的墨色幽灵按钮（新建会话），下面是常驻的搜索框；再往下依次是「等你处理」（有时才有，组名后是中性计数）、每个项目、「无项目」，分组规则与侧栏相同，置顶的会话排在各自分组的最前面并带一枚图钉；组名旁一条 `--line` 细线，项目组右端有「在 … 中新建会话」，列表末尾是「已归档」；点开后顶部有返回的一行。还没有会话时，列表开头左对齐地写「还没有会话」（次级墨色）、一行提示墨色的说明与 xs 次按钮「新建会话」，不放插画。列表末尾是一行提示墨色的 `laptop` 图标与运行 Host 的电脑名称，右端是幽灵按钮「同步最新状态」（重新读取 Host 的状态，进行中转圈）：连接正常时也能在列表上同步，没有会话时同样在。
- **行高 64**：第一行是标题（有事要你看时 `--ink`·500，否则 `--ink-2`）与状态槽（与侧栏同一套词）；第二行是 16 的 Harness 图形（单色）、Agent 名称与一件事：在「等你处理」里是项目，其余是分支，有结果未知时是「N 条结果未知」。文件数尚无来源（`TaskSummary` 没有这个字段），所以不写。没有会话内容的预览：Host 不提供。行间是一条 `--line`；按下与被打开的那一行是悬停底。按住一行（触屏或手写笔 500ms，或右键与上下文菜单键）打开这个会话的菜单底部面板（重命名、置顶、归档、导出 Markdown、删除；重命名与删除再各开一个「取消 · 问题 · 动作」的底部面板），这次松手不会打开会话；菜单开着时这一行保持按下的底色，看得出菜单属于哪一行。
- **搜索**：搜索框按标题即时过滤，并搜索正文；使用时右边出现「取消」，它清空搜索并离开输入框。桌面与平板没有这个搜索框：面板里的「搜索」打开命令面板。
- **新开的标签页**停在会话列表上（桌面与平板打开最近的会话）；重新载入的标签页回到它上次打开的会话。
- **会话页**推入在列表之上：新的一页以 `--m-push` 从右侧滑入，列表同时左移 24% 并在遮罩色下变暗，被盖住时设为 `inert`，焦点移到新一页的返回按钮（从新会话面板开始的会话同样如此）；返回（页头的「返回会话列表」）反向，页面以退出曲线用 70% 的时长滑出后才放开这个会话，焦点落回它在列表里的那一行。随页面一起载入的会话直接在那里，不滑入。减少动效时页面只淡入，什么都不移动。页头在侧栏灰上（52 加安全区）：左侧 44 的返回，中间居中的标题按钮（16/22·600 加常显的向下箭头，打开会话菜单的底部面板：重命名、置顶、归档、导出 Markdown、删除与「同步最新状态」），标题下面一行是提示墨色的「Harness · 项目」以及不是默认时的状态词、完全访问、演示与连接状态，右侧 44 的「侧边面板」。刚开始的会话在 Host 列出它之前就已推入：这时页头的形状不变，标题写「新会话」，标题菜单、下面一行与「侧边面板」等它被列出后出现。对话是页头下面一张从下往上铺开的画布：上圆角 16、1px `--line` 描边，文字在画布顶部 4–18px 之间淡出，永远不压在圆角下；横幅在画布的顶部，输入框浮在画布内底部，只有一行：静止时 52 高，发送或停止在这一行的右端；内容变多时按行长高，按钮留在最后一行旁边。Harness、模型与思考、权限在输入框下面，放不下就换行，其他选项在「⋯」里；设备不能改这个会话时这几个控件仍然显示，不可更改（选择器在手机上是底部面板，触屏上值后面的箭头常显）；下一条消息要换模型时，选值写出「下一条：…」，菜单里是「撤销切换」，输入框上方只多一个说明它的小块，输入框本身仍是一行。
- **新会话**是列表上的底部面板（打开即停在窗口的 92%）：「取消 · 新会话 · 开始」，没有内容或不能开始时开始不可用。卡片逐行是项目、Harness、模型、思考、权限；项目、Harness 与模型各自打开底部选择面板。其他设备的 Harness 只有内置的一项。只有旧 Host 没有目录时才保留方式分段控件。打开时焦点在输入框。演示模型有明确标记；缺少模型时在引导卡片里添加服务；Harness 的列表写明内置 Harness 不能运行命令。输入框五行高，正文在固定高度的面板内滚动，原因换行时页头不动。取消保留草稿；开始后面板收起、会话页推入。每个嵌套面板使用自己的高度档位，不继承外层的 92%。新会话不绘制环境背景。
- **返回**：推入的每一页（会话页、右侧面板、设置与它的每一级）和每个底部面板打开时都在浏览器的历史里占一条（地址不变，[backStack.ts](../apps/web/src/hooks/backStack.ts)），所以平台的返回（Android 的返回键、iOS 的边缘滑动、浏览器的后退）关闭最上面的那一层，而不是离开 Latch；会话页用同样的滑出（浏览器自己已经画了返回时不再滑），焦点回到列表里的那一行。在页面上关闭的一层把它那一条还回去（一次后退越过所有不再有人用的条目）；与此同时打开的新一层接着用这一条，不会被这次后退关掉。重新载入时随页面回来的会话用原来那一条，不另加；没有对应层的旧条目在后退时被跳过。

**页面。** 设置与手机共用一个页面（[SettingsPage.tsx](../apps/web/src/settings/SettingsPage.tsx)），不是模态，盖在会话各栏上，本机确认对话框照样开在它上面。768px 起，分区列表放在侧栏的位置、直接在地面上（1024px 起与侧栏同宽，平板 200px），顶部一行「返回会话」，下面一条 `--line`；分区内容在工作面板里；设置的分区依次是通用、模型、Harness、项目、插件、快捷键、关于。分区行 32 高、8 圆角，选中是选中卡片与 500 字重，图标不变蓝；页面落在第一个分区，标题写在标题行；分区内容在主区域，最宽 720px 居中，上下各 48px。分区里的页面（某个 Agent、某个模型服务、「其他设备可用的项目」这类列表，[navigation.tsx](../apps/web/src/settings/navigation.tsx)）在 768px 起原地替换分区内容，上方一个幽灵的返回链接写着上一级的名称。手机上每一级都是一页：分区列表是设置标签页的根页面，依次是通用、模型、Harness、项目、插件、手机与设备、关于（没有快捷键），分区从右侧推入，分区里的页面再推入在分区之上，各有自己的标题栏与返回按钮（读屏名称说出回到哪一级），返回留在分区所属的标签页；新的一页以 `--m-push` 从右侧滑入，上一页同时左移 24%，盖住后从阅读顺序中移除，返回是同一滑动的反向；一级只有一个返回，页面里不再有返回链接。第一次进入分区也是滑入：分区在进入标签页时就排在屏幕外。换分区、进入分区里的页面或从页面回到分区时内容从下方 4px 淡入（120ms）。减少动效时手机的各级只交叉淡化（120ms），其余只淡入。Esc 在手机上回到上一级。

**会话面板。** 上面是「新会话」与「搜索」（32，幽灵行，快捷键是普通文字）；下面依次是「等你处理」（有时才有，中性计数）、每个项目、「无项目」和安静的「已归档 N」；底行固定，列表再长也够得着。组头 20 高、没有分隔线，字是 12/16·500 `--muted`；悬停时出现折叠箭头（折叠后常显并写出条数）与右端的 ＋、⋯，折叠状态每台设备各记各的。置顶的会话排在各自分组的最前面，带一枚图钉。

每个会话都是两行（52）：第一行是标题（`--ink-2`）加状态槽，静止时是时间（`TaskSummary` 没有文件数）；第二行是 `--muted` 的 12px 单色 Harness 标记（品牌文件本身，不带磁贴的底与细环）与等宽的模型：经模型服务时是 `modelRoute.model`，否则是 `model`，都没有时写「默认模型」（外部 Harness 报告模型之前）；标记是中性图形的 Harness（Claude Agent、Cursor、自定义命令）在模型后面再写名字。模型太长时以省略号结束，不撑宽侧栏。分支、工作树与 Harness 的名字在行的提示里；结果未知时第二行末尾写「N 条结果未知」。「等你处理」里的行第二行只写摘要里有的：等的种类（「审批」「2 个问题」「看不懂的请求」，或「没有动静 3 分钟」）用琥珀字，再写项目名，从不写路径或请求要做的事；分组已说明它在等，所以第一行仍是时间。分组头与「已归档」的计数是等宽数字。悬停时状态让位给「归档」与 ⋯。

状态词只说 Host 说过的（[sessions.ts](../apps/web/src/sessions.ts) 的 `rowStatus`），变化每秒最多一次，时钟只在这一格里每秒更新：

| 情况 | 状态槽 | 进「等你处理」 |
| --- | --- | --- |
| 审批或提问 | 琥珀盾牌加「等你处理」（侧栏的「等你处理」里是时间，等的种类写在第二行；手机上带盾牌） | 是 |
| `live.silent` | 琥珀「没有动静 3 分钟」，从 `lastEventAt` 算起；不会因为时间长自己下这个判断（侧栏的「等你处理」里写在第二行） | 是 |
| Harness 发来不认识的请求，之后再无动静 | 琥珀「等你处理」；Harness 一有动静，Host 让列表重读，这一行回到运行中 | 是 |
| 运行中 | 蓝色转圈加摘要里的活动种类与时钟：「在跑命令 0:42」「在等模型 0:04」「在用工具」「在启动」，没有种类时「运行中 1:12」；时钟从 `live.runStartedAt` 算起，不含等人的时间，旧 Host 没有这个字段时不写时间 | 否 |
| 停止中 | 「正在停止」，直到这次运行真正结算；此前等你处理的会话也离开这个分组 | 否 |

归档后行淡出，面板底部出现「已归档 · ⌘Z 撤销」；输入框有焦点时 ⌘Z 仍归输入框。权限模式变化不在行上画红，由会话自己说明。

**可调宽的侧栏（1024px 起）。** 侧栏的内侧边缘（对话画布的左边框）是调整宽度的把手（`ResizeHandle`，见「界面原语」）：宽度在 220–400px 之间，默认 248px，对话画布始终至少 480px，拖拽中与窗口变窄时都按此收紧（右侧面板并排时也算上它）；双击恢复默认宽度。拖到 160px 以下就收起，与标题行「收起侧栏」按钮是同一个状态：侧栏的格道滑到 0（`--m-panel`），内容保持原宽被裁切、不重新换行，收起后不可聚焦；拖拽越过这个点时（收起，或把收起的侧栏拖出来）格道同样滑过去，而不是跟着指针一下跳到位，之后的宽度才继续跟手。标题行的「新建会话」（有会话等你时还有带琥珀计数的「等你处理」）随格道一起展开与收起（宽度与淡入都是 `--m-panel`，淡出是 `--m-micro`）；侧栏打开时它们不可聚焦，也不在无障碍树里。⌘K 打开命令面板，不动侧栏；展开或从窗口左缘拖出时回到上次的宽度。键盘：把手可聚焦，←/→ 一步 8px（Shift 32px），Home/End 到最窄与最宽，Enter 收起或展开；用标题行的按钮收起、展开时，焦点移到做相反动作的那个按钮。拖拽中跟手的宽度不做过渡、不选中文字，指针由把手捕获。宽度与收起状态按设备保存在本地偏好里（从不发给 Host），读不到或不合规的值按默认处理。平板与手机没有把手。

**右侧面板。** 改动、文件、打开的文件标签与插件面板共用一个面板（[SessionPanels.tsx](../apps/web/src/components/SessionPanels.tsx)，放法在 [panelLayout.ts](../apps/web/src/shell/panelLayout.ts)），按剩余宽度并排或显示为独立页面。标题行的「侧边面板」开关在每个宽度都有（打开时是中性的悬停底），⌥⌘B 关上后再打开回到关上时那一面，页面被 Esc 或平台的返回送走时也一样。1024px 起它是外壳网格的最后一列，面是地面上的第二块面板（与工作面板同样留出 8px、圆角 12、`--sh-panel`，两块之间是 8px 的地面），标签条与对话的标题行同高、同样可以拖动窗口：打开与关闭时格道滑动（`--m-panel`），内容保持打开时的宽度被裁切，不重新换行。它朝画布的边缘是调整宽度的把手（`ResizeHandle`）：默认 520px，360px 到窗口的 70%，双击复原；对话放不下 480px 时换成盖在对话上的浮层，留在工作面板里、标题行之下，右边与下边贴着面板的边，浮层可以拖窄，窄到放得下就回到并排。手机上换成一页：页面从右侧推入（`--m-push`），对话在下面向左移四分之一，返回时反向（70% 的时长），焦点进入页面，返回后回到切换按钮；对话在页面下保持挂载并设为 `inert`，阅读位置不变；切换会话时页面关闭。未打开过时不打开，打开状态与宽度记在本设备，从不发给 Host。

**启动面板。** 面板打开而没有任何一面时显示启动面板：标题「打开一个面板」下是 32 高的行（手机 44），行尾是字母键（改动 D、文件 F，键盘焦点在启动面板内时生效），之后是插件面板。只有开关或命令面板打开它时焦点才进入；切换会话、重新载入与 Host 列出新会话时它只是出现，不从输入框拿走焦点。只列出这个会话真能打开的；浏览器与终端的界面尚未实现，不出现。什么都打不开时居中写「这个会话没有可以打开的面板」。

**标签条。** 用 `PanelTabs`：改动（只在别的标签显示时带 `+60 −6`）、文件、打开的文件（图标按类型，悬停变成 ×，轮次生成而还没看过的带圆点，标签已满 6 个时新文档不挤掉已有的标签，留在这一轮的文件卡片上）、插件面板；行尾是「铺满」与「关闭」。启动面板时没有选中的标签，也不能铺满。手机上标签条保留，行尾按钮收起，用页头返回。

## 界面原语

原语在 workspace 包 `@latch/ui`（[index.ts](../packages/ui/src/index.ts)），是 React 组件加上它们在 ui 层的样式。页面从这里取按钮、状态词、开关、分段控件、选值、菜单、对话框、提示与磁贴，不再各自画一份；同一种意思只有一种画法。样式只读令牌。类名以 `ui-` 开头，变体与尺寸写在 `data-variant`、`data-size`、`data-tone` 上，状态直接用 ARIA 属性（`aria-pressed`、`aria-checked`、`aria-expanded`、`aria-disabled`、`aria-busy`、`aria-invalid`），所以样式跟着可访问性状态走，不另设状态类。

**交互约定。** 悬停与按下的底在 `--m-micro` 里变化；列表里选中的切换同样是交叉淡化，不做滑动的选中块。按下时按钮缩到 97%（打开菜单的按钮、禁用与运行中的按钮以及减少动效时不缩），其余控件按下只深一档（`--press`）。禁用的控件用 `aria-disabled`：整个控件降到 45%，仍能用键盘聚焦，提示框说明原因，点击与表单提交都被拦下（不用原生 `disabled`，否则原因无人能读）。键盘焦点是 2px 的蓝色描边，画在元素边内 2px（`outline-offset: -2px`），所以滚动容器裁不到它；实心的主按钮与销毁按钮画在边外 2px，衬着所在的表面。成组的单选控件（分段控件、文字标签页、筛选、单选列表）整组只有一个 Tab 停靠点，方向键移动并立即选中，Home / End 到首尾，跳过不可选的项。弹层与菜单在顶层（top layer）显示，滚动容器与对话框都裁不到它；打开时焦点进入当前项或第一项，Escape 关闭并把焦点还给触发器，Tab 离开即关闭，点外面或滚动让触发器移动了 1px 以上时关闭（打开时把触发器滚进视野的那次滚动、别处的滚动都不算）。手机宽度（<768px）下，菜单、选值与弹层都换成底部面板。对话框与底部面板里 Tab 只经过真正的 Tab 停靠点（`tabindex="-1"` 的菜单项和单选组里的其余项不在其中），从最后一个回到第一个。

**图标与转圈。** Lucide（ISC）线性图标只用 12、14、16、20、24 五个尺寸，描边 1.75，最小的 12 与 14 是 2；`ICON_STROKE` 按尺寸取值，用其他尺寸时类型检查失败。静止的图标是提示墨色，悬停与激活时是正文墨色，和文字放在一起时随文字颜色；图标只在表示状态时带色相：失败是红色的 `circle-alert` 或三角，等你处理是琥珀色的盾牌，被选中的完全访问是琥珀色的 `shield-alert`。箭头各有一种意思：向右是进入下一层或展开（展开时转 90°），上下双箭头是原地选值，向下是下拉动作。停止是 10×10、圆角 2 的实心方块，不是描边图形。转圈（`Spinner`）是一圈当前颜色 22% 的轨道加满色的上四分之一，800ms 一圈，12、14、16 的线宽 1.5px，20 的 2px；页面上所有转圈按文档时间线对齐相位，并排时不会错开；离开视野时暂停，减少动效时停在静帧。它表示正在进行的事：运行中的 Agent 与工具、加载行、按钮运行中、取消中；颜色随所在的文字，状态词与过程行里是墨色。

**按钮。** 尺寸只有四档：xs 24（圆角 6、12/16 字：提示与行内的动作、回合脚部与项目弹层里的行内动作）、sm 28（桌面默认：页头、卡片按钮行、行尾）、md 32（对话框与面板的脚部）、lg 44（手机，胶囊形）；圆角 8、13/18·500，带前导图标时起始内边距少 4。变体：主按钮（primary）是一个界面里唯一的蓝色，只给执行或创建的动作（发送、允许一次、请求本机确认、添加服务），带一层内侧高光与淡蓝的落影；「保存」「保存默认值」这类不执行操作的确认用次按钮。次按钮（secondary）是悬停底那样的中性填充，没有环，悬停换成按下的深度；描边按钮（outline）是控件的面（`--pop`）加一圈 `--line-strong` 与 `--sh-1`，在面板、卡片与对话框上一样立得起来，用在要和静止内容分开的地方；放在警告或红色调的容器里（容器标 `data-tint`，内联提示自己会标）时次按钮也换成描边的样子，因为半透明的墨叠在红色调上会发脏，警告里与它保持一致。幽灵按钮（ghost）是次级墨色的字，悬停时出现底并换成正文墨色，用于工具栏、行尾与「重置」这类安静的动作；链接样式只用于跳到别的页面或位置（`ButtonLink` 是同样画法的 `<a>`），悬停时出现点状下划线；页面上的危险操作（danger）是红字的描边按钮；实心红（destroy）只在确认对话框里。运行中的按钮宽度不缩、前导位换成转圈、文案可以换成进行时（「检测中…」），并标 `aria-busy`，不再接受点击；运行中的按钮不算禁用，页面同时禁用它时也不降透明度，主按钮运行中仍是蓝色。此刻按了真会生效的键画在按钮上（`keys`，如 `['mod', 'enter']`）：文字后每个键一个键帽、相隔 2，末端比只有文字时少 4 的内边距；主按钮与销毁按钮上是深一档的键帽配白字；触屏（粗指针）不画；读屏名称只有文字，键进 `aria-keyshortcuts`，提示框不再重复这些键。不在此刻生效的快捷键只写在提示框里（「允许一次 ⌘⏎」）。每张卡、每个对话框脚部与面板头部最多两个可见按钮，次在前、主在最后，第三个动作进 ⋯ 菜单。图标按钮是 24、28（圆角 6）、32（圆角 8）、44（圆形）的正方形（图标 14、16、16、20），名称同时是它的提示框；静止是提示墨色，悬停是悬停底与正文墨色；切换按钮的「开」与菜单打开时的触发器（`aria-expanded`）也是悬停底与正文墨色，不用蓝；输入框里的发送与停止是圆形。图标按钮的面（悬停、按下与「开」的底，以及键盘焦点环）按它自己的尺寸画在中间，所以在任何屏幕上看起来一样大；触屏上它的盒子长到 44×44，工具栏与图标栏里相邻的按钮因此相隔 44，点按区不重叠；页面在密集的行里保留较小的盒子时（回合脚部的复制、列表头的筛选），透明的点按区仍伸到面四周的 44×44。计数放在面的右上角外 4px，垫着一层所在表面的颜色并镂空一圈 2px（`--surface`），字形不被遮住。`--surface` 默认是画布色；放在别的表面上的容器把它改成自己的颜色：图标栏与侧栏在侧栏色上，所以是侧栏色；菜单、弹层、对话框与 Toast 是弹层面（`--pop`），单选列表是浮起色，底部面板是侧栏色。

**提示框。** 悬停 400ms 后出现，键盘聚焦时立即出现；离开、按下或 Escape 立即消失；一个提示框消失后的 300ms 内移到相邻的控件时，新的提示框立即出现，并从上一个的位置滑到新位置（`--m-micro`），不再从头淡入。提示框是反色的：浅色里是近黑底配白字，深色里是比浮起亮一级的灰；圆角 6、至少 24 高、12/16 字、最宽 320，从 98% 放大并淡入（`--m-enter`），不接收指针；提示文字同时是触发器的读屏描述（图标按钮的名称已经是同一段文字时除外）。禁用控件的原因（按钮、图标按钮、选值）、开关与分段的说明和开发版标记的整句都用它，不用浏览器原生的 `title`。触屏上不出现。

**状态词、徽标、计数、状态点与按键。** 状态用几个字说出，最多带一个 12 的图形，颜色就是它的意思（`StatusWord`，12/16·500、等宽数字）：等你处理是琥珀字加盾牌，运行中是墨色字加转圈（「运行中 1:12」随计时不变宽），失败是红字加 `circle-alert`，已完成是墨色字加对勾，警告（不可用、演示、原内容未知）是没有图形的琥珀字，其余（已停止、已停用）是提示墨色。状态没有胶囊，也没有前导点；`StatusPill` 按页面与插件面板用的 `Tone`（`neutral`、`warn`、`err`、`ok`）画同一种状态词：提示墨色、琥珀字、失败与已完成；插件面板经 `PluginPanelProps.ui` 拿到它。徽标（`Badge`）是跟在名字后面的属性（默认、本机、内置、离线、开发版、演示）：18 高、圆角 4、11/14·500，中性是标签底（`--tag`，没有边与下唇，和按键分开）配提示墨色，琥珀是同样的标签底配琥珀字，红是淡红底配红字；它从不表示卡片或行的状态。计数（`Count`）是 12/16·500 的等宽数字，不加底，超过 99 写 99+：被动计数随周围文字，新结果是墨色，等你处理是琥珀；页面亲眼看到计数变了时新数字淡入（`--m-micro`）。状态点桌面 6、手机 8，琥珀与红点总要和文字或图形一起出现，叠在磁贴上时用所在表面的颜色（`--surface`）镂空一圈。按键（kbd）像一个键：18 高、圆角 4，自己的键面（`--key`）带一圈边与 2px 的下唇（`--sh-key`），11/14·500 提示墨色，只出现在提示框、菜单项尾部、搜索框、审批卡聚焦时的提示行，以及此刻按了真会生效的按钮上（见「按钮」）。计量（`Meter`）是格子不是胶囊：整数个格子、整像素的间距（sm 是 3px 的格相隔 1、8 高，12 格 47 宽，用在状态行；md 是 14px 的格相隔 2、10 高，用在图例与面板），调用方给数字，填满的格数按比例取整、大于零时至少一格；填满的格是 `--meter`，其余是 `--track`，两个主题都不带色相，也没有动画；读屏是 `role="meter"`，名称是它量的东西，`valueText` 写出值（「62k / 128k」）。上限刻线与超出的一段尚未实现（等第 3 步的用量上限）。

**选值（ValuePicker）。** 在原地从一组互斥的值里选一个，只显示当前值：幽灵、28 高（`size="xs"` 是 24、箭头只在悬停或聚焦时出现；触屏上常显）、值 13/18 常规字重、末尾上下双箭头，前导、值与箭头彼此相隔 6。值总是紧跟前导（没有前导时从内边距开始），所以外扩的一列值与列的边缘对齐；手机设置面板里的值离箭头 6，同一张卡的值右缘对齐。悬停与菜单打开时是悬停底，值换成正文墨色；只有一个可能值时是不可点的文字；没有选择时写「选择模型」这类说法，用提示墨色，不用警示色。读屏名称是「标签：值」。菜单打开时焦点在当前值上，Enter 选中，可以按首字母跳转；不可选的值也能聚焦，下面一行带禁止图标的原因保持原色并被读出。选中即生效，不弹提示；值改变时淡入（`--m-micro`）。调高权限这类要验证的改动返回一个 Promise，等待期间前导位是转圈、值换成「等待验证…」，取消验证时值不变。箭头不动：设置行尾部的选值向左伸展；输入框工具栏里左对齐的权限菜单（`reserve`）预留值与「等待验证…」中较宽的宽度，多出的宽度留在值和箭头之间。只有可能等待验证的选值才预留，模型、项目这类选值、24 高选值与手机行都不预留。设置行尾部的选值按 `--bleed` 向右外扩 6px，使箭头与同卡导航行的箭头对齐。长列表可以带搜索行。值可以带自己的图（`media`，Harness 或模型服务的磁贴），放在勾选槽之后；一组值可以在组标题前带服务的磁贴。值与列表里的写法不同时（下一条消息才生效的模型切换，「下一条：…」），`valueText` 写出触发器上显示的话，读屏名称随之改变。`panel` 让弹层原地换成一块小面板（在选值的地方添加一个值，例如从「添加模型服务…」进入），弹层保持打开，手机上由底部面板承载；面板与脚部动作用 `useLayerClose` 关闭所在的弹层，焦点回到触发器；`onOpenChange` 报告每一次打开与关闭。只有一个可能值、又没有脚部与面板时才显示为不可点的文字。禁用的选值降到 45%，原因在提示框里。手机上是底部面板里的单选列表，打开时焦点在当前值上（单选组唯一的 Tab 停靠点），不论它排在第几；`variant="row"` 是手机设置面板里的一行（标签、值、箭头），同一张卡里相邻的行之间有一条从文字边开始的 `--line` 细线，最后一行下面没有。

**权限菜单（PermissionMenu）。** 有序的权限等级只用这一个菜单，不用一排分段：整层 320 宽，头部写作用对象，四个两行项从低到高，每项一句后果，默认项带中性徽标「默认」，越级的项不可选并写出原因，脚部是一行导航或带锁的说明。菜单里的完全访问不带琥珀；只有它被选中后，触发器前才出现琥珀色 `shield-alert`。调低立即生效，调高走上面的验证流程。等级的文案由页面传入，原语只负责顺序、画法与交互。手机上的单选面板用同一份文案：头部写在列表上方并作为单选组的名称，「默认」徽标跟在标题后面，脚部说明与单选和标题两列对齐。

**菜单与弹层。** 菜单、选值的层、内容自管的弹层（`Popover`，例如计划）与选值里原地换上的面板都是最高的面（`--pop`，不透明）、圆角 12、`--sh-lift`，组与组之间只有一根细线；菜单内边距 6。弹层面上最安静的墨色在深色里差一点到 4.5:1，所以层里的 `--faint` 换成 `--muted`。最小宽 220（给出的宽度都是整层的外宽，内边距在内；可搜索的选值 360），距触发器 6，设置行里右缘对齐触发器，输入框里左缘对齐。放在整层放得下的一侧（先试给定的一侧，再试另一侧）；两侧都放不下时，留在至少有 240 的一侧，限高并在层内滚动，始终离窗口边缘 8。层的内容改变大小时（菜单原地换成添加面板、宽度变宽）重新放置，已在的一侧仍放得下就不换边。打开时从 98% 放大并淡入（`--m-enter`），放大的原点在它朝向触发器的那一侧、对齐的那一边，像是从触发器里长出来；关闭倒放，用 70% 的时长与退出曲线。菜单项 32 高（带说明 48），圆角 8，内边距 10，前导槽 16 与标题相隔 8：选值菜单里当前项是墨色对勾、标题换成 500 字重，动作菜单里是图标；没有任何项带图标的动作菜单（例如审批卡的 ⋯）不留前导槽，文字从菜单的内边距开始；尾部只放一样（元信息、徽标或按键），元信息是最安静的墨色；两行项（带说明或不可选的原因）把前导与尾部放在标题那一行，不放在两行中间；原因行在上一行下 4、禁止图标与文字相隔 6；高亮瞬时变化。菜单项的图标静止时是提示墨色，悬停、键盘高亮与按下时换成正文墨色。危险项（删除）排在最后，前面一条分隔线（`--line-strong`，左右缩到项的文字边），文字与它的图标都是红色。菜单的读屏名称是它的标签加头部写的作用对象（「权限：在这台电脑上发起的会话」，头部只重复标签时不再加），头部的元信息是它的读屏描述。分隔线下的脚部行与菜单项用同一网格，32 高、圆角 8，文字从标题那一列开始：导航行（「管理项目…」）是正文墨色 13/18，前导槽空着，末尾向右箭头；留在原地的动作（「撤销切换」「添加模型服务…」）不带箭头，可以在前导槽放一个 14 的图标，`closes` 的动作先关闭弹层；说明行（「在 Mac 上的 Latch 里添加项目」）把锁放在前导槽中间，文字 12/16 提示墨色。脚部行不在菜单列表里时（弹层里一列按钮之后，或底部面板里）是普通按钮，用 Tab 到达，没有图标时不留前导槽。菜单项可以带值自己的磁贴（`media`），在前导槽之后、标题之前。`Popover` 的焦点进入它的第一个控件。

**输入。** 要输入的地方是井：文本字段与搜索框沉在所在的表面下（`--sunken` 与 `--sh-well`），悬停时叠一层悬停底；聚焦时（不只是键盘）井的边换成 1px 蓝环，外面一圈 3px 的淡蓝外晕。标签在上（12/16·500），提示在下（12/18 提示墨色），占位符是最安静的墨色；出错时环变红、下面一行红字写原因与改法，并作为读屏描述。桌面 32 高、圆角 8；手机 44 高、圆角 12、16px 字，iOS 聚焦时不缩放。页面内的搜索框也是井，前导 14 的放大镜（与文字相隔 6，控件内图标与文字的间距），有内容时尾部是 24 的清除按钮（触屏上四周有 44×44 的透明点按区），Escape 先清空；聚焦时留在井里并带同样的蓝环与外晕。侧栏里的搜索用 `variant="ghost"`：与那一列的行同样 36 高、16 的放大镜距起点与文字各 8，静止时没有底，悬停是悬停底，只有聚焦时成为井并带蓝环。

**开关与选择。** 开关只给能立即开关的行：桌面轨道 34×20、滑块 16（触屏 44×26、22），关是计量轨道的灰（`--track`），开是蓝色；滑块是白色、带自己的小阴影，与轨道的颜色一起在 `--m-micro` 里到位，按住时向前进方向拉宽 4px；Space 切换；键盘焦点环画在轨道外 2px，跟着胶囊的形状，不画在更大的点按盒子上。`SwitchRow` 整行是开关的标签，点标题也能切换，整行不响应悬停；被策略锁住时开关关闭并降到 45%，前面一把锁，说明换成原因。分段控件只用于 2–3 个对等的视图或模式（类型只允许 2 或 3 项）：一口井（`--sunken` 与 `--sh-well`，圆角 8、内边距 2）里放等宽的段，24 高、12/16·500；选中段立在井里：控件的面（`--seg-on`）加一圈 `--line-strong` 与它自己的阴影，配正文墨色，其余是提示墨色、悬停换成正文墨色；选中在 `--m-micro` 里交叉淡化，不滑动；md 是 28 高，手机 32；它是一个单选组，段的说明（例如为什么不可选）在提示框里。文字标签页与筛选（`Tabs`、`FilterPills`）没有轨道：24 高（手机 32）、圆角 6、12/16·500，可以带 12 的图标；选中是悬停底配正文墨色，其余是提示墨色，选中不滑动、从不下划线、不用蓝；标签页是 tablist，筛选是一组 `aria-pressed` 的切换按钮。复选框与单选框是 16px 的原生输入：未选中是浮起底加 1.5px 的 `--line-strong` 环，选中是蓝色（实心加白勾，或 5px 的蓝环）。单选列表放在浮起的卡片里，每行 48（手机 56），前导单选、标题与一句后果，选中项标题 500，单选与标题在同一行，下面有说明或原因时也不下移；不可选的行降低单选与标题，原因一行保持原色。

**选中的三种画法。** 列表里的对象（侧栏的会话行、设置导航）是 `--selected`：浅色是侧栏灰上的一张白色卡片（一圈淡环与 1px 落影），深色是一层柔和的白，标题换成正文墨色；被勾选的控件（单选、复选、开关的开）是蓝色，菜单里的当前项是墨色对勾；视图、筛选与外观（分段、标签页、筛选）是中性的浮起块或悬停底。蓝色从不画在选中行上。

**对话框与底部面板。** 对话框是原生模态 `<dialog>`：480（确认）、560（表单）、720（双栏），弹层面（`--pop`）、圆角 16、`--sh-dialog`，后面的遮罩把内容模糊 4px；头部 56（标题 15/22·600、可选副标题、关闭），下面不画线；正文左右与底部留 24；脚部 56，是状态带（`--band`，对话框自己的面上淡淡的一条），上缘一条细线（左侧说明，右侧最多两个 md 按钮，次在前、主在最后）；没有头尾的确认四边留 24。打开时聚焦第一个输入（没有输入时是正文的第一个控件），Tab 在对话框里循环，Escape 与点遮罩关闭（从对话框或面板里再打开的一层，例如新会话面板里的选择器，Escape 只关闭最上面这一层），关闭后焦点回到打开它的控件；打开时从 98.5% 放大并淡入，遮罩一起淡入（`--m-sheet`），关闭倒放，用 70% 的时长与退出曲线。底部面板（手机）是侧栏灰、上圆角 16，抓手、52 高的头部（左「取消」是常规字重的幽灵按钮、中间标题、右侧动作：执行操作的主按钮，或只关闭面板的次按钮「完成」，热区都是 44；只用来查看的面板（弹层在手机上的样子，例如计划）没有「取消」，只有右侧的「完成」；「取消」的文字与动作的右缘都落在下面卡片的 16 那条线上；两侧按钮从不被挤窄，标题短时居中，长时在两侧之间以省略号结束），从底部滑入（`--m-sheet`），以 70% 的时长滑出；内容高时先停在窗口的 65%，向上拖到 92%，向下拖过三分之一或快速下滑则关闭；`detent="large"` 的表单类面板（例如新会话）一打开就停在 92%，不随内容伸缩。页面可以经 `LayerHistory` 给每个打开的底部面板一个返回的位置（手机上是浏览器历史里的一条，见「手机的页面栈」）。手机上的菜单也是这样的底部面板：菜单项放在一张浮起的卡片里，48 高；标题只写对象本身（会话菜单的标题是会话名，菜单的读屏名称仍是「会话：…」）；用触屏打开时焦点仍在第一项（或选中项）上，但在按下按键之前不画焦点底，不会看起来像选中了什么。改动即时生效的面板不放「确定」。

**调整宽度（ResizeHandle）。** 侧边列（侧栏与右侧面板）的边缘：跨在边缘上的 6px 透明命中区，光标是 `col-resize`；悬停 300ms 后（避免划过时闪烁）、拖拽中立即、键盘聚焦时随焦点环一起，在中间画一条 1px 的 `--line-strong` 竖线，不用蓝色，也不占布局。它是竖向的 `role="separator"`，读屏名称写明作用（「调整侧栏宽度」），`aria-valuenow`、`aria-valuemin`、`aria-valuemax` 是像素宽度，收起时 `aria-valuetext` 为「已收起」。它只报告宽度：拖拽中报告指针下的原始宽度、松开时再报告一次（由页面收紧、吸附收起并保存），键盘一步 8px（Shift 32px）、Home/End 到两端，Enter 切换收起，双击复原；拖拽时捕获指针，并在根元素上标 `data-resizing`，整页显示调整光标、不选中文字。

**提示与 Toast。** 内联提示（也用作消息区顶部的横幅；横幅在页面看着条件变化时像折叠块一样展开与收起，收起时保留原来的文字，加载、重连或切换会话后直接在位）是浮起的表面加 1px 细线，圆角 8：错误叠淡红配红色的边，中性与警告只有浮起与细线；警告配三角，错误配圆形叉号，中性配信息图标；图标与标题用色调文字，说明是次级墨色 12/18；最多一个 xs 动作（警告与红色调里是描边按钮），可选一个关闭按钮。先写保留了什么，再写原因，最后给动作。错误提示是 `alert`，其余是 `status`。本地操作成功（保存、启用、获取到模型）用中性提示或只让值原位更新，不用绿色。Toast 是弹层面的一小块（`--pop`、圆角 8、至少 36 高、`--sh-lift`），从下方 4px 升起并淡入（`--m-enter`），前面一个色调图形，用于发生在别处的事（「已由「设备名」处理」）和失败；置顶、归档、删除这类在本页做的操作成功时不弹 Toast，列表行的移动或收起就是反馈。 窗口的 Toast 在输入框露出时升到它上方 12 并对齐它的中线，不盖住模型控件与发送（[Overlays.tsx](../apps/web/src/shell/Overlays.tsx)）。

**空、加载与错误。** 空状态是一句短名词（「还没有会话」）、一行说明和最多一个 xs 按钮，左对齐，不放插画。加载在对象旁边放 14 的转圈和一行提示墨色的文字；页面中央的连接状态用 20 的转圈；列表的骨架只做缓慢的明暗（不透明度在 1 与 .55 之间分四步来回，2.4s，离开视野时暂停，减少动效时不动），不做扫光，占的盒子与内容相同。界面出错的卡片是一张 480 宽的浮起卡片：红色三角、标题、一行说明会话和草稿都在执行端，最多两个按钮。

**磁贴。** Harness 与模型的方形磁贴：14、16、20、24、32、40、56，圆角按 round(边长 × 0.225)。磁贴放品牌自己的标志文件（`mark`），在浮起的表面上，外面一圈 1px `--line` 细环画在图形之上，标志贴到边时细环仍在；只有没有图标的东西才放调用方给的图形（`icon`），放在淡填充上；类型上二者必有其一，磁贴从不画字母。标志居中占 72%，文件自己带了很宽的留白时（`margin`）铺满；图形占 60%。彩色标志原样放（`<img>`），品牌另有深色版文件时（`dark`）按页面的主题换用；单色标志按品牌的单色复制方式，以文件为 CSS 遮罩、填成 `--ink`，所以浅色里是近黑、深色里是柔和的白，图形本身不改；品牌自己的应用图标（`tile`）自带底色与外形，原样显示，不加底与细环，也不按磁贴的圆角裁切。标志文件从不作为标记内联进页面。图形是正文墨色的 Lucide 图标，描边 1.75，16 的磁贴里是 2.2，10px 的图形也认得出来；16 及以下的位置上（选择器的按钮、顶栏与回复的来源行）没有图标的东西只画图形本身（`plain`），因为底上 10px 以下的图形认不出来；我的 Agent 的中性图形磁贴也一样。`plain` 只有图形没有磁贴，图形用次级墨色（单色标志仍是 `--ink`）。就绪度画在磁贴上，就绪不加任何标记：不可用（例如找不到命令）灰度并降到 40%；启动或检测中灰度、降到 70%，外面一圈 2px 的进度环（有进度时从 12 点起顺时针按比例画弧，否则一段弧 1.4s 绕一圈，离开视野时暂停，减少动效时停住）；失败在右上角放一个 8px 的红点并镂空一圈表面色。就绪度也要在文字里写出。

**磁贴选择（`TileChoice`）。** 支持大磁贴与紧凑两种布局，默认保留大磁贴供需要图片辨识的选择场景。紧凑布局 `variant="compact"`：20px 身份图标与名称、说明同行，桌面最小 36px、触屏最小 44px，选中是选中行那样的卡片（`--selected` 与它的环），长名称省略且保留提示。整组只有一个 Tab 停靠点；方向键选择并跳过不可选项，Home / End 到首尾。不可选项保持可聚焦，原因由说明与读屏描述给出，按下时在整行下面展开。

**状态。** 只有正在进行的工作会动（它的转圈），等你处理、失败、已完成与时间从不动；状态变化被页面亲眼看到时，新旧状态在同一格里交叉淡化（`--m-micro`），这是它们唯一的过渡。没有空闲动画，也没有闪烁、弹跳、扫光与涟漪。样式在 [status.css](../packages/ui/src/styles/status.css)。

- **状态槽（`StatusSlot`）。** 列表行第一行行尾的一格，右对齐、至少 24 宽，只显示一样：运行中（转圈加「运行中」，页面给出时长时写「运行中 1:12」，正在停止时写「正在停止」）、等你处理（琥珀盾牌加「等你处理」）、注意（没有盾牌的琥珀字，文字由页面给出）、失败（`circle-alert` 加红字，文字由页面给出，默认「失败」）、未读（12 的墨色对勾，会话被读过后消失）、已结束（`--muted` 的「已停止」）、时间（`--muted`、常规字重），或什么都没有。会话行按 `rowStatus` 选择。状态变了且页面看见时，旧的在同一格里以退出曲线淡出（70% 的 `--m-micro`），新的淡入；淡出播完就从页面上移走，离开的转圈不会在看不见的地方继续转。它对读屏隐藏，行自己用一句隐藏文字说出状态与时间。
- **过程行的状态（`StatusGlyph`、`StatusWords`）。** 工具的过程行与计划步骤共用：图形格里运行中是转圈（行里 12，工具卡 14），其余是这一行的图标（计划步骤按状态是空心圆、带点的圆与对勾，都是静止的）；`state` 写明图形表示什么。页面看着它变化时，旧图形淡出、新图形从 80% 长到原大并淡入，在同一格里交叉淡化（`--m-micro`）；状态文字（执行中 → 完成）淡入。失败只换图标与文字，不抖动。
- **只为看见的变化播放。** 这些过渡（还有计数的淡入）只为页面亲眼看到的变化播放一次：页面经 `LiveChanges` 给出重新同步的纪元，在上一次渲染之后换了纪元的变化直接显示新值；没有纪元或减少动效时也直接显示。外壳（侧栏、图标栏）的纪元是 Host 状态重新同步的次数（首次加载、重连后的快照同步、页面重新可见，见 [STREAMING.md](./STREAMING.md)「客户端：事件流、凭据与版本门禁」）；对话区与会话详情的纪元另加打开的会话，切换会话时那里不播。会话列表跨会话存在，所以打开一个未读的会话时，它那一行的对勾淡出、时间淡入。只在有东西等待时才出现的计数（侧栏的「等你处理」行、图标栏的待批准按钮）由所在的组件用 `useLivePrevious` 记住它出现前的值并传给 `Count` 的 `from`，所以第一项到达（0 → 1）也淡入。页面里的其他一次性过渡用同一个 `useLiveChange`。
- **正在思考（`Shimmer`）。** 进行中的文字是提示墨色：挂载 600ms 后，一道墨色的窄光用 1s 从左到右扫过文字，然后休息到 4s 一个周期结束，只动文字背后渐变的位置；离开视野时暂停，减少动效时是静止的提示墨色。`variant="working"` 是运行中的工作标签：一道光以 30 步、2.2s 一轮不休息地扫过，全页共用一个时钟，暂停与减少动效的规则相同。

**展开、替换与离开（[motion.tsx](../packages/ui/src/motion.tsx)）。** 动效只用来说明一个变化：高度只经网格行变化，其余只动不透明度与位移，所以展开的东西上方什么都不移动；减少动效时高度直接到位，只保留淡入淡出。`Collapse` 是展开块的身体：打开时网格行从 0fr 到 1fr，内容同时淡入（`--m-panel`）；关闭用 70% 的时长与退出曲线；打开并停稳后不再裁切（焦点环、外扩的行不被切掉）。关闭时身体留在文档里，是 `hidden="until-found"`：不在 Tab 顺序与无障碍树里，但浏览器的页内查找能找到它，并经 `onReveal` 请主人打开；关闭过程中是 `inert`。`lazy` 的身体第一次打开时才渲染，之后保留（工具的输出这类重内容）。首次渲染直接显示当时的状态。`Swap` 在值变化时替换内容：图形从 80% 长到原大并淡入（复制图标变成对勾，`IconButton` 的 `swap`），文字原地淡入（`effect="fade"`，例如「正在思考」变成「思考了 6 秒」），都是 `--m-micro`，首次渲染不播。`usePresence` 让离开的东西在退出动画期间留在页面上并标为离开（「回到最新」淡出、右侧面板的页面滑走），默认留 70% 的 `--m-micro`。`Shimmer` 是进行中的文字（见「状态」）。

**开发版与演示标记。** `DevMark` 是中性徽标「开发版」，整句说明（「开发模式：Host 代码可被本机修改」）是它悬停时的提示与读屏名称，从不用红；`DemoMark` 是琥珀色徽标「演示模型」（窄处写「演示」）。

**操作与面板部件。**

- **`SplitButton`。** 一个动作加一个收着同类动作的 V 形（「提交 ⌄」）：同一张面、两个控件、两个 Tab 停靠点，菜单与按钮右缘对齐。主动作禁用时 V 形仍可用，除非 `menuDisabled`，因为菜单里可能还有能做的事。
- **`SelectButton`。** 设置行里打开选择器的值：16 的磁贴或 14 的图形、值与 V 形，28 高，只画按钮，触发属性来自 `Menu` 或 `ValuePicker`。禁用时保持可聚焦，点击与按键都打不开。
- **`Button` 的 `pending` 与 `done`。** 用于打开系统表单的动作：表单打开时转圈留在原位，成功后绿色对勾变形进来并换成 `doneLabel`，这期间不接收点击。
- **`CopyButton`。** 图标在 `--m-micro` 里变成对勾，「已复制」锚定在按钮旁 1 秒；失败时在同一位置说明，读屏用 polite 状态。
- **`PanelTabs`。** 侧面板的标签条：24 高、圆角 6、12/16·500、最宽 160，选中立即移动不滑动，可带行数（`+60 −6`）与 6px 的新内容点。可关闭的标签悬停时图形让位给 ×，触屏上选中的标签一直是 ×，没有图形的也留出这一格；Delete 关闭并把焦点移到相邻标签。只有一个 Tab 停靠点，←/→ 移动并选择，溢出时横向滚动。
- **`DrawerStack` 与 `Drawer`。** 附在输入框上等待的东西（审批、问题、队列）：左右内缩 20、与卡片重叠 14、上圆角 16，从卡片后面滑上来（`--m-panel`），以 70% 的时长滑回，只为页面看见的变化播放。最后一个子项在最前，其余露出 10px 的边、宽 96% 且 inert，指针或焦点进入（触屏是点按）时展开。`arming` 让抽屉到达或回到最前后 320ms 内 inert，展开的堆叠里上一个抽屉离开时也一样。
- **`FoldHeader`。** `Collapse` 的整行头部，12 的 V 形在 `--m-panel` 里转 90°。
- **`ProgressBar`。** 2px 的线，给不知道时长的工作：缓动到 90% 后等待，结束时 150ms 走完并淡出；对读屏始终是不确定进度，因为 90% 不是测量值。
- **`Group` 与 `Row`。** 设置卡片：圆角 12 的浮起分组，可带标题，行之间是细线；里面的任何内容都有内边距。
- **`Scrim`。** 不是原生对话框的滑出层背后的遮罩：淡入 `--m-sheet`，`open` 转假后留下以 70% 的时长淡出，这期间不接收按下。

**原语与页面。** 页面里的按钮、图标按钮、开关、分段控件、筛选、状态词与徽标、计数、内联提示、发送方式的单选列表、加载行、Toast、开发版标记、Harness 与模型服务的磁贴、新会话的紧凑选择、输入框里的选值（项目、Harness、模型、Agent 的模型选项）、侧栏的调整宽度把手，以及会话行的状态槽、过程行的状态图形和文字、展开块、替换与进行中的文字都来自原语。菜单、模态外壳、异步确认与输入框也由 `@latch/ui` 提供；页面的 `overlays.tsx` 只保留兼容导出。内容自管的 `Modal` 支持 dialog、sheet、page，共用原生顶层、焦点循环和归还；`ActionMenu` 与 `ActionSheet` 把页面动作映射到同一菜单原语。页面负责内容、请求和布局。

[packages/ui/test/gallery](../packages/ui/test/gallery) 是只供测试的原语总览页：每个原语的每种状态都在一页上（悬停、按下与键盘焦点由截图时强制），不进入 `dist/web`。状态的变化在总览页挂载后一帧重放一次，另有几格把状态槽与过程行的交叉淡化、思考的光带定格在中途，便于评审；「动效」一节是收起与展开的块（可以点开）与两种替换；「状态」一节是四种尺寸的转圈、状态槽的每一种、侧栏的一组行、变化、过程行与正在思考；总览页自己的排版只作用于它自己的元素，原语的标题与字号保持原样；就地画出的对话框、弹层与底部面板在手机宽度下收进卡片，完整可见；截图时视口长到整页高度，手机与平板的截图因此带着触屏尺寸（44 的点按盒子、44×26 的开关）。

**Harness 与模型服务的图标。** 每个 Harness 与模型服务都显示它真实的品牌图标（条款只允许文字的 Harness 预设除外：Claude Agent 与 Cursor 标 `brandMark: false`，用中性的 `bot` 图形），放在磁贴上（`BrandTile`，[brands.ts](../apps/web/src/brands.ts)）：先用品牌自己的文件（项目仓库里的或官网上不需登录即可取得的），没有时用开源图标集 LobeHub Icons（MIT）在固定提交中的文件，品牌标志是彩色的就用彩色版，否则用单色版。文件原样复制到 `apps/web/src/assets/brands/`，不作为 npm 依赖；以 `?no-inline` 导入，构建产物里是同样字节的文件，不被改写成内联数据；只经 `<img>` 或 CSS（遮罩）使用，从不内联成标记。来源（仓库与路径及提交，或网址与日期）、许可证、图标集的 MIT 声明与「标志属于各自的所有者，只用于标明服务或工具」写在 `apps/web/public/licenses/brands/`（`SOURCES.txt` 与图标集的许可证）。目录里的会话与服务不带预设标识，所以按 Host 由预设派生的标识（`codex`、`codex-2`……）认出它的预设；设置里有预设标识时直接用它。没有图标的才用中性图形：自定义的 Agent 命令是 `bot`，插件是 `puzzle`，自定义的 OpenAI 兼容服务是 `plug`，演示模型是 `flask-conical`；Latch 内置的 Harness 用应用图标原样显示。[brands.test.ts](../apps/web/test/brands.test.ts) 检查每个 Harness 预设（`brandMark: false` 的除外，它们是中性图形）与模型服务预设都有图标，演示、插件与自定义各有图形，图标目录里正好是映射用到的文件，且每个 SVG 不含脚本、外来内容、事件属性、嵌入图片、样式表或指向文件外的引用。图标出现在侧栏的会话行、顶栏与每轮回复的来源行、选择器，以及设置里的模型服务（预设、列表与表单）与 Agent（预设、列表与表单）。

**侧栏。** 内容、分组与状态词见「会话面板」。抽屉里头行另有「关闭会话列表」；新会话页打开时「新会话」是切换按钮的「开」。设备只从底行的手机图标（手机上是设置）进入。连接有问题由底行的点与顶栏的话说出；桌面端保持这台 Mac 唤醒时，底行上方写提示墨色的「保持唤醒中」，悬停说明原因，点它同步最新状态。会话的工作目录落在哪个保存的项目里（取最深的一个）就归哪一组，其余归「无项目」；组按其中最近更新的会话排序，组内置顶在前、最新的在前；Host 不提供项目列表时按工作目录分组。上一个与下一个会话的快捷键按屏幕上的顺序走：「等你处理」在前，跳过折叠的组。组头的 ＋ 在这个项目里新建会话（项目在本次启动时不可用，或设备不能发起会话时没有）。菜单提供重命名、置顶、归档、导出 Markdown、删除（需确认，运行中不可删除）；悬停、键盘聚焦或菜单打开时状态让位给「归档」与 ⋯。标题太长时最后 16px 渐隐，不用省略号；菜单打开时这一行保持悬停底。行标题默认用次级墨色；选中的行是选中卡片（浅色是侧栏灰上的白色卡片，深色是一层柔和的白；120ms 切换）与 500 字重；未读的行把标题换成正文墨色并在状态槽显示墨色对勾；连接中断时，等你处理的行仍是 500 字重。未读按设备记录。列表随 Host 变化时，移动的行与组从原位置滑到新位置，新到的行淡入（都是 `--m-enter`），离开的行（归档、删除、移到别的组）高度收起并淡出（`--m-micro`）；移动的行超过 30 个或换到已归档时直接重画，减少动效时都不动。

**新会话。** 问题居中（`--fs-question`），对着可见的字居中，全角「？」的空白半边悬出去；有项目时写「在 latch 里做什么？」，项目名是内联选值，没有项目时写「要做什么？」后面跟「选择项目 ⌄」（见下面「新会话页」），页脚多一个「选择项目」。下面是输入框（[NewSession.tsx](../apps/web/src/newSession/NewSession.tsx)）。没有建议卡片、提示行或背景。整块顶边固定为 `max(48px, 36vh − 52px)`，输入框下面出现说明时只向下长。

- **页脚**（[Composer.tsx](../apps/web/src/composer/Composer.tsx)，没有上下文条）：四个控件平铺，左边「+」、Harness、模型（谁来做、用哪个模型），中间空开，右边挨着发送是思考、权限（想多深、多小心），然后是用量环（上下文过半且 Harness 报告了才有）、「⋯」、发送。每个控件只写值，四个在任何宽度都看得见，放不下就换到下一行（右边一组仍靠右），不收进菜单。每个控件外面一层带 `data-composer-control`（`harness`、`model`、`thinking`、`permission`），按键找的是它里面的按钮。手机的会话页里四个控件都在输入框里，排成两行：Harness 与模型一行（模型 ID 太长时先省略模型，Harness 的名字不截），「+」、思考、权限与发送一行，发送在行尾；框外不再有一排控件。手机的新会话面板仍是它自己的几行。分支在卡片下面一行（项目或会话有可验证的分支时才有）。新会话的项目是只有一个文件夹的 Git 项目时，这一行最前面是「文件夹」选值（`xs`，菜单向右展开）：「当前文件夹」或「新工作树」，后者的说明写起点与「未提交的改动不会带过去」，菜单脚部写工作树只分开文件；选了「新工作树」时分支换成「从 main 的 3f2a1c9」。手机的新会话面板在「项目」下面有同样的「文件夹」一行。在工作树里开始的会话，这一行、顶栏项目名后面（提示墨色，宽度不够时先让位）与手机页头的第二行写「工作树 · <分支>」，侧栏与手机列表的行在标题前有 12 的工作树图标，提示写同一句。 这台电脑的 Harness 菜单脚部有「设为新会话默认」：之后这台电脑上每个新会话都从这个 Harness 与模型开始，在草稿里换一个只影响那一次（开始或重新载入后回到默认，也不写入记忆）；「取消新会话默认」后回到这台设备记住的上次选择。其他设备看不到也收不回这个默认，所以它只在这台电脑上生效，其他设备照旧记住各自的选择。它的 Harness 或模型用不了时（例如移除了服务的地址）默认不生效，也不替它换一个，恢复后重新生效。
- **Harness**（[ModelControl.tsx](../apps/web/src/composer/ModelControl.tsx)）：磁贴与名字。菜单顶上一句「开始后这个会话不能换 Harness。」，每个可用 Harness 一行加一句能做什么，Latch 内置排最后；选模型从不换 Harness。开始后是不带箭头的磁贴与名字，点开说明不能换，并给「新会话」。
- **模型**：只写模型，等宽的 ID；经服务时前面是 14 的服务标记。Harness 还没报告的模型写「默认模型」，菜单里一句话说明原因（开始之前都是如此，因为 ACP 要开会话才报告）。外部 Harness 先列它自己的模型，再列已保存的模型服务：Latch 能把这个 Harness 的请求转给的服务（协议相同，如 Codex 与 Responses 服务、Gemini CLI 与 Gemini 服务）列出它的模型，组名写「<服务> · 经 Latch」（Codex 写「<服务> · 实验性 · 经 Latch」）；其他服务列出但不能选，写明原因（协议不同、转换尚未实现，或这个 Harness 还不能经 Latch），见 [MODEL-CONFIGURATION.md](./MODEL-CONFIGURATION.md)。Latch 内置列模型服务。
- **思考**（[ThinkingControl.tsx](../apps/web/src/composer/ThinkingControl.tsx)）：小字「思考」加值。Latch 内置写自己的词（默认、低、中、高……，档位来自 设置 › 模型 里对这个模型的声明）；外部 Harness 写它自己报告的名字（`Low`、`High`），每档下面是它自己的一句说明。没有值或没有报告时写「默认」：这时不画箭头，但总能点开，菜单里只有「默认」一行和至多一句原因，因为触屏没有提示框。只有 Harness 报告了档位才有可选的行，Latch 不替没声明的模型编档位。会话里 Latch 内置换档与换模型一样从下一条消息起生效，写「下一条：低」。
- **权限**：始终显示、始终能点开（触屏没有悬停），菜单头是「什么时候问你？」。开始之前来自 `HarnessInfo.permission`：Harness 会询问时写「先问你」，下面说其他档什么时候能换：读取会报告模式的 Harness 写读取中、读取后可以换或没读到，打开权限就读取，Codex 这类读取不报告模式的写「发第一条消息后可以换」（见 [HARNESSES.md](./HARNESSES.md)「开始前的选项」）；Latch 知道它的模式时下面一行用这一档在这个 Harness 里的说明（与开始后同一行），否则写通用的一句；执行工具前不询问（「不询问 · 由 pi 决定」，下面一行说扩展要求确认时才问你）和读不回（「权限无法确认」）是琥珀色；Latch 没有 profile 的 Harness 能读取时写「读取后可以选」，打开权限就读取，读取中写「正在读取…」；读到的列表没有模式或读不了时写「开始后可以选」。开始后（或读到列表后）列 Harness 报告的模式：有档位的标题是「只看不改」「先问你」「按规则放行」「由模型判断」「不再询问」，下面一行是这个 Harness 自己在这一档怎么做；模式超过三个时只列三行主档，其余在「更多」里，当前的总在（见 [HARNESSES.md](./HARNESSES.md)「权限菜单」）。只有「不再询问」的标题、说明与图标是琥珀色。任何能发起会话的设备都能直接选任何一档，不弹确认；设备按 Harness 记住人选的档位，Latch 不替人选更宽的一档。这些限制只写在菜单里，输入框下面没有长句。
- **模型的判断**：Harness 自己的模型审阅一次请求的行写「Codex 的模型审阅」，图标是天平，状态词是「放行」「拦下」或「没有判断」，不是人的批准，不用决定记录的写法；拦下不算失败。Harness 在运行之前自己拦下的调用仍是那次调用的行，图标是禁止符号，状态词「拦下」，下面一行灰字写是谁拦下的与它自己的理由（「Claude Agent 的模型审阅：…」「被 Claude Agent 自己的规则或当前模式拦下：…」），不是红色，没有「重试」。在「由模型判断」档里没有问人就运行的调用，状态词是「没有问你」。
- **第一次用**：Harness 按设备记住。没有记录且可用 Harness 不止一个时询问，什么都不预选；只有一个会询问的 Harness 时不问；不替人选完全访问的 Harness，也不用 Host 的默认代替询问；只有这台电脑上由本人「设为新会话默认」的 Harness 才不问。分叉借用来源的 Harness、项目与方式，以及来源当时的模型、思考与权限档（换 Harness 时按值与档位对应；权限用同一档或更严的最宽一档，目标 Harness 两者都没有时用它最严的一档，可能比来源宽，这时和其他对应不上的一样在分叉说明下逐条写明），只对这份草稿有效，不写入记忆。其他设备只有内置 Harness。
- 新会话从哪里开始就在哪里：在打开的会话里新建时，预选那个会话所在的项目；从侧栏项目组的「+」新建时预选那个项目；其余用上次的选择。选择按设备记忆，并按 Host 当前目录修正。
- 缺少可用模型或 Harness 时显示一张卡片：缺模型服务时它的「添加模型服务」在卡片里原地展开同一块添加面板（服务的磁贴每格至少 104 宽，一行排下卡片宽度放得下的个数，弹层里是三列），其他情况通往设置。演示模型在顶栏（手机在面板）有明确标记。Host 不发目录时只保留「对话 / Agent」分段控件。

**会话。** 顶栏（画布内 48）左侧是项目与标题：项目是幽灵按钮，打开项目弹层（见下）；会话在自己的文件夹里时只有文件夹图标，也打开它；标题也是一个幽灵按钮，悬停时露出向下箭头，打开会话菜单（重命名、置顶、归档、导出 Markdown、删除）；接着是不是默认时的状态词（失败为红字，已取消、已中断、正在取消为提示墨色；运行中与已完成不标）。右侧依次是连接状态（只在连接不正常时出现：琥珀字写出状态与「· 重试」并带刷新图标，静止时没有底与边，悬停才有淡琥珀底，没有圆点，手机上同样写出文字；点击同步）、完全访问会话的琥珀状态词（`shield-alert` 加「完全访问」）、演示标记（"演示模型"，手机为"演示"）、「侧边面板」开关（每个宽度都有，打开时是中性的悬停底，不用蓝色）与更多菜单（会话的操作与「同步最新状态」；新会话页里只有后者）。手机上标题是文字，会话的操作都在更多菜单里。连接中断或离线时，消息区顶部有一行琥珀色提示：三角图标与琥珀色标题（「连接已中断，正在重连…」或「当前设备已离线」），说明为次级墨色，右侧「重试」。Host 宣布过原因时，标题改为这个原因与开始时间：「电脑已休眠（22:41 起）」「电脑上的 Latch 正在重启」「电脑上的 Latch 正在更新」「电脑上的 Latch 已停止（21:03 起）」，说明写何时自动重新连接；桌面端再按主进程的判断写出「Latch Host 意外退出，2 秒后重新启动（10 分钟内第 2 次）。」等，反复崩溃后停止自动重启或 Host 没有响应时这行提示为红色，前者右侧换成「启动 Host」。

**对话与回合。** 对话按回合排列（[Transcript.tsx](../apps/web/src/components/Transcript.tsx)，推导在 [conversation.ts](../apps/web/src/conversation.ts)）：一个回合是用户的一条消息和回答它的一切。回合之间 32，回合内的块之间 12；只在悬停时出现的东西盖在回合下方的间隙里，不预留空间。对话列的第一行在顶栏下 16，避开 16px 的渐隐。只有用户消息有气泡：右侧的中性气泡，超过 176 高时收在渐隐后，带「显示全部」；下面是时间、「复制」与「从这里编辑」（在这条消息之前分叉，文字进入输入框；第一轮没有），桌面上悬停或聚焦时淡入（120ms），触屏上最新一条常显。消息送达的过程写在气泡下：发送中、Mac 已收到、Agent 已开始，Agent 开始回答后消失。页面亲眼看着到达的消息才有到达的动效：用户的气泡上移 6px 淡入（`--m-enter`），回复的第一块淡入（`--m-micro`），流进块里的文字不动；加载、重连与切换会话不播放。每个回合以作者行开始：16 的 Harness 标记、Harness 的名字，后面是提示墨色的模型；演示模型回答时模型前写「演示」。撤销之后下一条消息带给 Harness 的说明不进气泡，在气泡上方写一行「已告诉 Harness 改动被撤销了」。分叉出来的会话在第一轮之上写一行来源。

**工作行。** 思考与每次工具调用都是一行安静的工作（24 高，手机 28）：24 宽的图形列（16 的图标；运行中是 12 的蓝色转圈；失败是 12 的红色叉号）、按工具类型的动词加对象（文件写文件名，命令与搜索词是等宽字；读不出对象时只写工具自己的标题；工具声明了标题时写这个标题加对象；既没有标题、也读不出对象的工具写它的原名，不猜）、改动的行数，紧跟着 12 的箭头，展开时转 90°。行尾常驻决定的记录（「已允许 · 14:36」「已拒绝 · 14:32」「已过期」），用时只在悬停时出现。同一类的行相邻时图标只出现一次，紧接在展开的行之后除外。结束的回合里相邻的读取合成一行「读取 4 个文件」，展开是它们原来的行；运行中不合并，行不会跳。文件编辑写「编辑 providers.ts」加增删行数，新文件写「新建 a.ts · 42 行」；展开是最多 12 行改动的预览（新文件最多 8 行）和「在改动中打开」（新文件是「打开文件」）。右侧面板打开时它只有一行，选中文件时带悬停底，点击在面板里打开这个文件。其他工具展开是参数与输出，向内缩进 28，最高 320；输出在自己的框里，运行中跟随最新的行，运行中的命令有输出时自动展开，结束后收起。失败的行下面一行写第一行原因（不含内部代码）和「重试」，「重试」只出现在这一轮最后失败的地方。Agent 在审批未通过时仍报告执行了调用，行下多一行写出来。思考行运行中写「思考中」（带光）与秒数，身体自动展开，答案开始后收起并写「思考了 6 秒」。

**折叠的工作。** 回合结束后，工作收成一行「已工作 2 分 13 秒 ›」，下面一条 60% 的细线；Host 没有记录用时的旧历史只写「已工作」。折叠只收工作行：工具之间的正文和答案永远不折叠，问题和它的回答留在阅读顺序里。这一行不掩盖问题：折进去的行有失败或被拒绝时写出来（「· 1 步失败」「· 1 步被拒绝」）。失败、停止、中断的回合，以及结束时没有一句话的回合，工作保持展开。工作行在回合运行与结束时是同一棵树，页面亲眼看着回合结束时它们收起（网格行加淡出），重新打开的会话直接是收起的样子。

**状态行。** 运行中的回合以一行状态结束，说的是真实在运行的东西，不只是时间（[StatusLine.tsx](../apps/web/src/conversation/StatusLine.tsx)）：「运行中 · 0:47」「命令运行中 · swift test · 1:12」，全局只有这一种走时格式，文字每秒最多变一次。模型或命令沉默超过 Host 的阈值时变成琥珀色的询问：「等模型回应 · 3 分钟没有新内容」「pnpm test · 12 分钟没有输出」，带「继续等」（Host 翻倍这一轮的阈值）和「停止」；Agent 发来 Latch 不认识的请求而之后没有动静时写「Codex 发来一个看不懂的请求 · 查看」。按下停止后写「正在停止…」，直到真实结算。等你允许或回答时这一行不出现。连接中断时不再转圈或走时，只写「上次确认 10:42」。运行不是以普通回答结束时，回合下留一行：「Codex 已退出 · 这一轮没有完成」为红色，强制停止与中断为琥珀色，并列出结果未知的命令，带「重试」与「在新会话中继续」。

**回合卡片。** 结束的回合有文件变化时带一张卡（[TurnCards.tsx](../apps/web/src/conversation/TurnCards.tsx)）：「改动了 3 个文件 +64 −8」「显示文件」展开每个文件，点一行或「打开改动」在右侧面板的「改动」页签打开这一轮和这个文件；设备的数据范围不含项目文件时打开这个文件：工具编辑过的显示它的修改记录，只被命令改过的显示文件本身，已删除的不能打开。数字来自 Host 这一轮的记录；回合与记录按时间匹配，有歧义时不匹配，因为撤销本轮只作用于匹配到的那一轮。没有记录（旧 Host、设备的数据范围不含项目文件、匹配不上）时卡片来自这一轮工具的编辑和观察到的文件变化，没有撤销。「撤销本轮」在卡片头部，或在同一位置写出不能撤销的原因（运行中、之后又改过这些文件、内容没有留存；另一台设备上的 Agent 会话写「在 Mac 的 Latch 中撤销」）。有文件恢复不了时先在卡片里列出，确认后才执行，否则立即执行。撤销后卡片让位给一行记录「已撤销本轮改动 · 恢复 · 下一条消息会告诉 Codex」和没有恢复的文件；消息发出后「会告诉」不再出现。撤销或恢复没有得到答复时写「结果未知」，重试用原请求；Host 的记录表明已经生效时就按记录显示。Host 拒绝或回到页面时重读记录，另一台设备的撤销由此反映；卡片与「改动」页签在同一设备上互相通知，一处撤销后另一处随之更新。记录不完整时（文件夹太大）卡片写出，撤销碰不到没列出的文件。这一轮新生成的文档与媒体在「生成了 2 个文件」卡片里，每个文件一个「打开」；所有改动都是这些文件时只有这张卡，撤销放在它的头部。

**回合脚部。** 结束的回合的事实与操作盖在回合下方的间隙里（24 高，提示墨色、等宽数字），悬停或聚焦时淡入，触屏的最新一轮常显、点按显示其他的：回复发出的时间（悬停写开始、结束与不含审批等待的用时）、用时、「输入 12.4k tokens」「输出 850 tokens」（各步合计；手机宽度下省掉单位，写「输入 12.4k」「输出 850」，回合有「已工作 …」时省掉与它重复的用时，仍放不下时最后一格以省略号结尾），经 Latch 转发的回合用网关从服务回复里读到的令牌，提示里写明来源和每个模型的请求，没有令牌可写时写「经 Latch 3 次请求」（见 [HARNESSES.md](HARNESSES.md)「每轮的模型与用量」）；Agent 只报告整个会话的上下文时最新一轮写「上下文 74k tokens」；然后是「复制」「重试」（最新一轮；可能重复副作用时先在回合里说明要重复什么）、「从这里分叉」和更多菜单（复制到这里为止的记录）。服务说回答的模型与选的不同时，作者行写服务说的模型，旁边一段中性的「选的是 gpt-5.5」，提示写全两者；手机宽度下「选的是」另起一行，缩进到名字下面，两个名字都只在自己比屏幕宽时才截断。远处的回合跳过绘制时会裁掉盒子外的东西，所以结束的回合把下方的间隙算作自己的内边距，脚部始终在盒子里。没有正常完成的回合另有一行常驻的记录：「已停止 · 14:33 · 保留了部分回复」，失败时为红色并带「重试」。

**回合之间的分隔线。** 会话本身在两轮之间变了时，后一轮的气泡上方画一条横贯对话列的细线（`--line`），提示墨色的字在中间（[Transcript.tsx](../apps/web/src/components/Transcript.tsx)）：清空上下文写「清空了上下文」并带橡皮擦图标；模型或思考深度变了只写变了的那一项：「模型 small → large」「思考 低 → 高」，两者都变时「small · 低 → large · 高」。值来自 Host 记在助手消息上的模型与思考，没有记录的不画。iPhone 画同样的线（`TurnView.swift`，文字来自 `PhoneConversation`）。

**两轮之间的 Harness 命令。** 带 `idleOnly` 的 Harness 命令（pi 的 `/compact`）和其他 Harness 命令一样在斜杠菜单里插入可编辑的草稿，运行中不列出；运行中手动发出时输入框上方写 Host 的拒绝「/compact 不能排队或追加，请等本轮结束后发送。」，草稿留着。

**清空上下文。** 输入框的 `/clear`（斜杠菜单里「这个会话」一组，排在 Harness 命令前，选中后清空输入）与会话菜单的「清空上下文」都只在本设备上选定下一条消息开始新的上下文，不发请求：输入框上方出一个抽屉，写「下一条消息开始新的上下文」与「Codex 看不到之前的消息，记录仍留在这里。」，右侧「保留上下文」撤销；会话菜单里同一项这时写「保留上下文」。选定后点最新一轮的「重试」，重发的这一轮也在新的上下文里。运行中这一项不可选，写「这一轮结束后才能清空上下文」；一轮开始时选择撤掉、抽屉收起。Harness 不支持时两处都不出现。清空上下文的那条消息被拒绝而 Agent 已放下旧的会话时（Host 的 `contextCleared`），抽屉写「下一条消息开始新的上下文」与「上下文已经清空，Codex 看不到之前的消息，记录仍留在这里。」，没有「保留上下文」，`/clear` 与菜单项也不出现，下一条消息发出后抽屉收起。iPhone 在输入框上方写同样两句，对话里同样画「清空了上下文」的线，但还不能自己选清空上下文。

**说明。** 会话里的系统说明是一行提示墨色的记录；报告失败（模型服务出错、运行被中断）时与失败的工作行画法相同：红色叉号、红字、「重试」。

**回到最新。** 读者离开最新输出时，输入框上方 16 处浮起 32 的圆形按钮（上移 8px 淡入，`--m-enter`；回到底部时以 70% 的时长淡出），带离开后新到的块数。有等你允许的请求、而它的卡片不在视野里时，这个位置变成琥珀字的「等你处理 ↓」，点它滚到那张卡片，不在视野里才出现；读者上翻时有问题等你回答，同样写「等你处理 ↓」。块数按会话计，切换会话不算新内容。

**计划。** Harness 报告计划时，最新一轮的作者行下有一行工作「计划 2/5 ›」，展开是步骤列表。步骤的标记是静止的：空心圆、带点的圆（进行中，正文墨色与 500 字重）与对勾，已完成的步骤最淡；会话停下后，进行中的那一步读作未完成；步骤状态变化时标记交叉淡化。

**运行条与输入框。** 运行中输入框仍可编辑（占位写「可以先写，本轮结束后发送…」），但需等本轮结束才能发送；空闲时占位写出收件人（「回复 Latch 内置…」）。运行条只在一次停止的结果未知时出现在输入框顶部（高度随展开动效变化）：停止结果尚未确认时「尚未确认 · 重试」，这是唯一说它的地方：结果未知不是失败，不出红色提示，顶栏与侧栏也不说「正在取消」；以及计划小块。每张等待中的卡片用 IntersectionObserver 报告自己是否在对话滚动区里露出，运行条只读这一个结果。运行在做什么、做了多久由对话里最新一轮的活的一行说，运行条不再写。停止键是浮起的圆、`--line-strong` 的边与实心方块，停止不是风险操作，不变红；停止进行中它转圈且不可按（`aria-disabled`），结果未知时仍是方块，再按一次就是再停止一次。等待提问时这一格也是停止键（退为中性填充），写了回答才换成发送，触屏上停止键留在发送旁边。运行开始或结束时，发送键与停止键在同一格里替换（从 90% 长到原大并淡入 120ms，只在页面看着它变化时）。输入框随内容按行长高，最多八行，高度过渡 120ms（量高度时先撤掉过渡、放回原高，再设新高度，所以从原来的高度开始走；减少动效时直接变化）。输入框浮在自己的阴影上，聚焦时环换成 `--line-strong`，不变蓝：静止与聚焦的阴影是框上的两层，交叉淡化（进 `--m-micro`、出它的 70%），阴影本身不做动画；发送是输入框里唯一的蓝色按钮，没有内容时退为中性填充，仍可聚焦，提示框写出原因（「输入内容后发送」，或不能发起的原因），可用时提示框写出快捷键；发送中箭头与转圈交叉替换。这台设备只能查看时（完全访问会话在执行端以外的设备上，或没有发起权限），输入框换成虚线框、凹陷底，里面是锁与原因；运行条与停止键保留。不再接受输入的会话同样如此。模型或思考的切换从下一条消息起生效，触发器写「下一条：…」，菜单脚部第一行是「撤销切换，继续使用 …」；Agent 自己报告的模型与思考选项也在工具栏里，其他选项在页脚的「⋯」里（手机在输入框下面一行）；会话不再接受输入时，它们的当前值与原因写在标题行项目的弹层里（手机与没有项目弹层的会话写在启动面板下）。桌面 Enter 发送、Shift+Enter 换行；触屏设备 Enter 换行；⌘/Ctrl+Enter 总是发送；输入法组字时不会发送。

**项目弹层。** 顶栏的项目按钮打开：分支、会话的每个文件夹（完整路径，这个 Agent 用不到的是提示墨色；这个文件夹已找不到或已移出项目时带标记；可复制，桌面端可在访达中显示），多文件夹时写出这个 Agent 实际用哪些；位于 Latch 程序目录内时的琥珀提示；上下文用量；整个会话的输入与输出（悬停写出各部分）、Agent 报告的费用（注明「由 Agent 报告，不是账单」）、各轮用时合计与轮数、开始于。每轮的数字在回合脚部。

**设置。** 分区：通用、模型、Harness、项目、快捷键、关于，手机上另有插件与设备。模型、Harness、项目与插件需要「管理此 Host」权限，没有该权限的设备看不到它们。面板顶部是「搜索设置」（`/` 聚焦），按分区名和行上的词过滤。页面标题在标题行，内容最宽 640，组与组之间 32；组是标题加画布上的行，行之间是细线，不画卡片，所以页面里没有框中框。

- 通用：外观是三张小窗口（跟随系统、浅色、深色）；发送消息是分段控件，自动打开新文档是开关，这两行手机上不显示；桌面端另有通知（完成或需要我处理时、通知中显示标题）。「这台 Mac」写名称，桌面端有「登录时打开 Latch」「有任务时保持 Mac 唤醒」。Host 停止时的启动入口在连接横幅。
- 模型：「模型服务」每行是磁贴、名称（本地与默认是小字）、模型数、状态与 ⋯。状态来自这次打开页面时的模型列表请求（不消耗 tokens），不从是否存了密钥推断：回答了写「已连接」，拒绝密钥写红色「密钥无效」与「更新密钥」，连不上写红色「连不上」，服务不提供列表时什么都不写；还在问时写「检测中」。缺密钥与地址未确认是琥珀字。其他设备上「更新密钥」保持可见但不可用，提示写明去处。⋯ 里有编辑、更新密钥、刷新模型列表、移除。「添加模型服务」是 480 宽的面板：品牌网格（末项「自定义地址…」）、地址、密钥、检测连接，找到的模型是一列开关（12 个以内默认全开），也能手动加模型 ID；保存按钮写「保存」，地址要确认时写「用 Touch ID 保存」。新会话卡片、模型菜单与这里打开的是同一张表单（[ProvidersSettings.tsx](../apps/web/src/settings/ProvidersSettings.tsx) 的 `ProviderAddForm`），标题、末项、字段名（「地址」「密钥」，报错里也是）与保存字都相同，只有外框不同。其他设备上送人去 Mac 的句子写出电脑名（`computerName`）。模型的思考深度没设时写「思考：默认」。「用量」是 7 或 30 天的总量与模型、输入、输出表，精确数字在提示里，不画图、不估价。「显示的模型」是一列开关（六项起可搜索），只影响这台设备。
- Harness：「已安装」列出 Latch 内置与已添加且找得到程序的 Harness（状态词加启用开关，点开是启动方式、环境变量、检测与测试启动），「可以安装」列出没有添加的预设和找不到程序的定义。添加只收录可在本机安装运行的程序：许可证可核对的开源程序，或厂商官方支持的命令（Claude Agent、Cursor，许可证一栏写明专有与条款），Latch 不替你安装。
- 项目：每行是图标、名称、「N 个文件夹 · 路径」（路径从中间省略）与 ⋯（重命名、添加文件夹、在访达中显示、编辑、移除）；点开编辑器管理名称、十种中性图标与有序文件夹。第一个是主文件夹；支持键盘上下移动、拖动排序、设为主文件夹、移除和对缺失文件夹重新选择。添加与重新选择只经桌面端原生面板。不可用项目与每个失效文件夹保留并写明原因；活动会话使用的文件夹不能移除。启动目录是同一列表里的一行。列表下写 Host 真实的快照上限。
- 插件：按架子列出（工具、技能、连接），每行写已开启、未开启或需要处理；点开是这个插件的一页，开关在第一行；自定义插件应用过之后也有这个开关，不必打开编辑器。模型服务与 Harness 只在各自的设置页，这里不重复；一个人自己的包提供它们时仍算插件。内置插件写「始终开启」。
- 快捷键：可搜索的列表，只列当前平台的按键。
- 关于：图标、版本（开发版标记只在这里）、许可与条款（Latch 的开源许可，与每个 Harness 预设的许可证或条款）与一句话「Agent 和插件以你的权限在这台电脑上运行。」。
- 设备：见下。

**插件包界面。** 一个插件包可以同时提供技能、工具、界面与 Harness，只出现一次，能力按类别计数。「添加插件」从技能、工具、界面模板开始，或导入文件。编辑器与插件页都有一组「代码在哪里运行」：界面面板发到每台能查看会话的设备，在那台设备的 Latch 页面里运行，没有隔离，iPhone App 不运行它；工具和后台代码在这台 Mac 上运行，权限和 Latch 相同，也可以注册界面面板；技能和静态面板只是文字。编辑器随表单里的声明变化，在高级声明里按正在输入的文字（能解析时）说；插件页说保存的声明与 Host 正在运行的能力的并集，因为后台代码可以注册声明里没有的面板，草稿也可能去掉已应用版本仍在发送的面板；读不到声明时说明并可重试。文字在 `securityCopy.ts`。确认句不变。会话面板的标题与来源可见，加载、失败、空内容各有实际状态，失败允许重试。React 面板可以实现自己的表单和交互；示例见 `examples/`。

## 设备与权限

桌面端「连接手机」只有一个动作：打开配对表单。表单约 420×540，显示二维码与两行说明，二维码每分钟无提示地换一张，手机确认时变暗、模糊并停住，设备名称升到它上面，写「在系统窗口中确认」或「正在连接…」（手机还没报出名称时也是后者，这时 Mac 上还没有确认窗口）。确认之后表单没有关闭按钮，连按 Esc 也不起作用（`Modal` 的 `dismissible={false}`），只问「手机上显示已连接了吗？」：「是的，完成」或「没有，移除」（直接移除，不再弹对话框）。取消、超时、两台设备扫同一个码与其他网络的尝试各写一行在新二维码上方，下一张二维码没能生成时这一行仍然留着；没有网络或被完全访问的会话拦下时不显示二维码，也不提示扫码，恢复后自动出现；打开时这台 Mac 不能确认的，能确认后自动生成。没有地址、端口、权限选择、倒计时或复制。防火墙提示与「发送到其他设备」尚未实现，不显示；页面读不到这台 Mac 有没有 Touch ID（没有时系统窗口要的是登录密码），所以这里只说「系统窗口」。「关于连接」与空状态只说同一个 Wi‑Fi：官方中继尚未部署。

界面按设备的权限隐藏或禁用操作，只是为了不展示做不到的事；每条规则都由 Host 再次执行。门控规则集中在 [permissions.ts](../apps/web/src/core/permissions.ts)。

**安全文案。** 这些错误文案集中在 [securityCopy.ts](../apps/web/src/core/securityCopy.ts)。

**连接页。** 未登记或凭据失效的浏览器在侧栏灰上看到一张安静的画布卡片（[EnrollmentPage.tsx](../apps/web/src/components/EnrollmentPage.tsx)，静止卡片的 12px 圆角）：标题「连接到 Latch」、一句说明与一个主按钮「连接这个浏览器」，名称取自浏览器（「Mac 上的 Chrome」），按下才会弹出系统窗口。没有输入框、权限清单、校验码或倒计时；主按钮在 768px 起是 32px，手机上是 44px。链接允许管理这台 Mac 时（Host 经 `POST /link/api/enrollment-invitation` 回答，不用掉链接；只在回环上生效，桌面端的链接不含它，命令行的链接为没有桌面端的 Host 包含它），按钮上方一行琥珀色写「这个链接还可以管理这台 Mac」和「不要」，点后改成中性的「这个浏览器不会管理这台 Mac」和「还是要」；读不到回答时不显示这一行，也不申请。HTTPS 上的设备不申请，之后可以在设备页由 Mac 经本机确认开启。折叠的「连接详情」写名称、可以做的事与能看到的内容；等待时再加校验码与系统窗口的句子，校验码和 Mac 上「手机」页等待中的那一行（也在配对表单里，同样折叠）相同才是这台设备。经二维码的手机只有句子与权限：手机上没有校验码可比，它的核对是确认后的那一问。桌面端自己的第一次打开也是一张卡片：标题「Latch」、一句「第一次在这台 Mac 上打开 Latch。」与「继续」；这台 Host 还从未登记过设备时它不需要确认，之后桌面端再登记时那一句是「在这台 Mac 上用 Touch ID 确认后继续。」，名称取自这台 Mac（`enrollment-info` 只在 `host.sock` 上给 `hostName`），之后在「手机」页改；只有离线连接码的流程还有名称输入框，用 `TextField` 原语。提交后是「在 Mac 上确认」、一句说明、折叠的「连接详情」与「取消」。Mac 上取消、超时与密钥不一致用红色提示；需要邀请的入口要求重新获取邀请。本机确认不可用时，桌面端开头的说明改为用离线连接码完成登记（不再提 Touch ID），琥珀色提示写出原因与 `pnpm latch device enroll --offline`，表单只接受离线连接码，Host 接受离线连接码时正常表单下方也提供「使用离线连接码」；浏览器与手机上的琥珀色提示说明新设备要在运行 Latch 的电脑上确认，主按钮停用，不提供离线连接码。没有链接时只显示去哪里取：手机指向桌面端 手机 › 连接手机，其他电脑要运行 Latch 的人发来的链接，不写终端命令；这台电脑上的浏览器指向桌面端「在浏览器中打开」或 `pnpm latch device invite --loopback`；打开已经失效的链接时当场说明；浏览器无法在当前地址安全保存设备密钥时只显示一行红色说明，建议换用新版浏览器或桌面端。旧版登录状态显示「这台设备要在 Mac 上重新确认」并沿用旧设备名。撤销（红色）、满 30 天、换地址、丢失密钥、登记后浏览器没有保存凭据（例如禁止了 Cookie）与续期后浏览器没有保存新凭据（琥珀色）各有一行说明；后者建议允许 Cookie 后重新加载页面。设备名称可以包含表情（如「❤️ iPhone」「👨‍💻 Mac」）；含换行、不可见字符或改变文字方向的字符时，输入框下方用红色小字说明，提交按钮停用；旧设备名只在符合同一规则时沿用。登记完成后若第一次读取执行端状态失败，页面停在一行琥珀色提示与「重试」上，重试只重新读取状态，不会再登记一台设备。第一次连上 Host 之前，页面只显示「正在连接…」，失败时显示琥珀色提示与「重试」。

**新会话页。** 永远同一页：问题、项目、输入框。没选项目时问题是「要做什么？」后面跟「选择项目 ⌄」；列表依次是项目、「打开文件夹…」（系统面板选完立刻成为项目，被拒绝时列表重新打开并写 Host 的原因）和「不选项目」。选好后问题变成「在 rust-learn 里做什么？」，光标回到输入框。这里比只放按钮的首屏多一个输入框：人可以先写，按发送才问文件夹，草稿不丢，第二次按发送才开始。什么都不能运行时（[`nothingInstalled`](../apps/web/src/composerChoice.ts)，只在能保存定义的设备上）输入框上方是一张卡片：「没有找到可用的 Harness」、「先装一个：」每个预设一行安装命令与复制、「重新检测」和一行链接「也可以用 Latch 内置…」（就地打开添加模型）；已经装了程序只差适配器时（`AgentPreset.agentCommand`）标题是「还差一步」，那一行写「找到了 codex，还差让 Latch 连接它的适配器」。

**本机确认。** 只有这些操作要在这台 Mac 上确认：连接新设备、为设备增加权限、首次使用自定义或本机模型服务地址、把地址加入出站白名单、应用含代码的自定义插件。开始会话、放宽权限、批准操作、改 Harness 都不弹窗。按下后系统表单是唯一的窗口：发起的控件转圈，页面不重复表单里的句子；被取消或超时时一行原因留在原位。

**审批。** 审批在输入框上方的抽屉里决定（[ApprovalDrawer.tsx](../apps/web/src/composer/ApprovalDrawer.tsx)），会话记录里只留一行工具。中性表面，琥珀只给盾牌和「等你处理」；下面是做什么和对象、改动行数；工具的标题可能是它自己写的，所以工具 ID 与标题不同时总在下一行写出，只有普通的差异默认折叠在「查看改动」后，高风险、Agent 的询问、没有差异的调用和隐藏字符的内容一开始就展开参数与原因；按钮靠右，其余选择和「停止这一轮」在「⋯」。高风险的抽屉更高，原因单独一行红字，确认期间两个按钮都禁用。按钮到位 320ms 后才接受按压；Enter 不决定，Esc 拒绝一次（有文字时不拒绝）。几个请求用「‹ 1/2 ›」翻页。请求到达后在输入框打字时（[useRejectionNote.ts](../apps/web/src/composer/useRejectionNote.ts)）「拒绝」变成「拒绝并发送」，文字随拒绝交给模型，拒绝没有生效时文字回到输入框；Agent 的询问带不了文字，文字留作下一条消息。请求到达之前就写着的文字（[useEarlierDraft.ts](../apps/web/src/composer/useEarlierDraft.ts)）仍是下一条消息，不当作回答，清空后再写才算，问题的「其他…」也能认领它。文字发不出去（过长、含隐藏字符）时「拒绝」不受影响，直接拒绝并留下文字，只有按 Enter 才说明原因。结果未知时给「重试」，沿用同一 `requestId`。

**提问与排队。** Agent 的提问也在抽屉里：谁问、1/2、带数字键的选项、「其他…」把焦点交给输入框，那里写的就是这一题的回答。排队的消息在「排队」抽屉里编辑和移除；有文字且运行中时发送键变成「排队」。尚未实现：调整顺序、立即发送并打断（需要 Host 接口）。

**差异。** 折叠行只显示文件名、改动行数与展开控件，完整路径在提示与读屏名称中保留。展开后直接阅读改动，不常驻显示目录前缀、「新文件」或「新内容哈希」。Host 确认文件不存在时直接显示新增内容；文件存在但原文未能展示时保留琥珀色「原内容未显示」，没有说明时保留「原内容未知」，两者都说明可能覆盖已有内容且不显示删除行数。新增与删除行数仅在非零时使用相应色调。差异容器只有一层边框，代码区域不再套一张卡片。

`DiffView` 有三种模式。`hunks` 是默认：每段在 @@ 头下带符号与两列行号，审批提案必须这样完整呈现。`full` 用于审阅：一列行号、不画符号（3px 的色条表示增删）、标出改动的词、段之间是「N 行未改动」的带（每按一次展开 20 行），长行在代码区内横向滚动、页面向下滚动时文件头留在视野内；Host 或来源说明的新文件与已删除文件画成文件本身，不分栏。`compact` 是对话里的预览：没有头部，至多 12 行改动（新文件是前 8 行），每行截断在边缘，脚部写还剩多少。三种模式都照实说原内容未知或未显示，二进制文件不显示行数。`layout="split"` 时行内批注横跨两栏，两栏的行保持对齐。`gutter` 与 `annotation` 是留给评论的位置。目前工具卡、审批与文件历史都用 `hunks`，还没有页面使用 `full`、`compact` 与这两个位置。

**会话权限。** 只有完全访问会话在顶栏右侧显示琥珀色的「完全访问」状态词，前面是 `shield-alert`（手机上同样）；逐项询问（L1）是默认，顶栏不显示。输入框在以下情况换成带锁图标的只读说明（虚线 `--line-strong` 边的托盘，不带阴影，不像一个等待输入的输入框），运行条与停止按钮保留：Agent 定义变化、项目中的 Agent 配置在开始后变化、会话创建于安全升级之前，以及无法确认 Harness 已进入预期的权限模式为琥珀色，在这台设备的输入或选项修改被 Host 以对应错误码拒绝后出现。新会话选择器中的完全访问 Harness 带中性的 L3 小徽标（没被选中的选项不报警，选中后由顶栏的琥珀标记表达）。

**开发版标记。** Host 报告开发模式时（当前的构建都未经签名发布，所以总是如此），「设置 › 关于」在名称旁显示一个中性小标签「开发版」，悬停提示与读屏名称写明这台 Mac 上的程序可以修改 Latch 的代码。

**手机页。** [PhoneDevicesPage.tsx](../apps/web/src/settings/devices/PhoneDevicesPage.tsx) 在宽窗口上把「连接手机」、设备行与「关于连接」放在侧栏的位置，主区域显示一台设备，名称在标题行；手机上是一列设备，点开推入设备页（在「设置 › 手机与设备」）。正在看页面的桌面端就是这台 Mac，不算连接进来的设备，不列出；其他桌面端设备（比如钥匙串清除后留下的）仍持有桌面端的权限，所以列出并可以移除。已移除的设备不列出，记录在审计里。设备行只有图标、名称与上次在线（Host 不报告其他设备的实时连接，所以「在线」只说正在看页面的这台），⋯ 菜单是「重命名」与「移除」。设备页有名称（回车或离开输入框时保存，改其他设备的名称只能在 Mac 上）、上次在线与「移除…」：移除不需要 Touch ID，对话框与副行按设备类型说明之后要重新扫码或重新邀请，由它邀请的设备会受影响时一并写明，完成后显示 Toast。需要处理的状态写在设备页：三十天未验证只能查看，邀请它的设备被移除后只能查看并提供「恢复使用」（Mac 上经本机确认）。浏览器设备另有「可以管理这台 Mac」开关：关闭在任何能管理的设备上立即生效，开启只在 Mac 上经本机确认；手机不能开启，以前留下这项权限的手机同样显示开关，关闭后不再显示。页面不显示地址、端口、证书、中继、权限清单或指纹，Host 照常执行；HTTPS 入口只由命令行配置，手机地址不进入这个页面。设备名中的隐藏字符按审批区的规则显示为 `\u{XXXX}`，包括确认与 Toast 里的名称；改名时的校验与连接页相同。「在浏览器中打开」只在 macOS 桌面端的管理设备上出现，打开后在面板下方写一行灰色小字说明下一步，失败时显示红色提示，邀请码不在页面上出现。「关于连接」是一句关于中继的说明，有更早版本保存的中继或地址目录时可以在这里移除；新增尚未实现。「保持可连接」尚未实现，所以不显示。审批卡与错误文案统一说「运行 Latch 的电脑」。


配对被完全访问会话阻塞时，桌面端说明是哪一会话，并提供查看与停止；会话结束后重用仍有效的邀请。匿名登记请求不返回会话信息。

**模型服务与 Agent。** 桌面端以外的设备不能输入或更换密钥（仍可移除），字段换成一行原因与去处，命令行替代 `pnpm latch provider set-key <id>` 只在没有本机确认的桌面端给出；已保存的密钥注明「密钥只发往 <源与路径>」，修改地址时提示会清空密钥，改到没有确认过的地址时另说明保存时要用 Touch ID 确认。预置服务商地址的密钥直接保存，不弹确认；自定义与本机地址在桌面端确认一次（地址、密钥与出站许可一次确认），之后不再询问。已确认的地址在桌面端模型页列出（[ConfirmedAddresses.tsx](../apps/web/src/settings/ConfirmedAddresses.tsx)）：每行写出哪些服务在用、它带来的出站许可；移除要在对话框里说清后果，不要系统确认，因为只是收回，同一 `host:port` 没有其他地址在用时许可一起移除；不属于任何地址的许可也可以这样移除。没有桌面端时，在 Host 停止时从 `policy.json` 的 `confirmedAddresses` 移除，本机或局域网地址另外从 `hostEgressAllow` 移除，改动写入审计。已确认的地址出站许可被移除时，检测失败处给出「用 Touch ID 允许访问 <地址>」。添加 Agent，以及修改名称、启动命令、参数、环境变量与启用状态，任何能管理这台 Mac 的设备都可以做，不弹确认，每次改动写入审计；每个 Agent 标注中性的 L3 与许可证小徽标；未验证的定义在 Harness 行上就带中性小徽标「未验证的定义」并显示实际命令，不显示预设的说明，已验证的预设是默认，不加标记。程序不在这台 Mac 上的定义列在「可以安装」，不在「已安装」。

「登录」一组在「测试启动」之上，只在 Harness 有登录方式、状态或退出时出现：一行状态（「已登录」带 Agent 自己的标签与到期日，「还没登录」「已退出登录」「登录状态未知」），组标题右侧「重新检查」，没登录时下面列出登录方式（命令、复制、这台 Mac 上的「在终端里登录」），已登录时右侧是「退出登录」（Agent 能退出时，危险确认框）或「换账号」（展开登录方式）。下面的「测试启动」读到不同的登录状态时，这一组重新检查并跟着变；重新检查仍说已登录、最近一次测试启动却说还没登录时，标题是「登录可能已失效」，一行说明两者不一致，下面列出登录方式，「退出登录」照旧。登录方式只在这一组列出，「测试启动」里不重复。新会话上方，登录 10 天内到期时是一条琥珀色提示，不挡发送。

Agent 的「测试启动」沿用设置页的一组紧凑行：右侧一个 14 图标的次按钮，按下后不弹确认、直接运行，运行中按钮转圈、说明写「最多等待 20 秒。」，结果写「启动握手成功」「需要先登录」或「测试启动失败」。成功时明确写「登录状态与模型访问尚未验证」，能力只说 Agent 声明了什么；最近测试时间、程序名与版本用次级文字，不增加成功徽标；适配器驱动这个人自己装的程序时（Codex），两个版本写在一起，组合不在适配器构建时的范围内时下面一条琥珀提示「这个组合 Latch 没有核对过」，说明仍可以开始会话，不阻止启动。失败时诊断用可换行、最多 240 高的等宽区域和「复制诊断」，隐藏字符仍由 VisibleText 标出。结果未知时提供同一次请求的重试。旧 Host 没有能力标记时隐藏这一组。列表同时显示最近测试、当前可见会话数与最近会话时间；未开启过会话的定义写「还没有开启过会话」，与仅做握手的诊断区分。

**旧版 Host。** 快照中没有 `host` 时，Host 来自升级前的构建：界面退回旧规则（普通的允许与拒绝、由旧的主设备身份决定设置），隐藏设备、邀请与本机确认相关的界面，并在消息区顶部显示一行中性提示「此 Host 仍是旧版本，重启 Host 后启用设备确认。」；未登录的浏览器在这样的 Host 上看到「此 Host 版本过旧，请在电脑上重启 Latch。」

**审计回滚。** 审计记录被回滚时显示红色横幅，可核对或关闭。

**界面出错。** 工作区渲染出错时不会整页空白：显示一张卡片「界面出错，当前内容无法显示。」，提供「回到新会话」与「重新加载」；本机确认对话框不受影响。单条回复渲染出错时，这一条按纯文本显示。

## 流式与阅读

| 情况 | 界面行为 |
| --- | --- |
| 等待首段输出 | 最新一轮的状态行写正在启动 Agent 或运行中；不伪造思考内容或百分比 |
| 推理到达 | 思考行写「思考中」与秒数，身体自动展开并跟随最新的推理 |
| 正文到达 | 在稳定身份的同一消息行内更新 Markdown，完成后沿用该行；思考行收起并写出思考用时 |
| 工具调度 | 工作行区分等待执行、等待确认、执行中、完成、失败、取消；运行中的输出在自己的框里跟随最新的行 |
| 审批 | 合并在对应工具卡片内，展示原因、参数与预览；卡片写「等你处理」，回合里没有第二处说它，已运行时间停住 |
| 取消 | 请求中保留取消状态；超时显示"尚未确认"并允许重试（同一请求，不会停止之后开始的一轮）；要停止的一轮已经结束时立即退出取消状态，并用提示说明；部分回复保留，回合下留一行「已停止 · 保留了部分回复」（没有正文时只写「已停止」） |
| 结束 | 状态行消失，事实进入回合脚部；正常完成的回合把工作收成一行，正文不折叠 |
| 离线 | 保留已读内容；运行中的回合不再转圈或走时，写「上次确认 10:42」；连接状态单独标注，恢复并同步后才显示已连接 |
| 上翻阅读 | 进入阅读模式，流式输出不夺走位置；"回到最新"带着新到的块数，点它恢复跟随 |
| 切换会话 | 阅读位置按会话保存；旧会话的异步结果不得写入当前会话；消息内容层淡入，带遮罩的滚动容器不做透明度动画（避免可见控件失去点击命中）；不播放消息到达的动效 |

所有程序性滚动集中在 `useReadingPosition`（`jumpToLatest`、`reveal`）；消息与工具行使用 `data-message-id` 作为锚点。不要在组件中另外写入 `scrollTop` 或调用 `scrollIntoView`。布局改变、代码展开、展开块的动画与视口变化不等于用户主动滚动。思考与工具输出这类嵌套的滚动框用 `column-reverse` 从末尾排布来跟随最新内容，不写滚动位置。从改动面板定位到一个已折叠的工具时，页面先请折叠的祖先打开（与页内查找同一个 `beforematch` 路径），再交给 `reveal`。

Markdown 支持标题、列表、引用、表格、内联代码与代码块；回复里的原始 HTML 不执行：`<br>` 换行，注释不显示，`<details>` 与 `<summary>` 只留其中的文字并全部展开，其余句中的标签显示为文字、成块的显示为 HTML 代码块，文字不丢失；URL 只允许安全协议；只有网页与邮件地址是链接（加上回复自己的脚注），图片从不加载，网页图片显示为「外部图片：说明」链接；嵌套过深的回复以一行灰色说明加纯文本显示；表格与代码在自身容器内滚动；代码可复制与展开，剪贴板失败有明确提示；工具读取文件的输出按文件名着色；代码中的不可见字符显示为 `\u{XXXX}` 标记，工具栏注明「含不可见字符」，复制内容保持原样。实际点击的网页或邮件链接由桌面主进程直接交默认应用打开；脚本触发的外链另需确认。流式全文不设 `aria-live`，避免逐字播报。

**路径标记。** 回复里指向文件的链接（相对路径、`../`、绝对路径、`file://`，带 `:行` 的文件名也算）不是链接，是路径标记（[FileChip.tsx](../apps/web/src/components/FileChip.tsx)），点击从不让页面离开：中性的 `--hover` 小块（悬停、按下与菜单打开时 `--press`，圆角 4），前面是按扩展名选的 12 号文件类型图标（演示文稿、表格、图片、文档、代码、压缩包、文件夹，其他是普通文件），后面是链接自己的文字，文字就是路径或文件名时用等宽字。一行放不下时从路径的文件夹部分省略，文件名始终完整（`/Users/me/acme/…deck.pptx`），完整路径在提示里。在桌面端，看起来像路径的行内代码（`deck.pptx`、`src/app.ts:12`）在回复结束后、Host 确认它是会话文件夹里的文件时，也画成同样的标记，其余行内代码不变；完成的工具打开后，最上面一节「文件」列出它读写过、Host 确认存在的文件。文件图片（`![说明](chart.svg)`）是同样的标记：次级墨色的「图片」，然后是说明，最后是三级墨色的文件名；没有说明时只有文件名。每台设备上点击都打开同一种 260 宽的菜单（手机上是底部面板）：标题是文件名，然后是可做的动作，分隔线后是「复制路径」，底部一行写原因或去处。不在 Latch 桌面端时只有「复制路径」，底部带锁写「在运行 Latch 的 Mac 上用桌面端可以快速查看和打开。」；没有文件动作的旧桌面端写「重新启动 Latch 桌面端后，可以在这里快速查看和打开。」（info 图标）。复制后图标换成勾（120ms），读屏播报「已复制路径」。在桌面端的会话里，点击先问一次 Host（400ms 内有回答就直接带着结果打开，更慢时先写「正在检查…」；问的过程中再点同一个标记不会再问，双击的第二下不会关掉菜单），菜单只列 Host 允许的动作「快速查看」（仅 macOS）、「用默认应用打开」「在访达中显示」（按平台叫「在资源管理器中显示」「在文件管理器中显示」），「复制路径」复制的是从会话文件夹算起的完整路径（不带行号），可以直接用于访达的「前往文件夹」或终端。不提供的动作直接不出现，原因写在菜单底部的一行，文案来自 `securityCopy.ts`：锁只用于 Latch 有意拒绝的情况（可能含密钥、Latch 的私有数据、不在会话的文件夹里、会话的文件夹已不在项目里、类型不放行或暂不快速查看、内容与扩展名不符），并写出原因与去处，例如「网页和 SVG 用浏览器打开时可以联网，Latch 不直接打开；可以在访达中显示后自己打开。」「这个文件不在会话的文件夹里，Latch 不替你打开它。复制路径后，可以在访达中按 ⇧⌘G 前往。」；去处与说明用 info 图标（「这是文件夹；Latch 只在访达中显示项目的文件夹。」「重新启动 Host 后可以在这里打开文件。」）；没有成功的事用 circle-alert（「找不到这个文件。」「没有找到能打开这个文件的应用。」「上一个操作还没有完成，请稍后再试。」）。成功不提示（访达、快速查看或应用本身就是反馈）；被拒绝或失败时菜单重新打开，底部写出原因。旧 Host 缺少文件预览能力时保留这一菜单；支持内容服务时，单击改为打开文件标签。

## 验收

UI 改动需要在桌面、平板、手机宽度检查真实渲染，覆盖正常、进行中、失败或等待状态，以及浅色与深色。`e2e/design.e2e.ts` 覆盖 320 / 375 / 414 / 768 / 1440px 的可达性、溢出与真实点击区域，包括开发版标记；`e2e/enrollment.e2e.ts` 在 1440×1000、768×1024、390×844 下截取连接页的表单、等待、拒绝、本机确认不可用与旧版重新确认，并检查连接页在注入的样式下不变；`e2e/permissions-ui.e2e.ts` 截取高风险审批与拒绝后的记录、拒绝时写下的说明、浏览器里完全访问会话的询问（桌面与手机）与权限漂移（含深色）；`e2e/visual.e2e.ts` 在 390×844、768×1024、1440×900 下以浅色与深色截取浏览器能到达的每个状态与原语总览页（`ui-gallery`），并可与上一次运行逐像素比较（见 [TESTING.md](TESTING.md#视觉截图)「视觉截图」）。原语的角色与名称、键盘、焦点、提示框、禁用与运行中、对话框的焦点限制与归还、手机上的底部面板、触屏命中区、减少动效，以及转圈的同一相位与离开视野时暂停、状态词与状态槽、只为亲眼看到的变化播放的一次性动效、动效令牌与减少动效，由 `packages/ui/test/` 在真实浏览器里检查（`pnpm test --project @latch/ui`）。截图写入被忽略提交的 `test-results/`，不包含任何凭据。桌面端才有的界面由 `e2e/desktop.e2e.ts`（`LATCH_ELECTRON_E2E=1`）覆盖并以浅色与深色截图：审批卡里的高风险审批、行内卡片（等待、没有执行与被完全访问会话挡住）、手机配对（未生成、二维码、过期与被运行中的会话挡住）以及桌面端可以回应的「仅提示」询问。浏览器尺寸模拟不等于 iOS/Android 真机的软键盘、后台挂起与读屏验收。

Electron 另截输入框与设置里的行内确认；自动化不会替代系统表单的人工验收。

从模型选择器添加模型服务时，预置服务和自定义地址都在同一个弹层内使用与设置页共用的表单：可手动填写模型 ID，自定义地址只确认一次；保存后关闭弹层并选中它的默认模型，按钮不另写「保存并使用」。有「管理」但不在这台 Mac 上的设备，两个外框的规则不同，这是有意保留的：设置页的对话框可以先不填密钥保存需要密钥的服务，等在 Mac 上填写；原地面板不打开这类服务（以及地址未确认的无密钥服务）的表单，只说去哪台电脑，因为从这里开始的会话用不了它。

## 工作台搜索与起步

会话切换保留原会话的未发送文字，返回相同会话 ID 才恢复；切到其他会话不带入。最多在内存保留二十份、合计 256,000 个 UTF-16 字符，优先保留最近使用的草稿，不写浏览器存储。提交确认后清除该会话缓存，换设备清空，撤回个人访问时清私有草稿。新建会话仍从空输入开始，未知提交继续复用原请求，不从草稿另发一次。

手机的列表搜索先显示标题匹配，再显示「内容中包含」的正文结果；其他宽度由命令面板搜索。正文请求防抖 300ms，旧查询在切换时取消；命中项保留原会话与消息身份，通过阅读位置控制器定位，短暂提示该行。归档视图提供批量恢复和删除，支持 Shift 范围选择，部分失败保留失败项供重试；删除前明确说明只删除记录。

⌘K（Windows/Linux 浏览器为 Ctrl K）打开命令面板（[palette/](../apps/web/src/palette)）：宽 576、距顶 12vh、最高 420、无模糊的薄遮罩。未输入时是「最近会话」与「命令」，有请求等你处理时命令里多一行跳转；输入后依次是「会话」「文件」「Agent」「设置」「命令」，「在消息中」总在最后。再按 ⌘K 收起。Esc 先清空输入、再退回上一层（「搜索项目文件」是一层，⌘P 直接进入），最后才关闭；页脚的字随之写「返回」或「关闭」。关闭后键盘回到输入框，除非刚运行的动作把焦点带走，或是触屏（不弹键盘）。回车打开的是看到的那一行：第一行一出现就按身份记住，迟到的结果或重新排序的会话不会换掉它，被推到视野外时跟过去；输入法组合期间回车不触发。「会话」最多二十行，多出时明说。关闭面板或查找条后，接着落下的 Esc（以及按住不放的 Esc）不会停止运行，也不会拒绝请求，要先停顿半秒或按过别的键。搜索进行中写「正在搜索消息…」，失败写「消息搜索失败：原因」，只有 Host 答完才写「消息里没有「…」」或「没有匹配结果」；结果不全时明说。危险动作只从其具体页面执行；缺少能力的旧 Host 不显示对应入口。文件检索只在 Host 声明能力、设备拥有完整文件数据范围且预览回调可用时出现。

⌘F 打开当前会话的查找条：宽 300，浮在对话右上角（距顶 10、距右 20），不挤压对话；匹配在会话最上方、滚动也无法移出条下时，内容下移到让出它为止。条已打开时再按回到输入框并选中文字。Enter/Shift Enter 切换、Esc 关闭并归还焦点；匹配用选区色，当前项更深。文字通过 CSS Highlight API 标记，不替换消息 DOM；搜索也覆盖尚未挂载的工具输出，只展开当前匹配所在的卡片；最多五百项，不为查找挂载全部输出。匹配的内外折叠经 `beforematch` 展开，滚动仍只由阅读位置控制器写入：当前项已在可读范围内就不滚动，否则放到视口三分之一处，长回答里的匹配同样如此。运行中新增的文字只更新计数，读者留在当前项：匹配按所在行与行内次序认定，前面多出匹配时序号跟着变，高亮不换。

快捷键只有一张表（[workbenchShortcuts.ts](../apps/web/src/workbenchShortcuts.ts)），命令面板与设置 › 快捷键（⌘/，手机上没有）只显示当前客户端的按键，且只列已经实现的绑定。

首次使用的新会话页显示三个可操作步骤：选择 Agent 与模型、选择项目、写下首个任务；已有模型或项目显示勾选；Agent 与模型直接复用当前页的添加面板，保留草稿。每步可以跳过，产生首个会话后隐藏，关于页可重新显示。真实模式提供三个只填草稿的任务灵感，演示模式仍使用标明演示的示例。桌面端首次后台任务完成后，仅在前台显示一次「开启通知 / 暂不需要」；选择经主进程持久化，设置仍可更改，不声称已获得系统通知许可。旧壳与普通浏览器不显示此入口。其他会话新增待处理请求时显示六秒内嵌提示。侧栏悬停或键盘聚焦时可点「下一个」，与桌面端 ⌥⌘A、浏览器 Alt Shift A 共用按时间排序的游标。

提示模板在通用设置中管理名称、正文与适用范围。模板建议与 Agent 实际上报的 slash 命令只改变草稿，模板列表只在版本变化时重读。命令面板可切换侧栏、右侧面板、文件标签与外观，打开设备实际可用的设置分区并导出当前会话；缺少权限或能力时不列入口。桌面端导航为 ⌘N、⌘B、⇧⌘[ / ⇧⌘]、⌘1–⌘4、⌘/、⌘L（聚焦输入）；浏览器使用对应 Alt 组合。空输入框 ↑ 取回上一条用户消息；输入框连续两次 Esc 取消当前运行，单次不清草稿，输入法组合期间不触发。文件快捷键由具备能力的宿主处理：⇧⌘E / Alt Shift E 在没有文件标签时打开文件树，否则轮换已有标签。

模型选择器在超过八项时提供模糊文字搜索，按字符顺序容忍名称中的标点。最近五次选择单列在「最近使用」，其他分组不重复它们；已经移除的模型不在最近列表中恢复显示。通用设置中的模型列表开关只影响这台设备，隐藏不关闭模型服务。当前已选模型保持可见，切换之后才从普通列表隐藏；选择器可展开隐藏项。用量提供最近七天与三十天，以实际记录的 tokens 为准，细分缺失如实说明，表格在窄屏内横向滚动。

保存的项目常驻侧栏，桌面端的底行有「添加项目」，打开系统文件夹面板，选中后立即建好。项目组菜单可原地重命名、用原生面板添加文件夹，并进入编辑器；分组按记录的项目身份，旧会话才按最深主目录回退。没有项目的会话在「无项目」中，自己的专用文件夹从标题行的文件夹图标打开，桌面端在会话菜单里通过主进程签名的会话 ID「存为项目」。从组内新建优先使用该组，普通新建继承当前项目，「无项目」的 + 选好「不选项目」。不选项目时 Latch 内置只回复文字：项目行写「不读写文件，不运行命令」，权限位置写「不读写文件」；其他 Harness 写「在一个新的空文件夹里开始」。没有单独的开关。新会话选择器保留不可用项目及原因，显示多文件夹摘要与 Agent 的数量上限，使用主文件夹的 Agent 在输入区下说明实际范围。标题行项目的弹层（手机与没有这个弹层的会话写在启动面板下）显示开始时记录的所有文件夹，标记已移出项目、找不到或未传给 Agent 的文件夹，并提供可用的显示与复制操作。

文件标签的内容头是 36 高的一行：面包屑（每一级文件夹连同它后面的箭头是一个菜单，列出这一级的文件，打开时才读取；文件名最后才被省略），右侧是「源码」（Markdown、CSV、HTML、SVG）、「引用到对话」、桌面端的「在访达中显示」与「用默认应用打开」，以及「⋯」。「⋯」里先是渲染器自己的选项（查找、自动换行、复制文件内容、CSV 分隔符、显示修订、适应宽度、运行页面脚本、复制选区、冻结首行首列），后面是快速查看、查看改动、复制路径、下载文件、更新预览。正文不写文件大小与免责说明。「引用到对话」引用选中的内容；文档没有选区时引用当前页，文本没有选区时把文件作为引用放进输入框。打开的 PPTX 是一列幻灯片，每张上方写「3 / 12」与可展开的备注。文档默认半窗、最小 480px；文本、代码与图片记住独立内容列宽度，默认 320px、最小 280px。手机和平板窄屏推入一页。文件变化、已删除、秘密、超限与权限失效都有文字状态，读取失败可重试。会话及选中项目按上下文记住最多六个文件标签，不保存字节。文本有行号与分页，查找与跳行在 ⌘F 或「⋯」打开的一行里；文档保留自己的内容排版，外壳使用 UI 令牌。细节见 [DOCUMENT-PREVIEWS.md](DOCUMENT-PREVIEWS.md)。

### 从轮次分叉

已结束轮次的更多菜单提供「从这里分叉」与「复制到这里为止的记录」。分叉进入新会话设置，预选项目和 Agent，二者可改，输入可编辑；说明文件不复制或回滚，同一项目会话共用文件夹。模型、思考与权限档沿用来源会话的（见 [HARNESSES.md](HARNESSES.md)「权限菜单」的「默认」），没能沿用的在这条说明下每条一行。首条消息的 Host 上下文默认折叠，展开内容按纯文本显示，保留隐藏字符提示；Harness 用自己的记录分叉时（pi）首条消息只写一行「pi 自己带着会话「…」到第 N 轮为止的记录」，没有可展开的文字，因为文字没有发给它；分叉到这样的 Harness 时，草稿的分叉说明下多一行它会用自己的记录分叉、做不到时以文字带上；环境块的「分叉自」可以返回来源。没有 `catalog.features.fork` 的 Host 不出现分叉入口，查看设备仍可复制记录。

代码使用八个 `--syn-*` 角色令牌：正文、关键字、字符串、注释、数字、函数、常量和标点。关键字以 600 字重辅助识别；颜色保持低彩度墨色，不复用动作蓝、警告琥珀、风险红或差异绿。深浅主题均核对 OKLCH 彩度不超过 .06，且在 pane 与 sunken 背景上的对比度至少 4.5；注释有意更淡，至少 3。安全区域同样锁定这些令牌。

### 后续输入托盘

支持排队的 Host 上，运行中草稿非空时发送槽显示箭头，提示「本轮完成后发送」，停止移到左侧；草稿为空时仍只显示停止。托盘在输入框内部、运行信息下方，用折叠原语展开，行上可编辑或移除。多行编辑使用表单对话框，保留正常草稿。暂停项写 Host 原因并提供明确发送按钮；失去权限的项显示未发送，不承诺自动继续。远程完全访问会话可以查看托盘，有 run 时仍可移除，没有编辑或继续入口。消息时间提示附排队时间；结果未知沿用原请求标识并保留待确认项。

### Agent 提问卡

内置 Agent 的提问显示在对应工具行的位置，用琥珀「等你回答」标记。多题向导显示题号、上一题与下一题，支持单选、多选和「其他…」；提交要求每题有效，其他答案非空。草稿仅保存在本设备，提交中锁定选择，结果未知时保留同一回答供重试。已提交的结果折叠为「已回答 N 题」，展开可核对选择，随后显示模型继续的回复。缺少功能标记的旧 Host 保留普通工具展示。

### 附件与显式文件引用

附件用输入框工具栏的单个文件按钮，以及紧凑的文件行表达，上传比例使用中性墨色。取消发送保留文字与文件；长粘贴折叠成可编辑文字附件。已提交附件进入统一文件列，新会话的草稿只在输入框预览。独立的 `@` 打开项目文件选择，结果表明相对路径与文件夹 ID，普通邮件地址保持文字。模型图片能力由模型设置中的显式开关表示。

### 发送中的消息

支持消息身份的 Host 上，提交文字立即出现在本设备的消息位置，500ms 后才写「发送中…」。确认的消息取代临时投影，不重复追加。结果未知写「未确认送达」，可原样重试；排队输入不显示气泡。临时状态只表示提交过程，不生成完成轮次或模型回复。
文件变化的范围、运行结算、可选插件契约与验证见 [运行期间的文件变化](FILE-OUTPUTS.md)。

右侧面板的「改动」页签见 [CHANGES.md](CHANGES.md)：一行放范围、合计与撤销（或没有撤销的原因），琥珀只给要留意的行，红色只在不能恢复的确认框里。文件树从 6 个文件起、差异还能留 560 宽时自己打开；差异列 760 宽起左右对照；路径放不下时整段丢掉前面的文件夹。

审阅改动在「改动」标签，见 [CHANGES.md](CHANGES.md)。这台设备读不了文件夹、或 Host 不提供改动时，回复里的文件打开它的工具差异记录，也可以从文件标签的「⋯ › 查看改动」进入：按文件夹与路径区分同名文件，可切换本轮与历史、行内与左右对照，已删除文件的记录仍保留。

文档预览保留当前文件的页码与适应状态；缩放使用键盘或双指，窄列收起页工具栏。自动打开新增文档为默认开启的本设备偏好，在 1024px 起的宽窗口上按右侧面板此时的位置打开（放得下对话时在旁边，否则盖在对话上），至少 480px，并保留输入焦点与草稿；手机只显示文件入口，用户可关闭自动展开，见 [文档预览](DOCUMENT-PREVIEWS.md)。

项目文件树按需出现在右侧文件区，窄屏沿用文件页。首次打开默认展开主根；目录按展开读取，长列表分批显示，隐藏项开关收进菜单。文件单击预览，菜单可复制相对路径或引用到草稿；新会话未发出消息时也能预览选中项目。文件搜索沿用命令面板和键盘导航，返回相同的文件列，不另开工作流。

项目编辑页的会话数是静态信息；「最近会话」另列当前设备快照中归属该项目的最近三条记录。归属复用项目分组规则，早先助手跑过的会话不会混入；打开入口返回同一工作台，权限撤回后撤下。
