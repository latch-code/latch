# Git 基线、PR 审阅与跟进

在「改动 › 分支与基线」查看当前分支与主分支分叉后的已提交改动。能查看全部数据的设备还可以选择本地分支、最近提交，或输入完整提交号和已获取的远端跟踪分支名（如 `origin/main`）。完整提交号须由本地分支、远端跟踪分支或当前 HEAD 可达。列表显示比较两端的提交号，文件行来自这两个提交的净差异。展开文件时两端若已移动，需要重新打开比较。设备的数据范围收窄为「会话与项目的文件」后，页面恢复自动基线。

## 从 PR 建树

在新会话的「文件夹 › 其他起点 › PR」输入编号。「获取 PR 提交」使用项目已配置的远端、你的 Git 和已登录的 gh，通过基准仓库的专用 PR 引用取得实际 head。在 fork 上工作的贡献者无需给本机增加远端。Host 核对 PR 号、仓库和完整提交号，从上游查询到本地获取之间 head 改变时，页面要求重新获取。

选择前可以查看来源仓库、分支、是否来自 fork 及提交号。Host 的核对值绑定设备、项目、目录与 Git 入口的磁盘身份、远端仓库、PR 号和实际提交。开始会话要再次核对设备的文件与运行权限。另一个设备或项目要自行重新获取。新工作树使用自己的 Latch 分支，保留已确认的版本，初始上下文按外部来源处理。获取先写审计，关闭钩子、filter 和子模块，沿用交付的受限获取流程。

## 跟进绑定的 PR

在会话的交付面板选择「后台提醒」或「跟进并自动续办」。开启时读取当前检查与讨论作为起点。此后 Host 每 30 秒轮询一批已开启的会话，按轮转顺序每批最多四个，持续进行的请求不重复开始。每次读取前核对绑定关系和授权设备，丢失文件权限、设备被撤销、会话归档或换绑后不再读取。减少设备的文件范围或撤去运行、查看权限时，设备记录的跟进授权版本同步改变，旧授权立即失效。即使在两次轮询之间恢复权限或重启 Host，也要重新开启跟进。止于合并或关闭。只读 GitHub，远端暂不可用时保留上次观察，在以后的轮次再试。

会话元数据分别保存最近 512 个失败检查与 512 条评审或评论的摘要哈希。部分分页暂缺的旧条目再次出现时沿用已见记录。记录满后，不能凭时间确认是新的条目只供人工查看。只向能读相关文件的设备返回新反馈的计数、发生时间及续办结果。再次打开原对话可查看反馈、选取摘录并加入草稿。

「跟进并自动续办」为原会话单独授权。只有可信的内置 Standard 普通 Code 会话可执行，授权设备仍需具备完整数据范围并满足无人值守的存活与等级上限。按定时运行的依据检查模型、插件执行修订、项目与策略，另核对已确认的 MCP 配置。来源于原生连接的授权仍须在有效验证窗口内。自动运行前还要核对工作树的分支、当前 HEAD 与 GitHub 报告的提交一致。存在审批、排队、待核对结果、配置变更或其他不能确认的条件时，反馈保留供人处理。

自动续办先持久记录本次反馈，再审计并发起原会话的一轮。接收这一轮前，执行端最后复核授权和原手机验证窗口。该轮按外部资料对待评论，以无人值守策略重新询问工具，且不提供会话引用工具或设备输入授权。等待审批受 Standard 的无人值守时限约束。执行端核对实际选择的模型与思考档位，本轮不会改写会话的模型选择或看管档位。崩溃或发送结果未知会暂停自动续办，同一观察结果不重发。停止跟进后可以重新授权。
