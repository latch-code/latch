# 文档预览

## 引用与文件更新

引用是用户明确加入草稿的可编辑文字，不能自动发送。文本和 Markdown 可引用选中文字，Office 与 PDF 可引用选区或当前页，表格可引用实际选中的单元格范围。摘录最多 2,000 个 UTF-16 单元，来源行包含页码或工作表范围，附上引用时的文件大小与修改时间。项目文件仍使用原有结构化相对引用，附件只引用摘录，不伪造项目根。摘录只作为草稿文字，随草稿存在这台设备的浏览器存储里，删除会话、撤权或退出时清除（[STREAMING.md](STREAMING.md)）；发送后按普通用户消息处理。

可见文件仍每两秒检查一次元数据；ETag 改变时自动解析新版本。文本保留行位置，Office 保留页码、适应与缩放，表格保留工作表、选区、列宽、滚动与冻结偏好，PDF 保留当前页内位置。大小相同的 PDF 更新也会重新读取。更新不聚焦输入框或改变已有草稿；草稿已有该文件摘录时提示它可能已过时，原摘录不被悄悄替换。短暂读取失败或文件删除保留已经读到的内容与提示，401/403 则清空预览；每次读取固定原版本的 ETag，不能混合两个版本的 Range 数据。

表格默认冻结首行和首列；已有文档的冻结范围继续使用其有限元数据。用户可用内容头「⋯」里的「冻结首行首列」关闭或恢复，偏好仅在当前打开的文件中保留。复制仍最多一万个单元格、引用最多两千个单元格；异步读取可取消，文件切换后的结果不能写入新草稿。

网格按 64 行请求数据，仅保留五个批次并保护当前可见批次和冻结首行。每条框消息仍最多一百万字符；遇到异常长的单元格时，在该批次的有限配额内显示带省略号的值，并说明截断。单批数据的限制不会缩短整个工作表的总行数，也不会让后面的行无法访问。CSV 与 XLSX 使用同一批次限长函数；文件级的行、列与单元格总数上限仍由解析器独立判断。

`DocumentPreview` 接收已授权的 `FileMetadata`、文件版本键、读取字节的回调与 `renderFrame`。读取回调的 Range 末端是包含端点；PDF 的范围传输把其排除端点减一再交回父页。秘密文件和没有 `actions.preview` 的文件在读取前拒绝。文件、版本或组件撤下时取消读取与渲染，销毁 worker 和 MessagePort。

PPTX 使用逐页纵向窗口化列表、适应宽度与手机横向滑动，每张上方写页码，方向键翻页。备注从每页关系对应的 notesSlide 提取，只作为文字放在该页的折叠块；不增加缩略图栏、搜索或放映。DOCX 保留分页、页眉页脚、脚注，修订显示在内容头的「⋯」里。文档原色与排版由框内渲染器处理，界面外壳跟随 UI 令牌。

XLSX 由第一方读取器处理工作表、共享/内联字符串、缓存公式、数字格式、1900/1904 日期、合并区域、列宽与冻结信息。公式不执行、外部链接和宏不读取。隐藏表保持隐藏；超出预算时标明部分内容未显示。CSV/TSV 在 worker 解析，按 BOM 判断 UTF-8/UTF-16，分隔符在内容头的「⋯」里切换；公式形状的输入仍是文字。

`SheetGrid` 在页面上做行列虚拟化，提供范围选择、方向键、TSV 复制与列宽调整，使用 `role=grid`。复制限制为一万个单元格与一百万字符，超出时要求缩小选区。PDF 使用核心 API 的 canvas 与纯文本层，不执行 PDF 动作。PDF 字符选择的几何行框使用文档单位，不继承界面字号。

公开许可证目录（`apps/web/public/licenses/`，说明在其中的 `README.txt`）保留实际依赖的许可证和内嵌 MPL 代码的对应源码位置。供应链金丝雀检查依赖年龄和脚本策略；格式 e2e 使用生成的样例与真实 worker，覆盖缓存公式、字面文本、PPT 窗口化、PDF 范围读取及查找。

## 工作台与文件服务

Host 声明 `catalog.features.filePreview` 时，回复中的文件标记单击打开同一会话侧列的文件标签，右键或向下箭头打开原文件菜单。可信插件面板保留各自标签，不共用文档运行环境。每个会话或项目/Harness上下文最多六个文件；本设备最多记住四十个上下文的相对路径与文件夹 ID，不保存文件字节或句柄。Office、PDF、HTML 默认半个窗口，至少 480px；文本、代码、图片默认 320px，最窄 280px，分别记住内容列与文档列宽度。对话保留 520px，必要时收起侧栏，窄屏推入文件页。展开按钮可把文件列变为整页。渲染器的选项经 `viewerActions.tsx` 交给文件标签的内容头：引用到对话、源码开关与「⋯」里的行都由内容头画，渲染器自己不留工具栏。一轮生成多个新文档时，第一个打开，其余的标签带圆点等着，看过即消失；圆点只在内存里，刷新后不保留。旧 Host 缺少能力时保留原来的文件菜单与复制行为。

父页通过已授权句柄读内容，并给分块读取附上原始 ETag 的 `If-Match`；媒体地址通过 `v` 绑定同一版本。Host 返回 412 时拒绝混入新版本。可见文件每两秒查元数据，变化后保留旧内容并提示更新，删除保留已读画面和原因，权限被撤回则卸载内容。句柄过期只自动重取一次，失败后要求重新打开。下载随标签卸载取消。大文本按 200 行呈现并支持查找、跳行、换行，超过读取上限标明截断。媒体沿用同一受限 Range 服务。

可能含密钥的文件只显示文本。文件的复制、引用到输入框，以及桌面端真实可用的访达、快速查看、默认应用动作仍经原先的 Host 裁决；Quick Look 未完成真实网络验收的格式继续拒绝。

### 文件树与项目上下文

文件树从右侧面板的「文件」进入；新会话选中已保存项目时从标题行的「浏览项目文件」打开，默认私有会话目录尚未创建时不虚构文件。首个根自动展开，其余目录按点击加载一层；目录里只有一个子目录且列表完整时，子目录随之打开并合成一行（`a/b/c`），收起时一起收起，根目录不合并。键盘支持上下、首尾、左右展开/折叠与 Enter 打开；符号链接只标记。客户端串行读取目录，每层先显示 100 项、按需再显示 100 项，整棵树最多显示 1,000 行；保留至多 32 个展开的有内容目录，并回收已收起的旧缓存。隐藏项和生成目录可切换，目录变化可就地重试，项目根配置变化会清理树缓存。

文件标签的持久状态显式保存 session 或 workspace/Harness 上下文，兼容旧的 sessionId 记录；不持久保存字节、文件句柄或搜索结果。项目预览、相对 Markdown 链接、图片和文件搜索都用同一上下文。首页仍保留旧会话阅读时，显式浏览与搜索使用新草稿的项目/Harness 上下文，在独立浮层复用文件面板；原会话的预览与文件标签不切换。手机新建面板从历史页浏览项目时退出历史覆盖，返回文件页后恢复该新建草稿。引用动作把根 ID 与相对路径作为结构化 `fileRefs` 随原请求发送，并保留原草稿；Host仍重新授权。`work`设备隐藏树与文件搜索，已有会话引用继续可打开。

文件行的右键、Shift-F10 和菜单键打开同一套原语菜单；退出后焦点回到该行的操作按钮。根行的菜单复制这个文件夹的路径，桌面端还可在访达中显示。浏览器提供引用到对话与复制路径（相对路径）。桌面端的「复制路径」是完整路径，在点击时重新 resolve，并且只拼接该根在当前上下文中冻结的路径，不猜主目录；没有对应根时不提供。访达动作同样先取得新的设备句柄，再交给声明 `files.protocolVersion:2` 的桌面主进程；「用默认应用打开」与「快速查看」同样如此，继续经过 Host 的本机动作裁决与审计，页面不向本机桥发送绝对路径。

`FileTree` 的可选 `fileChanges` 只接受 Host 观察到的根与相对路径，变化点说明它也可能包含其他程序的改动。宿主用 `revision` 传入实际文件集或运行代次的变化，不能绑定每个文本流分片；组件只重新读取已展开目录，保留展开项、选择和现有行的焦点，仍串行、有界且可取消。切换会话、项目、Harness 或隐藏项设置会丢弃原目录缓存；授权或根读取失败清除可见缓存，不以旧名称继续提供文件操作。

## 浏览器与桌面边界

预览在浏览器隔离框内运行，不是 OS 沙箱，浏览器也不保证文档数据的完整机密性；可能含密钥的文件只显示文本。

## 代码、Markdown、公式和图表

`useHighlightedTokens` 把有界源文交给共享 Shiki worker，返回逐行 `{text, role}`；页面核对每个字符与原输入一致，只接收固定八种角色，通过 React span 和 `VisibleText` 显示。30 种常用语法按需加载，使用 JavaScript 正则引擎；不返回 HTML 或任意颜色。整块超过 200 KB、不支持的语法或同一内容两次超过 worker 时限，均保留纯文本；超过 1,000 字符的单行只有这一行保留纯文本，其余行照常着色。调度、缓存与超时见 [STREAMING.md](STREAMING.md#markdown代码与安全边界)。流式回复的未闭合围栏逐行着色，最后一行保持纯文本；差异块按完整旧/新文本着色后逐行取出。查看器与工具读取的输出使用同一 hook，查看器保留行号、查找和跳行。

`MarkdownPreview` 使用 `MessageContent` 静态模式，保留 URL 检查、跳过 HTML、深度限制和文件路径标记。文件列提供预览与源码切换，相对链接按该文件的目录归一化，在同一会话、同一冻结根中打开。会话正文和文件列共用图片解析器：先通过会话文件服务授权，再使用绑定 ETag 的句柄 URL；不取得绝对路径或其他文件的内容。`work` 范围仍只允许会话已经提到的路径，不因 Markdown 中出现一个新链接而放宽。秘密、未知尺寸、过大或不可读图片保留路径入口；元数据给定尺寸后再加载图片，点击可打开文件列。图片回调只接受同源 Host 文件句柄 URL 或宿主创建的 blob，最大显示宽度 320px。远端图片仍为普通链接，不发送第三方请求。秘密文件保持纯文本，不调用高亮、数学或图表渲染器。

源码查看器复用共享高亮 worker，保留行号、复制、查找与跳行；在查看器内按 Command/Ctrl-F 聚焦本列查找。首次展开查找栏的延后聚焦不打断人已选中的跳行或其他栏内控件，再次按快捷键仍立即回到查找框。更新文本期间保留已读内容与行位置，新版本变短时夹到末尾；查找词和换行偏好保留。正常会话在 Host 声明文件预览能力时启用图表框，没有能力的旧 Host 保留代码块。

`remark-math` 解析美元围栏，单美元两侧必须贴着非空白文字，货币保持文字；第一方预处理还接受代码之外的 `\(…\)` 和 `\[…\]`。KaTeX 延迟加载；失败显示 TeX 源码。

Mermaid 在独立框内加载，渲染结果作为图片显示。可以切换图与源码、放大后滚动；触摸设备与 WebKit 由点击开始渲染。缺少 frame 宿主时保留代码块，卸载回收 frame 和 Blob URL。

新增依赖均固定在 catalog，发布至少七天；`micromark-extension-math>katex` override 收紧到 0.19.0。公开目录 `licenses/rich` 保留依赖许可证；EPL-2.0 的 elkjs 源码位置见 `licenses/README.txt`。

消息附件使用同一个文件列，但通过 `attachmentId` 换取独立内容句柄，标签保存其有限 ID。私有附件没有项目路径、原生文件动作或文件引用到输入框；草稿尚无会话时只在输入框预览。详细契约见 [ATTACHMENTS.md](ATTACHMENTS.md)。

## HTML 页面

HTML 默认静态显示；桌面端可在内容头的「⋯」里按文件开启「运行页面脚本」，脚本没有网络与同源权限。另一台电脑的窗口里没有这一项：那里的预览框是 `latch-frame://h-<hostId>/preview/<名称>.html`，只给 `office`、`diagram`、`html` 三个固定引导页，由主进程经 HTTPS 从那台 Host 取来并按哈希核对（[ARCHITECTURE.md](./ARCHITECTURE.md#桌面端与其他电脑)）。

页面在框的文档加载完成之后才装入，所以 `html`、`body` 上的属性由框带过来（已经过同样的过滤），脚本运行后框补发一次 `DOMContentLoaded` 与 `load`，页面的启动代码照常执行。

演示页面按它写定的尺寸显示：框读取页面，有写定像素尺寸的舞台（约 16:9 或 4:3）时用这个尺寸；由相邻的 slide 或 scroll-snap 组成且铺满视口的页面用 1280×720。框的视口就是这个尺寸，父页只把框整体等比缩放并居中到面板里，所以页面自己的缩放、`vw`/`vh`、点击位置和 `resize` 都不变，也不会缩放两次。这个尺寸在页面脚本运行之前就已生效。普通页面保持面板宽度：隐藏的元素不算舞台，舞台或幻灯片组必须容纳页面的文字，除非页面根本不能纵向滚动。判断只是推测，「⋯」里的「按桌面尺寸显示」可以按文件改回或打开。

静态显示时，演示的脚本不运行：框把只靠脚本定位的舞台移回视口，并显示一页。一次只显示一页的演示由框自己翻页：方向键、滑动或预览下方的按钮，文件更新后停在同一页；能滚动到其余幻灯片的演示不增加翻页。一行提示「页面脚本没有运行。」；桌面端的这行提供「运行页面脚本」，运行后键盘交给页面。没有认出幻灯片的舞台只说翻页可能不可用。框没有 `allow-fullscreen` 与 `allow-modals`，页面自己的全屏与打印不起作用。

外部脚本和样式（包括 CDN 上的演示框架）仍被移除。普通页面照常不提示；舞台或幻灯片组成的页面缺少这些文件时，同一行提示显示可能不完整。文件改写后按新内容重新判断，是否为演示、提示与页数都随之更新。

图片的 100% 对应一个图片像素到一个 CSS 像素；适应模式按可用宽高缩小，不放大小图。Command/Ctrl 加滚轮、加减键与双指缩放围绕当前点调整，拖动平移，0 回到 100%，F 适应；同一标签更新后保留缩放。棋盘可在固定的浅、深背景间切换，颜色来自 UI 的预览令牌，不随主题反转。SVG 仅作为 img，并可切换源码。Host 签发元数据时就拒绝超过本机一亿、其他设备五千万像素的预览；未知尺寸只提供元数据与有界下载，页面不尝试解码。格式不支持或头部不足以确认尺寸时也按此处理。

文本查找用 CSS Custom Highlight 标记当前两百行中的匹配，能跨越语法 span，不改写 DOM；最多一千个可见匹配。查询最多 512 字符，不支持 Highlight 的浏览器仍可查找并跳行。

## 编辑

文本、代码与 Markdown 文件的内容头有「编辑」，只在 Host 给出 `actions.edit` 时出现：会话里的文件、设备有 `run` 且数据范围是 `all`、不像密钥、不超过 1 MiB（`FILE_EDIT_LIMIT`），页面读到的是完整的 UTF-8 文本且有 WebCrypto。Latch 写入时按 R2 处理的路径（`isProtectedWorkspacePath`：Git 钩子、`.husky`、依赖清单、CI 工作流、Agent 设置、环境文件等）只给有 `approve:elevated` 的设备；Latch 程序目录（与它重叠的文件夹）里的文件从不编辑；混用 CRLF、LF 或 CR 的文件不编辑，不悄悄统一换行（Host 按文件开头判断，页面读到整个文件后再按同一规则判断一次）；来自已移除 Agent 的只读会话不提供编辑。这几种情况 Host 在 `refused.edit` 里给原因（`file-edit-elevated`、`file-code-root`、`file-mixed-eol`），「编辑」显示为不可用，读屏名称就是原因；直接请求时同样拒绝。会话或同一文件夹里有一轮在运行时按钮不可用，读屏名称是「Agent 运行中，不能编辑」。编辑器（`FileEditor.tsx`）是等宽的纯文本框加行号，不换行，没有高亮或补全；顶部一行是「取消」、文件名与状态词、「保存」，⌘/Ctrl S 保存，Esc 取消。手机上它是整屏的一页，高度跟随可见视口，所以键盘弹出时顶部的保存栏和正在输入的行都在键盘之上；平台的返回与「取消」一样，有未保存的修改时先问「放弃你的修改？」。编辑器的文本、冲突与未答复的保存按会话与文件（文件夹 ID 加相对路径）留在页面内存里（`editDrafts.ts`），切换标签或面板后回来照旧；关闭这个文件的标签或换到另一个会话前同样先问「放弃你的修改？」，标签真正关闭时它的编辑内容随之删除，重新载入页面时浏览器先问。第七个标签挤出的是最早一个没有打开编辑器的标签；每个标签都开着编辑器时先问要不要放弃最早那个。

打开编辑器时页面固定读到的文本与它字节的 SHA-256（`baseHash`），之后预览照常跟着文件更新，编辑器的基准不变。「保存」发送 `PUT /tasks/:id/files/:handle { requestId, baseHash, content }`；Host 重新按读取的规则裁决句柄（在会话的文件夹里、不是受保护路径、路径中没有符号链接、普通文件），在改动记录的锁里再读一次文件：

- 内容已经是要写的文本：不写，回答 `unchanged`（上一次保存的回答丢失后重试也落在这里）。
- 哈希不是 `baseHash`：409 `file-changed`，带现在的 `currentHash`，一个字节也不写。
- 否则在锁里按设备此刻的权限再核对一次（`run`，受保护路径另核对 `approve:elevated`；写审计之后与改名之前再各核对一次），先写审计 `file.edit`（会话、路径哈希、类型、保护类别 `none` 或 `protected-path` 与前后字节数，没有内容），再在同一文件夹写临时文件、`fsync`、保留原权限位，改名前再核对文件夹、文件身份与哈希，最后 `rename`；这一步发现文件又变了同样 409 `file-changed`，并补一条 `action.failed`。属主、扩展属性与其他硬链接不随新文件保留。

文本框给出的换行是 LF；Host 按原文件写回：多数换行是 CRLF 的文件用 CRLF，结尾有没有换行与原文件一致，UTF-8 BOM 保留。不是 UTF-8 的文件 409 `file-not-text`，含 NUL 或孤立代理项的内容 400 `file-edit-invalid`，路径已变成链接 409 `file-not-regular`。同一设备、会话与 `requestId` 的成功回答在内存中保留一小时，重试得到同一回答并带 `replay`；同一 ID 换了内容 409 `request-id-reused`。桌面端的页面代理只放行这一条写入（会话里的句柄，`PUT`），请求体上限 6 MiB + 4 KiB，与 Host 相同，足够 1 MiB 的文本在 JSON 里全部转义。超时或断线时编辑器显示「结果未知」与「重试保存」，重试发送原请求。

409 `file-changed` 时什么也没有写：编辑器读取文件现在的内容，状态写「文件已在别处修改」，两边并排（手机上下）显示「文件现在的内容」与「你的修改」，与 iPhone/iPad 相同只给「复制我的修改」与「载入最新」：「载入最新」把文件现在的内容作为新的基准与正文（人没有先复制时先问「载入最新？」），之后的保存以它的哈希为 `baseHash`；网页与桌面端都不提供覆盖。设备没有 `run` 或数据范围不是 `all` 时，Host 在 `refused.edit` 里写 `file-edit-scope` 或 `file-edit-data-scope`，「编辑」不可用，读屏名称说明原因。保存成功后编辑器关闭，预览重新读取并短暂显示「已保存」。iPhone/iPad App 只编辑它整份读到的纯文本预览（`PhoneFileEdit`）：`baseHash` 是读到的字节的 SHA-256，409 `file-changed` 时写「文件已在别处修改」，只给「载入最新」与「复制我的修改」，不从手机覆盖；只在 UTF-8 正文转成 JSON 后放得进 1 MiB 请求、且换行不混用时给「编辑」。没有答复时写「保存结果未知」与「重试保存」（重试发原请求）和「核对并放下」：重新读这个文件，与这次保存的文字比较后丢掉待确认的副本，并写明「已保存」或「没有保存」；句柄过期（410）也这样收尾。

保存会记入改动记录（[CHANGES.md](CHANGES.md#人的编辑)）：「改动」的这个会话范围把它标为「你的修改」，Agent 的下一轮消息前带一段说明「用户编辑了 <路径>」。同一页面里的「交付」在之后有保存时，给已提交或已推送的那一行加「需要复验」：它的钩子没有检查过这次编辑。这个标记只在做出编辑的页面里，其他设备看不到。

## 单个文件的历史改动

文件标签的「⋯ › 查看改动」打开同一文件列的历史视图，预览入口仍可读取当前文件；Host 不提供「改动」时，这一轮改动的文件也打开它。数据范围为 `work` 的设备收不到差异正文（见 [STREAMING](STREAMING.md#文件差异的设备投影)），没有历史视图可开，同一入口打开本会话写出的文件本身。历史按冻结文件夹 ID 和相对路径归组；相同文件名不会跨根合并，也不改写文件名的 Unicode 编码。界面显示文件夹名称，ID 只用于内部关联。

历史直接使用 Host 已记录的工具差异，按用户轮次关联，保留消息顺序的原始记录；界面从最新修改开始展示，可切换本轮与历史。它不运行 Git、不重新读取旧文件或创建本地快照。仍在排队、等待审批或实际未运行的拒绝调用不计入；已经执行的 Agent 调用保留其真实记录，即便它的权限询问只是建议。文件删除后，历史仍可查看；预览当前文件另经原文件服务裁决。切换视图只记在本设备的文件标签状态中，不把差异字节另存浏览器。


Office 更新版本时保留当前页、适应状态与有限缩放比例，页数变少时夹到末页。⌘/Ctrl ± 与双指缩放不增加工具栏按钮，⌘/Ctrl 0 恢复适应宽度。文档只读，页首说明排版可能与原应用不同。点击文档里的外链在默认浏览器打开。

PDF 同样只保留「适应」开关；页面区域取得焦点后，⌘/Ctrl 加减调整 10–400% 的实际比例，0 恢复适应宽度。触控板的修饰键滚动和双指捏合以手势中心为阅读锚点，单指仍可正常滚动。100% 使用 PDF 点到 CSS 像素的 96/72 换算，缩放重新绘制 canvas、文字层与链接热区，不用 CSS 拉伸旧位图。每页实际取整后的 canvas 总计不超过一千六百万像素，单边不超过 16,384，DPR 最多 2；达到像素上限时保留安全绘制比例。虚拟页只渲染视口附近的内容，重新测量后恢复原页中的相对阅读点；文件更新沿用当前比例和阅读位置，编辑输入框中的组合键不改 PDF 缩放。

设置中的「运行结束后自动打开新生成的文档」默认开启，仅作用于本设备，保留用户明确关闭的偏好。`useAutoOpenOutputs` 只考虑当前视图确实见过运行中的那一轮，等待输出观察结算，在 1024px 起、文档将打开的面板至少 480px 的窗口中展开首个明确新增的文档：放得下对话时在旁边，否则盖在对话上；面板先前可以关闭；当前概要栏的 400px 默认宽度不代表文档的预期宽度，用户已选择的面板宽度仍有效。首页和全部会话覆盖阅读时不自动打开。打开不移动输入焦点、不改草稿；手机、平板、其他入口页面和展开审阅时不抢占当前页面。失败、取消、修改文件、加载历史或切换会话后的旧结果都不自动打开。macOS 快速查看仍由文件宿主按白名单与设备权限决定。

`@latch/testkit` 的 `documentFixtures` 生成 DOCX、XLSX（缓存公式、日期、合并与隐藏表）、窗口化 PPTX（1–500 页与备注）及 PDF；测试提供已有 ZIP 编码器，无第三方样本进入仓库。没有所有者从 PowerPoint/Keynote 导出的参照图时，只报告真实渲染结果，不声称原应用逐像素保真。

代码审阅在宽屏提供行内与左右对照，左右布局先展开文件列；窄屏保持行内及旧/新行号。每个修改块独立保留两侧行号与空行，插入或删除缺失的一侧留空，不把未提供的原内容说成新文件。代码在各自区域横向滚动；多文件导航按冻结根与路径区分。历史初始最多五次修改，最新一项展开，其余折叠，更早记录按需加载；语法高亮仍只在可见展开项中请求。
