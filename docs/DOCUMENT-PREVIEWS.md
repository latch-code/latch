# 文档预览

文件预览在会话侧列的文件标签里显示项目文件与附件。字节由 Host 的会话文件服务授权（见 [ARCHITECTURE.md](ARCHITECTURE.md)），解析与渲染在页面、worker 与隔离框里进行。

- 预览在浏览器隔离框内运行，**不是 OS 沙箱**，浏览器也不保证文档数据的完整机密性。
- **可能含密钥的文件只显示文本**，不调用高亮、公式或图表渲染器，没有 `actions.preview` 的文件在读取前拒绝。
- 文档只读（「编辑」只对纯文本，见下）。公式不执行，宏与外部链接不读取，PDF 动作不执行，远端图片不请求。
- 布局与控件见 [DESIGN.md](DESIGN.md)；`apps/web/src/preview/AGENTS.md` 写改解析器、框与 worker 时的规则。
- 语言切换经已建立的预览端口更新幻灯片备注按钮，只接收 `zh-CN` 与 `en`。不重新加载文档，保留页码、缩放和选择；表格的未命名标签与无缓存占位按界面语言显示，复制和引用沿用原有内容。

## 工作台与文件服务

- Host 声明 `catalog.features.filePreview` 时，回复中的文件标记打开同一会话侧列的文件标签。可信插件面板保留各自标签，不共用文档运行环境。
- **标签。** 每个会话或项目/Harness 上下文最多 6 个文件标签；本设备最多记住 40 个上下文的相对路径与文件夹 ID，不保存文件字节、句柄或搜索结果。第七个标签挤出最早一个没有打开编辑器的标签。
- **`DocumentPreview`** 接收已授权的 `FileMetadata`、文件版本键、读取字节的回调与 `renderFrame`。读取回调的 Range 末端是包含端点。文件、版本或组件撤下时取消读取与渲染，销毁 worker 和 MessagePort。
- 渲染器的选项经 `viewerActions.tsx` 交给文件标签的内容头，渲染器自己不留工具栏。
- **附件**用同一个文件列，但通过 `attachmentId` 换取独立的内容句柄；私有附件没有项目路径、原生文件动作或「引用到对话」（[ATTACHMENTS.md](ATTACHMENTS.md)）。
- **本机动作。** 复制、引用，以及桌面端的访达、快速查看、默认应用动作都经 Host 裁决与审计；页面不向本机桥发送绝对路径。桌面端的「复制路径」在点击时重新解析，只拼接该根在当前上下文中冻结的路径；没有对应根时不提供。

### 版本与更新

- 父页通过已授权句柄读内容，分块读取带原始 ETag 的 `If-Match`，媒体地址通过 `v` 绑定同一版本。Host 返回 412 时拒绝混入新版本：一次读取不能混合两个版本的 Range 数据。
- 可见文件每两秒检查一次元数据，ETag 改变时解析新版本。大小相同的 PDF 更新也会重新读取。
- 更新保留阅读位置：文本的行位置，Office 的页码、适应与缩放，表格的工作表、选区、列宽、滚动与冻结偏好，PDF 的页内位置；页数变少时夹到末页。
- 更新不聚焦输入框，不改已有草稿。草稿已有该文件的摘录时提示它可能已过时，原摘录不被替换。
- 短暂读取失败或文件删除保留已读到的内容与提示；401/403 清空预览。句柄过期只自动重取一次，失败后要求重新打开。下载随标签卸载取消。

### 文件树与项目上下文

- **上下文。** 会话（session）和绑定 Harness 的项目（workspace/Harness）是两个显式上下文。项目预览、相对 Markdown 链接、图片和文件搜索都用同一上下文；切换会话、项目、Harness 或隐藏项设置会丢弃原目录缓存。
- **读取有界。** 客户端串行读取目录，每层先显示 100 项、按需再显示 100 项，整棵树最多显示 1,000 行、32 层；保留至多 32 个展开的有内容目录。符号链接只标记，不进入。
- 目录里只有一个子目录且列表完整时，子目录随之打开并合成一行（`a/b/c`）；根目录不合并。
- 默认的私有会话目录尚未创建时不虚构文件。授权或根读取失败清除可见缓存，不以旧名称继续提供文件操作。
- **`fileChanges`**（可选）只接受 Host 观察到的根与相对路径，它也可能包含其他程序的改动（[FILE-OUTPUTS.md](FILE-OUTPUTS.md)）。宿主用 `revision` 传入实际文件集或运行代次的变化，不能绑定每个文本流分片；组件只重新读取已展开目录。
- **引用到对话**把根 ID 与相对路径作为结构化 `fileRefs` 随请求发送，Host 重新授权。
- 数据范围为 `work` 的设备没有文件树与文件搜索，已有会话里的引用仍可打开。

## 引用与文件更新

引用是用户明确加入草稿的可编辑文字，不能自动发送。

- 文本和 Markdown 引用选中文字，Office 与 PDF 引用选区或当前页，表格引用实际选中的单元格范围。
- 摘录最多 2,000 个 UTF-16 单元（`QUOTE_LIMIT`）；来源行包含页码或工作表范围，附上引用时的文件大小与修改时间。
- 项目文件用结构化相对引用；附件只引用摘录，不伪造项目根。
- 摘录随草稿存在这台设备的浏览器存储里，删除会话、撤权或退出时清除（[STREAMING.md](STREAMING.md)）；发送后按普通用户消息处理。
- 异步读取可取消，文件切换后的结果不能写入新草稿。

## Office、PDF 与表格

**XLSX** 由第一方读取器处理工作表、共享与内联字符串、缓存公式、数字格式、1900/1904 日期、合并区域、列宽与冻结信息。隐藏表保持隐藏；超出预算时标明部分内容未显示。

**CSV/TSV** 在 worker 解析，按 BOM 判断 UTF-8/UTF-16；公式形状的输入仍是文字。

**表格网格**（`SheetGrid`，`role=grid`）在页面上做行列虚拟化：

- 按 64 行请求数据，只保留 5 个批次，并保护当前可见批次和冻结首行。
- 每条框消息最多一百万字符。遇到异常长的单元格时，在该批次的有限配额内显示带省略号的值并说明截断；这不缩短工作表的总行数。CSV 与 XLSX 用同一批次限长函数；文件级的行、列与单元格总数上限由解析器独立判断。
- 复制最多一万个单元格、一百万字符，引用最多两千个单元格，超出时要求缩小选区。
- 默认冻结首行和首列；文档自带的冻结范围继续使用。关闭或恢复的偏好只在当前打开的文件中保留。

**PPTX** 是逐页纵向的窗口化列表。备注从每页关系对应的 notesSlide 提取，只作为文字。不提供缩略图栏、搜索或放映。

**DOCX** 保留分页、页眉页脚、脚注与修订。文档原色与排版由框内渲染器处理；页首说明排版可能与原应用不同。点击文档里的外链在默认浏览器打开。

**PDF** 使用核心 API 的 canvas 与纯文本层：

- 范围传输把排除端点减一再交回父页。
- 100% 使用 PDF 点到 CSS 像素的 96/72 换算，比例 10–400%。缩放重新绘制 canvas、文字层与链接热区，不用 CSS 拉伸旧位图。
- 每页实际取整后的 canvas 总计不超过一千六百万像素，单边不超过 16,384，DPR 最多 2；达到像素上限时保留安全绘制比例。
- 虚拟页只渲染视口附近的内容，重新测量后恢复原页中的相对阅读点。
- 字符选择的几何行框使用文档单位，不继承界面字号。

## 代码、Markdown、公式和图表

**语法高亮。** `useHighlightedTokens` 把有界源文交给共享 Shiki worker，返回逐行 `{text, role}`：

- 页面核对每个字符与原输入一致，只接收固定八种角色，通过 React span 显示；worker 不返回 HTML 或任意颜色。
- 30 种常用语法按需加载，使用 JavaScript 正则引擎。
- 整块超过 200 KB、不支持的语法或同一内容两次超过 worker 时限，保留纯文本；超过 1,000 字符的单行只有这一行保留纯文本。
- 流式回复的未闭合围栏逐行着色，最后一行保持纯文本；差异块按完整旧/新文本着色后逐行取出。
- 调度、缓存与超时见 [STREAMING.md](STREAMING.md#markdown代码与安全边界)。

**文本与源码查看器。** 大文本按 200 行呈现，支持查找、跳行与换行，超过读取上限标明截断。查找用 CSS Custom Highlight 标记当前 200 行中的匹配，不改写 DOM；最多一千个可见匹配，查询最多 512 字符。不支持 Highlight 的浏览器仍可查找并跳行。

**Markdown。** `MarkdownPreview` 使用 `MessageContent` 的静态模式，保留 URL 检查、跳过 HTML、深度限制和文件路径标记：

- 相对链接按该文件的目录归一化，在同一会话、同一冻结根中打开。
- 图片先通过会话文件服务授权，再使用绑定 ETag 的句柄 URL；不取得绝对路径或其他文件的内容。图片回调只接受同源 Host 文件句柄 URL 或宿主创建的 blob。
- 秘密、未知尺寸、过大或不可读的图片只保留路径入口。远端图片是普通链接，不发送第三方请求。
- `work` 范围只允许会话已经提到的路径，不因 Markdown 中出现一个新链接而放宽。

**公式。** `remark-math` 解析美元围栏；单美元两侧必须贴着非空白文字，货币保持文字。预处理还接受代码之外的 `\(…\)` 和 `\[…\]`。KaTeX 延迟加载，失败显示 TeX 源码。

**图表。** Mermaid 在独立框内加载，渲染结果作为图片显示；触摸设备与 WebKit 由点击开始渲染。缺少框宿主时保留代码块，卸载回收框和 Blob URL。

## HTML 页面

- **默认静态显示。** 外部脚本和样式（包括 CDN 上的演示框架）被移除。桌面端可按文件开启「运行页面脚本」，脚本没有网络与同源权限。
- 框没有 `allow-fullscreen` 与 `allow-modals`，页面自己的全屏与打印不起作用。
- **另一台电脑的窗口**里没有「运行页面脚本」：那里的预览框是 `latch-frame://h-<hostId>/preview/<名称>.html`，只给 `office`、`diagram`、`html` 三个固定引导页，由主进程经 HTTPS 从那台 Host 取来并按哈希核对（[ARCHITECTURE.md](./ARCHITECTURE.md#桌面端与其他电脑)）。
- 页面在框的文档加载完成之后才装入：`html`、`body` 上的属性由框带过来（经过同样的过滤），脚本运行后框补发一次 `DOMContentLoaded` 与 `load`。

**演示页面按它写定的尺寸显示：**

- 有写定像素尺寸的舞台（约 16:9 或 4:3）时用这个尺寸；由相邻的 slide 或 scroll-snap 组成且铺满视口的页面用 1280×720。
- 框的视口就是这个尺寸，父页只把框整体等比缩放并居中，所以页面自己的缩放、`vw`/`vh`、点击位置和 `resize` 都不变，也不会缩放两次。这个尺寸在页面脚本运行之前生效。
- 隐藏的元素不算舞台；舞台或幻灯片组必须容纳页面的文字，除非页面根本不能纵向滚动。判断只是推测，可以按文件改回。
- 静态显示时演示的脚本不运行：框把只靠脚本定位的舞台移回视口，一次只显示一页的演示由框自己翻页，文件更新后停在同一页。界面写明页面脚本没有运行；缺少被移除的外部文件时提示显示可能不完整。

## 图片

- 100% 对应一个图片像素到一个 CSS 像素；适应模式按可用宽高缩小，不放大小图。
- SVG 仅作为 `img` 显示，可切换源码。
- Host 签发元数据时就拒绝超过本机一亿、其他设备五千万像素的预览。未知尺寸、格式不支持或头部不足以确认尺寸时，只提供元数据与有界下载，页面不尝试解码。

## 编辑

文本、代码与 Markdown 文件可以在预览里编辑并保存，只在 Host 给出 `actions.edit` 时出现。

**条件：** 会话里的文件；设备有 `run` 且数据范围是 `files` 或 `all`；不像密钥；不超过 1 MiB（`FILE_EDIT_LIMIT`）；页面读到的是完整的 UTF-8 文本且有 WebCrypto。

**拒绝**（Host 在 `refused.edit` 里给原因，直接请求时同样拒绝）：

| 原因 | 情况 |
| --- | --- |
| `file-edit-scope`、`file-edit-data-scope` | 设备没有 `run`，或数据范围是 `work` |
| `file-edit-elevated` | Latch 写入时按 R2 处理的路径（`isProtectedWorkspacePath`：Git 钩子、依赖清单、CI 工作流、Agent 设置、环境文件等）只给有 `approve:elevated` 的设备 |
| `file-code-root` | Latch 程序目录（与它重叠的文件夹）里的文件从不编辑 |
| `file-mixed-eol` | 混用 CRLF、LF 或 CR 的文件不编辑，不悄悄统一换行。Host 按文件开头判断，页面读到整个文件后再按同一规则判断一次 |

- 来自已移除 Agent 的只读会话不提供编辑。
- 会话或同一文件夹里有一轮在运行时不能编辑（409 `file-turn-running`）。
- 编辑器（`FileEditor.tsx`）是纯文本框，没有高亮或补全。文本、冲突与未答复的保存按会话与文件（文件夹 ID 加相对路径）留在页面内存里（`editDrafts.ts`）；关闭标签、换会话或放弃前先确认，标签关闭时编辑内容随之删除。

**保存。** 打开编辑器时页面固定读到的文本与它字节的 SHA-256（`baseHash`），之后预览照常跟着文件更新，编辑器的基准不变。「保存」发送 `PUT /tasks/:id/files/:handle { requestId, baseHash, content }`。Host 重新按读取的规则裁决句柄（在会话的文件夹里、不是受保护路径、路径中没有符号链接、普通文件），在改动记录的锁里再读一次文件：

1. 内容已经是要写的文本：不写，回答 `unchanged`（上一次保存的回答丢失后重试也落在这里）。
2. 哈希不是 `baseHash`：409 `file-changed`，带现在的 `currentHash`，一个字节也不写。
3. 否则在锁里按设备此刻的权限再核对一次（`run`，受保护路径另核对 `approve:elevated`；写审计之后与改名之前再各核对一次）。
4. 先写审计 `file.edit`：会话、路径哈希、类型、保护类别（`none` 或 `protected-path`）与前后字节数，没有内容。
5. 在同一文件夹写临时文件、`fsync`、保留原权限位，改名前再核对文件夹、文件身份与哈希，最后 `rename`。这一步发现文件又变了同样 409 `file-changed`，并补一条 `action.failed`。

属主、扩展属性与其他硬链接不随新文件保留。

**字节形状。** 文本框给出的换行是 LF，Host 按原文件写回：多数换行是 CRLF 的文件用 CRLF，结尾有没有换行与原文件一致，UTF-8 BOM 保留。

**错误：**

| 回答 | 情况 |
| --- | --- |
| 409 `file-not-text` | 不是 UTF-8 的文件，或不能编辑的文件类型 |
| 400 `file-edit-invalid` | 内容含 NUL 或孤立代理项 |
| 409 `file-not-regular` | 路径已变成链接 |
| 409 `request-id-reused` | 同一 `requestId` 换了内容 |

- **幂等。** 同一设备、会话与 `requestId` 的成功回答在内存中保留一小时，重试得到同一回答并带 `replay`；拒绝不重放，重试时重新裁决。
- **结果未知。** 超时或断线时编辑器显示结果未知，重试发送原请求。
- **桌面端的页面代理**只放行这一条写入（会话里的句柄，`PUT`），请求体上限 6 MiB + 4 KiB，与 Host 相同，足够 1 MiB 的文本在 JSON 里全部转义。

**冲突。** 409 `file-changed` 时什么也没有写。编辑器读取文件现在的内容，并排显示「文件现在的内容」与「你的修改」，只给「复制我的修改」与「载入最新」：「载入最新」把文件现在的内容作为新的基准与正文，之后的保存以它的哈希为 `baseHash`。网页、桌面端与手机都不提供覆盖。

**iPhone/iPad** 只编辑它整份读到的纯文本预览（`PhoneFileEdit`），规则相同：只在 UTF-8 正文转成 JSON 后放得进 1 MiB 请求、且换行不混用时给「编辑」。没有答复时可以重试（发原请求），或「核对并放下」：重新读这个文件，与这次保存的文字比较后丢掉待确认的副本，并写明保存了没有；句柄过期（410）也这样收尾。

**保存之后。** 保存记入改动记录（[CHANGES.md](CHANGES.md#人的编辑)），Agent 的下一轮消息前带一段说明用户编辑了哪个文件。同一页面里的「交付」给之后有保存的已提交或已推送的那一行加「需要复验」（[GIT-DELIVERY.md](GIT-DELIVERY.md)）；这个标记只在做出编辑的页面里，其他设备看不到。

## 单个文件的历史改动

文件标签可以打开同一文件列的历史视图；Host 不提供「改动」时，这一轮改动的文件也打开它。

- 历史直接使用 Host 已记录的工具差异，按用户轮次关联，保留消息顺序。它不运行 Git、不重新读取旧文件或创建本地快照。
- 历史按冻结文件夹 ID 和相对路径归组；相同文件名不会跨根合并，也不改写文件名的 Unicode 编码。
- 仍在排队、等待审批或实际未运行的拒绝调用不计入；已经执行的 Agent 调用保留其真实记录，即便它的权限询问只是建议。
- 文件删除后历史仍可查看；预览当前文件另经文件服务裁决。
- 数据范围为 `work` 的设备收不到差异正文（[STREAMING](STREAMING.md#文件差异的设备投影)），没有历史视图，同一入口打开本会话写出的文件本身。
- 初始最多五次修改，更早的记录按需加载；语法高亮只在可见的展开项中请求。差异字节不另存浏览器。
- 对照视图里每个修改块独立保留两侧行号，插入或删除缺失的一侧留空，不把未提供的原内容说成新文件。

## 自动打开新文档

设置中的「运行结束后自动打开新生成的文档」默认开启，仅作用于本设备，保留用户明确关闭的偏好。`useAutoOpenOutputs`：

- 只考虑当前视图确实见过运行中的那一轮，等待输出观察结算（[FILE-OUTPUTS.md](FILE-OUTPUTS.md)），展开首个明确新增的文档。一轮生成多个新文档时其余的只做标记，标记只在内存里。
- 只在 1024px 起、文档将打开的面板至少 480px 的窗口中打开。手机、平板、其他入口页面和展开审阅时不抢占当前页面。
- 打开不移动输入焦点、不改草稿。
- 失败、取消、修改文件、加载历史或切换会话后的旧结果都不自动打开。

## 验证范围

- `@latch/testkit` 的 `documentFixtures` 生成 DOCX、XLSX、PPTX 与 PDF 样例；没有第三方样本进入仓库。大文档基准见 [DOCUMENT-PERFORMANCE.md](DOCUMENT-PERFORMANCE.md)。
- 没有所有者从原应用导出的参照图时，只报告真实渲染结果，不声称原应用逐像素保真。
- macOS 快速查看未完成真实验收的格式继续拒绝，由文件宿主按白名单与设备权限决定。
- 随产品分发的许可证与内嵌代码的对应源码位置在 `apps/web/public/licenses/`（说明见其中的 `README.txt`）。
