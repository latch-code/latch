# 安全审阅

1. 运行 `pnpm security:scan`，审阅某个提交以来的改动时加 `-- --base <ref>`。它列出新增行中的秘密形状与 `AGENTS.md` 排除的 API、需要一起修改的文件，以及改动所属的 `AGENTS.md`。发现只是待审的位置；没有发现也不说明没有问题。
2. 读它列出的 `AGENTS.md`（根文件的「不变量」与「本机运行安全」，以及各项目的不变量），再读 `git diff <ref>` 与改动文件的上下文，逐条对照。
3. 只报两级，风格、命名与一般的正确性问题不报：
   - P0：可被利用的安全问题；秘密进入日志、输出、URL、SSE、错误信息、Git 或截图；绕过设备凭据、scope、本机确认、出站策略或无人值守运行的上限（`policy.json` 的 `unattended`）；远程设备得到只限执行端电脑的能力；测试代码或测试确认后端进入构建产物；数据丢失。
   - P1：违反不变量但不能直接利用：出错时放行；授予权限的操作没有先写审计，或减少权限的操作因审计失败受阻；新的持久化字段没有加入 zod schema；兼容标识改名没有迁移；文档或界面暗示隔离；安全行为没有测试。
4. 每条写明级别、文件与行、违反的不变量（引用 `AGENTS.md` 中的条目）、后果与修复建议。没有 P0/P1 时写明「没有发现 P0/P1」，并给出审阅的范围与 `pnpm security:scan` 的结果。
