# 验证改动

要跑什么由脚本按改动路径算出（规则在 `scripts/verify-plan.ts`）；本技能只负责运行与汇报，不另列清单。

1. 运行 `pnpm check -- --plan`，对比某个提交时加 `--base <ref>`。它只列这次改动影响的部分：「运行」与「不需要运行」两组命令，每条带触发它的改动文件；规则不认识的路径会让清单变成全部检查。整批改动合入后或发布前改用 `--full`，跑一次全部检查。
2. 按顺序运行「运行」中的命令，不额外加全量单测或全量 e2e。计划列出的 e2e 是改动的用例、同名用例与所属流程的用例；还有 e2e 驱动这条流程时一并加上，见 [TESTING](../../../docs/TESTING.md#按改动选择回归)。启动 Host、浏览器或 Electron 的用例遵守根 `AGENTS.md`「本机运行安全」：只用临时目录与端口 0，不碰用户正在运行的 Host；Electron 用例只在 macOS 运行，先 `pnpm build`。
3. 有失败时先读输出、修好原因，再重跑失败的命令与受它影响的命令；不跳过检查，不放宽规则或阈值。失败与这次改动无关时（主干上已有的失败、机器负载导致的超时），单独重跑该文件确认，并在汇报中写明。
4. 对清单最后的 `pnpm docs:affected` 列出的每个文档，判断行为变化是否需要更新它。
5. 汇报：
   - 已执行：每条命令与结果，失败的写明原因与处理；
   - 未执行：「不需要运行」中的命令（全量单测与全量 e2e 留到整批结束的 `--full`），以及因环境无法运行的命令（例如非 macOS 上的 Electron 用例），各写原因；
   - 自动化不覆盖的部分：测试确认后端、演示模型与夹具不等于 Touch ID、真实模型或真机验收（根 `AGENTS.md`「完成标准」）。
